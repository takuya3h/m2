## 前提: M1 は SKIP になった

既存成果物に **epoch 別 val 履歴が存在しない**ため、M1-2 / M1-3 / M1-5 / M1-6 は実行できなかった。
- `metrics.json` は `best_epoch` のみ、run ディレクトリに**チェックポイントなし**
- 学習ログは **10 epoch ごとの 5 点のみ**、しかも `val_acc` だけ（同じ行の `loss` は train loss）
- TensorBoard / wandb / `*.pth` は 0 件
- したがって R-loss（val loss argmin）と R-mf1（val macro-F1 argmax）は**計算不能**

指示書 M1-1 の第 3 分岐に従い、**M2 で「epoch 別 val 履歴を保存する」ことを必須要件に加える**。

## 選択規則: 事前登録するのは「規則そのもの」ではなく「規則の決め方」

M1 で `val_metric_sd` を測れなかったため、規則を事前に名指しできない。代わりに
**規則の決定手続きを事前登録し、その手続きを M2 自身の run に適用する**。

### 手続き（結果を見る前に固定）

1. M2 の全 run で **epoch 別 val 履歴**（val accuracy / val loss / val macro-F1）を保存する
2. 同一の学習軌跡から **5 規則すべて**の選択結果を事後評価する
   （規則ごとに別 run を回さない。同じ run を使うことで ICC の差を「規則の効果」に厳密に帰属できる）

| ID | 規則 |
|---|---|
| R-acc | val accuracy の argmax（**現行**。比較の基準） |
| R-last | last epoch |
| R-loss | val loss の argmin |
| R-mf1 | val macro-F1 の argmax |
| R-topk | val accuracy 上位 k=3 epoch の重み平均 |

3. 各規則について `val_metric_sd`（その規則で選んだ epoch の **val** 指標の、同一 seed の反復間 sd）を算出する
4. **`val_metric_sd`（val accuracy 基準）が最小の規則を主判定に用いる**
5. 同点（差が 1e-6 未満）の場合は、以下の**事前に固定した機構的優先順**で決める

```
R-loss > R-mf1 > R-topk > R-acc > R-last
```

優先順の根拠（結果を見る前に述べる）:
- **R-loss を最優先**: val loss は連続値なので同点・近同点が起きにくい。
  一方 val accuracy は 1,515 フレームで **1/1515 刻みに量子化**されており、
  近同点が構造的に多発する。これは観測された機序（平坦な指標の argmax が微小ノイズで勝者を移す）の直接の原因である
- R-mf1 は連続値だが、GT 不在クラスを除く macro 平均のため分母がクラス構成に依存し不安定になり得る
- R-topk は平均化で分散を下げるが、重み平均が TCN の非線形性下で意味を持つ保証がない
- R-acc は現行だが量子化の問題を抱える
- **R-last は選択ノイズがゼロだが過学習リスクがある**。採用する場合は
  val 曲線が後半で単調減少していないことを確認し、根拠をレポートに書く

6. **決定性制御（`use_deterministic_algorithms` 等）は M2 では入れない。**
   規則と同時に変えると ICC の改善をどちらに帰属できなくなる。
   規則が無効（予測 1 が成立しない）だった場合の次手として残す

## 予測（結果を見る前に固定）

- **予測 1**: 分散分解で `var_within_seed`（反復間）> `var_between_seed`（seed 間）が
  M1 の規則適用後は解消する。すなわち **ICC が上がる**
  - 検証法: 同一の 72 run から R-acc と採用規則の ICC を算出して比較する
- **予測 2**: (8−7) は **mask≠bbox のフレームに限った解析**で判定閾値を超える。
  根拠: 手の充填率 0.578 は術具 0.204 より高く、マスク化による画素数減少の損失が小さい。
  **★ この部分集合解析を主判定に含める**（前回は事後解析だったため昇格させなかった）
- **予測 3**: (3−2) は術具では非超過または負のまま。すなわち充填率が低い対象では
  マスク化は利得を生まない
- **予測 4**: (9−2) は macro-F1 でも判定閾値を超える。前回の非超過は選択ノイズによる
  検出力不足であって効果の不在ではない
- **予測 5**: (5−1) は非超過のまま（S3 の PASS が n を増やしても維持される）

## 判定手法

S2 で確定した方法。ただし n が 3 → 9 に増えるため:

- **SE は反復を含めた全 run（n=9）から算出する**。`SE = sqrt(sd_A²/9 + sd_B²/9)`、Welch の df
- **分散分解（between-seed / within-seed）を併記する**。一元配置変量効果モデル
  （seed を群、反復を群内）で `var_within = MSW`、`var_between = (MSB − MSW)/3`、
  `ICC = var_between / (var_between + var_within)`。負になった場合は 0 に切り上げて明記する
- **併記**: 動画別の差の符号一致（val 2 動画 / test 3 動画）。
  帰無仮説下で全動画同符号となる確率は val 0.50 / test 0.25 であり、
  慣習的な有意水準には原理的に到達しない。方向の一貫性の証拠としてのみ報告する
- **補足**: 動画単位クラスタ・ブートストラップ（相異なる多重集合が val 3 通り / test 10 通り）
- 主指標は **per-phase F1**。overall accuracy / macro-F1 は併記
- val と test の両方で評価し、**val だけの結果を結論と呼ばない**

### (8−7) の部分集合の定義

「mask≠bbox のフレーム」を**特徴レベルで厳密に定義する**:
`handROImask2` の特徴ベクトルが `handROIbbox2` と一致しないフレーム。
（フレーム内の全ての手 box が bbox にフォールバックした場合、両者は完全に一致する）
部分集合の **n とフレーム数を必ず併記する**。

## 事前に想定される無効化条件

- 72 run が同一 commit・同一ホストで実行されていない場合、比較を無効とする
- いずれかの run で MSDeformAttn CUDA 拡張のロードが失敗した場合、その run を無効として除外する
- epoch 別 val 履歴が保存されていない run がある場合、規則の事後評価が不能なので M2 を無効とする
