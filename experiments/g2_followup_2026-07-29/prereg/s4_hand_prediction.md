## 問い

手の情報は術具の情報に対して本当に冗長か。

過去の H-6（+0.0004）は分母が oracle-tool（acc 0.9583）で、**上限まで 0.0417 しか残っていない飽和領域**での
測定だった。しかも判定閾値 0.0099 を下回っており、**測定できていなかった**。実運用に近い動作点
（base acc 0.8318 / bboxROI acc 0.8925、いずれも G-2 実測）では一度も測られていない。

## S4-1 の実測（設計の前提。指示書 §1.5 との差異を含む）

分母 = canonical 15,437 フレーム、`ann >= 1` 基準、join は basename。

| split | cov_frame(手 mask) | cov_frame(手 bbox) | 幾何マッチ率 | クラス食い違い率 |
|---|---:|---:|---:|---:|
| train | 0.5869 | 0.9969 | 0.8986 | 0.0017 |
| val | 0.8871 | 1.0000 | 0.9992 | 0.0000 |
| test | **0.4910** | 0.9977 | 0.9982 | 0.0000 |
| 合計 | **0.5899** | 0.9974 | 0.9347 | 0.0011 |

**指示書 §1.5 との差異 2 点（事実を採用する）:**

1. **手 mask は 2 クラスしか無い**（First Person's Left/Right Hand）。手 bbox は 4 クラス
   （Own/Other × Left/Right）。**"Other hands" に対応する mask が存在しない。**
2. **手 mask の cov_frame は 0.5899** で、術具（0.9728）より大幅に低く split 依存が強い。
   test では **50.9% のフレームに手 mask が 1 件も無い。**

## 系統（すべて base 3,840-d を起点に加算。D = 256）

```
1.  base                    3,840-d                     （G-2 の系統 1 と同一定義）
2.  bboxROI                 3,840 + 15x256 = 7,680-d    （G-2 の系統 2 と同一定義）
6.  +handPresence           3,840 + 4       = 3,844-d   手 GT presence 4 次元（bbox 4 クラスの有無）
7.  +handROI(bbox,2cls)     3,840 + 2x256   = 4,352-d   手 GT box の ROI（First Person L/R）
7b. +handROI(bbox,4cls)     3,840 + 4x256   = 4,864-d   手 GT box の ROI（4 クラス全部）
8.  +handROI(mask,2cls)     3,840 + 2x256   = 4,352-d   手 GT mask の ROI（First Person L/R）
9.  bboxROI + handROI(bbox,2cls)  3,840 + 15x256 + 2x256 = 8,192-d  ★実運用条件での主判定
```

**クラス体系を揃える理由**: 系統 7 を 4 クラス・系統 8 を 2 クラスで作ると、(8−7) が
「mask vs bbox」と「2 クラス vs 4 クラス」を**交絡**する。(8−7) を「背景除去の効果」として
読むために 7 と 8 を同じ 2 クラスに揃え、§1.5 が挙げる「他人の手」の寄与は
**(7b−7) として別途測る**。

ROI チャネルの作り方は G-2 の `build_roi_channels.py` と同一手続きに揃える
（検出器 neck level0 / stride 8 / D=256、box 内の画素平均、mask は box に IoU≥0.5 で幾何マッチ、
**mask 無しは bbox にフォールバック**、未検出クラスはゼロベクトル）。

## 予測（結果を見る前に固定）

- **予測 A**: (6−1) は判定閾値を超える。過去の +0.0004 は飽和領域の artifact であり、
  非飽和な動作点では手は寄与する
- **予測 B**: (9−2) も超える。すなわち術具 ROI があっても手は追加情報を持つ
- **予測 C**: 手は充填率 median 0.578 と高く（術具 0.204）、box 内の背景混入が少ない。
  したがって G-2 で観測された「ROI を絞ると悪化する」現象は手では弱く、
  **(8−7) は術具の (3−2) ほど負に振れない**
- **予測 D**（S4-1 を受けて追加）: (7b−7) は判定閾値を超えない。
  「他人の手」は工程認識に対して自分の手ほどの情報を持たない

## 判定手法

S2 で確定した方法を用いる:

- **主判定**: seed 水準の Welch。`SE = sqrt(sd_A²/3 + sd_B²/3)`、Welch の df、
  `|差| > t(0.975, df) × SE` を「超過」とする
- **併記**: 動画別の差の符号一致（val 2 動画 / test 3 動画）。
  帰無仮説下で全動画同符号となる確率は val 0.50 / test 0.25 であり、
  慣習的な有意水準には原理的に到達しない。**方向の一貫性の証拠としてのみ報告する**
- **補足**: 動画単位クラスタ・ブートストラップ（B=2,000）。
  相異なる多重集合が val 3 通り / test 10 通りしかない旨を明記して併記する
- 主指標は **per-phase F1**。overall accuracy / macro-F1 は併記のみで判定に使わない
- val と test の両方で評価し、**val だけの結果を結論と呼ばない**

## 希釈への対応（S4-1 を受けて固定）

test では 50.9% のフレームに手 mask が無く、そこでは `handROI(mask) = handROI(bbox)` になるため
(8−7) のコントラストが強く希釈される。したがって:

- **主判定は全フレーム**（実運用条件）で行う
- **あわせて「手 mask が 1 件以上あるフレームのみ」の部分集合で (8−7) を再集計して併記する**
  （per-frame 予測を保存するので再学習不要）。部分集合の n とフレーム数を必ず併記する
- 部分集合の結果を主判定に**昇格させない**。両方を並べて報告する

## 事前に想定される無効化条件

- run が同一 commit・同一ホストで実行されていない場合、比較を無効とする
- 手 ROI 抽出時に MSDeformAttn CUDA 拡張のロードが失敗した run は無効として除外する
- 新たに学習する base / bboxROI が S3（`1eec7ba`）の値を再現しない場合、
  差異を定量化して報告する（S3 で発見した同一 seed 非再現性のため、
  **再現しないことを既定の想定とする**）

## 既知の制約（S3 で発見。結果の読み方に直結する）

**同一 seed でも結果が再現しない。** 同一ホスト・同一 seed・同一設定でも、
同一 seed の再実行差が seed 間 sd を 8 項目中 7 項目で上回った
（最大は base の test macro-F1 で 0.0449、seed 間 sd は 0.0220）。
機序は best-epoch 選択の離散増幅（val accuracy が epoch 間でほぼ平坦なため、
微小な非決定性が argmax の勝者を別 epoch に移す）。

したがって S4 では:

- 3 seed の sd は「seed 起因のばらつき」ではなく **「run 間ばらつき」の推定値**として読む
- **点推定の精度は accuracy で約 0.01、test macro-F1 で約 0.045 が下限**であり、
  それより細かい差を主張しない
- n=3 の分散推定が不安定であることを結論に必ず併記する
- **この制約下で「非超過」だった対比を「効果が無い」と読み替えない**（検出力不足と区別できない）
