### 判定表に当てはまらなかった理由

`env.json` の**内容は 12 run でバイト同一**（md5 1/12）。判定表では「全 run で同一文字列 → TEMPLATE」だが、実態は異なる。

`env.json` のフィールドは `torch` / `cuda_version` / `cuda_available` / `gpu` / `cudnn` / `host` /
`commit` / `ninja_on_path` / `python` / `msdeformattn_extension_loaded` の **10 個すべてが環境水準の定数**であり、
run 固有の値（時刻・seed・秒数・in_dim）を **1 つも含まない設計**である。したがって内容がバイト同一になるのは
仕様どおりで、雛形の使い回しの証拠にはならない。run 固有情報は `metrics.json` 側にあり、そちらは 12/12 ユニーク。

### S1-2: 拡張ロード成否はどこで測られているか

### S2-4: ブートストラップの限界（全列挙・実測）

復元抽出で生じる相異なる多重集合を**全列挙**し、多項係数から出現確率を厳密に算出した。

| split | 動画 | n | 相異なる多重集合 | 公式 C(2n−1,n) | 順序付き抽出 n^n |
|---|---|---:|---:|---:|---:|
| val | 09, 10 | 2 | **3** | 3 | 4 |
| test | 04, 05, 07 | 3 | **10** | 10 | 27 |

**val の 3−2（accuracy）が取りうる値は 3 点のみ**:

| 多重集合 | 順序数 | 確率 | diff |
|---|---:|---:|---:|
| 09×1 + 10×1 | 2 | 0.5000 | +0.000880 |
| 09×2 | 1 | 0.2500 | +0.000000 |
| 10×2 | 1 | 0.2500 | +0.001337 |

test は 10 点（min −0.021820 / max +0.034111、最頻の 04+05+07 が確率 0.2222 で +0.000782）。

**B=2,000 回のブートストラップが実現した相異なる値の数を実測したところ、val 3 個・test 10 個ちょうどで
全列挙と完全一致した。** すなわち B をいくら増やしても点は増えない。**解像度は B ではなく動画数で決まる。**

これが **CI 端点に `+0.00000` が頻出していた理由**である。val の 3−2 accuracy では 2.5 パーセンタイルが
必ず最小値 0.000000（確率 0.25 の点）に落ちる。percentile CI はこの少数の離散点の重み付き分位数にすぎず、
連続分布の信頼区間として読むことはできない。

### この 2 手法が答えている問いは別である（誠実性のための明記）

- **seed 水準 Welch** は「**この動画集合の上で**、別の seed を引いたら同じ結果になるか」に答える。
  動画集合は固定として扱われており、**別の動画への一般化は保証しない**。n=3 seed で df は 2.0–4.0。
- **動画別の符号一致**は「別の動画でも同じ向きか」に答えるが、**動画が 2–3 本しかない**。
  効果ゼロ（各動画の符号が独立に等確率）という帰無仮説の下で「全 n 本が同符号」になる確率は
  **val で 2·(1/2)² = 0.50、test で 2·(1/2)³ = 0.25** であり、慣習的な有意水準には**原理的に到達できない**。

したがって「3/3 の動画で同符号」は**方向の一貫性の証拠**として報告するにとどめ、
統計的有意性の主張に読み替えない。この 2 つを併記することが、動画 3 本で CI を出すより誠実である。

### S2-6: G-2 の判定は変わるか

**核心の判定は変わらない。**

- **3−2（背景除去）**: 指定 3 工程 × 2 split の **0/6 で正方向に超過せず**（旧手法と同じ）。
  test/incision は **−0.0308（p=0.0034、3/3 同符号）** で、旧手法より**むしろ明確に負**。
  → 事前登録の **FAIL＝「背景は region-token のボトルネックでない」は維持**。
- **2−1（ROI チャネル追加）**: test の incision / closure / accuracy / macro-F1 が
  いずれも Welch 有意かつ **3/3 同符号** で、旧手法の「超えた」を維持・補強。

判定が変わったのは **3 件のみ**で、いずれも **val（動画 2 本）** の周辺項目である。

| 項目 | diff | 旧（Welch AND boot） | 新（Welch 主） | Welch p | boot が 0 を跨いだ | 全動画同符号 |
|---|---:|---|---|---:|---|---|
| val / 2−1 / hemostasis | +0.1223 | 非超過 | **超過** | 0.0060 | Yes | No（+1/0:1） |
| val / 2−1 / closure | +0.0128 | 非超過 | **超過** | 0.0003 | Yes | No（+1/0:1） |
| val / 4−2 / closure | −0.0027 | 非超過 | **超過** | 0.0226 | Yes | No（+0/−1/0:1） |

3 件とも「Welch は有意だがブートストラップが 0 を跨いだ」ケースで、旧手法では AND 条件により落ちていた。
新手法では Welch を主とするため超過になる。**ただし 3 件とも全動画同符号ではない**（val は動画 2 本で、
うち 1 本の差がちょうど 0）。§7 に従い、**この 3 件は「seed 水準では有意だが動画方向の一貫性は無い」
という状態のまま記録する**。いずれも G-2 の結論（3−2 の FAIL、2−1 の有効性）には影響しない。
