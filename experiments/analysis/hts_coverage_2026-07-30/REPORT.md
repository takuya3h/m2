# EgoSurgery-HTS の tool/phase に対するカバレッジ監査

- 日付: 2026-07-30
- 目的: EgoSurgery-HTS の 3 アノテーション種（hand seg / tool seg / hand-tool seg）が、
  既存実験で使っている egosurgery_tool（術具+手 bbox）および egosurgery_phase に対して
  どの動画・どのフレームで欠落しているかを網羅的に確認する。
- 再現: `scripts/audit_hts_vs_tool_phase.py`（本文の集計を標準出力に再現）
  / `scripts/audit_hts_coverage_export.py`（`csv/` 3 本を再生成）

## 判定方法

- 判定単位は **フレーム basename**（例 `03_1_0001`）。
- HTS の `json_per_video/<seg>/<seg>.json` は**親動画の全フレームを重複列挙する**ため
  （例: `03_1.json` の中身は 03_1 + 03_2 の 1,472 枚）、basename で dedupe して集計。
- 「アノテーションあり」= **annotation を 1 件以上持つ image**。
  `images` に列挙されているだけでは不十分（`03_tool/json_per_video/03_1` は 0 anns）。
- 欠落を 2 種に分離:
  - **(a) `not_in_hts_universe`** … HTS の対象フレーム集合（19,560）に存在しない → **真の欠落**
  - **(b) `listed_but_zero_annotation`** … 列挙されているが注釈 0 件 → 対象物が写っていない**正当な負例**

## 参照側・HTS 側の規模

| データ | フレーム数 | 動画 | セグメント |
|---|---|---|---|
| 元フレーム画像（disk） | 27,535 | 15 | 26 |
| HTS 対象フレーム集合 | 19,560 | 15 | 25（**03_3 なし**） |
| egosurgery_tool（術具 bbox） | 15,437 | 15 | 22 |
| egosurgery_tool/hand（手 bbox） | 15,397 | 15 | 22 |
| egosurgery_phase | 17,233 | 15 | 23 |

HTS 側の注釈実在フレーム: hand **19,432** / tool **18,499** / hand-tool **18,397**。

## 結論 1: 全 15 本の動画は 3 種すべてに含まれる

hand / tool / hand-tool のいずれも動画 01〜15 を網羅。**丸ごと欠落した動画は無い。**

ただしセグメント単位では以下が欠落:

| セグメント | 状況 |
|---|---|
| `03_3`（disk 261 枚 / phase 168 枚） | **3 種すべてで完全欠落**。`json_per_video/03_3/` は存在するが 0 anns で中身は 03_1/03_2 のフレーム（空の殻）。master `03/annotations.json` も 03_1+03_2 のみ |
| `03_1` | tool seg のみ 0 件（hand 127 / hand-tool 123） |
| `12_2` | HTS 対象は 269 枚中 8 枚のみ。hand-tool は 0 件 |

`03_1` / `12_2` / `15_2` は tool・phase 側に存在しないので参照比較には影響しない。

## 結論 2: egosurgery_tool に対しては実質欠落ゼロ（真の欠落 0%）

| HTS 種別 | カバー | 欠落 | 内訳 |
|---|---|---|---|
| hand seg | 15,397 / 15,437 = **99.74%** | 40 (0.26%) | 宇宙外 0 + 注釈0件 40 |
| tool seg | 14,967 / 15,437 = **96.96%** | 470 (3.04%) | 宇宙外 0 + 注釈0件 470 |
| hand-tool seg | 14,977 / 15,437 = **97.02%** | 460 (2.98%) | 宇宙外 0 + 注釈0件 460 |

**tool bbox の 15,437 フレームは 100% が HTS の対象フレーム集合に含まれる**（宇宙外 = 0）。
欠落として現れる 40〜470 枚は全て「そのフレームに対象が写っていない」正当な負例。
手 bbox（15,397）に対しては hand seg のカバー率 **100.00%**。

動画別の注釈0件率（tool seg, 対 tool bbox）: 05 が 21.31% と突出、他は 0〜4.7%。

## 結論 3: egosurgery_phase に対しては 10.4% が真の欠落

| HTS 種別 | カバー | 欠落 | 内訳 |
|---|---|---|---|
| hand seg | 15,397 / 17,233 = **89.35%** | 1,836 (10.65%) | **宇宙外 1,796** + 注釈0件 40 |
| tool seg | 14,967 / 17,233 = **86.85%** | 2,266 (13.15%) | **宇宙外 1,796** + 注釈0件 470 |
| hand-tool seg | 14,977 / 17,233 = **86.91%** | 2,256 (13.09%) | **宇宙外 1,796** + 注釈0件 460 |

真の欠落 1,796 枚のセグメント別内訳:

```
03_3:168(全損) 04_1:238 09_1:154 08_1:149 10_1:135 11_1:111 03_2:106 10_2:100
01_1: 86 05_1: 78 04_2: 76 07_1: 75 02_1: 68 06_1: 51 15_1: 46 08_2: 42
14_1: 34 13_1: 21 06_2: 17 05_2: 15 14_2: 14 12_1: 10 07_2:  2
```

phase 側 15 本すべての動画で一部欠落（動画別 1.78%〜22.92%）。
最悪は動画 09（22.92%）・03（21.35%）・04（19.11%）・10（19.07%）。

## 結論 4: HTS は tool bbox に無いフレームを 3,420〜4,035 枚追加で持つ

hand 4,035 / tool 3,532 / hand-tool 3,420 枚が tool bbox の対象外。
うち `03_1`(127) `12_2`(8) `15_2`(317) は tool/phase に一切存在しないセグメント。
動画 12_1(571) 15_1(393) 07_1(347) 06_1(297) などで増分が大きい。

## 結論 5: split 構成は 1 ファイルだけ食い違う（要注意）

egosurgery_tool の split は train=10本 / val=2本 / test=3本（10/2/3）。

| ファイル | train | val | test | 一致 |
|---|---|---|---|---|
| `egosurgery_tool` | 01,02,03,06,08,11,12,13,14,15 | 09,10 | 04,05,07 | 基準 |
| `02_hand/coco_splits_4cls` | 同上 | 09,10 | 04,05,07 | ✅ |
| `03_tool/coco_splits_14cls_cleaned` | 同上 | 09,10 | 04,05,07 | ✅ |
| `04_handtool/seg_ann_4cls` | 同上 | 09,10 | 04,05,07 | ✅ |
| `04_handtool/coco_splits_5cls` | 01,02,06,08,11,12,13,15 | **04,05,07** | **09,10** | ❌ |

`coco_splits_5cls` は **val/test が入れ替わり、動画 03 と 14 が train から脱落**している。
train に test 動画（04/05/07）は入っていないので学習リークは無いが、
**評価セットの定義が egosurgery_tool と異なるため Δ 基準点の比較に使ってはいけない。**
`Two Hands Tool`（5クラス目）が必要な場合は、この split を捨てて
`json_per_video` から 10/2/3 split を再構成すること。

## 実験計画への含意

- **3 タスク同時学習に使えるフレーム（hand ∩ tool ∩ hand-tool）= 17,512 枚**
  - vs tool bbox: 14,570 / 15,437 = 94.38%
  - vs phase: 14,570 / 17,233 = 84.55%
- 検出（tool bbox）を軸にするなら HTS は実質フルカバー。**セグメンテーション補助タスクの追加は
  データ欠落を理由に妥協する必要がない。**
- 工程認識（phase）と HTS を同一フレームで結合する設計にすると **13% 前後のフレームを失う**。
  phase 主導のマルチタスクでは、HTS 側を欠損許容（タスク別マスク付き loss）にするのが安全。
- `03_3` は HTS 側に永久に存在しない。phase の 03_3（168枚）を使う実験では
  HTS 由来の入力・監督が全て欠損する前提で扱うこと。
