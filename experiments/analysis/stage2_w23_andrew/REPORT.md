## 1. 何を回したか

- 型: decoder-xattn（工程から検出、略 DX）と案 B（把持の地図を C5 に足す型、略 B）。受け取り手はどちらも検出塔 D*-COCO 折り A seed 42
- W: W2 と W3。腕: 空・予測-noCF・正解・入れ替え（利用者の指示 2026-11-02 で予測-CF・正解予測-CF と P1 を外した。計 16 本）
- 処方は W1 と同じ: 受け取り手の学習率 1e-4、界面 5e-4、AdamW（weight decay 1e-4）、batch 2、`presets.detr`、学習は bf16 の自動混合精度・評価は単精度、
  4 epoch の固定の長さ、最後の状態、seed 42。**`finetune_t1b` の群分けにより、backbone と `reference_points`・`sampling_offsets` の重みは学習率 × 0.1（1e-5）**
  （W3 で効く。既存の処方のまま）。腕と信号の対応は W1 の台本の写し（W1 の run の記録と 36/36 で照合）
- 1 枚 3 本で回した（W3 の記憶の山 11.4〜12.6 GB）。所要は W3 5.3〜5.9 時間、W2 3.1〜4.8 時間（同時に並べた本数で変わる）

## 4. 既知の限界（SPEC §6.4）

- 折りは 1 つ（A）、val は 2 動画（09・10）、seed は 1 つ。差はすべて 1 本ずつの差で、幅を持たない
- 受け取り手は train で学習済みで、W2・W3 は同じ train でさらに学ぶ。W3 で全腕が塔単独より下がったのはこれと、学習率が一定であることの両方が効きうる（分けていない）
- 長さは固定の 4 epoch で、受け取り手を学ぶときの収束規則に従っていない（利用者の決定）。W3 は epoch 4 でも epoch ごとに値が動いている
- 工程塔の W3 は本契約に無い（本契約の型の受け取り手はどちらも検出塔）
- 型を二つのホストに配分したので、bengio の型と並べるときはホストの差を含む。本契約の 16 本と、参考に並べた W1・P1 の run はすべて andrew
- 数値精度は前回の経路のまま（学習は bf16 の自動混合精度、評価は単精度）
- W&B は手元だけ（offline、版管理の外 `$S/wandb/`）。`train_t1b.py` は W&B を配線しておらず、後処理が epoch ごとの val を手元に記録した
