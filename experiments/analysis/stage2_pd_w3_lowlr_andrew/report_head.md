# REPORT — 工程から検出の W3 を受け取り手の学習率 1e-5 で回し直す（andrew）

**非公式の測定。関門と設計の判断に使わない。**

契約 T-2026-11-09-stage2-pd-w3-lowlr-andrew。ホスト andrew（RTX A6000 × 2、電力の上限 300 W）。折り A、seed 42、val の動画 09・10（1,515 枚）。test の動画（04・05・07）は学習にも評価にも通していない。

## 0. 何をしたか

- 前回の W3（bengio の P1・P2L・P3、andrew の DX。受け取り手 1e-4）と同じ処方で、**受け取り手の学習率だけ 1e-4 → 1e-5** にして 4 型 × 4 腕 = 16 本を回した
  - 型: P1（FiLM）、P2L、P3、DX（decoder-xattn）。どれも d9 の設定
  - 腕: 空（`--zero-ctx`）、予測-noCF（P0）、正解（P-GT）、入れ替え（直しの契約の並べ替え）
  - 処方: W3 = 界面 ＋ `--trainable all`（backbone の conv1・layer1 の 11 個を除く全体）、4 epoch を止めずに学び 4 epoch 目の状態を結果にする、AdamW（weight decay 1e-4）、batch 2、
    勾配の刈り込み 0.1、学習は bf16 の自動混合精度・評価は単精度
- 群の学習率（各 run の `lr_groups.json`。optimizer を作った直後・各評価の直前・最初の更新の後の 7 時点）:
  - 受け取り手の群（other・other_norm）1e-5
  - 比 0.1 の群（backbone・backbone_norm・linear_projection・linear_projection_norm）1e-6
  - 界面（phase）5e-4
  - 16 本とも 7 時点で 1 通り、更新は 19,236 回（4 × 4,809）
- 塔単独の値は B-2 の再現（記録との差 0.0）。前回の W3 の値は SPEC §1 から写さず、前回の各 run の記録から同じ関数で計算した。SPEC §1 の表とは小数 4 桁で全件一致した
- 所要: 総 15 時間 43 分（11-09 10:53 〜 11-10 02:37 JST）
  - 1 本あたり、P1・P2L・P3 は 5.74〜5.85 時間（1 枚 3 本）、DX は 3.99〜4.04 時間（1 枚 2 本）
  - 溢れ・発散・非数で止まった run は 0 本

## 3. 既知の限界（SPEC §6.4）

- 折りは 1 つ、val は 2 動画、seed は 1 つ
- 学習の長さは固定の 4 epoch である。学習率 1e-5 では、4 epoch で受け取り手が動く幅が小さい（相対の L2 0.0074。前回の DX は 0.0552）
  - 差が小さいのは、学習率が低いためとも読める
- 数値精度は bf16 の自動混合精度で、規約の precision 節の TF32 ではない
- 前回の W3 は、DX が andrew、P1・P2L・P3 が bengio の値である。W2 は P1・DX が andrew、P2L が bengio。ホストが違う値を並べた所は参考
- 検出塔の選び直し（`tower_reselect_search_dlsta`）が進んでいる。塔が替われば、本契約の値は旧い塔での測定になる
