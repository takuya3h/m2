## 5. 読み方の規則に沿った記述

1. **表の値は実測だけである。** 内訳は CPU の壁時計の区間で、各境界で GPU の処理の終わりを待っている。GPU の中で重なって動く処理（例: 先読みの転送と計算、逆伝播と勾配の all_reduce）は分けられない。
   - 同期は、学習が本来持つ CPU と GPU の重なりを消す。水準 1 の一歩 0.3905 s（同期あり、歩 21〜80）と直前の計測の 0.3915 s（同期なし、歩 11〜60、PR 290）は、窓も乱択の入力も違う。この二つの差 −0.0010 s を同期の費用とは読まない。
   - 同期なしの時計で読んだ場合に当たる「1〜5 の CPU の発行時間の和」は、水準 1 の rank 0 で 0.3542 s だった。同期ありの 1〜5 の和は 0.3841 s、一歩は 0.3905 s である。待ちを入れない時計では、逆伝播（0.1906 → 0.1644 s）と最適化器（0.0107 → 0.0071 s）の分が欠ける。
2. **GPU が遊ぶ時間**は二つの値で書く。どちらも参考の精度である。
   - (a) nvidia-smi の使用率が 0 の区間の長さ: 全水準・全 GPU で、歩の区間の標本（95〜201 個）に使用率 0 は 0 個だった。したがって 0 s/歩である。nvidia-smi の使用率は「標本の周期の間に kernel が一つでも動いていた時間の割合」なので、0.2 s より短い隙間は 0 として現れない。
   - (b) 内訳の 1・3・5・6 の和: 2 プロセスで batch 2 は 0.061〜0.068 s/歩、batch 4 は 0.079〜0.082 s/歩。1 プロセスで batch 2 は 0.048 s/歩、batch 4 は 0.064 s/歩。読み込み無しは 0.050〜0.099 s/歩。3 には GPU で動く損失の計算も含まれるので、(b) は GPU が止まっている時間そのものではない。
3. **歩の区間だけの GPU 使用率**は、読み込み有りの batch 2 で 77〜82 %、batch 4 で 88〜91 %だった。直前の計測（PR 290）の 43〜69 % は、記憶が 1 GiB を超えていた間の全標本の平均で、起動と止めの間の待ちを含む。本表とは平均を取る窓が違う。
