## 3. 既知の限界（§5.4）

- 折りは 1 つ、val は 2 動画、seed は 1 つ。区間推定もクラスタの推論もできない。工程は動画 09 が塔単独で上限に近く（Jaccard 0.993）、DP の差はほぼ動画 10 で決まる
- 4 epoch 目の値にも epoch ごとの揺れは残る（選び方の偏りは除くが、揺れは除かない）。たとえば P1-W1 の空の腕は epoch 0〜3 で 0.7312 / 0.7269 / 0.7302 / 0.7236
- 回し直した PD の run は前回の run と完全には一致しない（GPU の計算の非決定性。epoch ごとの val mAP の差は 0.0011 以内）。DP の回し直しは完全一致
- 入れ替えの腕は、フレームとの対応を壊すと同時に時間方向のつながりも壊す。差には両方が含まれる。val は動画が 2 本しかないため、入れ替えた後も
  55.6% のフレームは同じ動画のフレームの信号を受け取る（train は 11.5%）
- **ホスト**: P3 の予測-CF と正解予測-CF は bengio で、P3 のほかの 4 本と他のすべての run は andrew で回した（利用者の承認による逸脱）。
  入力の要約値と Relation-DETR の中身は andrew と一致させたが、GPU の個体差は残る。P3 の予測-CF・正解予測-CF の Δ空 と Δ入替 にはホストの差が混ざる
- **値の出所の混在**: PD の 12 本（P1-W1 の正解・予測-CF・正解予測-CF、P1-W2 の 4 腕、P2L の 5 腕）は前回の run の epoch 3 の記録で、回し直していない。
  そのうち 8 本は epoch 3 の予測が残っていないため、動画ごとの値が UNKNOWN（表に理由つきで書いた）
- 前回の限界（受け取り手も train で学習済み、塔のホストの違い、工程注釈だけのフレームを使っていない、型ごとに学習率を探していない）はそのまま残る
