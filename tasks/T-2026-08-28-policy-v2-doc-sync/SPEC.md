## 1.2 README と CLAUDE.md に書く内容の典拠

以下は方針 v2 の確定事項である。**実行者はこの範囲でのみ書き、ここに無い数値や主張を足さない。**
言い回しは実行者が整えてよいが、用語（塔・界面・参照入力段・学習範囲）はここの語をそのまま使う。

### 設計の骨格

- 従来の共有凍結 backbone 方式は、一方のタスクの情報が他方の判断を良くするかという問いに対して
  測定器の型が合っていなかった。新設計は**二塔・界面分離型**である
- 各タスクが自前の最良モデル（**塔**）を持つ。検出塔は術具ラベルのみ、工程塔は工程ラベルのみで学習し、学習後は凍結する
- 結合は塔と塔の間の小さな学習モジュール（**界面**）だけで行う。比較で変えるのは界面の**入力**だけ
- 方向マスクは、なし・検出から工程・工程から検出・双方向の四腕
- **参照入力段**は各方向で、空・予測・正解・正解と予測の和の四段。上限として使えるのは最後の段だけである
  （旧来の上限という語は廃止した）
- **学習範囲**は三水準。入力適合層のみ（W1）、末端ブロックまで（W2）、受け取り塔全体（W3）

### 判定の規則（CLAUDE.md の旧規則の置き換え先）

- 評価は動画単位の五分割と五つの種。**判定単位は動画で十五個の対の差**を得る
- 主判定は**折りをクラスタとするブロック・ブートストラップの信頼区間が零を含まないこと**。
  同一折りの三動画は同じモデルで評価されるため独立ではなく、クラスタは折りに取る
- **主判定は一つだけ**置く。確認的な腕は事前に列挙し、族内で Holm 補正を当てる
- 折り単位の全数同符号は主張に使わない（五分割では符号検定の最小の値が原理的に有意へ届かないため）。
  記述統計としてのみ併記する
- 工程の主指標は macro Jaccard、同方向要件として frame accuracy を併せる。
  検出は overall mAP と標的群 AP の二本立てに、陰性対照群を添える
- 効果量は差そのものと、分母の折り間の散らばりで割った値の両方を併記する

### 相互改善の定義と三段構え

- **定義 A（同時改善）**を主判定とする。双方向腕で検出と工程の差がともに正で主判定を満たすこと
- 達成できない場合は第二段（一方向のみ改善・他方は非劣化。執筆方針を変え改題を検討）、
  第三段（両方向とも差が実質零。分析論文と単独の最高性能）へ移る。各段の論文の形を先に決めてある

### 事前登録した競合三仮説

- **H1 方向依存** — 転移の符号はどちらの方向かで決まる
- **H2 次元選択則** — 符号と大きさは通す次元の性質で決まり、方向は二次的
- **H3 受け取り手表現依存** — 情報の価値は送り手の質ではなく受け取り手の表現に条件付けられる

論文の主張は先に固定せず、識別実験で残った仮説から決める。

### 段階と関門

- Stage 0（土台整備）から Stage 5（拡張）まで。関門は G0・G1・G1.5・G2・G3・G4
- 現在地は **Stage 0 の起票前**である
- 投稿先は MICCAI 2027 または IPCAI 2027。**どちらを主目標にするかは G0 の所要時間実測後に決める（未決）**

### 保留と未了

- 中核主張の一つ（凍結源を替えると工程側の差の符号が反転したという記録）の**数値の出所照合が未了**である。
  Stage 0 の調査契約で照合する
- 手術の手アノテーション完全版の組立は**保留**（利用者の判断待ち）。手信号を使う腕はその後

### 撤回された原則（README の設計原則から外すもの）

- 全比較対象を同一の凍結 backbone に載せる（比較の三角形）
- 工程側の分母を独立に最適化しない
- 分母を系統ごとに複数運用する
- 段階実験の連番による命名と、その分母追跡を中核に置く枠組み

置き換え後の新しい原則は「受け取り手（塔と界面の型・容量・水準・スケジュール・種）を全腕で同一にし、
変えるのは界面の入力だけ」である。

### 延期している要素（将来拡張として残す）

セグメンテーション、関係推論、視点外カメラ。

## 7. 想定外の扱い

| 事象 | 対処 |
|---|---|
| 時系列ログの境界が一意に決まらない | 候補の境界と根拠を報告して停止（escalate） |
| 撤回済みの語が履歴以外の節に説明として必要 | 書き換えずに該当箇所を報告して停止（escalate） |
| 文書系の検査が Makefile に見当たらない | 「存在しない」と断定せず、全対象の一覧を audit に載せて停止（escalate） |
| リンク検査で既存の壊れリンクが今回の変更と無関係に見つかる | 直さない。今回の変更で新たに壊したものが零件であることを差分で示し、既存の壊れは件数と一覧を audit へ |

失敗時の巻き戻し: 変更はすべて作業分岐上にあり、統合前なら正本に影響しない。
停止する場合も分岐と audit を残したまま stopped で報告する。

## 8. 報告の構成

RESULT.md は起票者が判断に使う事実だけを書く。目安は百五十行以内。

- 判定: verdict と関門の結果
- 完了判定: §5 の表に実測値を埋めたもの
- 実測: 次の契約で使う値（履歴ファイルの経路と要約値・時系列ログの境界・置換した commit hash・撤回済みの語の残存件数）
- 起票者の誤り: 型と内容。一件三行以内
- 逸脱・想定外・UNKNOWN
- 送出: PR 番号と exit code のみ

命令とその出力の全文・検証の出力・差分の一覧は audit.md へ置き、
RESULT.md からは行番号で指す。同じ内容を二度書かない。

報告の後、同期の抑止の目印は削除ではなく別名への移動で解除する。
