## 4. 予測（結果を見る前に書く）

1. P\*-20 は P\*-15 を 5 折り平均の val macro Jaccard で**両系統とも上回り**、差は **0.01〜0.03**
2. 上がり幅は **COCO 系統の方が小さい**（初期化が強い分、データ追加の余地が小さい）
3. efros の P\*-15（ホスト差の対照）は ilya の値と**折り A の seed 間 SD の 2 倍以内**で一致する
4. 工程塔の送り手の train と val の macro Jaccard の差は **3pt を超える**（交差適合の対象になる）
5. val と test の乖離は P\*-15 と同程度

## 5. Primary endpoint

系統ごとの 5 折り平均の折り内 val macro Jaccard（折り A は 3 seed の平均、他は 1 seed）。co-primary は frame accuracy。

## 6. 判定規則

1. 選定は行わない。recipe は三周目の確定値に固定し、二系統の P\*-20 を確定する
2. test は確定塔について折りごとに一度だけ評価し、台帳に記録する（2 系統 × 5 = 10 回）
3. ホスト差の対照が seed 間 SD の 2 倍を超えたら停止して諮る
4. 工程塔の送り手の train−val 差は 4 塔（2 系統 × P\*-15・P\*-20）について折りごとに記録し、3pt を超えれば交差適合の対象とする。主指標と co-primary が食い違えば両方を記録する

## 7. 対照

- ホスト差: efros の P\*-15 一本と ilya の同じ run
- 折り表の照合: 追加 5 動画が train にだけ入り、val・test に無いこと（集合差）。動画 22 が無いこと
- recipe の照合: 三周目の config と本契約の config の差分（追加動画と出力先とホスト以外 0 項目）

## 8. 停止条件

- efros に必要なもの（三周目の recipe・道具・COCO backbone の重み・15 動画のフレーム・追加 5 動画のフレームと注釈）が欠けている → 停止し、欠けの一覧を出して利用者に移送を頼む
- 追加 5 動画のフレーム数が注釈と一致しない → 停止
- ホスト差が seed 間 SD の 2 倍を超える → 停止
- 1 本の fine-tune が 8 時間を超える、記憶領域が収まらない → 諮る
- 装置が使われている → 停止
