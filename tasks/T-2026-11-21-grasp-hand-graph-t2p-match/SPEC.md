## 3. T→P と揃える条件

### 3.1 学習の長さと記録する epoch

- **主**: 4 epoch 学習し、途中で止めず、4 epoch 目の状態を結果にする（T→P の W1 と同じ）
- **副次**: 学習率の予定が全体の長さに依らない場合に限り、同じ run を 16 epoch まで続け、8・12・16 epoch 目の状態も記録する。最良の回を選ばない。早期打ち切りを使わない
- 長さに依る場合は 4 epoch だけ回し、副次は記録しない（停止しない。報告に理由を書く）
- 続けた run の 4 epoch 目の状態が、4 epoch で止めた run と同じであることを、W ごとにグラフ 1 本（DGH-noCF、設定 s1）と T→P 1 本（D1-L1 の予測-noCF）で確かめる。val の確率が一致しなければ、主の値は 4 epoch で止めた run を全腕で回して取り、続けた run は副次だけに使う

### 3.2 学習設定（T→P の記録から写す）

- interface の学習率・weight decay・optimizer、1 歩の単位（前回までは動画 1 本）、受け取り手の学習率と weight decay、時間ヘッドの train／eval の扱いを、T→P の run（W1 は `stage2fix_*` の D1-L1・D1-L2・D2・D3-L2、W2・W3 は `w23b_*` の同じ型）の config と記録から写す。写した値と出所を報告に書く
- 型の間で値が食い違えば停止して利用者に尋ねる（どれを写すかで「同じ条件」の中身が変わるため）
- グラフの腕も T→P の参照の型の腕も、写した同じ値で回す。前回のグラフの値（§1.1）と違えば、両方を報告に並べる
- optimizer の群ごとの学習率と weight decay の実際の値を、学習の記録から読んで写した値と比べる

### 3.3 学習範囲

- W1 は interface だけ、W2 は W1 に時間ヘッドの最後の段を足す、W3 は W1 に時間ヘッド全体を足す（backbone はどれでも凍結。§1.1 の T→P の定義）
- グラフの腕と T→P の参照の型の腕で、W ごとに学ぶパラメータのうち受け取り手の側の名前の集合が同じであることを示す

### 3.4 評価

- 評価は val（動画 09・10）。指標は 6 工程の Jaccard（val に現れる 7 工程から dressing を除いた 6 工程の平均。前回の契約と同じ定義）、frame accuracy、7 工程の Jaccard、工程別 Jaccard、動画ごとの値

### 4.1 グラフ（前回の定義のまま。変えない）

### 4.2 入れ替えたグラフ

- noCF のグラフを、フレームごとに丸ごと別のフレームのグラフと入れ替える（術具の節・手の節・持ち手の特徴・辺をまとめて動かす。フレームの中の関係は保ち、フレームとの対応だけを壊す）

## 7. 読み方（差を出すだけ。採否・順位は書かない）

| 差 | 読むこと |
|---|---|
| c-noCF − c-S（c は 5 腕） | フレームに対応した信号の中身による差（主） |
| c-S − A0 | 信号の値の分布だけによる差（フレームとの対応なし） |
| c-noCF − A0 | グラフを入れたことの全体 |
| c-CF − c-noCF | 学習時の信号の質（評価時はどちらも確定の塔） |
| DG-noCF − D-noCF | 把持の上乗せ |
| DH-noCF − D-noCF | 自分の手の位置の上乗せ |
