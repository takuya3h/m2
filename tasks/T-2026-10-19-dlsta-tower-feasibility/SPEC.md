# dlsta で両塔を学べるかの実測（入力の実在、検出塔の構築、両塔の記憶領域と処理量、ホストをまたぐ評価、受け渡しの経路）

**task_id:** T-2026-10-19-dlsta-tower-feasibility  **kind:** analysis

実行するホストは dlsta（repo は `~/local/m2`。`context/env-facts.md`）。**本契約では GPU を使用する**（利用者の許可 2026-10-19）。
ただし他の利用者のプロセスがある GPU は使わない。

## 1. 背景

両塔（工程塔 P\*-15-COCO と検出塔 D\*-COCO）の処方を、学習率以外も含む探索で選び直して学び直す。
利用者は 2026-10-19 に、塔の学習（折り A の探索、上位の候補の回し直し、確定の塔、交差適合用の塔と診断点の塔）を
すべて dlsta（RTX A5000 × 5）で行い、andrew は Stage 2 の界面に使うと決めた。比べるのは設定どうしであり、
比べる腕を同じホストに置けば規約 `conventions#symmetry` の「ホストと装置型」を満たす。確定の塔とその変種も同じホストに置く。

その前に、dlsta で処方を変えずに回せるかを測る。分かっていないことは四つある。

1. 検出塔の本体が dlsta に無い（2026-09-26 の実測）。repo の写しから構築できるか
2. 工程塔の三周目の処方は、記録のホストで GPU の記憶領域を最大 27.06 GiB 使った。A5000 は一枚 24,564 MiB で、一枚に収まらない見込み
3. 学んだ塔を andrew で使うとき、ホストをまたいで評価の値が変わらないか（検出塔は未測定）
4. dlsta から andrew へ checkpoint を渡す経路

本契約は測るだけである。**処方を決めない。実装を変えない。全体の学習を回さない。** 測った値は選定と関門の判定に使わない。
結果は、探索の手続きのカード（装置の構成と並べ方）、工程塔を複数の GPU で回す実装の契約の要否、学び直しの実験契約の起票に使う。

## 2. 背景にある利用者の決定（参考。本契約の作業はこれに依存しない）

- 塔の学習はすべて dlsta、Stage 2 の界面は andrew（2026-10-19）
- 選び直しは学習率以外も含む探索に広げ、両塔とも同じ数の設定を折り A で探し、上位 3 件を 5 折り × 2 種で回し直して選ぶ（2026-10-19）
- 工程塔の入力は短辺 800 の全画面のまま（2026-10-18。規約 `conventions#symmetry` の理由 3 の入力の縮小規則）
- 検出塔の学習の精度は fp16 の autocast（`conventions#precision`）
- 本契約で dlsta の GPU を使ってよい（2026-10-19）

5. `REPORT.md`、`RESULT.md`、`result.yaml`、`audit.md`、`tasks/inbox.d/T-2026-10-19-dlsta-tower-feasibility.md` を置き、commit、push、PR（base は `phase0`）
6. `make task-report` で台帳へ送る。task スキルの「8. 終える」で抑止を外す

## 5. 禁止事項

**禁止は実行者の操作に対するものであり、同期処理による配布を含まない。**

1. `data/raw/` と `data/external/` に書き込まない（欠けた入力は利用者が送る）。`data/splits/` の既存ファイルを変えない。
   `data/` に書いてよいのは Task B の 4 の条件で作る折りごとの注釈だけ。測定の特徴のキャッシュは `data/processed/` に置かない
2. 他の利用者のプロセスに触れない。他の利用者のプロセスがある GPU を使わない
3. 既存のスクリプトと道具の挙動を変えない。工程塔の実装を変えない（複数の GPU への対応は次の契約）
4. ほかのホストからファイルを取り寄せない。検出塔のソースは repo の写しから、環境は公開の上流と package index から作る
5. ほかのホストへは TCP の接続の確認だけにする。認証しない。既知のホストの記録を変えない
6. 全体の学習（収束規則まで）を回さない。処方・設定を決めない。測った値を選定や関門の判定に使わない
7. checkpoint、特徴、画像、画像から作った派生物を commit しない（repo は公開である）
8. `context/auto/*` と `tasks/inbox.md` を再生成しない。生成物の検査（`make taskindex-check`、`make inbox-check`）を回さない
9. `runindex/**` を手で編集しない。`context/conventions.md` に触れない。既存の `tasks/*/` を変えない（本契約のディレクトリと受け皿を除く）
10. 凍結源と既存の確定塔の checkpoint を変えない
11. 統合しない（PR を作るところまで）。外部への送信は `make task-report` 以外の経路で行わない

## 7. 想定外と停止条件

- repo の位置や装置から dlsta と確かめられない → 停止して諮る（G1）
- 他の利用者が使っていない GPU が二枚未満 → 停止して諮る（G1）。途中で使用中の GPU に他の利用者のプロセスが現れたら、
  本契約の処理を止めて諮る。他の利用者のプロセスには触れない
- 入力が欠ける → 一覧にして諮り、同じセッションで待つ（G2）
- 検出塔の復元や環境の構築に外への到達が足りない、要約値が合わない、拡張が読み込まれない → 出力を示して諮る（G3）
- 測るために既存のスクリプトや道具の挙動を変える必要が出た → 停止して諮る
- 工程塔が一枚に収まらない → 停止しない。結果として記録し、Task E の 2〜5 へ進む
- 検出塔の処方が組の 2 枚に収まらない → 停止しない。結果として記録し、収まる条件を測る（処方の変更として区別する）
- `make spec-check` が本文の書き方について出す該当 → 報告に含める（終了コードは変わらない）

## 8. 報告の構成

`RESULT.md` は起票者が判断に使う事実だけ。**目安 150 行以内**（「1. 解決された参照」は原文が要るので行数に数えない）。

| 節 | 内容 | 入れないもの |

| 判定 | `verdict` と各 Gate の結果 | 手続きの全文 |
