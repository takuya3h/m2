# 完了報告を投影から読めるようにし、検証の摩擦と派生物の食い違いを解く

**task_id:** `T-2026-08-17-report-projection-and-friction`
**kind:** `impl`
**depends_on:** `T-2026-08-16-docs-reconciliation`
**実行ホスト:** `lecun`

## Goal

**最優先は Phase A である。** 起票者は完了報告の中身を人が転記しなければ読めない。
投影には件数しか出ないため、**何が誤っていたか・指示どおりなら何が起きたか**が伝わらない。
これを投影から読める形にする。

残りは運用の摩擦と、派生物どうしの食い違いである。

| Phase | 内容 |
|---|---|
| A | 完了報告の様式を広げ、投影へ転記する |
| B | 分母を宣言しない契約で母集団の警告を出さない。数の主張の規約 |
| C | 同じ出所から生成される派生物を揃える |
| D | 未解決の失敗と外部記録の実績を調べる（**変更しない**） |

**分量が多い。Phase の途中で行き詰まったら、そこで止めて報告すること。**
急いで進めるより、実測を残すほうが価値がある。

### 起票者からの申し送り

起票者の検査コマンドが検証対象を検証できていない誤りが **16 task 連続**で発生している。
直近では、**起票者自身が 15 task 連続で警告してきた型を、自分の測定コマンドで犯した**。
実態を測る指示が数字を含む対象を落とし、実行者が誤った結論へ進みかけた。

実行環境の対話シェルは bash ではない。**変数の直後に記号が続く場合は波括弧で囲むこと。**
配列の添字による終了コードの取得は使えない。単語分割も起きない。

**本 SPEC の検査も同型の誤りを含みうる。** 次を守ること。

| # | 注意 |
|---|---|
| 1 | 一致件数が 0 のとき、別の探し方でも 0 になることを確かめる |
| 2 | 仕組みの挙動は実装を読んでから信じる |
| 3 | 記録を作る流れに表示用の切り詰めを混ぜない |
| 4 | 検査が空振りでないことを陽性対照で確かめる |
| 5 | **対象の一覧そのものが正しいかを確かめる**（一覧が縮んでも検査は通る） |

# Phase A — 報告を投影から読めるように

## Task 1: 様式を広げる

**Files:** Modify `tasks/_schema/result.schema.json`、Modify `tasks/_templates/result.yaml`

現在の様式は件数しか持たない。**評価に必要なのは中身である。**

- [ ] **Step 1: 現在の様式を読む**

    sed -n '1,60p' tasks/_schema/result.schema.json

- [ ] **Step 2: 広げる項目を決める**

| 項目 | 現在 | 拡張後 |
|---|---|---|
| `gates` | id と verdict | **`note` を足す。何を実測したか** |
| `issuer_defects` | type と note | **`note` の要件を明記する** |
| `deviations` | 件数 | **一覧にする。`type` と `note`** |
| `followups` | 本文 | 変えない |
| `unknowns` | 本文 | 変えない |

`issuer_defects[].note` は次の 2 つを含むこと。

- **何が誤っていたか**
- **指示どおり実行すると何が起きたか**

`deviations[].type` は次の 3 種に固定する。

| 型 | 意味 |
|---|---|
| `spec_defect` | 契約の誤りによる |
| `environment` | 実行環境の差による |
| `judgement` | 判断が必要だった |

**列挙にない型が要る場合は、完了時に提案として報告する。勝手に増やさない。**

- [ ] **Step 3: 検証を足す**

`deviations` が空でないこと。`gates[].note` が空でないこと。
`issuer_defects[].note` が一定の長さを持つこと。**長さの基準は実装を読んで決め、記録する。**

**過去の完了報告は対象外とする。** 版で分ける。

- [ ] **Step 4: 失敗する試験を書く**

**通る例と通らない例の双方**を置く。拡張した項目が欠けると拒むこと。
列挙にない型を拒むこと。**古い版の記述は拒まないこと。**

## Task 2: 投影へ転記する

**Files:** Modify `tools/build_taskindex.py`、Modify `Makefile`

- [ ] **Step 1: 出力を足す**

- [ ] **Step 3: 失敗する試験を書く**

- [ ] **Step 4: G1 ゲート — 読める形になったことを確認する**

## Task 5: 生成経路の揃え

**Files:** Modify `tools/harvest_runindex.py`（**新しい列の出力のみ**）

索引には外部記録の列があるが、**一部の個別記録には出ていない。** 生成経路が二系統ある。

- [ ] **Step 1: 実態を測る**

**推測しない。** どの記録に列があり、どれに無いかを数える。

    python - <<'PY'
    import json, pathlib
    n_with, n_without = 0, 0
    missing = []
    for p in sorted(pathlib.Path("runindex/runs").glob("*.json")):
        d = json.loads(p.read_text(encoding="utf-8"))
        if "wandb_run_id" in d:
            n_with += 1
        else:
            n_without += 1
            missing.append(p.name)
    print("列あり:", n_with, "列なし:", n_without)
    for m in missing[:10]:
        print("  ", m)
    PY

**二系統がどこで分かれるかを実装から確かめる。**
