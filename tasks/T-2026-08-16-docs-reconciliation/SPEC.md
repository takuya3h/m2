# 運用文書を現在の実態へ合わせ、書かれた手順が実在することを機械で確かめる

**task_id:** `T-2026-08-16-docs-reconciliation`
**kind:** `impl`
**depends_on:** `T-2026-08-15-template-leak-and-autosync-conflict`
**実行ホスト:** `bengio`

## Goal

短期間に多くの仕組みが加わり、**運用文書が実態から離れている可能性がある。**
文書は人が読んで従うものであり、誤っていると事故を生む。実際に、テンプレートの
記述を写した結果として全台が同じ論理名を名乗る事故が起きている。

**文書を実態へ合わせ、書かれた手順が実在することを機械で確かめる。**

### 直近で加わった、または変わったもの

| 領域 | 内容 |
|---|---|
| 契約の配布 | 配布台帳から識別子だけで取り込める。添付経由 |
| 契約の検証 | 実行直前の検査が機械化されている |
| 完了報告 | 散文に加えて構造化された対を書く |
| 投影 | 実装の履歴と申し送りの集約が生成される |
| 判断の受け皿 | 契約ごとの記録に分かれた |
| 依存の導入 | 一括で行う手順がある |
| 資格情報 | 読み込みの経路が変わった。編集と再暗号化の順序に規約がある |
| 論理名 | 各ホストの起動時設定で注入する。共有設定へ入れない |
| 定位置分岐 | 命名が統一された |
| 索引 | 正本を生成できるホストの条件が定まった |
| 自動同期 | 契約の実行中に抑止する手段がある |
| 実装系 | 二つある |

**上は起票者の把握であり、実態とは限らない。** すべて実測で確かめること。

## 本 task の性質

**文書のみを扱う。実装は変更しない。** 文書と実装が食い違い、実装の側が誤っていると
判断される場合は、**文書を実装に合わせたうえで未解決事項として起票する。**

## 0. 前提と禁止事項

作業は次の分岐で行う。契約の実行中は自動同期を抑止する。

    cd /home/ubuntu/slocal2/m2
    git fetch origin
    git checkout -b feat/docs-reconciliation origin/phase0
    touch .sync-pause
    source .venv/bin/activate

**抑止が稼働中の常駐処理に反映されているかは未確認である。** 反映前なら効かない。
実行中に常駐処理による統合が起きた場合、**それは実行者の逸脱ではない。事実として記録する。**

報告を終えたら `rm -f .sync-pause` を実行する。**解除を忘れるとそのホストだけ同期が止まる。**

| # | 禁止 |
|---|---|
| 1 | **過去の記録を書き換える**（過去の契約・実験証跡・調査記録・外部由来の複製） |
| 2 | 実装を変更する（本 task は文書のみ） |
| 3 | `context/conventions.md` を変更する |
| 4 | `runindex/**` `context/auto/**` を**手で**編集する（生成は可） |
| 5 | `experiments/**` `transfer/**` `data/splits/**` を変更する |
| 6 | 資格情報の値を出力・記録する |
| 7 | 演算装置を使う |
| 8 | 未測定の値を書く。未測定は UNKNOWN |
| 9 | 統合する。自動統合を有効化する |

### 起票者からの申し送り

起票者の検査コマンドが検証対象を検証できていない誤りが 15 task 連続で発生している。
直近では、同じ契約の中で禁止事項と完了判定が両立しない箇所を 3 件同時に出した。
また稼働中の処理が抑止の対象になっているかを確かめない判定を書いた。

実行環境の対話シェルは bash ではない。**変数の直後に記号が続く場合は波括弧で囲むこと。**
配列の添字による終了コードの取得は使えない。単語分割も起きない。

**本 SPEC の検査も同型の誤りを含みうる。** 次を守ること。

| # | 注意 |
|---|---|
| 1 | 一致件数が 0 のとき、別の探し方でも 0 になることを確かめる |
| 2 | 仕組みの挙動は実装を読んでから信じる |
| 3 | 記録を作る流れに表示用の切り詰めを混ぜない |
| 4 | 検査が空振りでないことを陽性対照で確かめる |

追跡下の文書を列挙し、**現行の手順を述べるもの**と**過去の記録**に分ける。

判定の基準は「**いま読んで従うものか**」である。過去の出来事を述べるものは記録である。

- [ ] **Step 2: 実態を測る**

文書と照合するための実態を集める。**推測しない。**

    grep -E "^[a-z-]+:" Makefile | cut -d: -f1 | sort
    ls -1 tools/*.py scripts/sync/*.sh
    ls -1 context/auto/
    ls -1 tasks/_schema/ tasks/_templates/
    git branch -r | grep "origin/exp/"

**それぞれの出力を控える。表示用の切り詰めを混ぜない。**

- [ ] **Step 3: 食い違いを探す**

現行手順を述べる文書について、次を照合する。

| 観点 | 探し方 |
|---|---|
| 存在しない操作を書いていないか | 文書中の `make <名前>` を抜き、実在と突き合わせる |
| 存在しない経路を書いていないか | 文書中のパスを抜き、実在と突き合わせる |
| 古い命名が残っていないか | 日付や作業状態を含む分岐名 |
| 新しい仕組みが書かれていないか | 上の一覧のうち文書に現れないもの |
| 誤った手順が残っていないか | 資格情報の編集と再暗号化の順序など |

**一致が 0 件のとき、別の探し方でも 0 になることを確かめる。**

# Phase C — 書かれた手順が実在するか

## Task 3: 機械で確かめる

**Files:** Create `tools/check_docs.py`（**例外的に実装を作る。理由は下記**）

**Phase B の禁止 2 に対する例外である。** 文書の正しさを人の目だけで保つのは続かない。
**検査を作ることは文書の更新の一部**とみなす。作るのは検査のみで、既存の実装は変えない。

- [ ] **Step 1: 何を検査するかを決める**

| # | 検査 |
|---|---|
| 1 | 文書中の `make <名前>` が Makefile に実在する |
| 2 | 文書中の追跡下のパスが実在する |
| 3 | 文書中の `tools/*.py` `scripts/**` が実在する |

**検査の対象は現行手順の文書に限る。** 過去の記録は対象外とする。対象の一覧は
`docs/docs_audit.md` の分類に従う。

- [ ] **Step 2: 誤検出を避ける**

**過去に、名前の部分一致や語境界の無視で偽陽性が出ている。**

| 危険 | 対処 |
|---|---|
| 例示のための架空の名前 | 除外の印を決めるか、対象の文書を限る |
| 変数を含む記述 | 変数が含まれる行は対象外とする |
| コメント中の記述 | 区別できないなら対象外とし、その旨を書く |

**検出できないものを検出したことにしない。** 対象外にした範囲を記録する。

- [ ] **Step 3: 失敗する試験を書く**

`tests/test_check_docs.py` に、**通る例と通らない例の双方**を置く。

実在する操作を書いた文書が通ること。存在しない操作を書いた文書が拒まれること。
存在しないパスを書いた文書が拒まれること。変数を含む行が対象外になること。
対象の文書が無くても落ちないこと。

- [ ] **Step 4: Makefile へ足す**

`docs-check` を足す。**挿入位置に注意。既存レシピの途中へ入れない。**

- [ ] **Step 5: G2 ゲート — 両方向で確かめる**

検査を実行し、現行手順の文書がすべて通ることを確認する。

そのうえで**陽性対照を置く。** 一時的な文書に存在しない操作を書き、**検査が非ゼロを返す**
ことを確認する。確認後、その文書を消して作業領域が清潔であることを確かめる。

**陽性対照が反応しないなら、この検査は無効である。** 停止して報告する。

- [ ] **Step 6: 検査で確かめられない記述を記録する**

**すべてを機械で確かめられるわけではない。** 手順の順序や前提条件は検査の対象外である。
**何を確かめ、何を確かめていないかを `docs_audit.md` に明記する。**
