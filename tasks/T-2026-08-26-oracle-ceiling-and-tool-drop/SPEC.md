# オラクル上限の本番確認と工程弁別性による術具除去の効果測定

## 0. 最初に読むこと — 本契約には締切がある

**本契約の成果は、配布からおよそ 24 時間後の進捗報告会で使われる。**

実行に使ってよいのは **配布から 16 時間まで**である。残りは報告の読み取りと資料の作成に要る。

**Phase A を始める前に、そのときの時刻を記録すること。** 以後の各 Phase の入口で経過時間を確かめ、
残り時間で完了しない見込みになったら**新たな学習を始めずに、そこまでの結果で報告する。**

**途中で打ち切ることは失敗ではない。** 本契約は Phase B までで報告してもよい設計になっている。
起票者はその可能性を承知している。**打ち切ったことと、その時点で何が測れていたかを記録すればよい。**

**数値を作らないこと。** 本数が足りず判定できない場合は「判定不能」と記す。
足りない本数から結論を引き出してはならない。

## 1. 背景

工程認識へ術具の情報を渡す機構について、GPU を使わない代理モデルの上で次の二つが観測されている。

- **完璧な術具存在を与えても、予測された術具存在に対する追加的な分類の利得はほとんど無い。**
  十五動画の一つ抜き検証で、正しさの割合の差は僅少であり、改善側へ倒れたのは十五のうち十であった。
- **工程を弁別しない汎用的な術具を信号から落とすと、macro-F1 が上がる。**
  六つの凍結源すべてで正、範囲は一点一から二点一の改善であった。
  時間方向の受容野を本番の時系列モデルと同程度まで与えても、この利得は残った。

**しかし、代理モデルで見えた効果が本番の構造で消えた前例が、同じ一連の調査の中にある。**
入力側の雑音除去は、代理では複数の split と複数の凍結源で一貫して分節の指標を改善したが、
時間方向の受容野を与えた途端に効果が消えた。

**したがって本契約の目的は、上の二つが本番の時系列モデルでも成り立つかを実測することである。**
成り立たなければ、そのまま報告する。

**現段階は、どの手法がどう効くかを調べる段階であり、主張を作る段階ではない。**
判明した事実を判明したとおりに報告することが求められている。

## 2. 何を確かめるのか

### 2.1 上限の確認（Phase B）

正しい術具存在を与えた場合に、工程認識がどこまで行くかを本番の時系列モデルで測る。
**再学習を要しない**。既存の学習済みの重みを使って評価するだけである。

この値が決まらないと、Phase D の効果量を解釈できない。**Phase B は Phase D より優先される。**

**この腕は上限の測定専用であり、手法の成果として報告してはならない。**
過去に同種の腕へ四重の歯止めを入れた前例がある。本契約でも、結果の記録に上限測定である旨を残すこと。

### 2.2 除去の効果測定（Phase D）

**工程を弁別しない術具を信号から落とす**腕と、**落とさない**腕を対にして測る。

落とす対象は、**その fold の学習側だけから求めた工程の条件付きエントロピーが、
規定の閾値を超えるもの全て**である。**術具の名を列挙して指定してはならない。集合で指定する。**

閾値は既に定まっている。**成績を見て閾値を選び直してはならない。**
過去の測定では、閾値の最良値が検証側と評価側で食い違っている。閾値の変更は起票者の判断事項である。

## 3. 実行の順序について

**対の両側を、腕ごとにまとめて走らせてはならない。**

同じ調査の中で、実行の並びが対の揺らぎを大きく変えることが実測されている。
腕ごとに一括で走らせた場合の揺らぎは、種ごとに隣接して交互に走らせた場合の数倍であった。
**桁が変わる。**

**したがって、対の両側は種ごとに隣接して交互に走らせること。**
そして**実際に走らせた順序を記録すること。**

## 4. 手順

### Task 1 — 開始の記録と抑止

**Step 1.** 現在時刻を記録する。以後この時刻を起点に経過を測る。

**Step 2.** 作業ツリーの状態を記録する。**開始前から在る未追跡ファイルは退避してよい。**
取り込みの操作は作業ツリーが汚れていると分岐を作らずに終了する。実測で複数の契約がここで止まっている。
**退避したものは一覧に残すこと。**

**Step 3.** 変更を伴う契約であるため、自動同期の抑止の目印を置く。
**報告を終えたら移動によって解除する。** 削除が拒否される環境があるため、解除は削除に固定しない。

### Task 2 — Phase A 入力の実在確認（GPU 不要）

**この Phase の目的は、後続が走るかどうかを先に知ることである。**

**在ると仮定してはならない。** 同じ repo の中で、比較表の首位を含む複数の検出器の重みが
当該ホストに存在せず、証跡だけが転送されていた実測がある。

**Step 1.** 後続の Phase が読む入力を、**一つずつ実在を確かめる。**
何が要るかは実装を読んで決めてよい。少なくとも次の四種が要るはずである。

- 時系列モデルの学習と評価の入口
- 凍結源となる検出器の重み、およびその要約値
- 術具存在の信号（予測された側と正しい側の双方）
- 分割の定義

**Step 2.** 見つからないものがあれば、**そこで止めて報告する。**
無いものを推測で代替してはならない。

**Step 3.** 一致が零件だった場合は、**探し方を疑うこと。**
対象が存在しないのか、条件に合わないのか、対象の集合を間違えているのかを区別する。
**異質な方法で二度確かめる。** 同じ仕組みに依存する二つの方法は同質であり、二度確かめたことにならない。
**先頭がドットのものを含めること。**

**Step 4.** 計算資源が使える状態かを確かめる。**本契約は lecun の GPU を使用する。**
他の利用者と競合した場合は、続行せずに止めて報告すること。

**Step 5.** 契約の欄のうち、起票者が埋められなかった二つを実測で差し替える。
どちらも起票の時点では存在しない値である。差し替えた値を報告に残すこと。

**判定 G1** — 必要な入力がすべて実在したか。**一つでも欠けていれば止める。**

### Task 3 — Phase B 上限の評価（再学習を要しない）

**Step 1.** 正しい術具存在を与えた場合の工程認識の成績を、本番の時系列モデルで評価する。
**分類の指標と分節の指標の双方を記録する。**

**Step 2.** 比較の相手として、予測された術具存在を与えた場合の成績も同じ手続きで得る。
**既存の記録から引いてよいが、引いた場合はその出所を記録すること。**
出所が当該ホストで測られたものでない場合は、その旨を明記する。

**Step 3.** 上限測定専用であることの印を、結果の記録に残す。

**Step 4.** 経過時間を確かめる。

**判定 G2** — 評価が完走し、双方の指標が記録されたか。

### Task 4 — Phase C 所要時間の実測と本数の決定

**起票者は本番規模の所要時間を知らない。** 基準点となる run のすべてが所要時間を記録しておらず、
既存の記録から見積もりを立てられないためである。**したがって実測してから決める。**

**Step 1.** 決定化を有効にした状態で、学習を一本走らせ、**所要時間を実測する。**
決定化は本契約では有効にする。過去の実測では、有効にすると二倍強の減速がある。

**Step 2.** 同じ設定で**もう一本**走らせ、**二本の結果が一致するかを確かめる。**
これが決定化が効いていることの確認である。**設定に有効と書いてあることは、効いていることを意味しない。**

- **陽性対照** — 種を変えれば結果は変わるはずである。変わらなければ、種が効いていない。
- **陰性対照** — 同じ種なら結果は一致するはずである。一致しなければ、決定化が効いていない。

**双方を確かめること。片方だけでは、常に同じ値を返す壊れ方と区別できない。**

**Step 3.** 実測した所要時間と、Task 1 Step 1 からの経過時間から、
**残り時間で対が何組入るかを計算する。** 計算の過程を記録すること。

**Step 4.** 対が一組も入らない場合、または対の両側をそろえられない見込みの場合は、
**Phase D へ入らない。** Phase B までの結果で報告する。

**判定 G3** — 残り時間で対が入る見込みがあるか。**無ければ Phase D を飛ばす。**

### Task 5 — Phase D 除去の効果測定

**Step 1.** 落とす術具の集合を決める。**その fold の学習側だけを使うこと。**
評価側の情報が判断に混ざってはならない。

**Step 2.** 決めた集合が正しく求まっているかを、**両方向で確かめる。**

- **陽性対照** — 工程をほとんど弁別しない術具を入力すれば、落とす集合に入るはずである。
- **陰性対照** — 特定の工程にほぼ限って現れる術具を入力すれば、落とす集合に入らないはずである。

**片方向だけでは、常に空集合を返す壊れ方や、常に全部を返す壊れ方と区別できない。**

**Step 3.** 落とした本数を数える。**部分一致で数えてはならない。**
既存の要素へ誤って一致する。**集合の差で求めること。**
件数が合っていることは、入れ替わりが起きていないことを意味しない。

**Step 4.** 対を走らせる。**種ごとに隣接して交互に走らせること**（第 3 節）。
**実際の順序を記録する。**

**Step 5.** 各対の入口で経過時間を確かめる。残り時間で**その対の両側**が入らないなら、
**その対を始めない。** 片側だけの腕を作らない。

**判定 G4** — 対の両側が同数そろい、順序が記録されたか。**そろっていなければ判断を仰ぐ。**

### Task 6 — Phase E 報告

**Step 1.** 効果量と、**改善側へ倒れた対の個数**の双方を出す。

**Step 2.** **判定を行わない。**
判定則は同時に走る別契約が確定させる。そこで確定した則を起票者が後から当てる。
**本契約で判定則を選んではならない。**結果を見てから則を選ぶことになるためである。

**Step 3.** 工程ごとの内訳を出す場合は、**評価側に現れない工程の扱いを明記すること。**
過去の測定で、評価側に支持の無い工程や、一度も当たっていない工程が存在した。

**Step 4.** 変更範囲の一覧を出す。禁止領域への変更が無いことを示す。

**Step 5.** 完了報告を**二つに分ける。**

- 事実の記録 — 判定、完了判定の表、次の契約で使う値、起票者の誤り、逸脱、想定外、送出。**目安は百五十行以内。**
- 証跡の記録 — 命令とその出力、参照の解決、対照の出力、変更範囲の一覧、台帳の応答。

**事実の記録から証跡の記録を行番号で指すこと。同じ内容を二度書かない。**

**Step 6.** PR を作る。**送り出しただけでは統合ではない。PR が存在する状態で終えること。**
**分岐が規定の接頭辞で始まっていることを確かめる。**

**Step 7.** 抑止の目印を移動によって解除する。

## 5. 禁止

**以下は実行者の操作に対する禁止であり、自動同期の仕組みによる配布を含まない。**
自動的に走る同期処理がファイルを動かすことは、本契約の禁止に当たらない。

1. 分割の定義を変えない。
2. 生の記録へ書き込まない。
3. 凍結源を変えない。
4. 測っていない値を書かない。**測れなかったものは、測れなかったと書く。**
5. **投影と集約の再生成を行わない。**
   複数の契約が同時に走っており、これらは必ず衝突する。**全ての PR が統合された後、一台で一度だけ回す。**
6. **落とす術具を決める閾値を変えない。** 変更は起票者の判断事項である。
7. **決定化を無効にしない。**
8. 上限の腕を手法の成果として報告しない。
9. **秘匿を検査する際、秘匿の値そのものを出力しない。** 判定に要るのは長さと有無だけである。
   **判定するのは件数ではなく形である。** 変数名・説明文・指紋・公開鍵は、それ自体では危険ではない。

## 6. 想定外への対処

- **道具が無い、権限が無い、対象が零件** — いずれも**そのまま採用しない。**
  何を、どの状態で、どの方法で見た結果かを確かめてから記録する。
- **禁止領域の検査が失敗する** — 本契約は新しい run を作る。
  検査は run を作る契約を構造的に通せないことが実測されている。**失敗そのものは契約違反ではない。**
  **内訳を一件ずつ示し、本契約の成果物によるものか、それ以外かを分けること。**
- **終了コードを件数と呼ばない。** 数えるなら数える命令を使う。
  成功と失敗を一行で分岐させる書き方は、表示側の失敗も失敗にする。**判定は別の命令で行う。**
- **配列の添字の書式はシェルによって違う。** 過去に二契約続けて、終了コードの検査が空振りしていた。
- **命令ごとに新しいシェルが起きる実装系がある。** 読み込みは同じ命令の中に入れる。
- **履歴を読む操作は頁送りを無効にすること。**
- **一度に一つの契約しか走っていない前提を置かない。** 他の四台で別の契約が同時に走っている。

## 7. 完了判定

**判定が通ったことは、その判定が働いていることを意味しない。**
各行に「空振りでないことの確認」を書く。**空欄にしない。「確認した」と書かない。**

| # | 判定 | 期待 | 空振りでないことの確認 |
|---|---|---|---|
| a | 必要な入力の実在を一つずつ確かめた | すべて実在、または欠けているものが特定されている | 存在しない経路を同じ方法で調べれば、不在として返るはずである |
| b | 上限の評価が完走した | 分類と分節の双方の指標が記録されている | 入力を与えずに同じ評価を試みれば、失敗するはずである |
| c | 学習一本の所要時間を実測した | 秒または分で記録されている | 記録された時間が零または負なら、測り方が誤っている |
| d | 決定化が効いている | 同じ種の二本が一致し、違う種では一致しない | 両方向を測る。片方だけなら常に同じ値を返す壊れ方と区別できない |
| e | 落とす集合が正しく求まる | 弁別しない術具は入り、弁別する術具は入らない | 両方向を測る。空集合しか返さない壊れ方と、全部返す壊れ方の双方を排除する |
| f | 落とした本数を集合の差で求めた | 除去前と除去後の差として得られている | 部分一致で数えた場合と値が異なるかを確かめる。同じなら数え方が区別できていない |
| g | 対の両側が同数そろっている | 片側だけの腕が無い | 片側だけの腕を数えれば零のはずである |
| h | 実行の順序を記録した | 走らせた順が残っている | 順序の記録が空なら、この判定は満たされない |
| i | 効果量と倒れた個数の双方を出した | 双方が記録されている | 片方しか無ければ満たされない |
| j | 判定を行っていない | 有意・非有意の語が結論に現れない | 現れていれば、本契約の範囲を越えている |
| k | 上限の腕に測定専用の印がある | 記録に印が残っている | 印の無い記録があれば満たされない |
| l | 変更範囲の一覧を出した | 禁止領域への変更が無い | 検査が失敗する場合は内訳を一件ずつ示す |
| m | PR が存在する | 番号が記録されている | 送り出しただけの状態は満たさない |
| n | 分岐が規定の接頭辞で始まる | 接頭辞が確認されている | 接頭辞の無い分岐なら満たされない |
| o | 報告が二つに分かれている | 事実の記録と証跡の記録が別にある | 一つしか無ければ満たされない |
| p | 締切に対する経過が記録されている | 各 Phase の入口の経過が残っている | 記録が空なら満たされない |

**禁止領域に触れていないことは、既存の検査で確かめる。**
**本契約は新しい run を作るため、検査は失敗しうる。失敗の内訳を示すこと。**

## 8. 起票者からの申し送り

**起票者は実行環境を持たない。** 以下は本契約の前提であって、実測ではない。**違っていたら報告すること。**

1. **入口となる実装の名は変わっている可能性がある。** 実装を読んで決めてよい。
2. **落とす集合を求める仕組みが本番側に実装されているかは未確認である。**
   代理側にしか無い場合は、**そこで止めて報告すること。**実装を新たに書き起こす契約ではない。
3. **凍結源の重みが当該ホストに在るかは未確認である。**
4. **決定化を有効にすると二倍強遅くなる。** これは別の入口で測られた値であり、
   本契約の入口で同じ倍率になるとは限らない。**Phase C で実測すること。**
5. **分母は既存の記録から引かない方がよい場合がある。**
   基準点として広く使われている値が、少数の run だけから作られており、
   真の揺らぎを二倍以上過小評価していたことが実測されている。**絶対値の比較を行う場合は出所を確かめること。**
6. **対の両側を新たに走らせる場合、既存の分母は要らない。**
7. **本契約と同時に、判定則を確定させる別契約が走っている。**
   本契約は判定しない。数字を出すところまでが範囲である。

## 9. 報告

事実の記録と対の記録を埋めて記録すること。逸脱は必須である。逸脱が無い場合も、無かった旨を一件書く。

**起票者の誤りを見つけたら、遠慮なく記録すること。**
何が誤っていたか、指示どおり実行すると何が起きたかの二つを含めること。
**これは起票者を改善するための記録である。**
