# 把持の対応を推論させ、その推論結果を工程分類へ渡す仕組みを実装する

**task_id:** `T-2026-08-11-grasp-inference-injection-impl`  **kind:** `impl`
**depends_on:** `T-2026-08-11-hts-comparability-audit`
**実行ホスト:** `lecun`

## Goal

工程分類のモデルに、**手と術具の把持の対応を推論する部分**を持たせる。その**推論結果を
工程分類の入力へ渡す**。推論する力は `hand_tool_seg` を教師として学習させる。

**最終的な出力は工程のみである。** 把持の推論はモデルの内側にあり、外へは出さない。

**本契約は実装までである。効果を測る実験は行わない。** 次の実験契約で事前登録つきで測る。

### これが「損失を足すだけ」と違う点

| | 損失を足すだけ | **本契約** |
|---|---|---|
| 推論結果の行き先 | どこへも渡らない | **工程分類の入力へ渡る** |
| 工程側への効き方 | 表現が間接的に整うことだけを期待 | **推論結果が直接入力になる** |
| 推論をやめたとき | 表現の整い方が変わる | **工程側の入力そのものが変わる** |

**渡した信号が工程側の出力に届いていなければ、実験を走らせても差は構造的に零になる。**
「効果が無い」のか「信号が届いていない」のかを区別できない。**Phase C で実測して確かめる。**

### 腕の構成

既存の実験は**注入と対照を同じ run の中で対にして**差を測っている
（索引の `control_of` と、既存の検出側の差の測り方）。**同じ枠に乗せる。**

| 腕 | 推論する部分 | `hand_tool_seg` で学習 | 工程分類へ渡すもの |
|---|---|---|---|
| A | 無し | — | — |
| **ctrl** | 有り | **する** | **無情報な信号**（同じ形・同じ大きさ） |
| **inj** | 有り | する | **推論結果** |

差の読み方。**本契約では計算しない。次の実験契約で測る。**

    inj − ctrl   推論結果を渡したことの効果。これが知りたい値
    ctrl − A     容量が増えたことと、推論を学習させたことの効果

**ctrl と inj で重みの総数が完全に等しいこと**、および**推論側の学習が両腕で同じに
行われること**が要である。違えば `inj − ctrl` が容量差や表現整形の差を含む。

**無情報な信号の作り方は実行者が選ぶ。** ただし次を満たすこと。

| # | 条件 |
|---|---|
| 1 | 形と大きさが推論結果と同一である |
| 2 | フレームごとの中身に把持の情報を含まない |
| 3 | 学習の間ずっと同じ規則で作られる |

零で埋める、定数で埋める、フレームの順を混ぜる、のいずれでもよい。
**選んだ方法と理由を記録すること。** 混ぜる場合は、混ぜた先が同じ動画の中に
留まらないよう注意する。留まると情報が残る。

### 把持の推論の教師

各フレームについて、5 クラスそれぞれに注釈が 1 件以上あるかを真偽で表した
**5 次元の標識**を教師とする。損失は次元ごとの二値交差エントロピー。

| 次元 | 意味 |
|---|---|
| 1 | 一人称の左手が写っている |
| 2 | 一人称の右手が写っている |
| 3 | **左手が器具を持っている** |
| 4 | **右手が器具を持っている** |
| 5 | **両手で器具を持っている** |

3 から 5 が把持の対応そのものである。**画素ごとの領域も面積も使わない。有無だけを使う。**

**推論の出来そのものを測る値を、学習中に記録すること。** 推論がまるで当たっていなければ、
それを渡しても工程が良くなる道理が無い。次の実験の解釈に要る。

# Phase C — 信号が届くことを陽性対照つきで検査する

## Task 3: 検査する（G2・G3）

**Files:** Create `tests/` 配下の新規検査, `audit/` 配下の記録

**通ることだけを確かめない。破れるべきときに破れることを確かめる。**

- [ ] **Step 1: 渡した信号が工程側の出力に届くこと（G2・本契約の要点）**

  **本契約で最も重要な検査である。** 渡す信号を変えたときに、
  工程側の出力が変わるかを測る。

  重みを固定したまま、**渡す信号だけを差し替えて**工程側の出力を二回得る。

  | 腕 | 渡す信号を変えたとき | 意味 |
  |---|---|---|
  | **inj** | 工程側の出力が**変わる** | 信号が届いている |
  | **ctrl** | 工程側の出力が**変わらない** | 無情報な信号に置き換わっている |

  **両方を確かめる。** inj だけでは、ctrl が実は本物を渡していても気づけない。
  ctrl だけでは、測り方が壊れていても気づけない。

  変化の大きさを数値で記録すること。**「変わった」とだけ書かない。**

  inj で変わらない、または ctrl で変わるなら **G2 は `stop`。**

- [ ] **Step 2: 重みの総数が一致すること（G3）**

  A・ctrl・inj の三つについて、学習可能な重みの総数を数える。

  | 比較 | 期待 |
  |---|---|
  | ctrl と inj | **完全に一致する** |
  | A と ctrl | ctrl の方が大きい。差の内訳を記録 |

  **凍結されている部分を含めるか否かで値が変わる。** 学習可能なものだけを数え、
  その旨を記録する。一致しなければ **G3 は `stop`。**

- [ ] **Step 3: 評価条件が基準点と一致すること（G3）**

  推論と注入を有効にした設定から作った評価条件が、基準点のものと一致することを
  `recipes_match` で確かめる。
