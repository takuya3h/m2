# 生成物の自動 PR を自動でマージする

**task_id:** `T-2026-10-07-auto-merge-regen-pr`  **kind:** `impl`
**depends_on:** `T-2026-10-07-auto-regen-projections`
**実行ホスト:** `philip`（どの台でもよい）  **repo:** `~/slocal2/m2`

## Goal

**前契約で、phase0 への push を契機に生成物を作り直し、PR を自動で作る仕組みができた**
（`.github/workflows/regen-projections.yml`）。**人の操作は「PR をマージする」だけ**になっている。

**本契約はそのマージも自動にする。**

    phase0 に push → 作り直す → 差分があれば auto/regen-projections へ push → PR を作る
      → 差分が生成物 4 ファイルだけで、基点が最新の phase0 なら → マージする

### 前契約で確定した事実

| 事実 | 値 |
|---|---|
| phase0 の保護 | クラシック。**PR 必須、承認 0 件**、`enforce_admins: true`。ルールセットは無い |
| Actions の既定権限 | `read`。workflow の `permissions` で上げている（`contents: write`） |
| PR の作成 | `AUTOSYNC_PR_TOKEN`（Pull requests の読み書きだけ）。**8/16 から失効していた実績がある** |
| 自己起動 | 自動 PR のマージで一度起動し「差分なし」で止まる（実測） |
| 生成物 | 4 ファイル。workflow は生成物以外に差分があれば exit 1 で止まる |

### 設計の方針

| 論点 | 方針 |
|---|---|
| **マージに使う認証** | **Actions 既定の `GITHUB_TOKEN`。** 期限が無く、PAT を増やさない |
| **マージしてよい条件** | **差分が生成物 4 ファイルだけ**で、**PR の基点が現在の phase0 の先頭**であること |
| 条件を満たさないとき | **マージしない。** 失敗として記録する |
| 空の自動 PR | **差分が無いのに自動 PR が開いていれば閉じる** |
| リポジトリの設定 | **変えない** |

**`GITHUB_TOKEN` による操作は、次の workflow を起こさないのが GitHub の仕様のはずである。**
**本当にそうかを確かめる。** 起こすなら、それでも収束することを確かめる。

### 起票者が把握していないこと

| # | 項目 | 崩れていたら |
|---|---|---|
| 1 | **必須の状態検査**が phase0 に設定されているか | マージが待たされる。**判断を仰ぐ** |
| 2 | **許可されたマージの方式**（merge / squash / rebase） | 許可されたもののうち、これまでの PR と同じ方式を使う |
| 3 | **`GITHUB_TOKEN` で PR をマージできるか**（保護との関係） | できなければ**判断を仰ぐ** |

| # | 禁止 |

| 4 | **生成物以外を自動でマージする形にする** |

| 10 | 装置を使う。他ホストへ接続する |
| 11 | 未測定の値を書く（未測定は `UNKNOWN`） |

**禁止 4 が要である。** 自動でマージしてよいのは生成物だけである。
**条件の判定が壊れると、何でもマージされる。** 陽性と陰性の両方で確かめる。

**禁止事項は実行者の操作に対するものであり、同期処理による配布を含まない。**

### 規約と申し送り

## Task 2 (Phase B): マージを足す

**Files:** Modify: `.github/workflows/regen-projections.yml`

- [ ] **Step 1: マージの段を足す**

| 要件 | 内容 |
|---|---|
| 時機 | 自動 PR を作った後、または既に開いていた自動 PR を更新した後 |
| **条件 1** | **PR の差分のファイル一覧が、生成物 4 ファイルの部分集合である** |
| **条件 2** | **PR の基点が、その時点の phase0 の先頭と一致する** |
| **条件 3** | **PR の作成元の分岐が `auto/regen-projections` である** |
| 満たすとき | マージする。方式は Task 1 で確かめたもの |
| 満たさないとき | **マージしない。** 理由を記録して失敗で終える |
| 認証 | **`GITHUB_TOKEN`**。必要な権限だけを宣言する |

**条件はマージの直前に読み直す。** 作った時点の値を使い回さない（その間に phase0 が進みうる）。

- [ ] **Step 2: 空の自動 PR を閉じる段を足す**

**作り直した結果に差分が無く、`auto/regen-projections` からの PR が開いていれば閉じる。**

- [ ] **Step 3: 失敗の文言を分ける**

**PR の作成で認証が失敗したとき、「未設定」と「無効」を言い分ける**（前契約の申し送り）。
**値は出さない。**

- [ ] **Step 4: 手元で試す**

**前契約の枠（偽の origin と偽の `gh`）を流用する。** 次をすべて試す。

| 場合 | 期待 |
|---|---|
| **生成物だけの差分** | **マージが呼ばれる** |
| **生成物以外を含む差分**（陽性対照） | **マージが呼ばれない。** 失敗で終える |
| **基点が古い**（phase0 が進んだ） | **マージが呼ばれない** |
| **作成元の分岐が違う** | **マージが呼ばれない** |
| 差分なし・自動 PR なし | 何もしない |
| **差分なし・自動 PR が開いている** | **閉じる** |

**二つ目から四つ目が要である。** 条件の判定が常に「通す」になる壊れ方を見つける。

**試した生成物は記録に含めない。** 作業ツリーが試す前と同じことを確かめる。

## 想定外が起きたときの扱い

| 事象 | 対応 |
|---|---|
| **必須の状態検査があり、マージが待たされる** | **停止して判断を仰ぐ** |
| **`GITHUB_TOKEN` でマージできない** | **停止して判断を仰ぐ。** 設定を変えない |
| 陰性の試験でマージが呼ばれた | **直してから試し直す。** 直せなければ停止して報告 |
| マージの後に実行が止まらず繰り返す | **報告する。** 統合前に分かれば送出しない |
| 許可された方式がこれまでの PR と違う | 許可された方式を使い、記録する |
| 実行基盤が操作を拒んだ | **迂回しない。利用者へ提示して許諾を得る** |

**言い訳をしない。事実と、測れなかったことを書く。**
