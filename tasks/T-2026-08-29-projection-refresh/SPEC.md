# T-2026-08-29-projection-refresh — 投影三種の再生成と退避の整理

kind: impl。**本契約では GPU を使用しない。** 実行ホストは philip。

## 0. 目的

前契約 T-2026-08-28-policy-v2-doc-sync の PR は統合された。
その契約では投影の検査三つが非零のまま残された。**これは実行者の誤りではない。**
起票者が「生成物を再生成しない」と禁じたためであり、規約は
「並行契約では再生成を禁じ、全ての統合が済んだ後に一台で一度だけ回す」と定めている。
本契約がその「一度だけ」を担う。

あわせて、前契約で philip に残った二件の退避と、同期の抑止の目印の状態を実測して整理する。

**本契約は投影三種の再生成を明示的に許可する。** ただし索引そのものの再生成は禁じる
（索引は走査するホストによって内容が変わるため、追跡外の run を持たないホストで行う規約がある）。

## 1. 確定している事実（ホストに依存しない値のみ）

- 投影の生成器は三つあり、入力はそれぞれ **索引・完了報告の対・受け皿の個別ファイル**である。
  いずれも版管理下の内容だけから作られ、走査するホストに依存しない
- 生成物には壁時計を入れない設計であり、**同じ入力からは何度回しても差分が出ない**。
  したがって検査の差分は「入力が変わったのに再生成していない」か「手で編集した」のいずれかを意味する
- 索引の生成器だけは**ディスクを走査するためホストに依存する**。本契約では回さない
- 前契約の実測: 検査三つが exit 2、`runindex_commit` は `7918b5dd9aab3d15b3c459f87aebdd9eb1653116`、
  `conventions_rev` は `a8c07e813696d3720ceee648e8aa202224285955`、
  索引の件数は index 1177 / experiments 213 / verdicts 1038。
  **これらは前契約時点の値であり、統合で動いている可能性がある。本契約で測り直すこと**
- 前契約が残した退避は二件で、片方は同期の除外設定の変更と未追跡五件、
  もう片方は解析用の三つのディレクトリ（中身は統合先に保全済みと照合されている）。
  **この記述は前契約の報告からの引用であり、現物は本契約で確かめること**

`inputs.data.split_files` は様式を満たすための記載であり、**本契約は分割を参照しない。**
参照しなかったことを報告に記すこと。

## 2. 変更対象

- 三つの生成器が出力する投影のファイル群（索引由来のもの・完了報告由来のもの・受け皿の集約結果）
- 退避の復帰によって現れるもののうち、**版管理へ記録する規約に当たるもの**

上記以外は変更しない（契約ディレクトリと受け皿を除く）。

## 3. Phase A — 前提の実測

### Step A-1 プレースホルダの置換

spec.yaml の `meta.created_from.runindex_commit`・`meta.created_from.counts`・
`contract.conventions_rev` を実測して置換する。これは本契約の手順であり逸脱ではない。
置換後に L1 と L2 を通すこと。

**要約値や commit の識別子を報告へ書くとき、短縮形で足りるなら短縮形を使ってよい。**
前契約では起票者が全長を要求したため、外部送信前の秘匿検査が長い十六進文字列に反応し、
何に一致したかを目視する手間を生んだ。**判定に要る精度を超える桁は書かない。**

### Step A-2 統合の完了を確かめる

**再生成は一台で一度だけ行うため、他に未統合の変更が残っていない状態で回す必要がある。**

- 起点の分岐に前契約の変更が入っていることを確かめる
- 未統合の PR が他に存在しないことを確かめる。**存在する場合は停止して報告する**（escalate）
- 作業ホストの定位置分岐と起点の分岐の差を確かめ、未統合の commit があれば件数を記録する

### Step A-3 再生成前の状態を記録する

**これは完了判定 b の前提である。再生成の前に測らなければ後から測れない。**

- 三つの検査それぞれの終了コードと、差分の要約（どのファイルに何行の差があるか）
- 三つの生成器の出力ファイルの一覧と、それぞれの要約値
- 索引の件数（三つの csv の行数）

### Step A-4 退避と抑止の実測

- 退避の一覧と件数、各退避が作られた分岐と時刻
- 各退避が含むファイルの一覧（**中身は出さない。経路と件数だけでよい**）
- 同期の抑止の目印が存在するか。存在する場合、前契約が解除しなかったことを意味する
- 抽出物の置き場（対話の抽出物を置く場所）に未追跡のものがあるか

**この段階では復帰も削除も行わない。測るだけである。**

## 4. Phase B — 再生成と整理

### Task 1 投影三種の再生成

三つの生成器を回す。**索引の生成器は回さない。**

- どの命令を回すかは、実行者が Makefile と `context/README.md` を読んで決める。
  **本 SPEC は命令を固定しない**
- 回した後、三つの検査がいずれも exit 0 になることを確かめる
- 差分が三つの生成器の出力ファイルだけに現れていることを確かめる。
  **他へ及んだ場合は停止して報告する**（escalate）

### Task 2 退避の整理

Phase A-4 の実測に基づいて次を行う。

- **復帰できるものは、本契約の分岐の上で復帰する。** 分岐は起点から作られており清浄なので、
  復帰しても契約の成果物と混ざらない
- **復帰が衝突する、または既存のファイルを上書きする場合は行わず、停止して報告する**（escalate）。
  退避は消さない
- 復帰して現れたもののうち、**対話の抽出物は版管理へ記録する**（規約による。捨ててはならない）
- **禁止領域の配下に現れたものは触らない。** 追跡下の同名のものと内容が同じかを要約値で照合し、
  結果だけを報告する。同じであっても本契約では消さない
- 上記のどれにも当てはまらないものは、経路と件数を分類して報告する。
  **処分は判断事項であり、実行者は決めない**

退避そのものは、復帰に成功したものを除き**残したままにする。**

### Task 3 抑止の解除

同期の抑止の目印が残っている場合、**報告を送り終えた後に、削除ではなく別名への移動で解除する。**
移動先が版管理の無視の対象に入っていないため未追跡として現れる。
現れた場合はその旨を報告に書く（本契約では記録も削除もしない）。

### Task 4 受け皿への記録

本契約の受け皿へ、次の二点を含めて記録する。

- 投影の再生成を「統合後に一台で一度だけ」の規約に従って行ったこと。回した命令と対象
- 退避の整理の結果と、判断待ちとして残したものの一覧

**受け皿へ書いた後に集約結果を作り直すと、Task 1 の再生成と順序が競合する。**
受け皿への記録は Task 1 より前か、集約の生成器を最後にもう一度回すかのどちらかで整合させ、
**どちらを採ったかを報告に書くこと。**

## 5. Phase C — 検査と送出

### Step C-1 完了判定

**四列目は実測で埋める。「確認した」とだけ書くことは認めない。**

| # | 判定 | 期待 | 空振りでないことの確認 |
|---|---|---|---|
| a | 投影の検査 | 三つの検査がいずれも exit 0 | 生成物のうち一つに一文字だけ足すと、**その生成器に対応する検査だけ**が非零になることを示す。復元を要約値で確認する |
| b | 再生成が実際に働いたこと | Phase A-3 で記録した再生成前の終了コードが非零であり、再生成後に零へ変わった | 前後の要約値を並べ、少なくとも一つのファイルの内容が変わったことを示す。全ファイルが不変なら「元から通っていた」ことになるので、その場合はそう報告する |
| c | 変更範囲 | 変更が §2 の対象と契約ディレクトリ・受け皿に限られる | 差分の一覧を audit に全量で載せ、対象外が零件であることを一覧から示す |
| d | 索引が変わっていないこと | 索引の配下の変更が零件 | 同じ検査を変更のある場所（契約ディレクトリ）へ当てると一件以上出ることを示す。**索引の配下に一時ファイルを置いて試さない** |
| e | 禁止領域 | 禁止領域の検査が exit 0 | 検査が生成物を除外したうえで走査していることを、対象件数から示す |
| f | 退避 | 退避の件数が Phase A-4 の実測と整合し、**消えたものが無い**（復帰に成功したものを除く） | 復帰の前後の一覧を並べ、差が復帰したものだけであることを示す |

### Step C-2 送出

- 分岐が `feat/` で始まることを確かめる
- **PR が存在する状態で終える**（push は統合ではない）。PR の base は**分岐の起点と同じ分岐**とする。
  既定の分岐へ向いていないことを確かめる
- 台帳へ完了報告を返す

## 6. 禁止事項

1. 索引の再生成（走査するホストに依存するため、別の規約で扱う）
2. 索引の手編集
3. 生成物の手編集（生成器を回して作る）
4. 退避の削除。復帰に成功したものを除き、退避は残す
5. 禁止領域の配下への書き込み・削除・移動
6. 過去の報告・完了済み契約・履歴の書き換え
7. 秘匿情報の出力・複製・移動
8. 実測していない値の記載

**禁止は実行者の操作に対するものであり、同期処理による配布や衝突ファイルの生成を含まない。**
同期由来の変化を観測した場合は、触らず件数と経路を報告する。

**本契約は投影三種の再生成を許可する。** 禁止 3 は手編集を禁じるものであり、生成を禁じない。

## 7. 想定外の扱い

| 事象 | 対処 |
|---|---|
| 未統合の PR が他に存在する | 停止して報告（escalate）。一度だけ回す前提が崩れるため |
| 再生成しても検査が非零のまま | 差分の中身を audit に載せて停止。手で直さない |
| 差分が生成器の出力以外へ及ぶ | 停止して報告（escalate） |
| 退避の復帰が衝突する | 復帰せず停止して報告。退避は消さない |
| 復帰したものの中に秘匿らしきものがある | 中身を出さず、経路と型だけを報告して停止 |
| 抑止の目印が既に無い | 前契約で解除済みを意味する。そう報告する |
| 索引の件数が前契約の記録と違う | 誤りではない。統合で動いた可能性がある。実測値を報告へ書く |

失敗時の巻き戻し: 変更はすべて作業分岐上にあり、統合前なら正本に影響しない。
停止する場合も分岐と audit を残したまま stopped で報告する。

## 8. 報告の構成

RESULT.md は起票者が判断に使う事実だけを書く。目安は百二十行以内。

- 判定: verdict と関門の結果
- 完了判定: §5 の表に実測値を埋めたもの
- 実測: **次の契約で使う値**（索引の件数、`runindex_commit`、`conventions_rev`、
  投影の来歴の要約値、退避の残件数）
- 起票者の誤り: 型と内容。一件三行以内
- 逸脱・想定外・UNKNOWN
- 判断待ち: 退避の中身のうち処分を決められなかったものの一覧
- 送出: PR 番号と終了コードのみ

命令とその出力の全文・差分の一覧・検査の出力は audit.md へ置き、
RESULT.md からは行番号で指す。同じ内容を二度書かない。
