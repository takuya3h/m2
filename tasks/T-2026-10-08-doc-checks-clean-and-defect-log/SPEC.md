## 3. 達成すべきこと

手段は実装を読んで決めてよい。決めた手段と理由を報告に書く。

### 検査の不合格

- **R1** agent-check の不合格を解消する。検査の判定を弱めるのではなく、文書の側を、各命令が単独で完結する
  形にするのが第一の候補である。検査の判定が誤っていると判断した場合は、その理由と対照を報告に書く
- **R2** docs-check の雛形の経路の不合格を解消する。雛形であることが読み手に分かる書き方に直すか、
  検査が雛形を対象外にするかは実行者が決める。外す印を使う場合は、その行だけに限る
- **R3** docs-check の結果が、無視されているホストの手元のファイルの有無で変わらないようにする。
  次の両方を満たすこと
  - 新しく取得した作業ツリーでも、手元のファイルが在るホストでも、結果が同じ
  - 版管理に在るはずの経路が実在しない場合は、変更後も検出する
- **R4** 変更が検査の検出力を下げていないことを、陽性対照で示す（実在しない経路を一つ足した写し、
  読み込みを別の命令に分けた行を足した写しで、それぞれ検出する）

### 欠陥の一覧

- **R5** `docs/issuer-defects.md` に次の一件を足す。節は既存の型から選ぶ（「禁止と要求が両立しなかった」が候補）
  - 内容: 完了判定で実環境の陰性対照を報告に含めさせながら、その操作を報告と送出の後の手順に置いた。
    書かれた順では結果が報告に入らない
  - 対処: 状態を変えない対照は commit の前に取らせ、状態を変える操作（抑止の解除）だけを最後に置く
  - 出所: `T-2026-10-07-pause-release-tool-digest-relocate` の RESULT「起票者の誤り」1

## 6. 完了判定

`spec.yaml` の `outputs.acceptance` と一致させている。**四列目を空にしない。**

| # | 判定 | 期待 | 空振りでないことの確認 |
|---|---|---|---|
| a | 手元で合格 | 二つの検査がどちらも合格 | 変更前の手元の出力（Task A の 3）に不合格が在ったこと |
| b | 新しい作業ツリーで合格 | 二つの検査がどちらも合格 | 変更前の新しい作業ツリーの出力（Task A の 4）に 7 件前後の不合格が在ったこと |
| c | 検出力 | 実在しない経路と、分けた読み込みをそれぞれ検出する | 対照を足さない写しでは検出しない |
| d | 手元のファイルの有無 | 在る場合と無い場合で docs-check の結果が同じ | 版管理に在るはずの経路を一つ消した写しでは、どちらの場合も検出する |
| e | 欠陥の一覧 | 一件足され、出所の契約を指す | 変更前の一覧に同じ契約の識別子が無いこと |
| f | 試験 | 失敗の名前の集合が同じか、減った名前が説明されている | 名前で比べる（件数だけで比べない） |

**禁止領域に触れていないことは `make forbidden-check` で確かめる。** 本契約は `allow_write` を宣言しない。

## 7. 想定外と停止条件

- 始める段が手順書どおりに働かなかった → 出力を記録し、停止して利用者に諮る
- 不合格の行を消すか検査を弱めるほかに合格させる手段が無い → 停止して諮る
- 無視されているファイルの扱いを変えると、実在しない経路の検出が減る → 停止して諮る
- 新しく取得した作業ツリーで、起票者の記した 7 件と違う件数が出た → 実測を正とし、全件を対象にする
- 実行基盤が書き込みや `rm` を拒む → 回避せず利用者に提示して許諾を得る
- 起票者の事実（§2）と実測が食い違う → 実測を正とし、起票者の誤りとして記録する
