## 3. 用語と型

- **PD** は工程から検出（受け取り手は検出塔）、**DP** は検出から工程（受け取り手は工程塔）
- **CF** は交差適合あり、**noCF** は交差適合なし。**確定塔** は §0 の二つの塔
- 全型に共通: **最後の層を零初期化し、学習前の出力が塔単独と一致する形にする。** 送り手の塔は常に凍結。
  **W1** は界面の重みだけを学ぶ（受け取り手の既存の重みは一つも動かさない）。**W2** は界面に加えて受け取り手の末端を学ぶ

| 型 | 方向 | 差し込む場所と形 | 学習範囲 |
|---|---|---|---|
| P1 | PD | 既存の FiLM。C5 に (1 + γ) × x + β。γ と β は信号から MLP（§2） | W1 と W2 の両方 |
| P2L | PD | 信号 → 9×15 の線形（bias つき、零初期化）を、既存の clsbias と同じ場所（decoder 各層のクラス logit）に足す。**15 クラスすべて**に通す。box には何もしない | W1 |
| P2F | PD | 学習なし。B[工程, 術具] = log P(術具が在る │ 工程) を、折り A の train の正解から求めて固定する（平滑化は在る数に 1、工程の数に 2 を足す）。バイアスは Bᵀ × 信号。足す場所は P2L と同じ | なし（評価だけ） |
| P3 | PD | 信号 → 9×256 の線形（零初期化）の出力を、decoder に入る全 object query の内容ベクトルに同じく足す | W2 |
| D1 | DP | 連結。工程塔の時間ヘッドの最初の層に、信号の次元の分の入力を零で足し、**足した分だけ**を学ぶ | W1 |
| D2 | DP | FiLM。P1 と同じ式・隠れ幅・初期化の MLP で、時間ヘッドの入力（フレームごとの 2048 次元の特徴）を変調する | W1 |
| D3 | DP | 集合への注意。術具ごとのトークンの集合を key と value、2048 次元の特徴を射影したものを query にして注意で一つにまとめ、零初期化の出力射影を通して特徴に足す。トークンが 0 個なら零 | W1 |

- **検出塔の W2** は、decoder の最終層と、その層のクラスと box のヘッド。最初の段の候補選択に使うヘッドは含めない。
  実装の構造が違えば、意味を保つ最小の集合を選んで記録する
- **P3 の query** に、学習時の denoising 用の query を含めるかは実装を読んで決め、全腕で同じにして記録する
- **D1** の時間ヘッドの最初の層が入力の線形写像（全結合か 1×1 の畳み込み）でなければ、代わりに
  「特徴 + 零初期化の線形（信号 → 2048）」とし、記録する
- **D3 のトークン**: 予測は確定塔の後処理後の出力のうち、スコアの上位 K 個。各トークンは、その query の 15 クラスのスコア、
  枠（中心と幅高を画像の大きさで割った 4 つ）、出所の印。K は「折り A の train の 1 フレームあたりの正解の枠の数の最大」
  とし、実測して記録する（乱数は使わない）。正解のトークンはクラスの one-hot と正解の枠。注意の次元と頭数は P1 と同程度の
  学習対象の数になるよう実行者が決め、記録する
- **D3-L2** は、上のトークンに、その query の埋め込み（256）を加えた版

## 5. 事前登録（測る前に固定する）

### 5.1 量

- 腕の差 Δ(型, 腕, s) = 指標(型, 腕, s) − 指標(同じ型の空の腕, s)。**同じ seed どうしで対にする**
- P2F の差 = 指標(P2F, 腕) − 指標(検出塔単独。Task B の値)
- その型の空の腕の幅 R(型) = 空の腕の 3 seed の指標の最大 − 最小
- DP は macro Jaccard（accuracy を併記）、PD は overall mAP と標的群 AP（併記）、陰性対照群 AP

### 5.2 読み方の規則（記述だけ）

1. 型ごと・腕ごとに、3 seed の Δ、平均、最小、最大、動画ごとの Δ を表にする
2. **「seed の幅を超える」** と書くのは、3 つの Δ が同符号で、かつ |平均 Δ| が R(型) より大きいときだけ。それ以外は
   **「幅の内」**。陽性・陰性・有意などの語は使わない（1 折り・val 2 動画では主判定が成り立たない）
3. PD で overall mAP と標的群 AP の書き方が食い違えば、両方を書き、一つにまとめない。DP の Jaccard と accuracy も同じ
4. 実現率 = 平均 Δ(予測-CF) ÷ 平均 Δ(正解予測-CF)。同じ型で正解予測-CF が「seed の幅を超える」かつ正のときだけ出す
5. **型どうしの比較**は、同じ腕の平均 Δ の差を並べ、その差が両型の R の大きい方を超えるかだけを書く。型の優劣は書かない。
   学習範囲が違う型（W1 と W2）は直接並べず、P3 は P1-W2 と並べる
6. P2F は学習が無いので、P2F と P2L の差は「学習の有無」の記述として並べるだけにする
7. 結果は関門の判定と設計の判断に使わない（§0）

### 5.3 予測（記述のための事前の記録。外れても本契約の判定は変わらない）

1. D2 と D1-L1 の正解の腕の Δ（Jaccard）は正で、seed の幅を超える
2. 各 DP の型で、予測-CF の平均 Δ は正解予測-CF の平均 Δ 以下である
3. P1-W1 の正解の腕の Δ（標的群 AP）は正である。陰性対照群 AP の Δ は幅の内である
4. 予測の腕は両方向・全型で、noCF の平均 Δ が CF の平均 Δ より小さい
5. P1-W1 の予測-CF の Δ（overall mAP）は幅の内である
6. P2F の正解の腕の差（標的群 AP）は正である

### 5.4 既知の限界（報告に必ず書く）

- 折りは 1 つ、val は 2 動画。区間推定もクラスタの推論もできない
- 受け取り手も界面の学習に使う train 動画で学習済みである（送り手の交差適合では直らない）
- 確定塔は efros、交差適合用の塔は andrew で学んだ
- 今ある塔は工程注釈だけのフレームを使っていない。評価のフレーム集合は PR #229 の frame_sets 規則と違う
- 界面の型は提案の関門を通っていない。型ごとに学習率を探していない
- D0 と D1-L1 は枠の幾何を含まない。D3-L2 と D1-L2 は検出塔の内部の埋め込みを使う

## 8. 停止して諮る条件

- 装置に本契約以外の compute プロセスがある（Task A-3）
- efros から読むのに扱えない資格情報が要る、または efros への書き込みが要る

- §3 の型の定義が実装の構造と合わず、型の意味を変えないと実装できない（§3 に書いた代わりの形がある場合はそれを使って記録する）
- andrew で検出塔の学習が動かない（Task E-4。検出の交差適合を要しない段は続けてよい）
- 記憶領域が足りない
- 既存スクリプトの既定の挙動を変えないと実装できない
- 発散・非数が出た腕は、その腕を止めて記録し、諮る。ほかの腕は続けてよい
- 実行基盤が書き込み・移動・削除を拒む（回避せず、利用者に提示して許諾を得る）
