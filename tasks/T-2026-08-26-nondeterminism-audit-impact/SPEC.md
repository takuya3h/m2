# 非決定性を含む揺らぎの上に下された既存の判定の棚卸しと再測定の優先順位

**task_id:** T-2026-08-26-nondeterminism-audit-impact  **kind:** analysis  **server:** bengio

---

## 0. 最初に読むこと

**本契約の成果は、配布からおよそ 24 時間後の進捗報告会で使われる。**

実行に使ってよいのは **Phase A の開始から 14 時間まで**である。
**Phase A を始める前に時刻を記録し、各 Phase の入口で経過を確かめること。**

**本契約は GPU を使用しない。**

**本契約は版管理された記録だけで完結する。**
実験の実体、データ、重みを必要としない設計にしてある。
**当該ホストに実験の証跡が少なくても実行できるはずである。**
できない場合は、何が足りないかを記録して止めること。

**本契約は他の四台と同時に走っている。** 生成物の再生成は禁じている（第 5 節）。

---

## 1. 背景

### 1.1 決定性の制御を欠く run が多数ある

横断索引の監査で、**計算の決定性を制御せずに走った run が多数あることが実測されている。**
学習の入口ごとに件数の内訳も出ている。**主要な入口のほとんどが該当する。**

**同じ種を与えても、同じ値が出るとは限らない状態である。**

### 1.2 揺らぎの解釈が混合になっている

投影の集約では、揺らぎの解釈が三つに分類されている。

- 種の効果によるもの
- **種の効果と非決定性の混合**
- 不明

**混合に分類されているものが最も多い。**

**これが意味するのは次である。**
種の間の差として測った揺らぎには、**種を変えたことによる差だけでなく、
同じ種でも走るたびに変わる分が混ざっている。**

### 1.3 これが判定に効く

**揺らぎが大きく見積もられていれば、判定は厳しい方向へ偏る。**
**小さく見積もられていれば、甘い方向へ偏る。**

どちらへ偏るかは、混合の内訳による。**内訳は測られていない。**

**さらに悪いことに、偶然小さく出た揺らぎの上で判定が下された事例が実測されている。**
ある結論は、全ての種で同じ向きに動き、比も大きかったため有意とされたが、
後の測定で真の揺らぎがはるかに大きいと分かり、**見かけの有意であったと判明した。**
**その結論は「信じてはならない」と記録されている。**

**同じことが他の結論でも起きている可能性がある。それが本契約の問いである。**

### 1.4 決定化の実測

決定化を有効にすると計算は遅くなることが実測されている。
また、決定化した場合の検出の下限も、種の数ごとに実測されている。

**これらは特定の入口で測られた値である。**
**他の入口へそのまま当てはめてはならない。**

---

## 2. 本契約が行うこと

**既存の判定を、脆いものと頑健なものに分類する。**

そのうえで、**再測定すべきものの優先順位を出す。**

**判定を覆さない。** 覆すのは再測定であって、本契約ではない。
**本契約が出すのは「どれを疑うべきか」の順序である。**

### 2.1 やってはならないこと

**実測されていない値を外挿すること。**

決定化した場合に揺らぎがどれだけ下がるかは、**特定の入口で測られた値しかない。**
それを他の入口へ当てはめて「この結論はこう変わるはずだ」と書いてはならない。

**書けるのは、実測された事実と、そこから直接言えることだけである。**

## 3. 手順

### Task 1 — 開始の記録

**Step 1.** 現在時刻を記録する。

**Step 2.** 作業ツリーの状態を確かめる。**汚れていれば退避してから進む。**
**退避には本契約の識別子を含む名前を付けること。** 退避したことを報告に残す。
**戻すのは契約が終わり、元の分岐へ戻ってからである。本契約の中で戻さない。**

**Step 3.** 抑止の目印を置く。**報告を終えたら移動によって解除する。**

### Task 2 — Phase A 索引と投影の所在確認

**Step 1.** 横断索引と、その投影が実在するかを**実測で確かめる。**
**在ると仮定してはならない。**

**Step 2.** 母集団の件数を実測で得る。
**契約に書かれている件数と一致するかを確かめること。**
**一致しなければ、索引が更新されている。その旨を記録し、実測の側を使う。**

**Step 3.** 決定性の制御を欠く run の件数と、入口ごとの内訳を実測で得る。

**Step 4.** 一致が零件だった場合は探し方を疑う。**異質な方法で二度確かめる。**
**先頭がドットのものを含めること。**

**判定 G1** — 索引が実在し、件数が実測で得られたか。

### Task 3 — Phase B 揺らぎの出所と解釈の突き合わせ

**Step 1.** 各実験について、次を突き合わせた表を作る。

- 揺らぎの出所（対の差から求めたものか、run の内側の種の散らばりか、記録が無いか）
- 揺らぎの解釈（種の効果か、混合か、不明か）
- 判定の結果
- 判定に使われた比
- 種の数
- 使われた学習の入口が、決定性の制御を欠くものかどうか

**Step 2.** **記録が欠けている欄を、推定で埋めない。** 欠けていると書く。

**Step 3.** 突き合わせの結果、**両立しない組み合わせがあれば特定する。**
たとえば、揺らぎの出所が記録されていないのに解釈が確定しているもの、
種の効果と分類されているのに決定性を欠く入口で走ったもの、などである。

**判定 G2** — 表ができ、両立しない組み合わせが特定されたか。

### Task 4 — Phase C 脆さの分類

**Step 1.** **分類の基準を、分類を行う前に書き出して記録する。**

**この Step を Step 2 より後に行ってはならない。**

基準に含めるべき観点を挙げるが、**実装と記録を読んで妥当な基準を決めてよい。決めたものを記録すること。**

- 判定の比が基準にどれだけ近いか。**近いものほど脆い**
- 種の数がいくつか。**少ないものほど脆い**
- 揺らぎの解釈が混合か。**混合ほど脆い**
- 揺らぎの出所が記録されているか。**記録が無いものは最も脆い**

**Step 2.** 対照を両方向で設置する。

- **陽性対照** — **既に脆いと判明している結論。**
  真の揺らぎがはるかに大きいと後から分かり、見かけの有意であったと記録されている結論が該当する。
  **分類は、これを脆い側に入れるはずである。**
- **陰性対照** — **効果量が大きく、種も多く、揺らぎの出所も記録されている結論。**
  **分類は、これを頑健な側に入れるはずである。**

**片方向だけでは、すべてを脆いとする分類と、すべてを頑健とする分類を区別できない。**

**Step 3.** 分類が対照を正しく分離しなければ、**基準を見直す。**
**見直した経緯を記録すること。** 見直したこと自体は問題ではない。
**問題なのは、対照を通らない基準で全体を分類することである。**

**Step 4.** すべての実験を分類する。**都合のよいものだけを選ばない。**

**判定 G3** — 分類が対照によって検証されたか。

### Task 5 — Phase D 再測定の優先順位

**Step 1.** 脆いと分類されたもののうち、**再測定すべき順序を並べる。**

順序を決める観点を挙げるが、**決めたものを記録すること。**

- その結論が、現在の研究の方針にどれだけ効いているか
- 再測定に要する規模（**実測できない場合は、その旨を書く。推測を数値で書かない**）
- 同じ入口の他の結論もまとめて測り直せるか

**Step 2.** **判定を覆さない。** 覆すのは再測定である。
**本契約が出すのは順序であって、結論の訂正ではない。**

**Step 3.** **実測されていない値を外挿しない。**
決定化した場合に揺らぎがどう変わるかは、特定の入口で測られた値しかない。
**他の入口へ当てはめてはならない。**

**判定 G4** — 優先順位が根拠とともに並んだか。

### Task 6 — Phase E 報告

**Step 1.** 報告会で使える形にする。読む側が最初に知りたいのは次である。

- 既存の結論のうち、確定した事実として扱えるのはどれか
- 再測定が要るのはどれか
- その理由は何か

**Step 2.** 変更範囲の一覧を出す。

**Step 3.** 完了報告を**二つに分ける。**

- 事実の記録 — 判定、完了判定の表、次の契約で使う値、起票者の誤り、逸脱、想定外、送出。**目安は百五十行以内。**
- 証跡の記録 — 命令とその出力、対照の出力、変更範囲の一覧、台帳の応答。

**事実の記録から証跡の記録を行番号で指すこと。**

**Step 4.** PR を作る。**送り出しただけでは統合ではない。**
**分岐が規定の接頭辞で始まっていることを確かめる。**

**Step 5.** 抑止の目印を移動によって解除する。

## 4. 同時に走っている別の契約との関係

**別のホストで、一つ抜き検証の判定則を作り直す契約が走っている。**

**二つは別の問題を扱っている。混同しないこと。**

- **その契約** — 一つ抜き検証の各 fold が互いに独立でないことによる、揺らぎの過小評価
- **本契約** — 計算が決定的でないことによる、揺らぎの解釈の混合

**どちらも「既存の判定がどれだけ信じられるか」を問うが、原因が違う。**

**本契約で一つ抜き検証の判定則を作り直してはならない。** それは別の契約の範囲である。

## 5. 禁止

**以下は実行者の操作に対する禁止であり、自動同期の仕組みによる配布を含まない。**

1. 分割の定義を変えない。
2. 生の記録へ書き込まない。
3. 測っていない値を書かない。**測れなかったものは、測れなかったと書く。**
4. **投影と集約の再生成を行わない。**
   四台で別の契約が同時に走っており、これらは必ず衝突する。
   **全ての PR が統合された後、一台で一度だけ回す。**
   **本契約は索引を読むが、作り直さない。**
5. **既存の結果の値を書き換えない。**
6. **判定を覆さない。**（第 2 節）
7. **実測されていない値を外挿しない。**（第 2 節 2.1）
8. **一つ抜き検証の判定則を作り直さない。**（第 4 節）
9. **GPU を使用しない。** 本契約に GPU を要する処理は無い。
10. **秘匿の値を出力しない。** 判定に要るのは長さと有無だけである。
    **判定するのは件数ではなく形である。**

## 6. 想定外への対処

- **道具が無い、権限が無い、対象が零件** — **そのまま採用しない。**
  何を、どの状態で、どの方法で見た結果かを確かめてから記録する。
- **索引の件数が契約の記載と食い違う** — **索引が更新されている。**
  実測の側を使い、食い違いを記録する。**契約の側に合わせない。**
- **禁止領域の検査が失敗する** — 本契約は新しい run を作らないため、失敗するなら別の原因である。
  **内訳を一件ずつ示すこと。** 開始前から在った未追跡が原因である可能性がある。
- **終了コードを件数と呼ばない。** 数えるなら数える命令を使う。
- **配列の添字の書式はシェルによって違う。** 過去に二契約続けて終了コードの検査が空振りしていた。
- **命令ごとに新しいシェルが起きる実装系がある。** 読み込みは同じ命令の中に入れる。
- **履歴を読む操作は頁送りを無効にすること。**
- **背景で走らせた処理の出力を、完了の前に読まないこと。**

## 7. 完了判定

**判定が通ったことは、その判定が働いていることを意味しない。**
各行に「空振りでないことの確認」を書く。**空欄にしない。「確認した」と書かない。**

| # | 判定 | 期待 | 空振りでないことの確認 |
|---|---|---|---|
| a | 索引の所在を確かめた | 実在する | 存在しない経路を同じ方法で調べれば、不在として返るはずである |
| b | 母集団の件数を実測した | 件数が得られている | 契約の記載と突き合わせる。食い違えば索引が更新されている |
| c | 決定性を欠く run の内訳を得た | 入口ごとの件数がある | 合計が母集団を超えていれば、数え方が誤っている |
| d | 揺らぎの出所と解釈を突き合わせた | 実験ごとの表がある | 欠けている欄が空欄で残っている。推定で埋まっていない |
| e | 両立しない組み合わせを特定した | 一覧がある、または零件である旨がある | 零件なら、探し方が働いているかを別の方法で確かめる |
| f | 分類の基準を先に定めた | 記録の時点が分類より前である | 記録が分類の後なら、この判定は満たされない |
| g | 陽性対照が脆い側に入った | 既に脆いと判明している結論が脆いと分類される | 入らなければ、基準が働いていない |
| h | 陰性対照が頑健な側に入った | 効果量が大きく種も多い結論が頑健と分類される | 入らなければ、基準がすべてを脆いとしている |
| i | すべての実験を分類した | 分類の無い実験が無い | 分類の無い行があれば満たされない |
| j | 優先順位を根拠とともに並べた | 各項目に根拠がある | 根拠の無い項目があれば満たされない |
| k | 判定を覆していない | 既存の判定の値が変わっていない | 変わっていれば範囲を越えている |
| l | 外挿していない | 実測されていない値からの推論が無い | 推論があれば、その旨が明示されている必要がある |
| m | 数値が実測へ遡れる | 出所が記録されている | 出所の無い数値があれば満たされない |
| n | 変更範囲の一覧を出した | 一覧がある | 検査が失敗する場合は内訳を一件ずつ示す |
| o | PR が存在する | 番号が記録されている | 送り出しただけの状態は満たさない |
| p | 報告が二つに分かれている | 事実の記録と証跡の記録が別にある | 一つしか無ければ満たされない |
| q | 締切に対する経過が記録されている | 各 Phase の入口の経過が残っている | 記録が空なら満たされない |

## 8. 起票者からの申し送り

**起票者は実行環境を持たない。** 以下は前提であって実測ではない。**違っていたら報告すること。**

1. **契約に書いた母集団の件数は、起票の時点の投影から引いたものである。**
   **索引が更新されていれば食い違う。実測の側を使うこと。**
2. **入口として挙げた実装は、名が変わっている可能性がある。** 実装を読んで決めてよい。
3. **当該ホストに実験の証跡が少ないことは承知している。**
   **本契約は版管理された記録だけで完結する設計にしてある。**
   それでも走らない場合は、何が足りないかを記録して止めること。
4. **既に脆いと判明している結論が、記録のどこにあるかは起票者が特定していない。**
   **探し方は実装と記録を読んで決めてよい。** 見つからなければ、
   別の陽性対照を選び、選んだ理由を記録すること。
5. **決定化の実測値は特定の入口で測られたものである。**
   **他の入口へ当てはめてはならない。**
6. **本契約は判定を覆さない。** 順序を出すところまでが範囲である。

## 9. 報告

事実の記録と対の記録を埋めて記録すること。逸脱は必須である。逸脱が無い場合も、無かった旨を一件書く。

**起票者の誤りを見つけたら、遠慮なく記録すること。**
何が誤っていたか、指示どおり実行すると何が起きたかの二つを含めること。
**これは起票者を改善するための記録である。**
