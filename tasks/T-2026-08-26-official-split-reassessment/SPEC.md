# 公開されている公式の分割で得た結果を主軸として整理し直す

**task_id:** T-2026-08-26-official-split-reassessment  **kind:** analysis  **server:** philip

---

## 0. 最初に読むこと

**本契約は、起票者の枠組みの誤りを正すために起票された。**

**実行に使ってよいのは、開始から十時間までである。**
**Phase A を始める前に時刻を記録し、各 Phase の入口で経過を確かめること。**

**本契約は GPU を使用しない。** 既存の記録の読み取りと再集計だけで完結する。

**本契約は他のホストの契約と同時に走っている。** 生成物の再生成は禁じている（第 6 節）。

---

## 1. 背景 — 何を間違えたか

### 1.1 起票者が評価の枠組みを勝手に移した

**このデータセットには、公開されている公式の分割がある。**
**これまでの研究はその分割に従って進められてきた。**

**しかし起票者は、直近の契約群で一つ抜き検証にもとづく数字を主軸として報告した。**
さらに「公式の検証側は条件が良すぎる」という趣旨の説明を添えた。
**これは事実上、公式の分割への批判であった。**

**利用者の確認を取らずに評価の枠組みを移したのは、起票者の誤りである。**

### 1.2 先行研究の指摘は逆方向である

**起票者は、一つ抜き検証の方が厳しい評価だと暗黙に前提していた。**

**しかし、この分野の評価指標に関する技術報告は逆を指摘している。**

- **公式の分割から逸脱した交差検証の結果は、先行研究と比較できない。**
- **交差検証では各回で学習に使う量が増えるため、数字が高く出る傾向がある。**
  固定した分割なら未見のままであるはずのデータが、学習側に入るためである。

**つまり一つ抜き検証は、厳しいどころか甘く出る方向に働く可能性がある。**

**起票者はこの前提を確かめずに報告した。**

### 1.3 撤回の判断が一つ抜き検証にもとづいている

**起票者は、工程を弁別しない術具を落とす手法を撤回すると報告した。**
**その根拠は一つ抜き検証での符号の個数であった。**

**しかし公式の分割での結果は別にある。**
記録によれば、公式の分割では分類の正しさは動かず、
**工程ごとの成績を平均した指標は改善していた。**

**したがって、公式の分割を主軸に据えるなら、撤回の判断そのものを見直す必要がある。**

**本契約はその材料を作る。判断そのものは行わない。**

## 2. 決定的に重要な制約 — 判定の使い回しを禁じる

### 2.1 一つ抜き検証専用の判定を公式の分割へ当ててはならない

**先行する契約が確定させた判定のうち二つは、分け方の間の相関を扱うものである。**

**公式の分割には分け方が存在しない。**分割は一通りである。
**したがってこれらの判定は当てられない。**

**当てれば、意味を持たない数字が出る。**
**そして数字が出てしまうと、意味があるかのように読まれる。**

**当てないこと。当てられない理由を記録すること。**

### 2.2 公式の分割で使える判定には別の限界がある

**公式の分割では、種を変えた反復にもとづいて揺らぎを測る。**

**しかし、別のホストで走った契約が次を実測している。**

- **これまでの判定のすべてが、計算の決定性を制御していない実行の上に立っている。**
- **したがって種の間の散らばりには、種の効果と非決定性が混ざっている。**
- **確定した事実として扱えるものはごく少ない。**

**公式の分割の判定も、この制約から自由ではない。**

**各結論について、揺らぎの出所と、決定性が制御されていたかを必ず併記すること。**

### 2.3 したがって本契約が出すのは判定ではなく材料である

**出すのは次である。**

- 公式の分割での効果量
- 種の数
- 揺らぎの出所
- 決定性が制御されていたか
- **どの判定が当てられ、どの判定が当てられないか**

**単一の判定へ丸めないこと。**

## 3. 手順

### Task 1 — 開始の記録

**Step 1.** 現在時刻を記録する。

**Step 2.** 作業ツリーの状態を確かめる。**汚れていれば退避してから進む。**
**退避には本契約の識別子を含む名前を付けること。** 退避したことを報告に残す。
**戻すのは契約が終わり、元の分岐へ戻ってからである。**

**Step 3.** 抑止の目印を置く。**報告を終えたら移動によって解除する。**

**この目印は版管理の自動統合を止めるが、ファイルの同期は止めない。**
**実行中に他ホストのファイルが現れたり、実装が消えたりすることがある。実測がある。**
**消えた場合は版管理から復旧し、実行の正本を同期の対象外へ置くこと。**

### Task 2 — Phase A 公式の分割で測られた結果の棚卸し

**Step 1.** 公式の分割で測られた結果がどこにあるかを、**実測で確かめる。**
**在ると仮定してはならない。**

**Step 2.** 対象とする結論を一覧にする。
**少なくとも次が含まれるはずである。含まれないものがあれば、その旨を記録する。**

- 術具の情報を工程認識へ渡すことの効果
- 全体平均の特徴を足すことの害
- 正しい術具存在を与えたときの追加の利得
- 入力側の雑音除去の効果
- 工程を弁別しない術具を落とすことの効果
- 工程の情報を術具検出へ渡すことの効果

**Step 3.** 各結論について、**検証側と評価側のどちらで測られたかを区別する。**
**混ぜないこと。**

**Step 4.** 一致が零件だった場合は探し方を疑う。**異質な方法で二度以上確かめる。**
**先頭がドットのものを含めること。**

**判定 G1** — 公式の分割の結果が実在し、一覧になったか。

### Task 3 — Phase B 効果量と揺らぎの整理

**Step 1.** 各結論について、次を表にする。

- 効果量
- 種の数
- 揺らぎの値
- **揺らぎの出所**（対の差から求めたものか、反復の散らばりか、記録が無いか）
- **決定性が制御されていたか**
- 測られた分割（検証側か評価側か）

**Step 2.** **記録が欠けている欄を推定で埋めない。** 欠けていると書く。

**Step 3.** **揺らぎの出所が記録されていない結論を特定する。**
**それらは効果量しか読めない。** その旨を明記する。

**判定 G2** — 表ができ、欠けている欄が空欄で残っているか。

### Task 4 — Phase C 判定の切り分け

**Step 1.** **どの判定が公式の分割へ当てられ、どれが当てられないかを整理する。**（第 2 節）

**当てられない判定を当ててはならない。**

**Step 2.** 当てられる判定について、対照を両方向で設置する。

- **陽性対照** — **効果が明らかに大きい既知の結論。**
  全体平均の特徴を足すことの害が該当する。**どの判定でも検出されるはずである。**
- **陰性対照** — **効果が実質的に無い既知の結論。**
  工程の情報を術具検出へ渡すことの全体的な効果が該当する。
  **どの判定でも検出されないはずである。**

**片方向だけでは、常に検出する判定と、常に検出しない判定を区別できない。**

**Step 3.** **陰性対照は、経路を通ったうえで零になるものを選ぶこと。**
**構造上どうやっても零になるものは、対照にならない。**
別の契約で、この型の欠陥が実測されている。

**Step 4.** 対照が正しく分離しなければ、**そこで止めて報告する。**

**判定 G3** — 当てられない判定を当てていないか。対照が働いているか。

### Task 5 — Phase D 二つの枠組みの並置

**Step 1.** 各結論について、**公式の分割での結果と一つ抜き検証での結果を並べる。**

**Step 2.** **食い違う結論を特定する。** これが本契約の主たる成果である。

**Step 3.** 食い違いについて、**どちらが正しいとは書かない。**
**枠組みが違えば違う数字が出るのは当然である。**
**書くのは、どちらの枠組みで何が言えるかである。**

**Step 4.** **撤回の対象とした結論について、公式の分割での結果を明示する。**
**撤回を維持するか取り消すかは、起票者と利用者の判断事項である。**
**本契約は判断しない。材料を出す。**

**判定 G4** — 二つが並び、食い違いが特定されたか。

### Task 6 — Phase E 報告

**Step 1.** 読む側が最初に知りたいのは次である。

- 公式の分割だけを見たとき、支持される結論はどれか
- 支持されない結論はどれか
- 一つ抜き検証と食い違う結論はどれか
- **撤回の対象とした結論は、公式の分割ではどうだったか**

**Step 2.** 変更範囲の一覧を出す。

**検査は失敗する。** 本契約の成果物の置き場所そのものが禁止領域として扱われるためである。
**これは道具の側の欠陥であり、契約違反ではない。**
**内訳を一件ずつ示すこと。**

**Step 3.** 完了報告を**二つに分ける。**

- 事実の記録 — 判定、完了判定の表、次の契約で使う値、起票者の誤り、逸脱、想定外、送出。**目安は百五十行以内。**
- 証跡の記録 — 命令とその出力、対照の出力、変更範囲の一覧、台帳の応答。

**事実の記録から証跡の記録を行番号で指すこと。**

**Step 4.** PR を作る。**送り出しただけでは統合ではない。**
**base は分岐の起点と同じ分岐にすること。既定の分岐ではない。**

**Step 5.** 抑止の目印を移動によって解除する。

## 4. 本契約が行わないこと

- **判定を単一の則へ丸めること。**
- **撤回を取り消すこと、または維持を確定させること。**
- **どちらの評価枠組みが正しいかを決めること。**
- **既存の報告の記述を書き換えること。**

**いずれも起票者と利用者の判断事項である。**

**本契約は材料を出すところまでが範囲である。**

## 5. 先行する契約から引き継ぐ実測

**以下は他のホストで実測された値である。前提としてよい。**

- **判定のすべてが、決定性を制御していない実行の上に立っている。**
- **決定化して走った実行は、判定を一つも持たない。**
- **脆いと分類された判定の大半が、二つの学習の入口に集中している。**
- **揺らぎに対する比の大きさは、頑健さの証拠にならない。**
  比が母集団で最大の判定が、既知の見かけの判定より散らばりが小さかった。
- **分母として指定されている実験自体が、決定性を制御していない。**
- 一つ抜き検証の分け方の間の相関は、実測では小さかった。
  **それでも補正すると多くの判定が落ちた。補正が保守的である可能性がある。**

## 6. 禁止

**以下は実行者の操作に対する禁止であり、自動同期の仕組みによる配布を含まない。**

1. **公式の分割の定義を変えない。読むだけである。**
2. 生の記録へ書き込まない。
3. 測っていない値を書かない。**測れなかったものは、測れなかったと書く。**
4. **投影と集約の再生成を行わない。**
   他のホストで契約が同時に走っており、これらは必ず衝突する。
   **全ての PR が統合された後、一台で一度だけ回す。**
5. **既存の結果の値を書き換えない。**
6. **一つ抜き検証専用の判定を公式の分割へ当てない。**（第 2 節）
7. **判定を単一の則へ丸めない。**
8. **撤回の可否を判断しない。**（第 4 節）
9. **自分の成果でないものを段階に上げない。**
10. **GPU を使用しない。** 本契約に GPU を要する処理は無い。
11. **秘匿の値を出力しない。** 判定に要るのは長さと有無だけである。
    **判定するのは件数ではなく形である。**

## 7. 想定外への対処

- **道具が無い、権限が無い、対象が零件** — **そのまま採用しない。**
  何を、どの状態で、どの方法で見た結果かを確かめてから記録する。
- **禁止領域の検査が失敗する** — **契約違反ではない。**（第 3 節 Task 6 Step 2）
- **実行中に成果物がファイル同期で消えることがある。** 実測がある。
  **消えた場合は版管理から復旧し、実行の正本を同期の対象外へ置くこと。**
- **他ホストの成果物が実行中に現れることがある。** 触れないこと。
- **終了コードを件数と呼ばない。** 数えるなら数える命令を使う。
- **配列の添字の書式はシェルによって違う。** 先行する契約で複数回、検査が空振りした。
- **命令ごとに新しいシェルが起きる実装系がある。** 読み込みは同じ命令の中に入れる。
- **履歴を読む操作は頁送りを無効にすること。**
- **背景で走らせた処理の出力を、完了の前に読まないこと。**
- **読み込みの遅い仕組みに注意する。** 配列を保持する形式には、
  参照のたびに全体を展開し直すものがある。**ループの前に実体化すること。**

## 8. 完了判定

**判定が通ったことは、その判定が働いていることを意味しない。**
各行に「空振りでないことの確認」を書く。**空欄にしない。「確認した」と書かない。**

| # | 判定 | 期待 | 空振りでないことの確認 |
|---|---|---|---|
| a | 公式の分割の結果の所在を確かめた | 一覧がある | 存在しない語で同じ探索を行えば零件で返るはずである |
| b | 検証側と評価側を区別した | どちらで測られたかが各行にある | 区別の無い行があれば満たされない |
| c | 効果量と種の数と揺らぎの出所を整理した | 表がある | 欠けている欄が空欄で残っている |
| d | 推定で埋めていない | 推定値が無い | 出所の無い数値があれば満たされない |
| e | 当てられない判定を当てていない | 分け方に依存する判定が公式の分割に無い | 当てていれば禁止に触れている |
| f | 当てられない理由を記録した | 理由が書かれている | 理由が無ければ満たされない |
| g | 陽性対照が検出された | 効果が大きい既知の結論が検出される | 検出されなければ判定が働いていない |
| h | 陰性対照が検出されなかった | 効果が無い既知の結論が検出されない | 検出されれば判定がすべてを検出している |
| i | 陰性対照が経路を通っている | 構造上の零ではない | 構造上どうやっても零なら対照にならない |
| j | 決定性の有無を併記した | 各行にある | 併記の無い行があれば満たされない |
| k | 二つの枠組みを並べた | 同じ表にある | 並んでいなければ食い違いを読めない |
| l | 食い違いを特定した | 一覧がある、または零件である旨がある | 零件なら、探し方が働いているかを別の方法で確かめる |
| m | どちらが正しいと書いていない | 優劣の判断が無い | 判断があれば範囲を越えている |
| n | 撤回の対象の結果を明示した | 公式の分割での値がある | 値が無ければ満たされない |
| o | 撤回の可否を判断していない | 判断が無い | 判断があれば範囲を越えている |
| p | 変更範囲の一覧を出した | 一覧がある | 検査が失敗する場合は内訳を一件ずつ示す |
| q | PR が存在し base が正しい | base が起点と同じ分岐 | 既定の分岐になっていれば満たされない |
| r | 報告が二つに分かれている | 事実の記録と証跡の記録が別にある | 一つしか無ければ満たされない |
| s | 締切に対する経過が記録されている | 各 Phase の入口の経過が残っている | 記録が空なら満たされない |

## 9. 起票者からの申し送り

**起票者は実行環境を持たない。** 以下は前提であって実測ではない。**違っていたら報告すること。**

1. **公式の分割で測られた結果が、効果量として読める形で残っているかは未確認である。**
   要約された値しか残っていないものは、読める範囲を明示すること。
2. **入口として挙げた実装は、名が変わっている可能性がある。** 実装を読んで決めてよい。
3. **記録によれば、公式の分割では術具を落とす手法について、
   分類の正しさは動かず、工程ごとの成績を平均した指標が改善していた。**
   **これが実測として確かめられるかを見ること。確かめられなければ、その旨を記録する。**
4. **起票者は先行する六つの契約で、合わせて二十二件の誤りを記録された。**
   **特に、実測していない前提を断定する誤りを繰り返している。**
   **本契約の背景に書いたことも前提である。違っていれば記録すること。**
5. **本契約は、起票者が評価の枠組みを勝手に移した誤りを正すために起票された。**
   **起票者の側の誤りであり、実行者や過去の作業の誤りではない。**
6. **陰性対照は経路を通るものを選ぶこと。**
   別の契約で、構造上どうやっても零になる対照を置いた欠陥が実測されている。
   **同じ型を繰り返さないこと。**

## 10. 報告

事実の記録と対の記録を埋めて記録すること。逸脱は必須である。逸脱が無い場合も、無かった旨を一件書く。

**起票者の誤りを見つけたら、遠慮なく記録すること。**
何が誤っていたか、指示どおり実行すると何が起きたかの二つを含めること。
**これは起票者を改善するための記録である。**
