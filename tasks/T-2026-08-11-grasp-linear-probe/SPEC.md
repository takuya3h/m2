# 把持の対応が凍結特徴から読み取れるかを線形の分類器で測る

**task_id:** `T-2026-08-11-grasp-linear-probe`  **kind:** `analysis`
**depends_on:** `T-2026-08-11-hts-comparability-audit`
**実行ホスト:** `bengio`

## Goal

工程分類のモデルは、**凍結された検出器の特徴**を入力にしている。その上に把持の対応を
推論する部分を載せる設計が進んでいる（`T-2026-08-11-grasp-inference-injection-impl`）。

**その入力に、把持を読み取れるだけの情報が残っているかを先に測る。**

残っていなければ、推論は当たらない。当たらない推論結果を工程へ渡しても効かない。
**実装と実験を作り込んでから気づくのを避ける。**

測り方は**線形の分類器**である。凍結特徴の上に一段の線形変換だけを載せて 5 次元の
標識を当てさせる。線形で読めるなら、その情報は特徴に素直な形で残っている。

**計算装置は使わない。** 凍結特徴は計算済みのものを読むだけであり、載せるのは
線形変換一段である。

**本契約は読み取りと測定のみである。学習コードも設定も変更しない。**

| **4** | **右手が器具を持っている** | **ここが本題** |
| **5** | **両手で器具を持っている** | **ここが本題** |

ということであり、注入する信号の設計を変える必要がある。

**見込みは起票者の推測である。外れてよい。実測を記録する。**

# Phase C — 対照を置いて値の意味を確かめる

## Task 3: 測り方が空回りしていないことを示す（G2）

**Files:** Create `AUD/control.txt`

**値が出たことを結果と混同しない。** 測り方が壊れていても値は出る。

- [ ] **Step 1: 偶然並みの入力で測る（陰性の対照）**

  同じ手順を、**情報を持たない入力**で回す。

  | 対照 | 作り方 |
  |---|---|
  | 教師の順を混ぜる | フレームと教師の対応を崩す。**動画をまたいで混ぜること** |
  | 特徴を乱数に置き換える | 形と大きさは同じにする |

  **どちらも曲線下面積が 0.5 前後に落ちること。**
  落ちなければ、**測り方が特徴以外の何かを拾っている。** G2 は `stop`。

  **教師の順を混ぜるとき、同じ動画の中に留めない。** 留めると隣り合うフレームの
  教師が似ているため、情報が残って対照にならない。

- [ ] **Step 2: 易しい問いで測る（陽性の対照）**

  **答えが分かっている易しい問いで、手順が働くことを示す。**

  凍結特徴から、そのフレームに術具の注釈が 1 件以上あるかを当てさせる。
  検出器の特徴なので、**これは当たるはずである。**

  当たらなければ、手順そのものか特徴の読み込みに問題がある。**G2 は `stop`。**

  **陰性と陽性の両方を置くこと。** 片方だけでは、測り方が常に高い値を返す壊れ方も、
  常に低い値を返す壊れ方も、どちらかを見逃す。

- [ ] **Step 3: 値の振れ幅を確かめる**

  乱数の種を変えて数回繰り返し、**値がどれだけ振れるか**を出す。
  振れ幅より小さい差を「差がある」と述べない。
