# Stage 2 の前提の実測: フレームと注釈の対応、送り手信号の時刻と形、参照入力段の実装、メタデータ、andrew の材料の所在

**task_id:** T-2026-10-14-frame-signal-audit  **kind:** analysis

## 1. 背景

Stage 2 は、凍結した二つの塔の間に小さな界面を置き、一方の塔の出力を他方へ渡したときの差を測る。
その設計を固める前に、次の四つが実測されていない。

1. **どのフレームに注釈があり、塔はどのフレーム列を「時間」として扱っているか。**
   工程の注釈と術具の注釈は同じフレームに付いているとは限らない。動画の中でフレーム番号が飛ぶ所もある。
   経過時間を対照に使う設計、時刻を揃えて信号を渡す設計は、この実態に依存する
2. **既存の送り手信号が、どの時刻の情報を使っているか。** 設計文書には「工程から検出へは一つ前の時刻まで」
   という規則があったが、既存の実装がそうなっているかは誰も確かめていない
3. **参照入力段の「正解」と「正解と予測の組み合わせ」が、どう作られているか**（連結か和か、次元）
4. **動画のメタデータ**（術式、術者、手術室、長さ、撮影日）が在るか。経過時間や術者が信号に紛れ込んでいないかを
   確かめる対照を作れるかが、これで決まる

あわせて、後続の二つの契約（工程塔 15 動画 COCO 系統の andrew での学び直し、時間ヘッドの分散の分解）の前提として、
**andrew に材料が在るか**を読むだけで確かめる。

**本契約では GPU を使用しない。** 学習も推論もしない。読む、数える、突き合わせるだけである。

用途は Stage 2 の設計と、提案カードの前提の訂正である。**結果は関門の判定には使わない。**

## 7. 想定外と停止条件

- 本ホストの repo の位置や起点が `context/env-facts.md` の記載と違う → 停止して諮る
- 注釈の版管理下のファイルが起点と一致しない → 停止して諮る
- 画像が本ホストに無い → 停止しない。画像に依存する項目を UNKNOWN とし、注釈だけで進める
- 既存スクリプトの挙動を変えないと測れない → 停止して諮る
- 読むための道具が大きくなりそうなら、作る前に範囲を記録する（本契約は読むだけの調査である）

## 8. 報告の構成

`RESULT.md` は起票者が判断に使う事実だけ。目安 150 行以内。

| 節 | 内容 | 入れないもの |
|---|---|---|
| 判定 | `verdict` と各 Gate の結果 | 手続きの全文 |
| 完了判定 | 表。各項目に実測値 | 命令の全文 |
| 実測 | 次の契約で使う値（四つの集合の件数、塔が見るフレーム列と飛び、時刻の根拠、評価の単位、経路ごとの時刻の表、参照入力段、信号の形、メタデータ、andrew の材料） | 経過の説明 |
| 起票者の誤り | 型と内容。一件三行以内 | 引用の全文 |
| 逸脱 | 何をなぜ | 手順の再掲 |
| 想定外・UNKNOWN | 測れなかったものと理由 | 不要なログ |
| 送出 | PR 番号、終了コードだけ | 出力の全文 |

`audit.md` へ: 命令とその出力、要約値、探した場所の一覧、対照の出力、変更範囲の一覧、台帳の応答。
`RESULT.md` から `audit.md` を行番号で指す。同じ内容を二度書かない。
