## 1. 目的と背景

利用者は `/task` に識別子を一行渡すだけで契約を始めたい。現状は起動の前に、分岐の確認、
作業ツリーの汚れの確認、目印の手作業、`make task-start` を利用者が手で並べている。
汚れで止まることが多く、手間がかかっていた。

前契約で次の二つが入った。

- task_start.sh が置く目印（`.sync-pause`）に所有の記録が入る
- 契約の終わりに目印を外す道具 `make task-release`（完了と中止の二つの終わり方）

会話の抽出物は 2026-10-07 から版管理の外へ出たため、作業ツリーの汚れの主因は無くなった。

本契約は手順書（`.claude/skills/task/SKILL.md`）を改め、始めから終わりまでを手順書の中で通す。

### 利用者の決定（2026-10-07、運用会話）

1. 手順書の恒久の変更として、始める段を手順書に入れる
2. 汚れが在るときは、分類して利用者に示し、選んでもらってから退避する（自動で退避しない）
3. 解除は道具で行う。完了の前提はすべて必須で、台帳の状態は含めない。解除の後の分岐はそのまま
4. 手順書の改訂は道具の契約とは別の契約にする（本契約）

### 終える段

- **R9** 終わり方を二つ書く
  - **完了**: commit、push、PR、`make task-report` の後に `make task-release` を完了で呼ぶ
  - **中止**: 完了せずに終えるとき（検証やプリフライトの失敗、gate の stop、利用者が止めた）に理由つきで呼ぶ
  - 利用者に問い合わせて同じセッションで続けるときは呼ばない
  - 完了の前提を満たせないとき、自分で中止へ切り替えない。利用者に諮る
- **R10** 一行の状態表示で結果を判定し、状態ごとの扱いを書く。道具の冒頭の状態の一覧と集合が両方向で一致すること。最低限、次を満たす
  - `RELEASED` と `ABSENT` は終わり
  - `PREREQ_MISSING` は欠けた前提を満たしてやり直す。満たせなければ利用者へ
  - `PREREQ_UNKNOWN` は一度だけやり直し、変わらなければ利用者へ
  - `OWNER_UNREADABLE` は、**始める段で task-start が「作成」と表示した場合に限り**手で外す。
    「実行前から存在」の場合は外さず利用者に伝える（人が保守で置いた目印を外さないため）
  - `OWNER_MISMATCH`、`POSITION_MISMATCH`、`RELEASE_FAILED`、`USAGE` は外さず利用者へ
- **R11** 解除の後に、git の状態を変える操作をしない。状態を変えない確認は commit の前に済ませる
- **R12** 解除の結果は版管理にも台帳にも残らないため、最後の応答で利用者に伝える
- **R13** 「7. 禁止事項」に、目印を手で置かない・手で外さない（R6 と R10 の例外を除く）を足す

## 5. 禁止事項

4. `context/auto/*` と `tasks/inbox.md` を再生成しない。`taskindex-check` と `inbox-check` も回さない
5. `experiments/**`、`data/**`、`runindex/**` に触れない
6. 開始前から在る未追跡を消さない
7. 外部への送信は `make task-report` と PR の起票（gh）以外の経路で行わない
8. 他のホストへ接続しない
9. 隔離した場の検証で、実物の `$M2DIR` の目印に触れない（Task F の 6 だけが例外）
10. `make docs-check` と `make agent-check` の既存の不合格（本契約と関係しない文書のもの）を直さない（別の契約で扱う）

## 7. 想定外と停止条件

- 既存の番号を付け替えないと段を置けない → 停止して諮る
- 二つの実装系の両方で成り立つ書き方が取れない → 停止して諮る
- task_start.sh の案内文の変更で既存の試験の期待が変わり、動作の変更と区別できない → 停止して諮る
- `make task-start` が作業ツリーの汚れで止まった → 開始前から在る未追跡は repo の外へ退避してよい。
  消さない。退避先と一覧を audit に残し、報告の後に戻すかを利用者に確かめる
- 実行基盤が書き込みや `rm` を拒む → 回避せず利用者に提示して許諾を得る
- 起票者の事実（§2）と実測が食い違う → 実測を正とし、起票者の誤りとして記録する
