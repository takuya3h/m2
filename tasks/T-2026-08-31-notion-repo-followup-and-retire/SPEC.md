# Notion 記録系の再構成に伴う repo 側の追随と旧経路の退役

**task_id:** T-2026-08-31-notion-repo-followup-and-retire  **kind:** impl

## 0. 位置づけ

Notion の記録系を再構成し、Claude アプリが読む正本（現在地・マスター・知見 DB・アーカイブ）を
2026-08-31 に作った。利用者の決定は次の三つである。

- CLI が Notion に触れるのは配布台帳（`task_distribution`）だけ。新しい面は CLI が読まない
- 旧データベース群（run 台帳、意思決定ログ、失敗知見、実験手順書、プロンプトライブラリ）は凍結し、アーカイブへ移す。内容は前契約 `T-2026-08-31-notion-legacy-toc-and-export`（PR #170）で repo へ写した
- 旧データベースへの自動書き込み（run 台帳への投稿、意思決定と教訓とプロンプトの保存）は止める

本契約はこれらを repo 側へ追随させる。GPU を使用しない。Notion への書き込みは行わない。
起票者は実行環境を持たないため命令を書かない。実装を読んで決めてよい箇所は実行者が決める。

対象ホストは任意。条件は資格情報の読み込みが成立することだけである。repo の位置と
合言葉の場所は `context/env-facts.md` の該当行に従う。

## 3. 達成すべきこと

- `configs/notion.yaml` に新しい面の識別子が載り、退役した識別子（旧 DB 群と旧頁群）は別の節へ移され「退役」と分かる。コードが読む鍵はすべて実在する。`task_distribution` は従来どおり
- 旧データベースへ自動で書く経路がすべて明示的に退役している。呼ばれたときに無言で成功したことにならない
- `scripts/notion_context_pack.py` は退役する。削除せず移動する。移動先は実行者が決めるが、現行手順の文書から参照されない場所にする
- エージェント向け文書は「CLI が Notion に触れるのは配布台帳だけ」と述べ、旧頁を MCP で読む手順と `notion_context_pack.py` の手順を含まない。新しい面は Claude アプリの面であり CLI は読まない、と一行で述べる
- 投影が一度だけ再生成され、両方の check が通る
- run 台帳の export が退役の後に取り直され、`docs/archive/notion/manifest.csv` の該当行が更新されている
- 旧マスター頁の見出しは、到達できれば取得され、できなければ `unreachable` のまま記録されている

## 4. 禁止事項

**実行者の操作に対する禁止である。同期処理による配布や自動 merge を含まない。**

| 2 | MCP を使う |
| 3 | Task B 以外での投影の再生成。Task B でも `make context` は回さない |

## 5. 手順

### Task A 前提の実測と門

- A-1 作業ツリーの汚れを確認する。開始前から在る未追跡は退避し、一覧を audit に残す
- A-2 `make task-start` で分岐と抑止を置く。分岐名が `feat/` で始まることを確かめる
- A-3 `spec.yaml` の `resolve-at-intake` と `counts` の零を実測値に差し替え、L1 と L2、`make spec-check` を回して結果を audit に残す
- A-4 **門**: `origin/phase0` に `docs/archive/notion/manifest.csv` があることを確かめる。無ければ停止して利用者へ戻す
- A-5 open な PR の一覧と、本契約以外の未統合の契約分岐を記録する
- A-6 試験を回し、失敗の一覧を記録する（作業前の基準）
- A-7 資格情報を読み込む。変数の有無と長さだけを記録する。成立しなければ Task E だけを `UNKNOWN` にして他を続ける（本契約の主目的は repo 側の追随であり、export の取り直しは従属する）

### Task B 投影の再生成（一度だけ）

- B-1 再生成の前に両方の check を回し、差分があることを記録する（陽性側。無ければそれも記録）
- B-2 `make taskindex` と `make inbox` を一度回す
- B-3 両方の check が通ることを確かめ、`make context-check` の結果も記録する（回すのは check だけ）
- B-4 再生成の差分を commit する。以後の Task で再生成しない

### Task C 登録簿の更新と自動書き込みの退役

- C-1 実装を読み、Notion の REST へ書く経路の集合を確定する（§2）。列挙は異質な二通りで行い、audit に両方の結果を残す
- C-2 各経路の呼び出し元を列挙する
- C-3 `configs/notion.yaml` を更新する。新しい面の識別子を載せ、退役した識別子を別節へ移し、コードが読む鍵の集合と登録簿の鍵の集合を照合する
- C-4 自動書き込みの経路を明示的に退役させる。方式は実行者が決める。呼ばれたときに退役の旨を記録して返し、無言で成功したことにしない
- C-5 退役を乾燥走行か模擬で確かめる。両方向で確かめる: 退役した経路は投稿せず退役の旨を返す、退役していない経路（配布台帳への報告）は従来どおり動く

### Task D 読み取り手順と文書の追随

- D-1 `scripts/notion_context_pack.py` を移動して退役させる。参照している文書と Makefile の目標を探し、追随させる
- D-2 `CLAUDE.md` `README.md` `docs/notion_integration.md` を §3 の内容へ書き換える。数を書かず出所を指す（`tasks/README.md` の規約）
- D-3 `make docs-check` と `make agent-check` を通す
- D-4 追跡ファイル全体で、旧頁を MCP で読む指示と `notion_context_pack` への参照が現行手順の文書に残っていないことを確かめる。一致零件なら異質な方法でも確かめる

### Task E run 台帳の再 export と旧マスターの見出し

- E-1 Task C の退役の後に、前契約の `export_notion.py` で run 台帳の export を取り直す。`manifest.csv` の該当行を更新し、前回との行数の差を RESULT に書く
- E-2 旧マスター頁の到達性を測る。到達できれば見出しを取り `toc_plan_master.md` を置き換える。できなければ `unreachable` のまま記録する
- E-3 到達性の実測に使った対象の `last_edited_time` を前後で照合する

### Task F 検査と報告

- F-1 試験を回し、失敗が Task A の基準から増えていないことを確かめる
- F-2 `make forbidden-check` を回して記録する
- F-3 変更したファイルに秘匿の形と電子メールの形が無いことを、値を出さずに確かめる
- F-4 `RESULT.md` `audit.md` `result.yaml` を書く（構成は §8）。`tasks/inbox.d/` に一行以上書く
- F-5 commit と push を行い、PR を存在させる。番号を RESULT に書く
- F-6 `make task-report` で台帳へ送る
- F-7 抑止を移動で解除し、退避物を元へ戻す
