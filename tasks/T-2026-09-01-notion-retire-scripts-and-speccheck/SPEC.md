# 個別投稿スクリプトの明示的退役、spec-check の偽陽性の修正、投影の末尾再生成

**task_id:** T-2026-09-01-notion-retire-scripts-and-speccheck  **kind:** impl

## 0. 位置づけ

前契約 `T-2026-08-31-notion-repo-followup-and-retire`（PR #171）で、run 台帳と意思決定・教訓・
プロンプトへの自動書き込みは入口で退役した。残った三つを片付ける。

- `notion_logger` と `notion_ops` を経由せず自前で REST を呼ぶ個別スクリプト（前契約の報告で四本）が、明示的な退役の印を持たない。登録簿で退役にしても Notion 側が書き込みを拒むわけではなく、識別子を自前で解決していれば投稿できる
- `make spec-check` の `integration_prohibited_without_pause` が二契約続けて偽陽性を出した。起票者の言い回し（統合の禁止と、抑止の設置・解除を別の節に書く）を検出器が想定していない
- 前契約は投影の再生成を冒頭に置いたため、自身の `result.yaml` と `inbox.d` が投影に載っていない。本契約は再生成を**末尾**に置く

GPU を使用しない。Notion への書き込みは行わない。起票者は実行環境を持たないため命令を書かない。
対象ホストは任意。資格情報は本契約では不要（Notion を読まない）。repo の位置は `context/env-facts.md` に従う。

## 2. 対象（集合で定義する）

## 3. 達成すべきこと

- 対象スクリプトが呼ばれても投稿に至らず、退役の旨が記録される。方式は実行者が決める（`scripts/retired/` への移動、入口での停止のいずれでもよい）。前契約の `RETIRED_DB_KEYS` と整合させる
- 対象スクリプトを参照する文書と Makefile の目標が追随し、`make docs-check` と `make agent-check` が通る
- `make spec-check` が三本の陰性例を fail させず、既存の陽性の教師例を引き続き検出する。規則の変更理由が教師データに残る
- 投影（`taskindex` と `inbox`）が本契約の報告を書いた後に一度再生成され、両方の check が通り、その状態で commit されている

## 4. 禁止事項

**実行者の操作に対する禁止である。同期処理による配布や自動 merge を含まない。**

| # | 禁止 |
|---|---|
| 1 | Notion への読み書き。退役の確認は乾燥走行か模擬で行う |
| 2 | MCP を使う |
| 3 | Task D の一度以外での投影の再生成。`make context` は回さない（runindex は変わっていない） |
| 4 | `runindex/` の手編集 |
| 5 | ファイルの削除。退役は移動か入口での停止。退避は `mv` |

| 7 | 秘匿の値の出力。`.env` `.env.gpg` と合言葉のファイルの編集 |
| 8 | `make task-report` と PR 作成以外の外部送信 |

禁止 3 と Task D の照合: 本契約は再生成を末尾で一度だけ行う。報告を書き終えてから回し、その差分を含めて commit する。

## 5. 手順

### Task A 前提の実測と門

- A-1 作業ツリーの汚れを確認し、開始前から在る未追跡を退避する。一覧を audit に残す
- A-2 `make task-start` で分岐と抑止を置く。分岐名が `feat/` で始まることを確かめる
- A-3 `spec.yaml` の `resolve-at-intake` と `counts` の零を実測値に差し替え、L1 と L2、`make spec-check` を回す。fail は罠 5 のとおり記録して続ける
- A-4 門: `origin/phase0` の `configs/notion.yaml` に `claude_app_surfaces` 節があることを確かめる。無ければ停止
- A-5 試験を回し、失敗の一覧を記録する（作業前の基準）

### Task B 個別投稿スクリプトの退役

- B-1 §2 の集合を異質な二通りで列挙し、両方の結果を audit に残す。差があれば理由を書く
- B-2 各スクリプトの識別子の解決経路を列挙する
- B-3 退役させる。呼ばれたときに投稿に至らず退役の旨を記録して返す
- B-4 乾燥走行か模擬で両方向を確かめる: 退役後は投稿しない、退役の印を外すと投稿を試みる（送らない）
- B-5 参照する文書と Makefile を追随させ、`make docs-check` と `make agent-check` を通す

### Task C spec-check の偽陽性の修正

- C-1 検出器の実装と教師データを読み、`integration_prohibited_without_pause` が何を見ているかを audit に書く
- C-2 三本の陰性例を教師データに加える
- C-3 規則を直し、陰性例で fail せず、既存の陽性例で引き続き検出されることを確かめる。陽性例が一件も無ければ、統合の禁止だけを書いて抑止に触れない SPEC の断片を陽性例として加える
- C-4 検出器の試験があれば回す。無ければ C-3 の両方向の実測を対照として記録する

### Task D 検査、報告、末尾の再生成

- D-1 試験を回し、失敗が Task A の基準から増えていないことを確かめる
- D-2 `make forbidden-check` を回して記録する
- D-3 変更ファイルに秘匿の形が無いことを値を出さずに確かめる
- D-4 `RESULT.md` `audit.md` `result.yaml` と `tasks/inbox.d/` の一行を書く
- D-5 **ここで** `make taskindex` と `make inbox` を一度回し、両方の check が通ることを確かめる
- D-6 commit と push を行い、PR を存在させる。番号を RESULT に書く（RESULT へ番号を書いた後に再生成の差分が出れば、check を回して差分の有無を audit に記録する。差分があれば再生成をもう一度回してよい。これは D-5 の続きであり、別の再生成ではない）
- D-7 `make task-report` で台帳へ送る
- D-8 抑止を移動で解除し、退避物を元へ戻す
