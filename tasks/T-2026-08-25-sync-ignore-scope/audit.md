## 4. 除外を足したとき既存のものがどうなるか（Task 1 Step 4）

**本契約で最も重要な測定である。** SPEC は「読み取れなければ `UNKNOWN` とし、
Phase B へ進まず判断を仰ぐ」と定める。**読み取れた。結論は「消えない」である。**

### 実装からの根拠（`~/bin/syncthing` v2.1.3 の文字列表）

| # | 実装中の文字列 | 何を意味するか |
|---|---|---|
| 1 | `contains ignored files (see ignore documentation for (?d) prefix)` | **除外された中身があるディレクトリの削除を拒む。** 拒むために専用の誤りを持つ |
| 2 | `(?d)` / `ignoreresult.(*R).IsDeletable` / `WithDeletable` | **削除してよい除外は `(?d)` を付けた行だけ。** 付けない行は削除の対象外 |
| 3 | `Marking file as ignored` と `Marking file as deleted` が別の文字列 | **除外と削除は別の操作として実装されている** |
| 4 | `is not empty; the contents are probably ignored on that remote device, but not locally` | **相手側の除外を削除と解釈しない。** 相手に無いことは削除を意味しない |
| 5 | `model.(*folder).scanSubdirsDeletedAndIgnored` | 走査時に削除と除外を**区別して**扱う |
| 6 | `protocol.(*FileInfo).IsIgnored` | 除外は転送手順の上で独立した状態を持つ |

**本契約の規則案に `(?d)` は使わない。** したがって削除の経路に入らない。

### 実測からの根拠

**(a) 除外の印が付いた項目は索引に残り、実体も残る。**

```
ignored 印: 全 2092 件（ファイル 0 / ディレクトリ 2092）
  ディレクトリ: 存在 2092 / 2092
```

**2092 件すべてが局所に存在する。1 件も消えていない。**

**(b) 既に除外されている実体が局所に残っている。**

| 対象 | 効いている規則行 | 局所の実体 |
|---|---|---:|
| `.venv` | 14 `.venv*` | **6,455,902,962 バイト（残存）** |
| `experiments/baselines/_*` | 39 | **317 件 / 9,734,031 バイト（残存）** |
| `experiments/phase0/_*` | 40 | **36 件 / 14,470 バイト（残存）** |
| `wandb`（除外行なし・`**` で落ちる分） | 68 | **4,608,611 バイト（残存）** |

**これらは索引に載っていない。にもかかわらず局所には在る。**
**除外は索引から外すだけで、実体には触れない。**

**(c) 過去に除外を広げた実例。**

```
$ git --no-pager show 57d2a57a -- .stglobalignore
Sun Jul 5 10:20:04 2026 +0000
fix(sync): venv変種(.venv-*)の同期・追跡漏れをワイルドカードで封鎖
-.venv
-venv
+.venv*
+venv*
```

**除外を広げた後も `.venv` は 6,455,902,962 バイトのまま局所に在る。**

### 相手から見てどうなるか

**除外された項目は索引に載らないため、相手へ「削除した」とは伝わらない。**
根拠 4 の文字列が、相手側で除外されている項目を削除と解釈しないことを明示する。
**根拠 1 は、逆向き（相手が消そうとしたとき）にも本ホストの実体が守られることを示す。**

### 判定

| 問い | 答え | 根拠 |
|---|---|---|
| 除外に入れたファイルは局所から消えるか | **消えない** | 実装 1・2・3、実測 (a)(b)(c) |
| 相手から見て「無い」ことになるか | 索引から外れるが**削除とは解釈されない** | 実装 4・6 |
| 既に届いたものは残るか | **残る** | 実測 (a)(b)(c) |

**危険な向きには倒れない。Phase B へ進んでよい。**

**ただし本測定は実装と既存状態からの推論である。** 「今から足した行」で消えないことの
直接の観測は、Phase C 適用後の件数・大きさの照合で取る（完了判定 K）。
**実物で試して確かめる装置は作っていない**（禁止 8）。

## 5. 反映の手段（Task 1 Step 5）

| 手段 | 使えるか | 再起動 | 備考 |
|---|---|---|---|
| REST `POST /rest/db/ignores?folder=m2` | **使える** | **不要** | `.stignore` を書き換えて即時に読み直す。**ただし keeper が 30 分以内に正本で上書きする** |
| `.stignore` を手で書く | 使える | 不要 | 同上。**keeper に戻される** |
| 正本 `.stglobalignore` を `origin/phase0` へ入れる | **使える（正規の経路）** | **不要** | `keeper.sh:48-49` が各台で `.stignore` へ反映 |
| 再起動 | 使わない | — | **禁止 2。使う必要が無い** |

**再起動は唯一の手段ではない。したがって判断を仰ぐ事由に当たらない。**

### 正規の経路（`scripts/sync/keeper.sh:47-49`）

```
  # Syncthing の同期ルール (.stignore) も phase0 の .stglobalignore から自動反映
  git -C "$M2DIR" show origin/phase0:.stglobalignore > "$M2DIR/.stignore.new" 2>/dev/null \
    && mv "$M2DIR/.stignore.new" "$M2DIR/.stignore"
```

**稼働中の `~/bin/keeper.sh` は版管理下の `scripts/sync/keeper.sh` と一致する**（`diff` で確認）。

### 変更が処理に届くまで

| 段階 | 手段 | 間隔 |
