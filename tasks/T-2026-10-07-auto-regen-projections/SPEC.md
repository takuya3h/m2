# マージのたびに生成物を自動で作り直す

**task_id:** `T-2026-10-07-auto-regen-projections`  **kind:** `impl`
**depends_on:** なし
**実行ホスト:** `philip`（どの台でもよい）  **repo:** `~/slocal2/m2`

## Goal

**生成物（`context/auto/*` と `tasks/inbox.md`）は契約が増えるたびに古くなる。**
並行する契約が同じファイルを書くと必ず衝突したため、**契約では作り直しを禁じ、
マージの後に人が一台で一度だけ作り直している。** この手作業をなくす。

**本契約は、phase0 へのマージを契機に生成物を作り直す仕組みを GitHub Actions で作る。**

    phase0 に push が起きる → make taskindex と make inbox
      → 差分があれば phase0 へ commit して push。無ければ何もしない

### 起票者が把握していないこと

| # | 項目 | 崩れていたら |
|---|---|---|
| 1 | **phase0 の保護設定**（自動で直接 push してよいか） | 自動で PR を作る形などに変える。**判断を仰ぐ** |
| 2 | **`make taskindex` `make inbox` が要る依存**（GitHub の環境で動くか） | 依存を足すか、判断を仰ぐ |
| 3 | **既存の workflow**（同じ契機で動くもの、既存の秘匿の参照） | 既存に合わせる |
| 4 | **自動の commit が別の workflow や常駐処理を起こさないか** | 起こすなら止める工夫が要る |

**Phase A で測ってから作る。** 推測で作らない。

### 環境の罠

- **workflow のファイルを push するには、認証に `workflow` 権限が要る。** 無いと拒否される。
  **拒否されたら迂回せず、利用者へ提示する**（権限の付与は利用者の判断）
- **Actions の既定の権限で作られた commit は、通常は別の workflow を起こさない。** 実際にそうかは確かめる
- **短い間隔で二つマージされると、二つの実行が競合しうる。** 同時実行を抑える設定と、push 前の取り込みが要る

`make taskindex` と `make inbox` が**何を読み、何を書き、何に依存するか**を実装から記録する。

| 確かめること | なぜ |
|---|---|
| 読む範囲 | 版管理の中だけで完結するか（同期で運ばれるものを読むなら Actions では再現できない） |

- [ ] **Step 3: 既存の workflow を読む**

`.github/workflows/` の一覧と、**phase0 への push で動くもの**、**参照している秘匿の名前**を記録する。
**値は読まない。名前だけ。**

- [ ] **Step 4: 認証の権限を確かめる**

**手元の `gh` の認証に `workflow` 権限があるか**を確かめる。

| # | 完了判定 |
|---|---|

- 手元の認証に `workflow` 権限が無い

## Task 2 (Phase B): 仕組みを作る

**Files:** Create: `.github/workflows/` 配下に一件

- [ ] **Step 1: workflow を書く**

| 要件 | 内容 |
|---|---|
| 契機 | **phase0 への push** |
| 処理 | 依存を入れ、`make taskindex` と `make inbox` を走らせる |
| 差分 | **生成物にだけ差分があれば** commit して push。**無ければ何もしない** |
| 対象 | **Task 1 で確かめた書くファイルだけを commit する** |
| 同時実行 | **同時に一つだけ。** 新しいものが来たら古いものを待つか止める |
| 競合 | push の前に最新を取り込む。**失敗したら一度だけやり直し、それでも駄目なら失敗で終える** |
| 自己起動 | **自分の commit で自分を再び起こさない**（Task 1 で確かめた性質に合わせる） |
| 権限 | 必要最小限（中身への書き込みだけ） |

**commit の作成者と文面は、自動のものと分かる形にする。**

- [ ] **Step 2: 手元で試せる範囲を試す**

**workflow の中の処理（依存の導入を除く生成と差分の判定）**を手元で同じ順に走らせ、
**差分が無いときに何もしないこと**、**差分があるときに生成物だけが対象になること**を確かめる。

**手元で作った生成物は commit しない**（禁止 3）。試した後に元へ戻し、作業ツリーが試す前と同じことを確かめる。

**書式の検査ができる道具があれば当てる。** 無ければ UNKNOWN。

- [ ] **Step 3: 契約側の検査との関係を記録する**

**PR の分岐では、統合前の生成物は古いままである。** 契約の検証で `*-check` が差分を報告し続ける。

**この扱いをどうすべきかを、起票者への申し送りとして書く。** 本契約では検査を変えない。

| # | 完了判定 |
|---|---|
| E | workflow を書いた（要件の各行をどう満たしたか） |
| F | 手元で、差分が無いとき何もしないことを確かめた |
| G | 手元で、差分があるとき生成物だけが対象になることを確かめた（**試した生成物を commit していない**） |
| H | 契約側の検査との関係を申し送りに書いた |

## 想定外が起きたときの扱い

| 事象 | 対応 |
|---|---|
| **phase0 が直接 push を許さない** | **停止して判断を仰ぐ**（PR を自動で作る形など、案を添える） |
| **生成物の出力が決定的でない** | **停止して判断を仰ぐ。** 道具の変更は禁止 5 に当たる |
| 依存が Actions で用意できない | **停止して判断を仰ぐ** |
| **`workflow` 権限が無く push が拒まれた** | **迂回しない。利用者へ提示する** |
| 既存の workflow と同じ契機で動くものがある | 衝突しない形にする。**変えるなら判断を仰ぐ** |
| 生成の道具が同期で運ばれるものを読む | **記録する。** Actions では再現できない部分を明示する |
| 実行基盤が操作を拒んだ | **迂回しない。利用者へ提示して許諾を得る** |

**言い訳をしない。事実と、測れなかったことを書く。**
