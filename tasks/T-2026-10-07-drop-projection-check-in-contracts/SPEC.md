# 契約の手順から生成物の作り直しと検査を外す

**task_id:** `T-2026-10-07-drop-projection-check-in-contracts`  **kind:** `impl`
**depends_on:** `T-2026-10-07-auto-regen-projections`
**実行ホスト:** `bengio`  **repo:** `~/slocal2/m2`

## Goal

**生成物（`context/auto/*` と `tasks/inbox.md`）は、phase0 への統合を契機に自動で作り直されるようになった**
（`.github/workflows/regen-projections.yml`）。

**一方、契約の分岐ではいまも次が起きている。**

| 事象 | 帰結 |
|---|---|
| 契約は並行の衝突を避けるため、作り直しを禁じている | 分岐の生成物は古いまま |
| 契約の検証で `*-check` が走る | **毎回「差分あり」で落ちる。** 報告に「意図した失敗」と書かれ続ける |
| `task` の手順書が作り直しを求める | **契約の禁止と食い違う。** 実行者が一度作り直してから戻した事例がある |

**本契約は、契約の手順から作り直しと `*-check` を外す。** 検査そのものは消さない。
**phase0 の上で使う道具として残す。**

### 起票者が把握していないこと

**`*-check` と作り直しが、どこから呼ばれているかを起票者は把握していない。**
少なくとも次が候補である。**洗い出してから直す。**

- `.claude/skills/task/SKILL.md`（実行者の手順書）
- `Makefile` の検証の目標
- 実行直前の検査（`task-preflight` の各項目）
- `AGENTS.md` や `CLAUDE.md` などの運用文書
- `scripts/` の道具

## 0. 前提と禁止事項

    cd ~/slocal2/m2
    git checkout phase0 && git pull --ff-only
    git --no-pager status --porcelain | grep -c ''
    source .venv/bin/activate && source scripts/load_env.sh \
      && make task-start TASK=T-2026-10-07-drop-projection-check-in-contracts

**三行目が 0 でなければ止まる。** 抽出物は規約どおり本契約の commit に含めてよい（秘匿と禁止語を検査してから）。
**抑止の目印は手で置かない。**

| # | 禁止 |
|---|---|
| 1 | **`taskindex-check` `inbox-check` の目標そのものを消す**（phase0 で使う） |
| 2 | **`tools/build_taskindex.py` `tools/build_inbox.py` を変更する** |
| 3 | **`.github/workflows/` を変更する**（別の契約が実行中である） |
| 4 | **生成物を作り直して commit する** |
| 5 | `runindex/**` `context/auto/**` を手で編集する |
| 6 | `context/conventions.md` を変更する（**必要と判明したら判断を仰ぐ**） |
| 7 | 他の検査（`task-validate` の静的検証、`forbidden-check`、秘匿の検査）を弱める |
| 8 | 未追跡の成果物を削除する |
| 9 | 秘匿の値を出力・記録する。検査そのものが値を出力してはならない |
| 10 | 装置を使う。他ホストへ接続する |
| 11 | 未測定の値を書く（未測定は `UNKNOWN`） |
| 12 | `experiments/**` `transfer/**` `data/**` を変更・削除する |

**禁止 7 が要である。** 外すのは生成物の鮮度の検査だけである。

**禁止 3 の理由。** philip で `regen-projections.yml` を変える契約が実行中である。触ると衝突する。

**禁止事項は実行者の操作に対するものであり、同期処理による配布を含まない。**

### 規約と申し送り

**`proposal_gate` の禁止語を送出物に当てる。** `folds` と `symmetry` は適用されない見込み。確かめて記録する。

**`conventions#issuer_cautions` を参照する**（注入される）。

- **呼び出し元を名前で探すだけでは足りない。** 間接に呼ぶもの（目標が別の目標を呼ぶ等）も追う
- **探して零件のときは探し方を疑う。** 異なる方法でも探す
- **手順書は Claude Code と Codex の両方の経路を確かめる**

`conventions_rev` は実行者が実測して置換する。`inputs.data` は参照しない。参照しなかったことを記録する。

## Task 2 (Phase B): 外す

**Files:** Task 1 で直す対象とした箇所

- [ ] **Step 1: 手順書から作り直しを外す**

**作り直しを求める一文を、「作り直さない。統合の後に自動で作り直される」に置き換える。**
**理由も一行添える**（並行の衝突と、自動化が入ったこと）。

- [ ] **Step 2: 契約の検証から `*-check` を外す**

**契約の検証の流れが `*-check` を呼んでいるなら、その呼び出しを外す。**
**目標そのものは残す**（禁止 1）。

**検証の結果の数え方（合格・警告・飛ばした・失敗）が変わるなら、その変化を記録する。**

- [ ] **Step 3: 契約で使う手順の説明を揃える**

**運用文書に「契約の中で `*-check` を回す」と書かれていれば、同じ趣旨で直す。**
**phase0 の上で使う道具としての説明は残す。**

- [ ] **Step 4: 直した結果を確かめる**

| 確かめること | 期待 |
|---|---|
| 契約の検証を本契約の分岐で走らせる | **生成物の鮮度で落ちない** |
| 他の検査 | **これまでどおり働く**（陽性対照で落ちることを確かめる） |
| `*-check` を phase0 の状態で単独で走らせる | **これまでどおり働く**（差分があれば落ちる） |
| Task 1 の検索をやり直す | 直す対象として挙げた箇所が残っていない |

**二つ目と三つ目が要である。** 外しすぎていないことを示す。
