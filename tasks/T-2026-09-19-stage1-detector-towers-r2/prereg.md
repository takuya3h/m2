# 事前登録 — T-2026-09-19-stage1-detector-towers-r2

学習開始より前に commit する。commit 後は変えない。変更は `meta.amendments` に追記する。

## 1. 問い

一周目（T-2026-09-18-stage1-detector-towers）は両塔を 12 epoch・`MultiStepLR([10])` で学習した。
これは COCO 事前学習済みの検出器を短く適応させる標準スケジュールで、**検出ヘッドが乱数初期化の塔には足りない**。

実測（折り A、実行者が学習ログから確認）:

| | D\*-COCO（3 seed） | D\*-ImageNet |
|---|---|---|
| 最終 epoch の伸び | +0.0004 前後 | **+0.0067**（約 5 倍） |
| lr 低下後 2 epoch の伸び | +0.0104〜+0.0254 | **+0.0319** |
| epoch 0 の val mAP | 0.5729 | 0.3249 |
| 最良 epoch | 11〜12 | 12（最終） |

D\*-COCO は頭打ち、D\*-ImageNet は最後まで上昇が続いている。**同じ epoch 数を与えても到達している収束度が違う。**
一周目の差 4.1 mAP のうち、表現の差と学習不足の分は切り分けられていない（UNKNOWN）。

このまま D\*-ImageNet を H3（受け取り手の表現依存）の腕に使うと、Stage 2 の差が表現の差なのか学習不足なのか
区別できない。M §5.1（2026-09-18 改訂）の「同一 epoch は同一の学習量を意味しない。収束の度合いを揃えることを
優先し、上限に張り付いた腕があれば上限を両腕で広げる」に従い、**収束基準を両塔に同じく当てて学習し直す。**

### 版 2 の訂正（起票者、2026-09-21、未着手のうちに差し替え）

版 1 は「上限 36、30 epoch で学習率を 1/10、8 epoch 改善なしで打ち切り」だった。これは**早く収束する塔ほど
学習率の低下に届かない**。COCO 初期化の塔は 20 epoch 前後で打ち切られ、30 の低下を受けられない。一周目では
低下直後に +1〜2.5 mAP 伸びていたので、COCO の塔だけが一周目より弱くなる非対称を作る。
版 2 は「**停滞したら学習率を下げ、再び停滞したら止める**」に替える。どちらの塔も自分の収束点で低下を受ける。

## 2. 処方

一周目からの変更は**学習の長さの決め方だけ**。他は一周目と同一（凍結源を生んだ処方）。

| 項目 | 一周目 | 二周目 |
|---|---|---|
| epoch | 12 固定 | **上限 36** |
| 学習率の低下 | `MultiStepLR([10])`（10 epoch 目に固定） | **val mAP が 4 epoch 続けて改善しなければ 1/10（一回だけ）** |
| 打ち切り | なし | **低下の後、val mAP が 4 epoch 続けて改善しなければ打ち切り** |
| 規則の適用 | — | **両塔に同じ規則。低下と打ち切りの時期は塔ごとに違ってよい** |
| 最良 epoch の選択 | val mAP | 同じ |
| その他 | 実効 batch 4、AdamW lr 1e-4、presets.detr、短辺 480〜800、fp16 autocast、stem のみ凍結 | すべて同じ |

- 折りは `conventions#folds`。seed は折り A が 42・123・456、折り B〜E が 42。計 7 run × 2 塔 = 14 run
- 一周目の run は捨てない。**同じ折り・seed の値を対照として並置する**（12 epoch 版と収束版の比較）

## 4. 予測（結果を見る前に書く）

1. D\*-ImageNet は一周目（折り A 0.6834）より上がる
2. 両塔の差は一周目の 4.1 mAP より**縮む**が、**零にはならない**（初期化源の効果が残る）
3. D\*-COCO は一周目と同程度（差 ±1 mAP 以内）。学習率の低下は一周目の 10 と同程度の時期に起きる
4. D\*-ImageNet の学習率の低下と打ち切りは D\*-COCO より**遅い**（収束が遅いため）
5. 折り B〜E の値は折り A より低い（一周目の実測で 0.43〜0.53 対 0.72。折りの難しさの違い）

## 5. Primary endpoint

各塔・各折りの **val mAP**（`conventions#eval_recipe`）。折り A は 3 seed の平均と SD。
副次に**標的群 AP**（2026-06-19 に事前登録した、工程で出現が変わる術具クラスの集合）と **AP rare**（Skewer、Syringe）。

## 6. 判定規則

1. 選定は行わない。両塔を確定する。確定に使うのは**二周目の値**。一周目は対照として並置
2. **いずれかの run で最良 epoch が上限 36 に達した場合**は、上限が結果を切っている可能性を報告し、利用者に諮る
3. **学習率の低下を一度も受けずに上限へ達した run** も報告する（規則が働いていない）
4. test は確定した両塔について折りごとに一度だけ評価し、台帳に記録する。合計 10 回

## 7. 対照

- **一周目の同じ折り・seed の値**を並置する。上がり幅が塔ごとに出る
- 学習率の低下と打ち切りの実装が両塔で同一であることを実装の行で示す（別々の分岐を通っていないこと）
- 折り表の照合: 各 run の画像集合を動画 ID に戻し、規約の表と集合差 0
- 陰性対照: 折り A の test 動画を一本入れ替えた注釈で照合の対称差が 2 になることを一度示す

## 8. 停止条件

- 打ち切りが働かず全 run が上限に達する → 停止して諮る（基準が緩すぎる）
- ImageNet 初期化が発散・非数 → 停止し記録を提示。**学習率を下げて再試行しない**（処方の変更。利用者が決める）
- 1 run が 27 時間を超える → run 数の見直しを諮る（36 epoch は実測 0.70 h/epoch で約 25 時間）
- 装置が使われている → 停止
