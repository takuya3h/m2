<a id="sigma"></a>
## sigma

sigma に関する列は 4 系統ある（backlog B-18）。

1. `{metric}_pstd` / `{metric}_sstd` — seed 間の sigma（母集団 / 標本）
2. `delta_pstd_{metric}` / `delta_sstd_{metric}` — 実験間 paired Delta の sigma
3. `sigma_source` — sigma の系統。値は paired_delta または within_run_seed_spread
4. `delta_sigma_source` — paired sigma の計算方法。値は paired または unpaired_pooled

3 と 4 は直交する（どの sigma を使ったか vs paired sigma をどう計算したか）。

### 既定値（spec.yaml が sigma_policy を省略した場合に継承される値）

    series: pstd
    sigma_source: paired_delta
    delta_sigma_source: paired

この既定は暫定である。正本（ddof=0 / ddof=1）は未決定であり、
決定され次第ここを変更する。変更時は過去の task を横断で再判定できるよう、
`RESULT.md` に解決済み sigma_policy が記録されていることを前提とする。

### 判定規約の表記

判定規約を `spec.yaml` や `prereg.md` に書くときは、絶対値を `abs(...)` の関数形で書く。
縦線による絶対値記法は markdown 表のセル区切りと衝突し、表を壊すため使わない
（backlog B-33 と同型の事故）。

    正: abs(delta) / sigma >= 1 かつ 全 seed 同符号
    誤: 縦線で delta を囲む記法

同じ理由で、区切りを表したいときは `/` かスラッシュ区切りの語を使う。

## 7. 逸脱

**逸脱は 5 件ある。「なし」ではない。**

1. **判断** — 前処理の resize を prereg の指す既定ではなく**一周目に揃えた**（起票者の誤り 3）。
   一周目との差が backbone の重みだけになるようにするため。増強は既定どおり `RandomHorizontalFlip` のみ。
2. **契約の誤り** — 凍結範囲が既定では stem のみでなかったため、SPEC Task A-5 に従い揃えた。
   既存スクリプトは書き換えず、新しい `scripts/stage1_ptower_r2.py` の `build_backbone` で
   `conv1`・`bn1` の `requires_grad` を落とし、`stem_eval` で凍結した stem の batch 統計を固定した。
3. **環境** — 追加 6 動画の画像が本ホストに 0 件で、**P\*-21 を一切学習・評価していない**。
   契約の 154 run のうち実施は 168 run（fine-tune 14・extract 14・時間ヘッド 140）。
   数の内訳が契約と違うのは、契約が extract を数に入れていないためである。
4. **判断** — 実行者が 1 本目の fine-tune の最中に出力の書き出し遅れを「データ供給が律速」と誤読し、
   停止と削除の命令を出した。`pkill -f` が自分の命令行に部分一致して自滅し、`rm -rf` に到達しなかったため
   成果物は無傷。設定は変更していない。さらに特徴抽出でも、`COMPLETE` の通知を完了の証拠として扱い
   「1 本目が完了」と誤って報告した（実際は走行中で `metrics.json` は空だった）。
   いずれも `conventions#issuer_cautions` の注意 6 と 12 の型である。
5. **判断** — 一周目のスクリプト 2 本に後方互換の変更を入れた（`stage1_ptower.py` の 5 箇所を
   `cfg.get(...)` へ、`run_stage1_ptower.py` の `completed()` に `task` 引数）。既定値はすべて一周目の値で、
   一周目の試験 8 件はそのまま通る。契約は実装の追加を指示していないため実行者の判断である。

## 8. 想定外・UNKNOWN

- **P\*-21 のすべての値。** 追加 6 動画の画像が本ホストに無く、学習も抽出も test も行っていない。
  判定 d・f の P\*-21 側は未測定である。**Stage 2 の主分母は P\*-21 であり、別契約が要る。**
- **S4 の test 値。** 本契約では val のみを並置した。
- **上限 12 epoch の妥当性。** 最良 epoch が上限に張り付いた fine-tune が 2 件（lr 1e-4 の折り C、
  lr 3.3333e-5 の折り D）、10 に達したものが 1 件ある。上限を増やせばさらに上がる余地は残るが、
  prereg が D\* と揃えて 12 に固定しているため本契約では増やさない。
- **val と test の乖離が広がった理由。** 0.10419 → 0.13092。fine-tune が折りの train 動画に
  適合した結果とみられるが、本契約は要因を分解していない。
