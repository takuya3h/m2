## Goal

過去の記録が検査の出力を汚し続ける二件と、写しが schema からずれる一件を、**記録を書き換えずに**機械で止める。

| 項目 | 内容 | 利用者の決定 |
|---|---|---|
| 旧様式の除外 | 旧様式の `result.yaml` が現行 schema の検査で失敗し続ける | schema の側に旧様式の除外一覧を置く（2026-09-23） |
| 完了済みの除外 | `spec-check` が完了済みの過去契約に宣言漏れを出し続ける | 完了済みの契約を対象外にする。判定は P13・P14 と同じものを使う（2026-09-23） |

### 申し送り

`conventions#issuer_cautions` を参照する（`inject_verbatim` で注入される）。本契約に固有の注意を足す。

- **実装を読んで手段を決めてよい。** 起票者は `validate_task.py`・`check_spec.py`・`preflight_task.py` を読んでいない。名前や形が本文と違えば実測を正とし、報告に書く
- **対照は両方向で取る。** 片方向では「常に何もしない」「常に除外する」壊れ方と区別できない
- **識別子の照合は完全一致にする。** 接頭辞や部分一致にすると、関係ない契約まで免除される（先行契約の P14 の例外で実測された）。末尾の改行・半角スペース・大文字小文字の違いも一致させない
- **照合に使う識別子はディレクトリ名**である。旧様式は最上位に `task_id` を持たず、ファイルの中身では引けない
- **`make task-validate` の最終行の書式 `N task(s), M failed` は変えない。** 手順書が最終行と終了コードの両方を見る前提で書かれている。除外の表示は別の行に出す
- **`make forbidden-check` は BASE を省くと phase0 の先端と比べ、分岐後に入った他の PR の差を違反に数える**（出所: `tasks/inbox.d/T-2026-10-04-ptower-attribution-val.md`）。分岐点を BASE に指定して回す
- 全契約で回す `make task-validate` は、変更前から 1 件失敗する既知の挙動がある（`inbox.d` に `spec.yaml` が無いため。出所: 先行契約 `T-2026-09-19-symmetry-gate` の報告）。**変更前の実測を記録し、増えていないことを見る**
- `make lint` は変更前から落ちている。**本契約が触ったファイルが `ruff check` を通ればよい。** repo 全体の整形はしない
- **試験の失敗数は開始前の値を分母として記録する。** 件数の一致だけで済ませず、失敗した試験名の集合で比べる
- **完了済みの判定は、`gates[].verdict` に空でない値があれば完了とみなす定義であり、`stop` や `ask` も含む。** したがって停止で終わった契約も完了済みに入る。**定義は変えない。** 除外される契約のうち `status` が `pass` 以外のものを数えて報告する
- `inputs.data.split_files` は雛形の必須項目であり、本契約は参照しない。参照しなかったことを記録する
- `make spec-check` を本契約自身に当てて `allow_write_incomplete` が出たら、足りない経路を `contract.allow_write` に足して `meta.amendments` に記録する。**起票者の誤りとして報告する**（逸脱ではない）
