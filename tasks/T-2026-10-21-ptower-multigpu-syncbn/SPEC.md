# 工程塔の三周目の処方を複数の GPU で回す実装（DDP と SyncBatchNorm、一枚と同じ学び方の照合、dlsta での記憶量と時間）

**task_id:** T-2026-10-21-ptower-multigpu-syncbn  **kind:** impl

実行するホストは dlsta（repo の位置は `context/env-facts.md` の「dlsta のみ」の行）。**本契約は GPU を使う。**
使ってよいのは GPU0〜GPU4 のうち、他の利用者が使っていないものだけである（利用者の許可 2026-10-21。§2）。
ほかのホストへ接続しない（`origin` からの取得と push、PR の作成、`make task-report` を除く）。

## 1. 背景

両塔の学び直しでは、dlsta を折り A のハイパーパラメータ探索だけに使う（§2）。検出塔は処方のまま dlsta で回せるが、
工程塔の三周目の処方は A5000 一枚に収まらない。物理 batch 16 は最初の forward で溢れ、一枚の最大は 13 である
（`experiments/analysis/dlsta_tower_feasibility/REPORT.md` §3）。batch を 13 以下にすると、正規化層が統計を取る枚数が変わり、
処方が変わる。

三周目の実装は複数の GPU に対応していない。ResNet-50 の正規化層 53 層のうち、学習中に統計を取るのは layer1〜4 の 52 層で、
**物理 batch 16 枚の統計**で正規化し running の統計を更新する（REPORT §5）。二枚に 8 枚ずつ分けるだけだと、統計は 8 枚ずつになり、
処方が変わる。

本契約は、一枚の既定の振る舞いを変えずに、二枚以上で回す道を足す。そして、二枚で回したときに一枚と同じ学び方になることを、
一枚に収まる大きさで陽性と陰性の対照をつけて確かめる。最後に、処方のままの大きさで、記憶量と一歩の時間を dlsta で測る。
足すものの候補は REPORT §5 に 8 項目ある（実装を読んだだけの列挙）。手段は実装を読んで決めてよい。

## 2. 背景にある利用者の決定

- 2026-10-21: 両塔の学び直しでは、dlsta を折り A のハイパーパラメータ探索だけに使う。上位 3 件の回し直し、確定の塔、
  交差適合用と診断点の塔は andrew で学ぶ。dlsta で学んだ塔を、ほかのホストで学んだ塔と比べない
- 2026-10-21: dlsta の工程塔は、複数の GPU で回す実装を足して、三周目の処方のまま学ぶ（本契約）
- 2026-10-21: 本契約では GPU0〜GPU4 のすべてを使ってよい。ただし、他の利用者が使っている GPU は使わない
- 2026-10-21: 決定性の設定のもとで SyncBatchNorm か GPU の間の集計が止まったときは、**止めて諮る**。緩め方は利用者が決める

したがって、本契約の実装は探索に使う道であり、andrew の一枚の道は変えない。dlsta の二枚の道で学んだ塔を、
一枚の道で学んだ塔と比べることはない。それでも「一枚と同じ学び方」を求めるのは、探索で選ぶ処方が、andrew で回し直す処方と
同じものでなければならないからである。

## 5. 満たすこと

### 5.1 実装の要件

1. **一枚の道は変えない。** 分散を初期化しない起動では、直す前と同じ値を出す（Task B の 3）。既存の設定の既定値の意味を変えない
2. `ft_batch_size` は、全 rank を合わせた物理 batch の意味のままにする。GPU ごとの batch は `ft_batch_size` を rank の数で割った値で、
   割り切れなければ始める前に止める。証拠の `effective_batch_size` は `ft_batch_size × ft_accum_steps` のままにし、rank の数と
   GPU ごとの batch を別の欄に記録する
3. layer1〜4 の正規化層は、全 rank の画像を合わせた統計で正規化し running の統計を更新する（SyncBatchNorm）。stem の `bn1` は
   eval のまま、running の統計を変えない
4. 勾配は累積の境でだけ rank の間で集め、それ以外の歩では集めない。集めた勾配と更新は、同じ画像の一枚の歩と同じになる
5. 各 epoch で、学習に使う画像の集合は一枚と同じで、重複も欠けも無い。末尾の端数（画像の数が物理 batch で割り切れないとき）と、
   累積の端数（歩の数が累積で割り切れないとき）の扱いは、一枚と同じ画像に対して同じ勾配になる
6. 画像の並びは、一枚の並びと同じでなくてよい（§2。dlsta の塔を一枚の道の塔と比べない）。ただし同じ seed なら同じ並びになる
7. 評価、checkpoint の保存、証拠（`ExperimentManager`）と W&B の記録は rank 0 だけが行う。学習率の低下と打ち切りの判断は
   全 rank で同じ epoch に行われる
8. 保存する checkpoint の鍵は一枚の道と同じで、一枚の道の読み込みでそのまま読める
9. 記憶量の最大（allocated と reserved）を rank ごとに記録する
10. 決定性の設定（§3.1）は二枚の道の全 rank でも有効にする。止まる演算があれば止まったまま報告する（§2。緩めない）

### 5.2 照合の要件

1. 比べる二つ: 一枚・batch 2B と、二枚・GPU ごとの batch B（全体で 2B）。B は一枚に収まる大きさで実行者が決める。
   累積は処方と同じ 4 にし、少なくとも二回の更新（累積の境を二度）をまたぐ
2. 両者に同じ初期の重みと、同じ画像の添字の列を与える。二枚では、一枚の各歩の 2B 枚を rank に B 枚ずつ分ける
3. 比べるもの: 各 micro-step の損失、累積の境での勾配（更新の前）、正規化層の running の統計（stem と layer1〜4）、更新後の重み。
   最大の絶対差と相対差を表にする
4. 末尾の端数: 画像の数が 2B でも累積でも割り切れない小さな集合で一 epoch を回し、末尾の歩の勾配と更新が一枚と同じになること
5. 各 epoch の画像の集合: 二枚の道で rank ごとに引いた添字を合わせたものが、学習の集合と一致し、重複が無いこと
6. 増強の乱数: rank ごとの左右反転の列が互いに同じにならないこと。**同じ seed をそのまま全 rank に使うと、各 rank の読み込みの
   乱数が同じ列を引き、一つの batch の中で反転が揃いうる**（実装を読んで確かめる）
7. stem の統計: 学習の歩の後で `bn1` の running の統計が変わっていないこと。陽性対照として、stem を train にした写しでは変わること
8. 再現: 二枚の道を同じ seed で二度回し、重みの要約値が一致すること。一致しなければ停止して諮る
9. 照合のとき、増強の乱数は両者で同じ画像を作るようにする（外すか揃える）。どちらにしたかを書く

### 5.3 通しの要件

1. 証拠のディレクトリ、checkpoint、W&B の run は rank 0 だけが作る（rank 0 以外が作ったものが 0 件であることを示す）
2. 学習率の低下と打ち切りを短い設定で起こし、各 rank の記録で同じ epoch に起きたことを示す
3. checkpoint を一枚の道の読み込みで読み、鍵の集合が一枚の道の模型と一致すること
4. `experiments/` と `runindex/` に足したものが 0（集合差）。W&B に送るか、送らない手段を使うかは実装を読んで決めてよい。どちらにしたかと、
   送った場合は run の名前を書く

### 5.4 測定の要件

1. 各構成で、rank ごとの torch の記憶量の最大（allocated と reserved）、nvidia-smi で見た最大、一歩の時間（micro-step）を記録する
2. 一歩の時間は、REPORT §3 と同じ取り方（読み込みの待ちを含む 60 micro-step の平均、最初の 8 を除く）を含める。ほかの取り方を足してもよい
3. 二本同時のときは、両方の一歩の時間を、単独のときと並べる
4. 一 epoch の歩の数と、そこから計算した一 epoch の時間を書く（推定と明記する）
5. 溢れた場合は、溢れた時点の記憶量を書き、処方を変えずに止める。batch を変えて収めることはしない（処方の変更になる）

### 5.5 実行者が知り得ない環境の罠（いずれも実装を読んで確かめる）

- 包みの forward は、rank の間で通信しうる。rank 0 だけが評価するときは、包みの外の模型で推論する
- 正規化層を SyncBatchNorm へ一括で変える関数は、stem の `bn1` も変える。eval のままにすること（§5.1 の 3）を変えた後で確かめる
- 記憶量の最大を測る関数は、設定の `device` を渡すと rank ごとの装置を測らない（§3.1）
- 同じホストで二本を同時に起動するときは、rank の待ち合わせの port を分ける
- `experiments/` の下に作ったものは、同期で全台に複製されうる（§3.2）。checkpoint と記録は repo の外に置く
- 証拠を作る関数は W&B の記録が始まらなければ止まる（§3.1）。資格情報の値を出力しない

## 6. 禁止事項

**禁止は実行者の操作に対するものであり、同期処理による配布を含まない。**

1. 使う GPU は GPU0〜GPU4 のうち、他の利用者が使っていないものだけ。他の利用者のプロセスに触れない
2. `data/` 配下に書き込まない（特徴の書き出しを試すときも `data/` の外に出す）。`data/splits/` の既存ファイルを変えない
3. `experiments/` と `runindex/` に何も足さない。`runindex/**` を手で編集しない
4. 一枚の道の振る舞いと、`configs/stage1_ptower_r3.yaml` の既存の設定の値と意味を変えない
5. 決定性の設定を緩めない。数値精度を変えない（fp32 のまま）。batch の大きさを変えて収めることをしない
6. `context/conventions.md`、`docs/issuer-defects.md` を変えない（本契約の範囲の外）。既存の `tasks/*/` を変えない
7. `context/auto/*` と `tasks/inbox.md` を再生成しない。生成物の検査（`make taskindex-check`、`make inbox-check`）を回さない
8. ほかのホストへ接続しない（`origin` からの取得と push、PR の作成、`make task-report` を除く）
9. 資格情報の値を記録・出力しない。資格情報の扱いが拒まれたら回避せず諮る
10. 統合しない（PR を作るところまで）。外部への送信は `make task-report` 以外の経路で行わない

## 8. 想定外と停止条件

- 本ホストの repo の位置や装置が `context/env-facts.md` の記載と違う → 停止して諮る
- 作業ツリーが別の契約の分岐にある、または別の契約が作業中 → 起動しない。停止して諮る
- 他の利用者が使っていない GPU が二枚未満、または途中で他の利用者の使用が現れた → その GPU で動かしている自分の処理を止めて離れ
  （他の利用者の処理には触れない）、停止して諮る
- 決定性の設定のもとで演算が止まった → 演算の名前を記録して停止して諮る（関門 G3。§2）
- 二枚の道を同じ seed で二度回して要約値が一致しない → 停止して諮る
- 末尾の端数の扱いを一枚と同じにできない、または一枚の道を変えずに足せない → 停止して諮る
- 照合の許容差で陰性対照と陽性対照を分けられない → 停止して諮る
- 処方のままの二枚の構成が溢れる → 溢れた時点の値を記録して停止して諮る（batch を変えない）
- 試験の失敗の名前の集合が増えた → 停止する
- 実行基盤が書き込みや移動を拒む → 回避せず諮る
