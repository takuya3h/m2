# 完了報告を配布台帳へ送り返し、起票者が即座に読めるようにする

**task_id:** `T-2026-08-18-report-back-to-ledger`
**kind:** `impl`
**depends_on:** `T-2026-08-17-report-projection-and-friction`
**実行ホスト:** `lecun`

## Goal

完了報告は現在、**人が転記しなければ起票者に届かない。**

投影へ転記する仕組みを作ったが、起票者が投影を読む経路には**索引の更新の遅れ**がある。
直近の実測では、統合した直後に読もうとしても数日前の内容しか返らなかった。
**投影は後から振り返るには使えるが、完了直後の受け渡しには使えない。**

一方、契約の配布は台帳経由で即座に届いている。**同じ経路を逆向きに使えばよい。**

    起票者 → 台帳（添付） → 実行者     ← 既に動いている
    実行者 → 台帳（本文） → 起票者     ← これを作る

## 既に分かっていること

| 事項 | 実測 |
|---|---|
| 単一の塊として置いた本文の往復 | 5364 バイトが一文字も変わらない |
| 記法として貼った本文 | 復元不可能に壊れる |
| 要約値の照合 | 壊れた本文を拒む |
| 台帳への到達 | 資格情報で読み書きできる |

**本文は記法として解釈されない置き方をすること。** 実装を読んで確かめる。

## 台帳の列（起票者が追加済み）

| 列 | 用途 |
|---|---|
| `status` | `done` へ変える |
| `verdict` | `pass` / `partial` / `stopped` |
| `completed_at` | 送った日時 |
| `n_issuer_defects` | 起票者の誤りの件数 |
| `report_sha256` | 報告の本文の要約値 |
| `report_bytes` | 報告の本文のバイト数 |

**列名は上記のとおりである。推測で別の名前を使わない。**

## 0. 前提と禁止事項

作業は次の分岐で行う。契約の実行中は自動同期を抑止する。

    cd /home/ubuntu/slocal2/m2
    git fetch origin
    git checkout -b feat/report-back origin/phase0
    touch .sync-pause
    source .venv/bin/activate
    source scripts/load_env.sh

報告を終えたら `rm -f .sync-pause` を実行する。**解除を確認してから報告する。**

| 2 | **秘匿らしき内容を含む本文を外部へ送る** |
| 3 | 台帳の他の行や他の管理データベースを変更・削除する |
| 4 | `runindex/**` `context/auto/**` を**手で**編集する（生成は可） |
| 5 | `experiments/**` `transfer/**` `data/splits/**` を変更する |

### 起票者からの申し送り

起票者の検査コマンドが検証対象を検証できていない誤りが **16 task 連続**で発生している。
直近では、起票者自身が長く警告してきた型を、自分の測定コマンドで犯した。

実行環境の対話シェルは bash ではない。**変数の直後に記号が続く場合は波括弧で囲むこと。**
配列の添字による終了コードの取得は使えない。単語分割も起きない。

**本 SPEC の検査も同型の誤りを含みうる。** 次を守ること。

| # | 注意 |
|---|---|
| 1 | 一致件数が 0 のとき、別の探し方でも 0 になることを確かめる |
| 2 | 仕組みの挙動は実装を読んでから信じる |
| 3 | 記録を作る流れに表示用の切り詰めを混ぜない |
| 4 | 検査が空振りでないことを陽性対照で確かめる |
| 5 | 対象の一覧そのものが正しいかを確かめる |

### 本 task に固有の危険

**外部へ送るのは一方向で、取り消せない。** 秘匿が混ざれば取り返しがつかない。
**送る前に検査する。検査が空振りでないことを先に確かめる。**

# Phase B — 秘匿の検査

## Task 2: 送る前に止める

**Files:** Task 1 と同じ

**外部へ送るのは取り消せない。** 送る前に検査する。

- [ ] **Step 1: 何を探すかを決める**

| 対象 | 例 |
|---|---|
| 資格情報らしき代入 | 鍵や token を含む変数名への代入 |
| 既知の接頭辞を持つ長い文字列 | 外部サービスの鍵の形式 |
| 実際に読み込まれている値 | 環境にある資格情報そのもの |

**3 番目が最も確実である。** 環境から読んだ値が本文に現れるかを直接照合する。
**値そのものは出力しない。**

- [ ] **Step 2: 偽陽性を避ける**

過去に、無関係な語への一致で偽陽性が出ている。**一致件数だけで判断しない。**

| 危険 | 対処 |
|---|---|
| 平易な識別子が資格情報として扱われる | 資格情報に限る。設定値は対象外 |
| 語の一部に一致する | 語境界を見る |
| 大文字小文字の違いで取りこぼす | 両方を見る |

**何に一致したかを目視できる形で出す。値は伏せる。**

- [ ] **Step 3: G2 ゲート — 両方向で確かめる**

**陽性対照と陰性対照を並べる。**

資格情報を含む本文を作り、**送信が拒まれること**を確認する。
含まない本文で、**送信が通ること**を確認する。

**片方だけを試して満足しない。** 拒む側が反応しないなら検査は無効である。

陽性対照に使った本文は**外部へ送らない。** 検査で止まることを確認するだけである。

- [ ] **Step 4: 失敗する試験を書く**

外部サービスへは接続しない。応答を差し替えて経路だけを検査する。

秘匿を含む本文が拒まれること。含まない本文が通ること。
対が無い契約が拒まれること。該当行が無いとき拒まれること。
二度送っても行が壊れないこと。
