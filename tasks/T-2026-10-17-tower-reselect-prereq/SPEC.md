### 5.1 `symmetry` 節に足す内容

「意図的に変える」の理由を三つにする。

1. 仮説の操作である
2. タスクの性質上避けられない
3. **各塔の構造の標準の処方である**

3 の使い方:

- 使える比較: 類型「塔どうし」だけ
- 使える行: 正規化層の扱い、学習率、勾配の刈り込み、weight decay、実効 batch、数値精度、決定性
- 使える条件: その塔どうしの差が、主判定（方向ごとの Δ）に入らないこと。つまり、比べる腕と分母が同じ受け取り手を
  持つ設計であること
- 使えない行: 初期化の鎖の各段、in-domain のデータの範囲、相手タスクのラベルを使わないこと、収束規則
- **同じ塔の変種どうし**（確定塔、交差適合用の塔、診断点の塔）には使わない。変える一点（データか初期化）以外を揃える
- 3 を使った行は、表の理由の欄に「各塔の構造の標準の処方」と書き、両腕の実際の値を書く
- 出所: 利用者の決定 2026-10-17（本契約の SPEC §2）

## 8. 想定外と停止条件

- 本ホストの repo の位置や起点が `context/env-facts.md` の記載と違う → 停止して諮る
- efros に届かない、資格情報が要る → 停止して諮る（関門 G2）
- efros の収束規則の実装が二周目の写しと一致しない → 停止して諮る（`decisions_required`）
- andrew だけの改変が見つかり、それが二周目の学習に要るファイルと重なる → 停止して諮る（`decisions_required`）
- 拡張を作り直さないと検出器が動かない → 停止して諮る（作り直さない）
- 試験が通らない、または変えてはいけないものの要約値が変わった → 停止する（関門 G3）
- 規約の文言を整えるときに、範囲・条件・数を変えたくなった → 停止して諮る

## 9. 報告の構成

`RESULT.md` は起票者が判断に使う事実だけ。目安 150 行以内。

| 節 | 内容 | 入れないもの |
|---|---|---|
| 判定 | `verdict` と各 Gate の結果 | 手続きの全文 |
| 完了判定 | 表。各項目に実測値 | 命令の全文 |
| 実測 | 次の契約で使う値（評価時の入力の大きさ、andrew の検出器の場所、新しい snapshot の場所と差、試験の結果、収束規則の引数の名前） | 経過の説明 |
| 起票者の誤り | 型と内容。一件三行以内 | 引用の全文 |
| 逸脱 | 何をなぜ | 手順の再掲 |
| 想定外・UNKNOWN | 測れなかったものと理由 | 不要なログ |
| 送出 | PR 番号、終了コードだけ | 出力の全文 |

`audit.md` へ: 命令とその出力、要約値の一覧（前後）、efros で使った操作の一覧、対照の出力、規約の差分の突き合わせ表、
変更範囲の一覧、台帳の応答。`RESULT.md` から `audit.md` を行番号で指す。同じ内容を二度書かない。
