- 学習率 3.07e-4（backbone と線形射影の群は 0.1 倍に連動）、max_norm 0.059、fp16、2 枚の道（accelerate、2 プロセス）、収束規則（停滞 4 epoch で学習率 0.1 倍を一度、再停滞 4 epoch で打ち切り、上限 36、val mAP）、presets.detr、COCO の初期化。すべて探索と同じ

### 2.2 固定する項目

探索の prereg §2.2 の表のとおり（初期化、入力解像度と増強、収束規則、optimizer、backbone と線形射影の倍率、精度、フレーム集合）。ホストは andrew（A6000 × 2、電力の上限 300 W、`NCCL_P2P_DISABLE=1`）。`num_workers` 4、`pin_memory` True（PR 292 の実測で worker 数は一歩に効かない）。

## 3. 主判定

1. 水準ごとに 2 本の val mAP の平均を出す
2. 平均が最大の水準を候補とする
3. **同点幅 0.0076**: runindex の `baselines/dcoco_foldA/dcoco_foldA@val` の mAP_sstd 0.0038（0.0037965。D\*-COCO の折り A、seed 42・123・456 の一周目と二周目の 6 本）の 2 倍。最大との差が 0.0076 以下の水準は同点とする（2026-11-06 の改訂。起票時の 0.0106 は二周目の 3 本だけの SD 0.0053 の 2 倍で、本文が定義に引く mAP_sstd と食い違っていた。起票者の誤り）
4. **同点の中で最も大きい batch を選ぶ**（時間が短い方。PR 290 の実測で b4 は b2 より 1 epoch が 14% 短い）
5. co-primary の平均で最良が別の水準でも、4 の選択を変えず、食い違いを記録する
6. 発散・非数の水準は候補から外す（1 本でも出たら停止して諮る。値を補わない）。b6 が溢れたら外して残り 2 水準で続ける
7. 記録: 水準ごとの 2 本の差（seed の揺れの目安）、b2 の平均と探索の 12 番の値（dlsta、0.7374）の差（ホストが違うので比べない。記録だけ）

### 3.1 予測（当たり外れを F に積む）

1. b4 の平均は b2 の平均と差の絶対値 0.0076 以内で、規則により b4 が選ばれる
2. b6 の平均は b2 より低い（更新回数が 3 分の 1 で、epoch 単位の収束規則の下で学習が足りない）
3. 発散は無い（学習率は探索で通った値）

### 3.2 読みの規則

- 値は折り A の 2 本の平均で、3 水準の最大を取るので上振れする。処方の効果として読まない
- b2 の値は dlsta の探索の値と並べない（ホストが違う。F 2026-10-21）
- 回し直しの契約は、選んだ batch を「固定した項目」として引く

## 5. 記録する量（各 run。選定に使わない）

1. 学習率を下げた epoch、打ち切った epoch、上限 36 への到達、checkpoint の epoch、総 epoch 数
2. checkpoint の epoch と最終 epoch の val mAP と標的群 AP
3. checkpoint での train mAP と val mAP の差（train の評価は規約の recipe で、train の全フレーム）
4. 立ち上げの歩数（実際に何歩で学習率が目標に達したか）、1 epoch の歩数、総更新回数
5. 発散・非数の有無と起きた歩
6. epoch あたりの時間（学習と評価を分けて）、rank ごとの記憶量の最大
7. optimizer の群ごとの学習率と weight decay の実際の値、DataLoader の batch の値
8. 刈り込む前の勾配のノルムの分位点（5・50・95%）と、刈り込みが働いた歩の割合

## 6. 停止条件

- COCO の重みを読んだ行が無い、または読んだ重みの要約値が checkpoint と違う: 停止して諮る
- 評価の道具が checkpoint を読まずに値を返した: 停止して諮る
- 設定（学習率、weight decay、max_norm、batch）が optimizer の群か DataLoader に届かない: 停止して諮る
- 発散・非数が 1 本でも出た: 停止して諮る
- b6 が溢れた: 記録して外し、残り 2 水準で続ける
- 記憶領域の空きが見込みの 2 倍を下回る、1 本の壁時計が見込みの上限（9 時間）の 2 倍を超える: 諮る
