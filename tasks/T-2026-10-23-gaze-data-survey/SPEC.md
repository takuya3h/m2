**task_id:** T-2026-10-23-gaze-data-survey  **kind:** analysis

実行するホストは **andrew**（repo は `~/slocal2/m2`）。**本契約では GPU を使用しない。** 学習は回さない。データは読むだけで、`data/` の下に書かない。

## 1. 背景

- 候補 5 の事前学習の案 1（`docs/proposals/2026-10-23-ptower-pretraining.md` の gaze-mae-scratch）は、EgoSurgery の視線でマスクを選ぶ映像 MAE（A-01 の GGMAE 型）を前提にする。利用者は 2026-10-23 に四案の採用を決め、動画 17〜21 にも視線データがあると述べた
- 原典 A-01 のマスクの作り方（起票者が 2026-10-23 に原典を読んだ。F の知見の行）: フレームごとの視線点に Gaussian を置いたヒートマップを作り、token（2 × 16 × 16 の管）ごとに値を足し、softmax（温度 τ = 0.5）で確率にし、多項分布で置き換えなしに 196 token 中 176 をマスクに選ぶ
- repo の `data/README.md` には視線の記述が無い。`raw/ego/` はフレームの jpg、`annotations/egosurgery_phase/` は `Frame,Phase` の CSV である（§3.1、§4.2）。**視線データが andrew のどこに、どの形式で在るかは起票者が測っていない。** 本契約がそれを測る
- 測った結果は、案 1 の実装の契約と exp の prereg（視線の無いフレームの扱い、17〜21 の腕の定義）の入力になる

## 4. Task

### Task A — 開始状態

1. 分岐が `feat/` で始まり、起点が `origin/phase0` であること。作業ツリーが清浄であること（手順書「0. 始める」の出力を写す）
2. `data/` が置かれた装置の空き容量
3. manifest の行数（17,233）と 17〜21 の CSV の行数の合計（10,461）を数えて §3 と照合する
4. 試験の失敗の名前の集合（`tests/`）

### Task B — 置き場を探す

視線データの候補を、**三つの異質な方法**で探す。先頭がドットのものを含める。

1. 名前で探す（gaze、eye、fixation、pupil、tobii などの語。大文字小文字を区別しない）。対象は `data/` の全体と、repo の外では `~/slocal2/` の直下
2. 内容で探す（名前に語が無くても、`raw/ego/` の各動画のディレクトリと `annotations/` の下にある **jpg 以外の**ファイルを種類ごとに数える。座標らしい数値の列を持つ csv・txt・json・npy を候補にする）
3. 記録で探す（`data/README.md`、各ディレクトリの README と AUDIT、`docs/` の EgoSurgery の記述、`git log` の文言）

見つかった場合: 経路、ファイル数、合計の大きさ、更新日時。
見つからない場合: 探した範囲と方法を書き、**対象が無い／条件に合わない／対象集合の誤り**のどれかを判定する。その上で、公式配布（Fujiry0/EgoSurgery）が視線データを提供しているかを **読むだけで** 確かめ、提供している場合は形式と大きさの記載を写す。**取得はしない**（利用者の決定）。

### Task C — 形式を読む

見つかった場合だけ。各形式について、

1. 欄の名前と型、実物の先頭数行の写し
2. 単位と座標系（画素か正規化か、原点、画像の解像度との関係）
3. 時間のレート（視線のサンプルは何 Hz か、フレームは 0.5 fps）とフレームへの対応の鍵（フレーム番号か、時刻か）
4. 欠けや無効の印（NaN、負値、0,0、フラグ列）

### Task D — 被覆と範囲

1. 動画 01〜15 と 17〜21 の各動画で、manifest（と 17〜21 の CSV）のフレームのうち、視線の値が対応づくフレームの枚数と割合。分母は注釈の行と画像のファイルの両方
2. 対応づくフレームのうち、座標が画像の中に収まる割合。画像の解像度は実物の jpg から読む
3. 一フレームに複数のサンプルがあるなら、その数の分布（最小、中央、最大）
4. 動画ごとの表にし、合計を manifest の枚数と照合する

### Task E — マスクの入力に足りるかの確認

一枚のフレーム（視線が対応づくもの）で、視線点に Gaussian（σ は仮の値。記録する）を置いたヒートマップを作り、大きさと、最大値の位置が視線点と一致することを記録する。学習はしない。図は本契約のディレクトリに一枚だけ置いてよい（大きさを記録する）。

### Task F — 検証と報告

1. 追跡されるファイルの変更が `experiments/analysis/gaze_data_survey/` と本契約のディレクトリと受け皿 `tasks/inbox.d/` の一件だけであること（集合差で示す）。`data/` の下の変更が無いこと
2. `make forbidden-check` が通ること
3. REPORT.md、RESULT.md、result.yaml を書き、PR を作る（base は phase0、Draft でない）
4. 台帳への送り返し（手順書「8. 終える」）
