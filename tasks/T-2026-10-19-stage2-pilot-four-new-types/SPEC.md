## 3. 型の定義

**記号。** P0 は工程塔単独の事後確率（9 工程）、D0 は検出塔単独の後処理の上位 300 から取ったクラスごとの最大スコア（15 クラス。
上位 300 に無いクラスは 0）、D-GT は術具の正解の在否（15）。どれも前回の信号の定義のまま。
**零から始める部分は、学習前の出力が塔単独と一致するためのものである（一致の確認で実装の誤りを見る）。** 実装は受け取り手の実装を読んで決めてよい。
定義の意味を変えないと実装できなければ停止して諮る。

### 3.1 decoder-xattn（工程から検出、W1）

- 入力適合層: 線形（信号の次元 → 32）。工程の token: 線形（32 → 4 × 64）で、64 次元の token を 4 個作る
- 置き場所: D\* の decoder の**全層**。各層の FFN の後、その層の出力から box を精緻化する計算の前
- 各層に一つの部分層: query の状態 h を LayerNorm し、射影（hidden → 64）を query、工程の token を key と value にした
  4 ヘッドの attention を取り、出力を射影（64 → hidden）する。h ← h + tanh(α_l) × 出力。α_l は層ごとのスカラーで、0 から始める
- token を 4 個にするのは、1 個だと attention の重みが常に 1 になり、query によらない加算（前回の P3 の形）に戻るため（カードの理由）
- 学習するのは入力適合層、token の生成、各層の部分層と α_l。D\* は凍結
- 記録: 層ごとの tanh(α_l) を epoch ごとに。全腕でゲートが 0 の近くに留まったときは、余地が無い証拠ではなく
  界面が使われなかったと記録する（カードの読み方）
- 参考: 旧設計の工程の cross-attention の写し `experiments/analysis/t1b_camt/code/` を読んでよい。置き場所は本節に従う

### 3.2 extra-queries（工程から検出、W1）

- D\* の decoder に、追加の query を **30 個**足す。a(t) は入力適合層（線形、信号の次元 → 32）の出力
  - 内容: 学習する埋め込み e_i と、a(t) の線形写像の和
  - 参照 box: sigmoid(u_i + a(t) の線形写像)。u_i は学習する
- decoder の自己注意の mask: **元の query は追加の query を参照しない。** 追加の query は元と追加の両方を参照する
- 追加の出力のクラス logit に、学習する定数を足す。**初期値は −10**（学習前に上位 300 に入らないため）
- **見落とし（利用者の決定: 字面どおり）**: train の各画像で、凍結した D\* の評価の後処理の出力（上位 300、確信度の下限なし）のうち、
  同じクラスで IoU 0.5 以上の検出が一つも無い正解の box。確信度がどれほど低い検出でも「覆う」に数える。
  train で一度だけ作り、全腕で同じ集合を使う
- 照合: 追加の query だけを見落としの box に一対一で照合し（D\* と同じ照合と損失の形）、残りの追加の query は物体なし。
  元の query の損失は使わない（W1 では元の出力が変わらない）
- 最終の検出: 元と追加の出力の和集合から、D\* の処方と同じ上位 300 を取る
- 学習するのは e_i、u_i、二つの線形写像、入力適合層、スコアの定数。D\* は凍結
- 記録: 見落としの box の数（クラスごと）。記述として、確信度の閾値ごとの見落としの数（閾値の集合は分布を見て実行者が決め、記録する）。
  学習後に、追加の出力が最終の上位 300 に入った数、照合した見落としの数、追加の出力を除いたときとの差（クラス別 AP、群 AP）

### 3.3 logit-correction（検出から工程、W1）

- ℓ0(t): 時間ヘッドの最後の段の出力（9 工程のロジット）
- u(t) = GELU(W_in x(t) + W_p softmax(ℓ0(t)) + b) ∈ ℝ^32、Δℓ(t) = W_out u(t)、ℓ1(t) = ℓ0(t) + Δℓ(t)
- W_out（bias を持たせるならそれも）を零で初期化する
- 時間: フレーム t の値だけを使う。ℓ0 と x を事前に計算してよい
- 損失と歩: 前回の検出から工程と同じ形（§2）。界面で変わるのは最後の段の出力だけ。1 歩 = train の動画 1 本
  （カードは batch を「契約で一つに固定する」と書いた。前回の型と同じ条件にする）

### 3.4 tool-history（検出から工程、W1。カードどおり）

- z(t): 時間ヘッドの最後の段で、工程のロジットを出す 1×1 の層（`conv_out`）に入る特徴
- h(t) = GRU(W_in x(t) + b_in, h(t−1)) ∈ ℝ^64。1 層。動画の先頭で h = 0
- z′(t) = z(t) + tanh(α) × W_o h(t)。**α は 0 から始める**。W_o は線形層の既定の初期化
- 系列は動画の先頭から全体を因果的に流す（打ち切らない）。フレームの並びは前回の検出から工程の列の作り方のまま
- 記録: tanh(α) を epoch ごとに
- 最後の段が「層の列 → `conv_out`」の形でない、または z(t) が一つに決まらないときは停止して諮る

### 3.5 tool-history のゲートなし版（利用者の決定）

- §3.4 と同じで、ゲートだけを置かない: z′(t) = z(t) + W_o h(t)。**W_o（bias も）を零で初期化する**
- カードの型からの変更であることを報告に明記する

### 3.6 殺し実験（記述だけ）

**K1 見落としの数え上げと神託（extra-queries。学習なし）**
- val の各画像で、§3.2 の読みで見落としを数える（クラスごと。確信度の閾値ごとの数も記述として）
- 見落としの box を、正しいクラスと位置、確信度 1 で D\* の出力に足し、上位 300 を取って評価する。塔単独との差（overall mAP、群 AP）

**K2 多項ロジスティック回帰（logit-correction。界面の学習なし）**
- val の 2 本で、片方で当てはめ、もう片方で測る（両方向）。特徴は (i) softmax(ℓ0)、(ii) (i) と D0、(iii) (ii) と D-GT
- 値: 測った動画の macro Jaccard（主）、frame accuracy、平均の負の対数尤度。方向ごとの値と、(ii)−(i)・(iii)−(i) の 2 方向の平均
- 正則化などの設定は測る前に一つに決めて記録し、測った動画の値で選び直さない。当てはめた動画に無い工程は記録する

**K3 検出の系列だけの GRU と stacking（tool-history）**
- (1) D0 の系列だけから工程を当てる GRU（1 層、64、線形で 9 工程）。train は交差適合版の D0、val は確定塔の D0。
  学習率・weight decay・1 歩の単位・長さ（4 epoch）・seed は §2 の検出から工程と同じ。val の事後確率を出す
- (2) K2 と同じ形で、(i) softmax(ℓ0) と、(i) と (1) の事後確率を比べる
- (3) (1) で学んだ GRU に、val の D0 を動画の中で時間の順だけ無作為に入れ替えた系列（seed 42）を入れて事後確率を作り直し、(2) を繰り返して差を記録する
- カードの「GRU の最終状態から術式を当てる精度」は、動画ごとの術式の対応が repo に在れば測る。無ければ UNKNOWN（作らない）

## 6. 事前登録（測る前に固定する）

### 6.1 量

すべて seed 42 の 4 epoch 目の値。

- **空の腕との差** Δ空(型, 腕) = 指標(型, 腕) − 指標(同じ型の空の腕)
- **入れ替えの腕との差** Δ入替(型, 腕) = 指標(型, 腕) − 指標(同じ型の入れ替えの腕)
- **塔単独との差** Δ塔(型, 腕) = 指標(型, 腕) − 塔単独の値。分母の強さが型ごとに違うため、型を並べるときに添える
- 指標: 工程から検出は overall mAP、標的群 AP（併記）、陰性対照群 AP。検出から工程は macro Jaccard、frame accuracy（併記）、クラス別 Jaccard
- ゲートの値（decoder-xattn の層ごと、tool-history）、extra-queries の追加の出力の寄与（§3.2）
- 殺し実験の値（§3.6）

### 6.2 読み方の規則（記述だけ）

1. 型ごと・腕ごとに、4 epoch 目の値、Δ空、Δ入替、Δ塔、動画ごとの Δ空と Δ入替を表にする
2. seed が一つなので、「seed の幅を超える」「幅の内」の判定はしない。差は 1 本ずつの差として書く。陽性・陰性・有意などの語は使わない
3. 予測-noCF の Δ入替を「その時刻の信号の中身による差」として読む。正解の腕の Δ入替も並べる
4. Δ空 と Δ入替 の符号が食い違えば、両方を書き、一つにまとめない。工程から検出の overall mAP と標的群 AP、
   検出から工程の Jaccard と accuracy の食い違いも同じ
5. ゲートを持つ型で、4 epoch 目のゲートの値が全腕で 0 の近くに留まったときは「ゲートが開かなかった」と書き、Δ の小ささを
   信号に情報が無い証拠として読まない
6. tool-history とゲートなし版の値は並べて書き、一つにまとめない
7. **ホストをまたぐ値を処置の差として読まない**（§2 の規約）。andrew の型と bengio の型の比較、本契約の型と前回・直しの契約の型の比較は、
   ホストの列を付けた参考の表にだけ置く
8. 検出から工程のクラス別 Jaccard は、空の腕との差が最も大きい工程を型ごとに書く
9. 殺し実験の値は記述だけにする。カードの「殺す」条件に当たるかは書いてよいが、その判定で何も決めない
10. 結果は関門の判定と設計の判断に使わない（§0）

### 6.3 予測（記述のための事前の記録。外れても本契約の判定は変わらない）

1. tool-history（カードどおり）の 4 epoch 目の tanh(α) の絶対値は、全腕で 0.05 未満である（起票者の見積もり 0.02。§1）
2. 予測-noCF の Δ空（Jaccard）の絶対値は、tool-history のゲートなし版の方が tool-history より大きい
3. extra-queries の見落としの割合（見落としの box の数 ÷ 正解の box の数）は、train の方が val より小さい
4. decoder-xattn の正解の腕の Δ空（標的群 AP）は正である

### 6.4 既知の限界（報告に必ず書く）

- 折りは 1 つ、val は 2 動画、seed は 1 つ。区間推定もクラスタの推論もできない。工程は動画 09 が塔単独で上限に近い
