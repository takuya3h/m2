### 5.1 `symmetry` の「各塔の構造の標準の処方」に足す内容

- 使える行に「**入力の縮小規則**（短辺の目標と長辺の上限）」を足す
- 使える条件に「入力の縮小規則の行に使うときは、**画面の残る割合（切り出し）が両腕で同じ**であること」を足す
- 使えない行に「**入力の切り出し**（画面の残る割合）」を足す
- 箇条を一つ足す: 入力の縮小規則に理由 3 を使うときは、「必ず置く行」の「入力解像度と切り出し」を二行に分ける。
  切り出しの行は「揃える」、縮小規則の行は「意図的に変える」で理由 3 とし、両腕の実際の大きさを書く
- 実例として次を書く: 検出塔の評価時の入力は 1333×749（pad 後 1344×768）、工程塔は 800×1422、画面の残る割合はどちらも 100%（出所は §3.1 の 1・2 行目）
- 既存の「同じ塔の変種どうしには使わない」は、入力の縮小規則にもそのまま当てはまる（変えない）
- 出所: 利用者の決定 2026-10-18（本契約の SPEC §2）

### 5.2 `symmetry` に足すホストの規則

- 「必ず置く行」に「**ホストと装置型**」を足す
- 規則（小節を立ててよい）:
  - 比べる腕と分母は、同じホスト・同じ装置型で回す。ホストの行は「揃える」以外にしない（理由 1〜3 のどれも使わない）
  - 別のホストの値と比べる必要があるときは、同じ設定を両方のホストで回した対照を置き、対照の差を並べて書く。対照の無いホストをまたぐ差を、処置の差として読まない
- 実測: 同じ設定で efros 0.7762、ilya 0.7066、差 +0.0696（折り A の seed 間の標本 SD 0.0186 の 3.7 倍）（出所は §3.1 の 3 行目）
- 出所: 利用者の決定 2026-10-06 と 2026-10-17（本契約の SPEC §2）

1. **本契約では GPU を使用しない。** 学習も推論もしない。Python の処理は装置を見えなくした状態で動かす
2. ほかのホストへ接続しない。到達性の記述は記録された測定だけで直す
3. `data/` 配下に書き込まない。データを読まない。`data/splits/` の既存ファイルを変えない
4. 規約の既存の規則の中身（範囲・条件・数）を、§5 が挙げるもの以外で変えない。既存の節を消さない。アンカーの名前を変えない
5. 折り表の正本の既存の実測の記録を消さない
6. 既存スクリプトと道具の挙動を変えない
7. `context/auto/*` と `tasks/inbox.md` を再生成しない。生成物の検査（`make taskindex-check`、`make inbox-check`）を回さない
8. `runindex/**` を手で編集しない。既存の `tasks/*/` を変えない。他の契約の `conventions_rev` を書き換えない
9. 資格情報の値を記録・出力しない。資格情報の扱いが拒まれたら回避せず諮る
10. 外部への送信は `make task-report` 以外の経路で行わない

## 8. 想定外と停止条件

- 本ホストの repo の位置や起点が `context/env-facts.md` の記載と違う → 停止して諮る
- 作業ツリーが別の契約の分岐にある、または別の契約が作業中 → 起動しない。停止して諮る
- 規約に置く行の出所が、§3.1 が挙げる文書の中に見つからない → その行を置かずに停止して諮る
- 規約の文言を整えるときに、範囲・条件・数を変えたくなった → 停止して諮る
- 意図しない節が変わった、アンカーが解決しない、カードの検査の結果が変わった → 停止する（関門 G2）
- 試験の失敗の名前の集合が増えた → 停止する
- 実行基盤が書き込みや移動を拒む → 回避せず諮る
