## 0. 位置づけ

2026-08-29 の三契約（k1-reeval-and-harvest、stage0-contract-b、lecun-detector-env-pd）が、
道具の側に原因がある欠陥を五件報告した。いずれも「契約どおりに実行すると道具が止める、

本契約は五件を直し、直した検査が **違反を検出し、非違反を誤検出しない** ことを対照で示す。
研究判断を含まない。数値を判定に変換しない。

## 2. 要求（何を満たすべきか）

### F1 禁止領域検査

- 契約が正当に書く領域（収穫による runindex の更新、契約の destination）を、**契約から機械で読める形で宣言**でき、検査がそれを許可として受け取れること
- 宣言の無い禁止領域への書き込みは、従来どおり失敗すること
- 宣言の置き場は実行者が決める（spec の欄、Makefile の変数、その他）。**spec に欄を足す場合は schema・雛形三種・validator の試験を同時に更新し、既存契約が壊れないこと**
- 許可を宣言しても data 配下と既存 run 配下への書き込みは許可できない（許可の上限を持つ）

### F2 preflight の未知名

- 未知の名前は **FAIL**（黙って PASS にしない）。実装は schema の enum か実行時の照合か、いずれでもよいが、両方に整合すること
- 既存契約が使っている名前の集合を実測し、それらは引き続き PASS すること

### F3 置換前提の欄

- 起票者が「実行者が索引で解決する」と宣言した参照を持つ契約が、取り込みで落ちずに設置され、**実行前に解決が済んでいなければ止まる**こと
- 解決の記録（何を何に置き換えたか）が RESULT の「解決された参照」の表に残る形であること
- 方式は実行者が決める（形式検査の順序を変える／宣言つきの仮値を許す／その他）。tasks/README にどちらを採ったかと理由を書く

### F4 収穫の検証

- 収穫の前後を比較する検査を一つの命令で行えること
- run 単位の索引: 追加のみ・削除零・既存行の変更零
- 集約表（experiments、verdicts、per_class）: **既存の群について判定に使う列（same_sign、verdict_pstd、verdict_sstd、agree、reason、n_seeds）が不変**であること。集計値の列は変わってよい
- 差分の全量を出力に含める（何が変わったかを人が読める）

### F5 秘匿検出

- 伏せ字（先頭数桁と省略記号のような表記）を含む要約値を非検出にする
- 秘匿値本体・鍵の書き出し・長い符号化文字列・名前に続いて値が現れる形は引き続き検出する
- **検査の出力に秘匿値の断片を出さない。対照に使う値は実在しない合成値だけを使う**

### 付随（文書のみ）

- tasks/README に「preflight の宣言は契約が実際に使う経路に限る（工程側だけを回す契約は検出器の拡張を宣言しない）」を一行加える。規約の変更ではなく注意の明文化

## 3. 手順

### Task 1 前提の実測（Phase A）

- Step 1-1 conventions_rev と created_from を実測し、違えば置換して記録
- Step 1-2 五件それぞれについて、**欠陥が再現する入力**と**正常に振る舞う入力**を作り、修正前の挙動を記録する。F1 は runindex への書き込みを模した一時ファイルで（実際の収穫はしない）。F3 は置換前提の値を持つ最小の spec で。F5 は合成値で
- Step 1-3 既存の全契約に対する静的検証（L1）の結果を、契約ごとに記録する（修正後の回帰の分母）
- Step 1-4 既存契約の preflight で使われている名前の集合を実測する

### Task 2 修正（Phase B）

- Step 2-1 F1 から F5 を直す。各修正に試験を足す（陽性・陰性の対照を対で）
- Step 2-2 spec に欄を足す場合は schema・雛形（exp、impl、analysis）・validator・試験を同時に更新する
- Step 2-3 tasks/README と docs の該当箇所を、実装と一致する形で更新する（数の主張は書かず出所を指す）

### Task 3 回帰と送出（Phase C）

- Step 3-1 Step 1-3 と同じ集合に L1 を回し、結果が一致することを確かめる
- Step 3-2 全テストを回す。実行前後の件数を記録する
- Step 3-3 変更範囲を実測し、experiments と data と runindex に変更が無いことを示す
- Step 3-4 commit、push、PR（base は起点と同じ分岐）。台帳へ報告

## 4. 禁止事項

1. GPU の使用
2. experiments、data、runindex への書き込み（一時ファイルは作業領域に置き、終了時に消す）
3. context/auto と tasks/inbox.md の再生成（並行契約が走っているため。統合後に一台で回す。関連する検査が非零で終わることは想定内）
4. 数値の推定を実測として書くこと。測れないものは UNKNOWN
5. 過去の報告・完了済み契約・履歴の書き換え（追記のみ可）
6. 秘匿情報の出力・複製・移動。対照に実在の資格情報を使うこと
7. 外部サービスへの書き込み・新規設定

**禁止は実行者の操作に対するものであり、同期処理による配布や衝突ファイルの生成を含まない。**

## 6. 想定外の扱い

| 事象 | 対処 |
|---|---|
| 五件のうち再現しないものがある | 再現しない旨と試した入力を記録し、その件は修正しない。他の件は続ける |
| 修正が既存契約を一件でも壊す | escalate して停止。壊れる契約と理由を報告する |
| F3 の方式が取り込みの互換を壊す | escalate して停止 |
| 原因が道具でなく規約の側にある | escalate。規約の変更は起票者とユーザーの判断 |

失敗時の巻き戻し: 変更は分岐上のみ。停止する場合も分岐と audit を残したまま stopped で報告する。

## 7. 報告の構成

RESULT.md は起票者が判断に使う事実だけを書く。目安は百五十行以内。

- 判定: verdict と関門の結果
- 完了判定: §5 の表に実測値を埋めたもの
- 五件それぞれの採った方式と理由（一件三行以内）
- 実測: 次の契約で使う値（許可の宣言の書き方、置換前提の参照の書き方、収穫検証の命令名）
- 起票者の誤り: 型と内容。一件三行以内
- 逸脱・想定外・UNKNOWN・判断待ち
- 送出: PR 番号と終了コードのみ

命令とその出力の全文・対照の出力・差分の全量は audit.md へ置き、RESULT.md からは行番号で指す。
