## 4. 測り方の原則（手段は実装者が決める）

- **重みは要らない。** 記憶量と一歩の時間は構造と入力の大きさで決まる。DINOv3 の重み（HF で同意が要る）も SurgVISTA の重みも読まず、同じ形の ViT を乱数で初期化して測る。重みを使う測定（精度）は本契約の外
- **一歩 = 順伝播＋逆伝播＋最適化の一回。** 最初の数歩を除いた定常の平均を取る。回数と除いた数を記録する
- **記憶量は torch の最大確保と予約、nvidia-smi の最大の三つ**を記録する（dlsta の実測と同じ三つ。`context/env-facts.md`）
- **収まる最大の batch** は、目標の batch から半分ずつ下げて最初に収まった値と、その一つ上で失敗した値の両方を書く。`expandable_segments` の有無を記録する
- **注意の実装**（PyTorch の SDPA の核が math・efficient・flash のどれか、fp32 では flash が使えない）を各行に書く。実装が自動で選ぶなら選ばれたものを記録する
- **入力の作り方**: 800 系統は比較の相手と同じ 800×1422 を patch 16 の倍数に切り上げるか詰めるかを実装者が決め、トークン数を書く（起票者の計算では約 50 × 89 = 4,450）。実データを読む必要はなく、乱数の画像で足りる。実データで読み込みの時間を見るのは Task B の較正だけ
- **学ぶ範囲の三水準**: 全体 fine-tune、上位 4 ブロックだけ、全凍結＋線形。adapter/LoRA の水準は「上位 4 ブロック」と「全凍結」の間に入るので本契約では測らない（起票時に内挿する）
- 1 epoch の見込みは、manifest から数えた枚数（Task A）と一歩の時間と batch から式で出す。推測の係数を掛けない

## 5. Task

### Task A — 開始状態

1. 分岐が `feat/` で始まり、起点が `origin/phase0` であること。作業ツリーが清浄であること（手順書「0. 始める」の出力を写す）
2. 装置: 型、容量、driver、二枚それぞれの compute プロセスの有無と確保量。本契約で使う一枚を決めて記録する
3. 版: torch、torchvision、timm、mamba-ssm、causal-conv1d。どれかが読み込めなければ停止して諮る（導入しない）
4. 空き容量: repo のある区画と `experiments/` のある区画
5. manifest の枚数: 17,233 と、折り A の train の枚数（規約 folds の train 10 動画）を manifest から数える。17,233 と一致しなければ停止して諮る
6. 試験の失敗の名前の集合（`tests/`）

### Task B — 較正

1. 比較の相手の処方（`configs/stage1_ptower_r3.yaml` の ResNet-50、800×1422、fp32、決定論的）で、batch 1・2・16 の一歩の記憶量と時間を測る。実データの読み込みを含めてよい（読み込みの時間は分けて書く）
2. batch 16 の最大確保を三周目の記録（27.06 GiB。別ホスト）と並べる。桁が違えば停止して諮る
3. batch 1 → 2 → 16 で最大確保が単調に増えることを確かめる（測り方が壊れていないことの対照）

### Task C — ViT の fine-tune

規模 {ViT-B/16, ViT-L/16} × 入力 {224², 448², 800 系統} × 学ぶ範囲 {全体, 上位 4 ブロック, 全凍結＋線形} の 18 行。各行で:

1. 目標の batch から始めて収まる最大を求める（目標: 224² は 64、448² は 16、800 系統は 4。目標が収まればそれ以上は探さない）
2. 収まった batch での一歩の時間、最大確保、予約、nvidia-smi の最大、注意の実装
3. 全凍結＋線形の行は、特徴の取り出し（順伝播だけ、勾配なし）の 1 枚あたりの時間も書く
4. 1 epoch の見込み（折り A の train の枚数 ÷ batch × 一歩の時間）を式つきで書く
5. 30 分を超える行は UNKNOWN として理由を書き、次へ進む

### Task D — MoCo v2 の一歩

1. ResNet-50 の MoCo v2（二つのビュー、224 のクロップ、queue と momentum の encoder）の一歩を、batch 256 から半分ずつ下げて収まる最大を求める。queue の大きさは原典の既定（実装者が原典で確かめる。地図に無い）
2. 収まった batch の一歩の時間、記憶量の三つ、1 epoch の見込み（折り A の train の枚数と、17〜21 を足した枚数の二通り。17〜21 の枚数は `docs/phase_annotation_stats_videos17-21.md` の行数 10,461 を使い、manifest に無ければその旨を書く）

### Task E — 映像 MAE の一歩

1. ViT-S/16 の encoder と小さな decoder、入力 10 フレーム × 224²、tube か random のマスク 0.90、batch 256 から半分ずつ下げて収まる最大
2. 収まった batch の一歩の時間、記憶量の三つ、1 epoch の見込み（クリップ数は折り A の train の枚数と同じとする。式を書く）
3. 視線のマスクは測らない（マスクの選び方は記憶量と時間をほぼ変えない。変えると考える理由があれば書く）

### Task F — mamba-ssm の決定性

1. 決定論的アルゴリズムの設定（`scripts/stage1_ptower.py` の deterministic と同じもの）のもとで、小さな選択的 SSM（状態次元 64、層数 2、入力 2048 次元、長さ 1,400 の列、batch 1）の順伝播と逆伝播を同じ seed で二度行い、出力と勾配の最大絶対差を記録する
2. 陽性対照: 決定論的アルゴリズムの設定を切り、入力に意図的に 1e-3 の差を足した二度で、差が 0 でないことを確かめる（検査が差を検出できることの対照）
3. causal-conv1d の有無（入っていれば使う）を記録する

### Task G — 検証と報告

1. `experiments/analysis/ptower_cand5_compute_probe/` に REPORT.md と、各行の生の記録（JSON か CSV）と、測定に使ったスクリプトを置く。checkpoint は残さない

3. `make forbidden-check` が通ること。試験の失敗の名前の集合が Task A の 6 と同じであること
4. RESULT.md と result.yaml を書き、PR を作る（base は phase0、Draft でない）
5. 台帳への送り返し（手順書「8. 終える」）
