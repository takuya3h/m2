## 3. Phase A — K1 数値の初出の再捜索

**探すのは run ではなく、数値が記録に最初に現れた場所である。** 四系統を必ず全て行う。
各系統について {方法・対象範囲・表現の揺れの一覧・件数} を audit に表で残す。

数値には表現の揺れがある（符号の有無・百分率・小数点以下の桁・pt 表記）。
**どの揺れを試したかを列挙すること。** 試していない揺れは「探した」に数えない。

### 系統 1 版管理の全履歴

リポジトリの全 commit 履歴に対し、K1 の数値文字列の**初出**（最初に現れた commit・ファイル・行）
を特定する。初出が見つかったら、その文書が何を典拠として引いているかを読み、典拠を一段ずつ遡る。

### 系統 2 生ログとメトリクスの直接走査（索引を経由しない）

experiments 配下を索引を通さずに走査する。範囲は aligndetr・hemostasis・phase を名前や内容に
含むファイルに限ってよいが、**限った範囲を明記する**。時期は 2026-06 から 07 を優先し、
見つからなければ広げる。読み取り専用。

### 系統 3 外部の実験記録（読み取りのみ）

環境に既に設定されている資格情報の範囲で、外部の実験記録サービスを**読み取りのみ**照会し、
該当時期の run に K1 の数値があるかを確かめる。
**新規の設定・書き込み・資格情報の出力は行わない。** 照会できない場合は理由つき UNKNOWN でよい。

### 系統 4 リポジトリ内の文書・スライド・ノート

docs 配下ほか、版管理下の文書全体（現在版）に対する数値の全出現を列挙し、
それぞれの出所記述の有無を確かめる。

### 検索器の対照

- 陽性: 前契約で実在が確定している数値（-0.050877）を同じ検索器で探し、一件以上出ること
- 陰性: 実在しない乱数の数値で零件になること

### 打ち切りと結論

四系統を終えたら、結論を二値で確定する:

- **発見**: 初出と典拠が特定できた。出所の連鎖（どの文書がどれを引いたか）を表にする
- **遡れない（確定）**: 四系統とも零件。以後 K1 は出所不明として扱う

互いに矛盾する複数の出所に遡れた場合のみ escalate。

## 7. 想定外の扱い

| 事象 | 対処 |
|---|---|
| 旧バンドルの添付が取得できない・要約値不一致 | 配置せず停止して報告（Phase A と Task 2・3 は続けてよい。部分完了として報告） |
| 系統 3 の外部照会が資格情報の不足で不能 | 理由つき UNKNOWN。残る三系統で結論を出し、その旨を結論に併記 |
| 数値の初出が複数文書で同時 | 同一 commit 内なら同時初出としてすべて列挙。矛盾する典拠を持つ場合のみ escalate |
| 取り込み拡張が既存検証（L1 など）と衝突 | 拡張の範囲を取り込みに限って衝突を避けられないか実装を読んで判断し、避けられなければ escalate |
| 検索の候補が大量で終わらない | 範囲の限定を明記して部分結果とし、残りを UNKNOWN とする |

失敗時の巻き戻し: 変更は分岐上のみ。停止する場合も分岐と audit を残したまま stopped で報告する。

## 8. 報告の構成

RESULT.md は起票者が判断に使う事実だけを書く。目安は百五十行以内。

- 判定: verdict と関門の結果
- 完了判定: §5 の表に実測値を埋めたもの
- **K1 の結論**: 二値のどちらか。発見なら出所の連鎖、遡れないなら四系統の表
- 実測: 次の契約で使う値（取り込み拡張後の宣言形式・配置ファイルの経路）
- 起票者の誤り: 型と内容。一件三行以内
- 逸脱・想定外・UNKNOWN
- 送出: PR 番号と終了コードのみ

命令とその出力の全文・捜索の過程・対照の出力・試験バンドルの内容は audit.md へ置き、
RESULT.md からは行番号で指す。同じ内容を二度書かない。
