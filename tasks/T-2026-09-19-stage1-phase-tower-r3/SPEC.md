# Stage 1 工程塔の三周目: 初期化の鎖と入力解像度を検出塔と揃える

**task_id:** T-2026-09-19-stage1-phase-tower-r3  **kind:** exp

## 1. 背景

二周目で二つの非対称が残っていた。COCO 検出の事前学習が P に無いこと、入力が 224 の中央切り出し（横 49%）であること。
利用者の判断（2026-09-18〜19）と M §5.1 の改訂に従い、P\* を D\* と対称にする。設計は `prereg.md`（対称性の表を含む）。

**本契約は GPU を使う**（利用者承認）。装置は ilya の 2 枚。

## 2. 確定した事実（ホストによらない値だけ）

- 二周目の成果物（PR、`experiments/phase1/stage1_ptower_r2/`、道具 `run_stage1_ptower.py`・`select_stage1_ptower.py`）。**統合状態を Task A で確かめる**
- 二周目の値: 5 折り平均 val 0.387 / test 0.256、折り A val 0.468、確定 recipe C・6 層・0.15・履歴 30・lr 1e-4。fine-tune は 1 本 411〜658 秒（224）
- 一周目の値: 5 折り平均 val 0.329 / test 0.225。線形対照（折り A）0.225
- S4 の折り A 参照: val Jaccard 0.6447 ± 0.0119（当初 3 run）
- D\*-COCO の初期化: Relation-DETR の COCO 検出 checkpoint。**その backbone 部分を P\*-COCO の初期値にする。** 重みの在処は検出塔の契約の記録（`third_party/Relation-DETR/checkpoints/` 配下）から特定し、要約値を D 側の記録と照合する
- D\* の解像度: 短辺 480〜800 の多尺度、評価は短辺 800、全画面
- 元画像は 1920×1080。短辺 800 なら 1422×800。二周目の 224 に対し画素数は約 22 倍。**所要時間と記憶領域は Task B で実測する**
- 追加 6 動画（17〜22）の注釈は ilya に在る。画像は Task A で有無を測る
- `train_phase_tower_r50.py` の前処理は二周目で「短辺 256 → 中央 224」（実測）。本契約は全画面・短辺 800 に変える。実装の変更箇所を記録
- 対話シェルは zsh。`git --no-pager`。`make` には読み込みを同じ命令に含める

## 3. Task

**コマンドは書かない。実装を読んで決めてよい。**

### Task A — 事前登録と開始状態

1. **最初に `prereg.md` を commit し、hash と時刻を `spec.yaml` に書く**
2. 作業ツリーの清浄、HEAD が phase0、装置の状態（`/proc/PID/exe` か引数の完全一致）
3. 二周目の道具と成果物が本分岐にあること（未統合なら分岐から取り寄せ、逸脱に書く）
4. **COCO 検出済み backbone の重み**を特定する。D\*-COCO が出発する checkpoint から ResNet-50 の重みだけを取り出せるか実装を読む。
   要約値を記録し、D 側の初期化と一致することを示す（完了判定 a）。無ければ停止
5. 追加 6 動画の画像の有無。在れば動画ごとのフレーム数と注釈の一致
6. 前処理を全画面・短辺 800 に変える箇所を実装から特定し、記録する。**切り出しが入っていないこと**を実装の行で示す（完了判定 c）
7. `conventions_rev` と `runindex_commit` を実測し占位を差し替える

### Task B — 一本目（所要時間と記憶領域）

1. P\*-COCO、折り A、seed 42、lr 3e-4 で 1 本。壁時計、GPU 時間、記憶領域の最大値を記録
2. 3 時間を超える、または記憶領域が収まらない → 諮る。**解像度を下げる案は出さない**（対称性が崩れる）。上限・停滞の epoch 数・batch の見直しを諮る
3. 学習率の低下が起きたか、打ち切りが働いたか、上限 36 に達したかを記録

### Task C — fine-tune 28 本

1. 系統 2 × 学習率 2 × 7（5 折り、A は 3 seed）。train 動画のみ。val の frame accuracy で最良 epoch。上限 36、4 epoch 改善なしで学習率 1/10（一回）、低下後また 4 epoch 改善なしで打ち切り（検出塔二周目と同じ規則）。規則は `train_phase_tower_r50.py` に足す（既定は従来どおり、引数で有効化）
2. 各 run の val frame accuracy を二周目の同じ折りと比べる。下回る折りがあれば停止（G2 相当）
3. 損失の推移を残す。発散・非数があれば停止

### Task D — 特徴と時間ヘッド

1. fine-tune 後の各 backbone から、その折りの全動画（追加 6 動画も画像があれば）の C5 GAP を短辺 800・全画面で抽出。決定性の確認
2. 10 構成 × 28 = 280 run。二周目の道具を再利用。task_id を刻む
3. 表に、二周目と一周目の確定塔の値を同じ折りで並置

### Task E — 選定・P\*-21・test・並置

1. prereg §6 の規則を**系統ごとに**当てる。一意に決まらなければ諮る
2. P\*-15 を系統ごとに確定。画像があれば P\*-21 を系統ごとに同じ recipe で学習
3. test は確定塔について折りごとに一度。台帳に記録。回数を数える（最大 4 塔 × 5 = 20）
4. 折り A の val を S4 と並置し、差を二周目の 0.177 と比べる
5. prereg §4 の予測 5 項目の当たり・外れ

### Task F — 検証と報告

1. L1、L2、L3（P13 を含む）、`make forbidden-check`、`make spec-check TASK=T-2026-09-19-stage1-phase-tower-r3`、試験、`make runindex`
2. 完了判定 a〜k を実測で埋める
3. `RESULT.md`、`result.yaml`（版 3）、`audit.md`、`tasks/inbox.d/`。T1 の材料の表
4. commit、push、**PR の base は phase0**。分岐名 `feat/stage1-phase-tower-r3`。`.sync-pause` を移動で解除
