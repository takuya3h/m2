# 起票者の誤りを、過去の実例を教師にして機械で捕まえる

**task_id:** `T-2026-08-11-issuer-defect-detector`
**kind:** `impl`  **depends_on:** `T-2026-08-11-artifact-merge-and-pause`
**実行ホスト:** `lecun`（repo は `~/slocal2/m2`）

## Goal

起票者の検査が検証対象を検証できていない誤りが **20 task 連続**で起きている。
手順書には注意項目が並んでいるが、**起票者は同じ日に自分で書いた注意を 2 度破った。**
**文言による自制は働いていない。**

一方、これらの誤りは**すべて構造化された記録に型つきで残っている。**
`tasks/*/result.yaml` の `issuer_defects` である。

**これは検出器の正解データとして使える。**

    検出器を作る → 過去の誤りに対して何件検出できるか測る → 検出率が出る

検出できない型も明示される。**「この型は構文では捕まらない」と分かること自体が成果である。**
これにより、**検出器そのものが空振りかどうかを測れる。**

## 4 層の設計

| 層 | 誰が回すか | 内容 |
|---|---|---|
| 1 | 起票者（起票のたび） | 契約の本文を走査し、既知の危険を検出する |
| 2 | 起票者（書く時点） | 完了判定の表に**陽性対照の欄**を必須にする |
| 3 | 実行者（報告時） | 対に**陽性対照の記録**を必須にする |
| 4 | 実行者（実行直前） | 層 1 と同じ検査を回す。**FAIL ではなく警告** |

層 4 が二重の網である。**起票者が層 1 を回し忘れても、実行の直前に出る。**

## 原理的な限界

**「この検査が対象を検証しているか」は一般には判定できない。** 意味論の問題である。
**全部は捕まらない。半分捕まえられれば発生率は半減する。**

したがって本 task は「全件検出」を目標にしない。**検出率を測り、捕まえられない型を
明示すること**を目標にする。**測れない主張を書かない。**

## 0. 前提と禁止事項

分岐の作成と契約の取り込みは配布時の命令で済んでいる。**抑止の目印を確かめる。**

**このホストの `.venv` には導入コマンドが無い。依存を増やさない。**
報告まで終えたら抑止を解除する。**解除は別名へ移す**（前 task の実測）。

| 3 | `context/conventions.md` を変更する |

### 起票者からの申し送り

**直近の契約で起票者は 3 件の誤りを犯した。** 一覧の取り方が 3 生成器のうち 1 つしか
拾わず、除外の陽性対照が空振りする設計で、終了コードが異なると測らずに断定した。
**本 task の教師データにこれらも含まれる。**

実行環境の対話シェルは bash ではない。**変数の直後に記号が続く場合は波括弧で囲むこと。**
配列の添字による終了コードの取得は使えない。単語分割も起きない。

**このホストに頁送りは無い**（前 task の実測）。`core.pager` が `cat` に設定されているため
失敗しないが、**設定に依存している。** 履歴を読む操作は `git --no-pager` を使う。

**本 SPEC の検査も同型の誤りを含みうる。** 次を守ること。

| # | 注意 |
|---|---|
| 1 | 一致件数が 0 のとき、別の探し方でも 0 になることを確かめる |
| 2 | 仕組みの挙動は実装を読んでから信じる |
| 3 | 記録を作る流れに表示用の切り詰めを混ぜない |
| 4 | 検査が空振りでないことを陽性対照で確かめる |
| 5 | 対象の一覧そのものが正しいかを確かめる |
| 6 | 終了コードで判定する前に、その命令が本当に走ったかを確かめる |

# Phase B — 契約の静的検査

## Task 2: 検査を実装する

**Files:** Create `tools/check_spec.py`、Create `tests/test_check_spec.py`、Modify `Makefile`

- [ ] **Step 1: 検出する規則を決める**

**Task 1 Step 4 で `syntactic` と `structural` に分類したものだけ**を対象にする。
**分類していない規則を思いつきで足さない。**

参考として、既知の危険を挙げる。**これは網羅ではない。教師データが正本である。**

| 分類 | 例 |
|---|---|
| syntactic | 終了コードの直前がパイプを含む／`git` に頁送りの回避が無い／記録を作る流れに切り詰めが混ざる／波括弧の無い変数展開の直後に記号／bash 専用の書式 |

**構造の検査には、操作と生成先の対応が要る。** 前 task で作った検査が生成器の実装から
