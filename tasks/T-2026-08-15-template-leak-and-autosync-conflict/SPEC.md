# 共有テンプレートに残るホスト固有値を除き、自動同期と契約の衝突を解消する

**task_id:** `T-2026-08-15-template-leak-and-autosync-conflict`
**kind:** `impl`
**depends_on:** `T-2026-08-14-bundle-attachment-transport`
**実行ホスト:** `lecun`

## Goal

**この契約は添付経由で配られた最初のものである。** 記法の解釈を受けない経路が
実際に使えるかの実証を兼ねる。

内容は 2 つ。いずれも直近の実測で判明した。

### 1. 共有テンプレートに固有の値が残っている

共有の暗号設定からはホスト固有の値を除いたが、**テンプレートには残っている。**
テンプレートは全台へ同じ内容が配られるため、それを写した各ホストが**揃って同じ名前を
名乗る。** これが「論理名が全台で誤った値になった」の機序である。

**導線が生きているため、新しいホストを立てるたびに再発する。**

### 2. 常駐処理が契約の禁止事項に抵触する

契約は「統合しない」を禁止事項に置くが、常駐する同期処理が**実行者の操作なしに
作業分岐へ統合を行った。** 実行者の努力では守れない。契約と環境の既定動作が衝突している。

## 0. 前提と禁止事項

作業は次の分岐で行う。

    cd /home/ubuntu/slocal2/m2
    git fetch origin
    git checkout -b feat/template-and-autosync origin/phase0
    source .venv/bin/activate

| # | 禁止 |
|---|---|
| 1 | 資格情報の値を出力・記録する |
| 2 | 暗号化された設定を変更・再生成する |
| 3 | 常駐処理そのものを停止・削除する |
| 4 | `runindex/**` `context/auto/**` を手で編集する |
| 5 | `experiments/**` `transfer/**` `data/splits/**` を変更する |
| 6 | 学習・評価コードを変更する |
| 7 | 演算装置を使う |
| 8 | 未測定の値を書く。未測定は UNKNOWN |
| 9 | 統合する。自動統合を有効化する |

**禁止 9 について。** 常駐処理による統合が起きた場合、それは実行者の逸脱ではない。
**事実として記録し、報告すること。** 抑止できたかどうかは Phase B の成果である。

### 起票者からの申し送り

起票者の検査コマンドが検証対象を検証できていない誤りが 14 task 連続で発生している。
直近では、確認用の行を除外対象の状態にせよという指示と、その行から取り込めという
ゲートが両立しなかった。**前の契約で実行者が決めた仕様を、起票者が把握していなかった。**

実行環境の対話シェルは bash ではない。**変数の直後に記号が続く場合は波括弧で囲むこと。**
配列の添字による終了コードの取得は使えない。単語分割も起きない。

**本 SPEC の検査も同型の誤りを含みうる。** 次を守ること。

| # | 注意 |
|---|---|
| 1 | 一致件数が 0 のとき、別の探し方でも 0 になることを確かめる |
| 2 | 仕組みの挙動は実装を読んでから信じる |
| 3 | 記録を作る流れに表示用の切り詰めを混ぜない |
| 4 | 検査が空振りでないことを陽性対照で確かめる |

# Phase A — テンプレートの固有値

## Task 1: 固有の値を除く

**Files:** Modify 共有テンプレート

- [ ] **Step 1: 実態を測る**

テンプレートの中で、ホストによって異なるべき値を持つ行を探す。

    grep -n "SERVERNAME\|HOSTNAME\|SERVER_NAME" .env.example

**行番号と内容を記録する。値そのものが秘密でないことを確認したうえで記録する。**

- [ ] **Step 2: 同種の値が他に無いかを調べる**

**一つ見つけて終わりにしない。** テンプレート全体を読み、ホストによって異なるべき値が
他に無いかを確認する。

    sed -n '1,80p' .env.example

判定の基準は「**全台で同じ値であるべきか**」である。同じでよいものは残す。

- [ ] **Step 3: 除く**

該当行を削除するか、値を空にして注釈を付ける。**どちらを選んだかと理由を記録する。**

注釈には、その値をどこで設定すべきかを書く。論理名は各ホストの起動時設定で注入される。

- [ ] **Step 4: G1 ゲート — 写しても誤らないことを確認する**

**陽性対照と陰性対照を並べる。**

一時的な場所へテンプレートを写し、そこから値を読み込んだときに固有の名前が
入らないことを確認する。修正前の版でも同じ手順を行い、**誤った名前が入ることを再確認する。**

修正前でも誤らないなら、この対照は無効である。停止して報告する。

**確認に使った一時的な場所を消す。** 作業領域に痕跡を残さない。

- [ ] **Step 5: 起票する**

同じ導線が他にもありうる。**共有される設定に固有の値を入れない**という規約が
明文化されていないなら、未解決事項として起票する。

採番は全ての遠隔分岐を走査して実在の最大を確認してから決める。
**引用符の有無に依存しない探し方をすること。**

- [ ] **Step 6: 記録する**

運用手順を述べている文書へ、**共有される設定に固有の値を入れない**ことを明記する。

# Phase B — 常駐処理との衝突

## Task 2: 契約の実行中に書き込ませない

**Files:** Modify 常駐処理の設定、または運用手順

- [ ] **Step 1: 実装を読む**

常駐処理がどの条件で統合を行うかを実装から確かめる。

    grep -n "merge\|branch\|exp/" ~/bin/m2-sync.sh 2>/dev/null || echo "対象が存在しない"

**対象の存在を先に確認する。** 無ければその旨を記録する。

**推測で条件を書かない。** 実装と食い違えば実装に従う。

- [ ] **Step 2: 抑止の手段を探す**

既存の実装に、抑止のための仕組みがあるかを調べる。環境変数による無効化、
特定のファイルの存在による停止、対象分岐の限定などが考えられる。

**無ければ作る。ただし常駐処理そのものは停止・削除しない。**

- [ ] **Step 3: 手段を選ぶ**

| 案 | 内容 |
|---|---|
| 目印のファイルを置く | 契約の実行中だけ置き、終わったら消す |
| 環境変数で無効化 | 常駐処理が読む場所に依存する |
| 対象分岐を限定 | 作業分岐を対象外にする |

**推奨は目印のファイルである。** 実行者が置き忘れても常駐処理は従来どおり動くだけで、
壊れない。ただし実装を読んで判断し、理由を記録する。

- [ ] **Step 4: G2 ゲート — 抑止されることを確認する**

**両方向で測る。**

抑止の手段を有効にした状態で、常駐処理が分岐へ書き込まないことを確認する。
無効にした状態では従来どおり書き込むことも確認する。

**確認のために常駐処理の周期を待てない場合は、同じ経路を手動で起動して測る。**
待てない旨と、代わりに何を測ったかを記録する。

`on_fail: ask` である。**抑止できない場合は停止せず、実測と代替案を提示して判断を仰ぐ。**

- [ ] **Step 5: 文書化する**

契約を実行する際の手順として、抑止の有効化と解除を明記する。
**解除を忘れると自動同期が止まったままになる**ため、その点も書く。
