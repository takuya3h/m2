# 誤りの形による壊れ方の違いを掃引して曲線として測る

**task_id:** T-2026-08-26-error-shape-selectivity  **kind:** analysis  **server:** philip

---

## 0. 最初に読むこと

**本契約の成果は、配布からおよそ 24 時間後の進捗報告会で使われる。**

実行に使ってよいのは **Phase A の開始から 14 時間まで**である。
**Phase A を始める前に時刻を記録し、各 Phase の入口で経過を確かめること。**

**本契約は GPU を使用しない。**

**本契約は他の四台と同時に走っている。** 生成物の再生成は禁じている（第 4 節）。

**判定を行わない。** 効果量と符号の個数を出すところまでが範囲である。
判定則は別のホストで走っている契約が確定させ、起票者が後から当てる。

## 1. 背景 — なぜこれを測るのか

術具存在の信号に人為的な誤りを与える介入実験で、次が観測されている。

**同じ誤り率でも、誤りの形によって壊れる場所が違う。**

- **孤立した反転**（一フレームだけ値が反転する）を与えると、**主に分節の指標が壊れる。**
- **持続する誤り**（連続する区間で値が誤り続ける）を与えると、**主に分類の指標が壊れる。**

正しさの割合を一点下げるあたりの分節の指標の損失で比べると、
孤立した反転は持続する誤りの数倍にあたる。
**学習側を正しいままにして評価側だけを汚すと、この差はさらに鋭くなる。**

### 1.1 なぜこれが重要か

**これは介入実験で直接示された因果的な主張である。**

一連の調査で得られた他の知見の多くは、既存の記録の再集計や、
代理モデルの上での比較である。**それらは本番の構造で消えた前例がある。**

一方この主張は、**信号に意図的な操作を加えて結果の変化を見る形**で得られている。
**操作の効果を直接測っているため、交絡の余地が小さい。**

**したがって、他の知見が判定則の変更や本番での再現で崩れたとしても、
この主張だけは残る可能性がある。**

### 1.2 しかし現状は一点でしか測っていない

観測されているのは、**特定の誤り率における一点**である。

**その一点で見えた比が、誤りの量を変えても、持続の長さを変えても保たれるのかは分かっていない。**

- 誤りが少なすぎれば、どちらの形でも何も壊れず、比は求まらない
- 誤りが多すぎれば、どちらの形でも全部壊れ、比は一に近づくはずである
- 持続の長さを一に近づければ、持続する誤りは孤立した反転と区別できなくなるはずである

**これらは予測であって、実測ではない。**

**一点の観測を「性質」として報告するのは危険である。**
同じ一連の調査の中で、単一の設定でだけ現れた現象を一般的な性質と誤って読んだ事例が複数ある。

**したがって本契約は、二つの軸に沿って掃引し、曲線として示すことを目的とする。**

## 2. 何を測るのか

### 2.1 二つの軸

**軸一 — 誤りの量。** 少ない側から多い側まで、複数の水準で測る。
水準の選び方は実装と既存の記録を読んで決めてよい。**選んだ理由を記録すること。**

**軸二 — 誤りの持続の長さ。** 孤立した反転から、長く続く誤りまで、複数の水準で測る。
**孤立した反転は、持続の長さが最短の場合として扱えるはずである。**
そう扱えるなら、二つの形は一つの軸の両端になる。**扱えるかどうかを確かめること。**

### 2.2 求めるもの

各点で、**分類の指標の損失と分節の指標の損失の双方**を求める。

そのうえで、**分類の指標を一点下げるあたりの分節の指標の損失**を求める。
これが選択性である。

**選択性が二つの軸に沿ってどう動くかを表にする。**

### 2.3 崩れる領域を探す

**本契約の価値は、選択性が成り立つ範囲を示すことにある。**

- どこまで誤りを減らすと、比が求まらなくなるか
- どこまで誤りを増やすと、比が一に近づくか
- 持続の長さがどこまで短くなると、二つの形が区別できなくなるか

**崩れる領域が見つかったら、それは失敗ではなく成果である。**
**全域で崩れなかった場合も、そのまま報告する。**

## 3. 手順

### Task 1 — 開始の記録

**Step 1.** 現在時刻を記録する。

**Step 2.** 作業ツリーの状態を確かめる。**汚れていれば退避してから進む。**
退避には本契約の識別子を含む名前を付けること。**退避したことを報告に残す。**
**戻すのは契約が終わり、元の分岐へ戻ってからである。本契約の中で戻さない。**

**Step 3.** 抑止の目印を置く。**報告を終えたら移動によって解除する。**

### Task 2 — Phase A 既存の介入実験の再現

**Step 1.** 既存の介入実験がどこにあるかを、**実測で確かめる。**
**在ると仮定してはならない。**

**Step 2.** **既に記録されている値を再現できるかを確かめる。**
再現しない場合、**そこで止めて報告する。**
再現しないものの上で掃引しても、得られた曲線がどこから来たのか分からない。

**Step 3.** 一致が零件だった場合は探し方を疑う。**異質な方法で二度確かめる。**
**先頭がドットのものを含めること。**

**判定 G1** — 既存の値が再現したか。

### Task 3 — Phase B 対照の設置

**Step 1.** **与えた誤りの量が、意図した水準になっていることを実測で確かめる。**

**これは省略できない。** 誤りを与える手続きが意図どおりに働いていなければ、
掃引の軸そのものが意味を失う。**設定した値と、実際に生じた誤りの量を突き合わせること。**

**誤りの量は集合の差で求めること。部分一致で数えてはならない。**
件数が合っていることは、入れ替わりが起きていないことを意味しない。

**Step 2.** 対照を両方向で設置する。

- **陰性対照** — 誤りを与えない場合。**分類も分節も損失は零のはずである。**
  零でなければ、誤りを与える手続き以外の何かが結果を動かしている。
- **陽性対照** — 誤りを極端に多く与えた場合。**分類も分節も大きく壊れるはずである。**
  壊れなければ、誤りが信号に届いていない。

**片方向だけでは、常に同じ値を返す壊れ方と区別できない。**

**Step 3.** 乱数を使う手続きは、**種を固定して二度走らせ、一致することを実測する。**
**種を変えれば結果が変わることも確かめる。** 両方向を測ること。

**判定 G2** — 対照が期待どおりに働いたか。

### Task 4 — Phase C 掃引

**Step 1.** 二つの軸の水準を決める。**決めた理由を記録する。**

**Step 2.** 格子の各点で測る。**各点で複数の種を使うこと。**
**種が一つでは、その点の値が偶然かどうか分からない。**

**Step 3.** 各点の入口で経過時間を確かめる。
**残り時間で格子が埋まらない見込みなら、水準を減らす。**
**減らす場合は、どの軸のどの水準を落としたかを記録すること。**
**格子を歪めないこと。** 片方の軸だけ細かく測ると、比較ができなくなる。

**Step 4.** 埋まらなかった点は**空欄のまま残す。推定で埋めない。**

**判定 G3** — 掃引が完了し、誤りの量が意図どおりだったか。

### Task 5 — Phase D 選択性の曲線化

**Step 1.** 各点の選択性を求め、**二つの軸に沿った表にする。**

**Step 2.** **種ごとの散らばりを併記する。** 平均だけでは、その点が安定かどうか分からない。

**Step 3.** **崩れる領域を特定する。**

- 比が求まらなくなる領域（分母が零に近づく領域）
- 比が一に近づく領域
- 二つの形が区別できなくなる領域

**分母が零に近い点では、比は大きく振れる。**
**振れているのか、本当に大きいのかを区別すること。**
区別できない場合は、区別できないと書く。

**Step 4.** **効果量と符号の個数を、判定とは別に記録する。**
判定は則に依存するが、これらは依存しない。**後から別の則を当てられるようにしておく。**

**Step 5.** **判定を行わない。** 有意・非有意の語を結論に使わない。

**判定 G4** — 表ができ、崩れる領域が特定されたか。

### Task 6 — Phase E 報告

**Step 1.** 報告会で使える形にする。読む側が最初に知りたいのは次である。

- 選択性は掃引の全域で保たれたか、保たれなかったか
- 保たれなかったなら、どの領域か
- 既存の一点の観測は、その全域の中でどこに位置するか

**Step 2.** 変更範囲の一覧を出す。

**Step 3.** 完了報告を**二つに分ける。**

- 事実の記録 — 判定、完了判定の表、次の契約で使う値、起票者の誤り、逸脱、想定外、送出。**目安は百五十行以内。**
- 証跡の記録 — 命令とその出力、対照の出力、変更範囲の一覧、台帳の応答。

**事実の記録から証跡の記録を行番号で指すこと。**

**Step 4.** PR を作る。**送り出しただけでは統合ではない。**
**分岐が規定の接頭辞で始まっていることを確かめる。**

**Step 5.** 抑止の目印を移動によって解除する。

## 4. 禁止

**以下は実行者の操作に対する禁止であり、自動同期の仕組みによる配布を含まない。**

1. 分割の定義を変えない。
2. 生の記録へ書き込まない。
3. 測っていない値を書かない。**測れなかったものは、測れなかったと書く。**
4. **投影と集約の再生成を行わない。**
   四台で別の契約が同時に走っており、これらは必ず衝突する。
   **全ての PR が統合された後、一台で一度だけ回す。**
5. **既存の結果の値を書き換えない。** 新しい成果物として書く。
6. **判定を行わない。**
7. **GPU を使用しない。** 本契約に GPU を要する処理は無い。
8. **格子を歪めない。** 片方の軸だけ細かく測らない。
9. **秘匿の値を出力しない。** 判定に要るのは長さと有無だけである。
   **判定するのは件数ではなく形である。**

## 5. 想定外への対処

- **道具が無い、権限が無い、対象が零件** — **そのまま採用しない。**
  何を、どの状態で、どの方法で見た結果かを確かめてから記録する。
- **禁止領域の検査が失敗する** — 本契約は新しい run を作らないため、失敗するなら別の原因である。
  **内訳を一件ずつ示すこと。** 開始前から在った未追跡が原因である可能性がある。
- **終了コードを件数と呼ばない。** 数えるなら数える命令を使う。
- **配列の添字の書式はシェルによって違う。** 過去に二契約続けて終了コードの検査が空振りしていた。
- **命令ごとに新しいシェルが起きる実装系がある。** 読み込みは同じ命令の中に入れる。
- **履歴を読む操作は頁送りを無効にすること。**
- **背景で走らせた処理の出力を、完了の前に読まないこと。** 過去に二契約続けて起きている。
- **読み込みの遅い仕組みに注意する。** 配列を保持する形式には、
  参照のたびに全体を展開し直すものがある。ループの中で繰り返し参照すると記憶が尽きる。
  過去に同型の事故が実測されている。**ループの前に実体化すること。**

## 6. 完了判定

**判定が通ったことは、その判定が働いていることを意味しない。**
各行に「空振りでないことの確認」を書く。**空欄にしない。「確認した」と書かない。**

| # | 判定 | 期待 | 空振りでないことの確認 |
|---|---|---|---|
| a | 既存の介入実験を再現した | 記録されている値と一致、または一致しない旨が記録されている | 入力を変えれば一致しなくなるはずである。変えても同じなら入力を読んでいない |
| b | 与えた誤りの量が意図どおり | 設定値と実測値が突き合わされている | 設定を変えれば実測値も変わるはずである |
| c | 誤りの量を集合の差で求めた | 差として得られている | 部分一致で数えた場合と値が異なるかを確かめる |
| d | 陰性対照が働いた | 誤りを与えなければ損失は零 | 零でなければ、別の要因が結果を動かしている |
| e | 陽性対照が働いた | 誤りを極端に増やせば大きく壊れる | 壊れなければ、誤りが信号に届いていない |
| f | 乱数の手続きが再現する | 同じ種で一致し、違う種で一致しない | 両方向を測る。片方だけでは区別できない |
| g | 二つの軸で掃引した | 格子の各点に結果がある | 埋まらなかった点は空欄で残っている |
| h | 各点で複数の種を使った | 種ごとの値が残っている | 種が一つの点があれば満たされない |
| i | 散らばりを併記した | 平均と散らばりの双方がある | 平均だけなら満たされない |
| j | 崩れる領域を特定した | 領域が示されている、または全域で崩れなかった旨がある | どちらも無ければ満たされない |
| k | 振れと大きさを区別した | 分母が零に近い点の扱いが記されている | 区別できない場合は、その旨が書かれている |
| l | 判定を行っていない | 有意・非有意の語が結論に現れない | 現れていれば範囲を越えている |
| m | 効果量と符号の個数を残した | 双方が表にある | 片方しか無ければ満たされない |
| n | 数値が実測へ遡れる | 出所が記録されている | 出所の無い数値があれば満たされない |
| o | 変更範囲の一覧を出した | 一覧がある | 検査が失敗する場合は内訳を一件ずつ示す |
| p | PR が存在する | 番号が記録されている | 送り出しただけの状態は満たさない |
| q | 報告が二つに分かれている | 事実の記録と証跡の記録が別にある | 一つしか無ければ満たされない |
| r | 締切に対する経過が記録されている | 各 Phase の入口の経過が残っている | 記録が空なら満たされない |

## 7. 起票者からの申し送り

**起票者は実行環境を持たない。** 以下は前提であって実測ではない。**違っていたら報告すること。**

1. **入口として挙げた実装は、名が変わっている可能性がある。** 実装を読んで決めてよい。
2. **孤立した反転と持続する誤りが、同じ仕組みの両端として扱えるかは未確認である。**
   別々の仕組みで実装されている場合、二つを一つの軸に載せられない。
   **その場合は、二つの形を別々に掃引し、扱えなかったことを記録すること。**
3. **持続の長さを変える手続きが実装されているかは未確認である。**
   無い場合、軸二の掃引はできない。**軸一だけで報告してよい。**
   **実装を新たに書き起こすかどうかは、残り時間を見て判断してよい。**
   書き起こした場合は、その旨と、正しく働くことの確認を記録すること。
4. **一つ抜き検証の各 fold は互いに独立ではない。**
   このため、fold にわたる散らばりから求めた判定は甘い方向へ偏る。
   **本契約が判定を行わないのはこのためである。**
5. **既存の一点の観測は、学習側も汚した場合と、評価側だけを汚した場合の二通りがある。**
   **どちらを掃引するかを決め、記録すること。** 双方を掃引できるならそれでよい。
   時間が足りなければ片方でよいが、**どちらを選んだかを明記すること。**

## 8. 報告

事実の記録と対の記録を埋めて記録すること。逸脱は必須である。逸脱が無い場合も、無かった旨を一件書く。

**起票者の誤りを見つけたら、遠慮なく記録すること。**
何が誤っていたか、指示どおり実行すると何が起きたかの二つを含めること。
**これは起票者を改善するための記録である。**
