## 1. 背景

### 1.1 先行する契約が測ったこと

先行する契約は、本番の時系列モデルで、正しい術具存在を与えた腕を測った。
**検証側の分割で、予測された術具存在を与えた腕に対し、分類と分節の双方で一貫した差が出た。**
改善側へ倒れた対は五つのうち五つであった。

### 1.2 しかしこれは比較できない二つを並べていた

**契約の背景に書かれていた「追加利得はほとんど無い」は、一つ抜き検証で得られた所見であった。**
**一方、先行する契約が測ったのは検証側の分割である。**

**この二つは比較できない。起票者の誤りである。**

さらに、**検証側の分割については、既存の記録に同じ水準の値が既にある。**
すなわち先行する契約の結果は、**検証側の分割で以前から見えていたことの再確認**である可能性が高い。

### 1.3 なぜ分割によって結果が変わるのか

**検証側の分割は、術具と工程の対応が異常にきれいであることが実測されている。**

手術ごとに、同じ工程で使う術具が違う。
たとえば、ある手術では止血に専用の器具を使うが、別の手術では汎用の鉗子を使う。
**検証側の分割にはこの揺れが少ない。**

**したがって、そこで測った上限は、未見の手術に対する上限ではない。**

### 1.4 本契約が切り分けること

**動画を一つずつ抜いて、抜いた動画で評価する。これを全動画について繰り返す。**

**これにより、結果が特定の分割の引きに依存していないかを確かめる。**

**縮めば** — 先行する契約の結果は分割に固有であり、既存の方針（検出器の強化に投資しない）は維持される。

**縮まなければ** — 既存の方針を覆す根拠になる。**これは重い結論である。**

**どちらであっても、そのまま報告する。**

## 2. 決定的に重要な検査 — 評価側が学習側に漏れていないこと

**一つ抜き検証で最も起きやすい事故は、評価に使う動画が学習側にも入っていることである。**

**漏れていれば、すべての結果が無意味になる。**
**しかも、結果は良く見える方向へ壊れる。**気づきにくい。

**したがって、すべての分け方について、評価側の動画が学習側に含まれていないことを実測すること。**

**さらに、この検査そのものが働いていることを確かめること。**

- **陽性対照** — **意図的に漏らした分け方を一つ作り、検査がそれを検出することを確かめる。**
  検出しなければ、検査は空振りしている。
- **陰性対照** — 正しく分けた場合、検査は何も検出しないはずである。

**陽性対照に使った漏れた分け方は、成果として記録してはならない。**
**検査のための一時的なものであり、証跡を残さないこと。**

**漏れが実際に見つかった場合は、直ちに止めて報告する。**

## 3. 何を測るのか

### 3.1 腕

**二つの腕を対にする。**

- 正しい術具存在を与えた腕
- 予測された術具存在を与えた腕

**正しい術具存在を与えた腕は、上限の測定専用である。手法の成果として報告してはならない。**
**先行する契約と同じ印を記録に残すこと。**

### 3.2 主終点

**主終点は正しさの割合とする。**

理由は、比較したい既存の所見が正しさの割合で述べられているためである。
**指標を揃えなければ、縮んだかどうかを言えない。**

**それ以外の指標も記録する。** 分類の指標、分節の指標の双方を残すこと。

### 3.3 出すもの

- 効果量
- **分け方のうち、改善側へ倒れた個数**
- **先行する契約が検証側の分割で得た値との並び**

**判定を行わない。** 判定則は別のホストで走っている契約が確定させ、起票者が後から当てる。

## 4. 手順

### Task 1 — 開始の記録

**Step 1.** 現在時刻を記録し、**先行する契約の締切までの残りを計算する。**

**Step 2.** 作業ツリーの状態を確かめる。**汚れていれば退避してから進む。**
**退避には本契約の識別子を含む名前を付けること。** 退避したことを報告に残す。
**戻すのは契約が終わり、元の分岐へ戻ってからである。本契約の中で戻さない。**

**Step 3.** 抑止の目印を置く。**報告を終えたら移動によって解除する。**

### Task 2 — Phase A 経路の確認（GPU 不要）

**先行する契約は、代理側にしか無い仕組みを本番側にも在ると仮定して止まった。**
**同じ型を繰り返さないこと。**

**Step 1.** 一つ抜き検証を回す経路が本番側に在るかを、**実測で確かめる。**
**在ると仮定してはならない。**

**Step 2.** 一致が零件だった場合は探し方を疑う。**異質な方法で二度以上確かめる。**
**先頭がドットのものを含めること。**

**Step 3.** 経路が無い場合、**軽い配線で足りるかを判断する。**

**配線してよいもの**

- 分け方を外から与える経路
- 学習側と評価側の動画の集合を指定する経路
- 上限測定専用の印の書き出し

**配線してはならないもの**

- 学習の数式、損失、最適化
- 既存の分割の定義そのもの

**Step 4.** **既存の分割ファイルを書き換えてはならない。**
一つ抜き検証は別の枠組みとして扱う。**既存の分割は読むだけである。**

**Step 5.** 大きな実装が要ると判断した場合は、**止めて報告する。**
**何が足りないか、どれだけ要りそうかを記録すること。**

**判定 G1** — 経路が在るか、軽い配線で足りるか。

### Task 3 — Phase B 一つの分け方での疎通

**Step 1.** 一つの分け方で、両方の腕を走らせる。

**Step 2.** **評価側の動画が学習側に含まれていないことを実測する。**（第 2 節）

**Step 3.** **漏れの検査そのものの陽性対照を行う。**
意図的に漏らした分け方で、検査が検出することを確かめる。
**この一時的な分け方の証跡を残さないこと。**

**Step 4.** 二つの腕で、**入力の信号が実際に違うことを確かめる。**
違わなければ、腕が分かれていない。

**Step 5.** 所要時間を実測し、**残り時間で入る分け方の数を計算する。**
計算の過程を記録すること。

**判定 G2** — 完走し、漏れが無く、検査が働いているか。**漏れがあれば直ちに止める。**

### Task 4 — Phase C 全ての分け方での対測定

**Step 1.** 残りの分け方について、対を走らせる。

**Step 2.** **対の両側は分け方ごとに隣接して交互に走らせること。**
実行の並びが対の揺らぎを大きく変えることが実測されている。**桁が変わる。**
**実際に走らせた順序を記録する。**

**Step 3.** 各分け方の入口で経過時間を確かめる。
残り時間で**その対の両側**が入らないなら、**その対を始めない。**
**片側だけの腕を作らない。**

**Step 4.** **すべての分け方で漏れの検査を行うこと。**（第 2 節）
一つでも漏れていれば、直ちに止めて報告する。

**判定 G3** — 対の両側がそろい、漏れが無いか。

### Task 5 — Phase D 報告

**Step 1.** 効果量と、**改善側へ倒れた分け方の個数**の双方を出す。

**Step 2.** **先行する契約が検証側の分割で得た値と並べて示す。**
**これが本契約の主たる成果である。**読む側が知りたいのは、縮んだかどうかである。

**Step 3.** **判定を行わない。** 有意・非有意の語を結論に使わない。

**Step 4.** 分け方ごとの内訳を出す。
**特定の動画が結果を支配していないかが分かる形にすること。**

**Step 5.** 工程ごとの内訳を出す場合は、**評価側に現れない工程の扱いを明記する。**
先行する契約の実測では、分母から外れる工程と、支持がありながら当たっていない工程があった。

**Step 6.** 変更範囲の一覧を出す。

**Step 7.** 完了報告を**二つに分ける。**

- 事実の記録 — 判定、完了判定の表、次の契約で使う値、起票者の誤り、逸脱、想定外、送出。**目安は百五十行以内。**
- 証跡の記録 — 命令とその出力、対照の出力、変更範囲の一覧、台帳の応答。

**事実の記録から証跡の記録を行番号で指すこと。**

**Step 8.** PR を作る。**送り出しただけでは統合ではない。**

**PR の base は、分岐の起点と同じ分岐にすること。**
先行する契約では、既定の分岐が base になり、起点と食い違った。
**起票者が明記していなかったための事故である。本契約では明記する。**

**分岐が規定の接頭辞で始まっていることも確かめる。**

**Step 9.** 抑止の目印を移動によって解除する。

## 6. 禁止

**以下は実行者の操作に対する禁止であり、自動同期の仕組みによる配布を含まない。**

1. **既存の分割の定義を変えない。書き換えない。読むだけである。**
2. 生の記録へ書き込まない。
3. 凍結源を変えない。
4. 測っていない値を書かない。**測れなかったものは、測れなかったと書く。**
5. **投影と集約の再生成を行わない。**
   四台で別の契約が同時に走っており、これらは必ず衝突する。
   **全ての PR が統合された後、一台で一度だけ回す。**
6. **学習の数式、損失、最適化に触れない。**
7. **決定化を無効にしない。**
8. 上限の腕を手法の成果として報告しない。
9. **漏れの検査の陽性対照に使った分け方の証跡を残さない。**
10. **判定を行わない。**
11. **秘匿の値を出力しない。** 判定に要るのは長さと有無だけである。
    **判定するのは件数ではなく形である。**

## 7. 想定外への対処

- **道具が無い、権限が無い、対象が零件** — **そのまま採用しない。**
  何を、どの状態で、どの方法で見た結果かを確かめてから記録する。
- **禁止領域の検査が失敗する** — 本契約は新しい run を作る。
  検査は run を作る契約を構造的に通せないことが実測されている。**失敗そのものは契約違反ではない。**
  **内訳を一件ずつ示し、本契約の成果物によるものかどうかを分けること。**
- **終了コードを件数と呼ばない。** 数えるなら数える命令を使う。
- **配列の添字の書式はシェルによって違う。**
  先行する契約でも、最初の終了コードの検査が空振りした。**同じ事故を繰り返さないこと。**
- **命令ごとに新しいシェルが起きる実装系がある。** 読み込みは同じ命令の中に入れる。
- **履歴を読む操作は頁送りを無効にすること。**
- **背景で走らせた処理の出力を、完了の前に読まないこと。**
- **検証の警告が母集団の件数の食い違いを報告することがある。**
  先行する契約でも起きた。ホスト依存の現象であり、**参照先の分母そのものが移動したかを確かめること。**

## 9. 起票者からの申し送り

**起票者は実行環境を持たない。** 以下は前提であって実測ではない。**違っていたら報告すること。**

1. **一つ抜き検証を回す経路が本番側に在るかは未確認である。**
   代理側には在ることが分かっている。**同じ型で先行する契約が止まっている。**
   **軽い配線で足りるなら行ってよい。大きな実装が要るなら止めること。**
2. **代理側の仕組みが読む入力は、本番の蓄えそのものである**と先行する契約が報告している。
   **これが本契約でも成り立つなら、配線は軽く済む可能性がある。確かめること。**
3. **計画した本数は、先行する契約が実測した所要時間から見積もったものである。**
   **本契約の入口で同じとは限らない。Phase B で実測すること。**
4. **先行する契約で、起票者が四件の誤りを記録された。**
   本契約でも同じ型がありうる。**遠慮なく記録すること。**
5. **本契約の結果が「縮まない」であった場合、それは既存の方針を覆す重い結論になる。**
   **だからといって結果を丸めてはならない。そのまま報告すること。**
6. **判定則は別のホストで走っている契約が確定させる。** 本契約は判定しない。

## 10. 報告

事実の記録と対の記録を埋めて記録すること。逸脱は必須である。逸脱が無い場合も、無かった旨を一件書く。

**起票者の誤りを見つけたら、遠慮なく記録すること。**
何が誤っていたか、指示どおり実行すると何が起きたかの二つを含めること。
**これは起票者を改善するための記録である。**
