# T-2026-08-29-k1-verify-policy-place — lecun での K1 現物確認と追跡外 run の棚卸し

kind: impl。**本契約では GPU を使用しない。** 実行ホストは **lecun**。

## 0. 目的

前契約 T-2026-08-29-k1-trace-policy-place は、K1 の数値がリポジトリ・philip の生ログ・外部実験記録の
いずれからも遡れないことを確定した。その後、起票者が記録側（実験の意思決定記録、2026-07-10 付）を
調べ、**出所が特定された**: K1 の三値は、lecun 上の六つの run
（transfer 系・relationdetr と aligndetr の各三 seed）の **3-seed 集計値**である。

- Δ_phase -0.0201 は aligndetr 側の平均 acc 0.8785 と分母 0.8986 の差
- hemostasis F1 の 0.801 と 0.179 は両側の **3-seed 平均**（0.8010 と 0.1788）
- 0.686 は aligndetr 作り直し版の検出性能 68.60
- 別に記録される -0.0691 は同じ実験の **paired 差の平均**であり、-0.0201 と矛盾しない

リポジトリから遡れなかった理由は、run 名が s4_phase_baseline 系ではなく **t1a_frozen_src 系**で、
かつ **lecun の run が索引に未収穫**だからと推定される。本契約は lecun でこの推定を現物確認し、
一致すれば K1 を実測扱いへ復帰させる。

**方針文書本文の配置は本契約から外した。** 起票者が本文を台帳へ運ぶ経路が今回使えないためであり、
実行者の作業ではない。配置は後日の別契約で行う。

## 4. Phase B — 照合と追記

### Task 1 記録値の再計算による照合

六 run の metrics から次を**再計算**し、§1 の表と突き合わせる。

- 両側の 3-seed 平均 acc とばらつき、分母 0.8986 との差
- 両側の hemostasis F1 の 3-seed 平均とばらつき
- seed 対応の paired 差（三つ）とその平均・ばらつき
- aligndetr の特徴の由来（config が指す特徴ファイルが作り直し版＝07-06 以降の生成物であること）

**分母 0.8986 は記録値である。** lecun 上に対応する run か記録があるなら実測で確かめ、
無ければ「分母は記録値のまま」と明記して差の照合は acc の側で行う。

結論は三値で書く:

- **一致（実測復帰）**: すべての量が許容差内。K1 は lecun の六 run の実測に遡ると確定
- **不一致**: どれかが許容差を超える。量ごとの乖離を表にする（解釈はしない）
- **run が無い・読めない**: 何がどこまで在ったかを記す

一部だけ一致して解釈が割れる場合は escalate。

**検算器の対照**: 陽性は既知の値（relationdetr 側の平均 acc）が再計算で一致すること。
陰性は一つの seed を除いた平均が**一致しなくなる**こと（集計が seed 数に感応している証拠）。

### Task 2 A7 と総括への追記

出所の種別を冒頭に明記して追記する（lecun 上の実測／記録側の記載／前契約の実測、を区別）。

- **A7 への追記**: 出所の連鎖を一表にする。
  リポジトリ内の初出（2026-08-02 の分析報告）← 記録側の意思決定記録（2026-07-10）←
  lecun の六 run（本契約の照合結果）。Task 1 の結論（三値）と再計算の数値を併記。
  一致の場合は「K1 は実測扱いへ復帰。ただし run は索引に未収穫」と記す
- **総括への追記**: K1 の行を更新する追記（前契約時点の「遡れない」が本契約で どう変わったか）

## 7. 想定外の扱い

| 事象 | 対処 |
|---|---|
| lecun の repo の位置・分岐・道具が記録と違う | 実測を優先し、何がどこにあったかを報告する。起動できない場合は利用者へその旨を伝えて中止 |
| 六 run の一部だけ実在 | 在るものだけで部分照合し、欠けを明記。結論は「不一致」ではなく「run が一部無い」 |
| metrics の指標名・形式が想定と違う | 実装と出力を読んで対応づけ、対応づけの根拠を audit に記す |
| 分母 0.8986 の実体が lecun に無い | 「分母は記録値のまま」と明記して照合を続ける |
| 台帳への報告送信が lecun からできない | 報告一式を分岐に残し、PR を作った上で、送信不能の旨を RESULT に記す |

失敗時の巻き戻し: 変更は分岐上のみ。停止する場合も分岐と audit を残したまま stopped で報告する。

## 8. 報告の構成

RESULT.md は起票者が判断に使う事実だけを書く。目安は百五十行以内。

- 判定: verdict と関門の結果
- 完了判定: §5 の表に実測値を埋めたもの
- **K1 の結論**: 三値のどれか。再計算値と記録値の対照表
- 実測: 次の契約で使う値（lecun の repo 位置と分岐・追跡外 run の件数・**GPU の型と枚数と空き状況**）
- 起票者の誤り: 型と内容。一件三行以内
- 逸脱・想定外・UNKNOWN・判断待ち（追跡外 run の収穫可否を含む）
- 送出: PR 番号と終了コードのみ

命令とその出力の全文・再計算の過程・対照の出力は audit.md へ置き、
RESULT.md からは行番号で指す。同じ内容を二度書かない。
