# Notion の旧頁の見出し抽出と旧データベースの保全 export

**task_id:** T-2026-08-31-notion-legacy-toc-and-export  **kind:** analysis

## 0. 位置づけ

Notion の記録系を再構成している。新しい正本（現在地・マスター・知見 DB・アーカイブ）を
2026-08-31 に作った。旧頁と旧データベースをアーカイブへ移す前に、二つを機械で取る。

- 旧マスター頁と現行版頁の**見出し構造だけ**。新マスターの章立ての参考にする。本文は人が読まない
- 凍結する旧データベース群の**全行**。Notion に残すだけでは検索も差分も取れないため repo へ写す

本契約は**読み取り専用**である。Notion へ一切書かない。GPU を使用しない。
起票者は実行環境を持たないため命令を書かない。実装を読んで決めてよい箇所は実行者が決める。

対象ホストは任意。条件は資格情報の読み込みが成立することだけである。repo の位置と
合言葉の場所は `context/env-facts.md` の該当行に従う。

## 3. 生成物と保存先

保存先は `docs/archive/notion/`（`outputs.destination`）。禁止領域の検査がこの場所を拒む場合は
**回避せず停止**して報告する。

| 生成物 | 内容 |
|---|---|
| `REPORT.md` | 対象、到達性、件数、対照の結果、秘匿と個人情報の検査、サイズ。数値はすべて実測 |
| `manifest.csv` | 対象一件一行。列: `key` `kind` `notion_id` `status` `n_items` `bytes` `sha256` `fetched_at` `note`。`status` は `exported` `unreachable` `stopped` のいずれか |
| `toc_plan_master.md` `toc_plan_current.md` | 見出し一件一行。字下げで入れ子の深さ、先頭に `H1` `H2` `H3` の別、続けて見出しの文、末尾に block id。子頁と子 DB は `PAGE` `DB` の別と題と id。**本文の段落を含めない** |
| `db/KEY/raw.jsonl` | query の応答の各 page オブジェクトをそのまま一行一件 |
| `db/KEY/properties.csv` | プロパティを平坦化した一行一件。複合値は JSON 文字列 |
| `db/KEY/bodies.jsonl` | 各行の本文ブロック（子を持つ容器は降りる）。本文を持たない行も一行として残し空を明示する |
| `export_notion.py` | 抽出と export に使った実装。引数で対象を受ける。新しいパッケージを入れない |
| `controls/` | 陽性対照と陰性対照のフィクスチャ（ローカル JSON） |

`KEY` は登録簿のキー名である。ファイル名に日本語を使わない。

## 5. 手順

### Task A 準備と到達性

- A-1 作業ツリーの汚れを確認する。開始前から在る未追跡は repo の外へ退避し、退避先と一覧を audit に残す
- A-2 `make task-start` で分岐と抑止を置く。分岐名が `feat/` で始まることを確かめる
- A-3 `spec.yaml` の `resolve-at-intake` と `counts` の零を実測値に差し替え、L1 と L2、`make spec-check` を通す。WARN は内容を audit に残して続ける
- A-4 資格情報を読み込む。変数の**有無と長さ**だけを記録する。成立しなければ停止して判断へ戻す
- A-5 既存実装を読む。対象は Notion の REST を呼ぶ既存コードの集合（`inputs.code.entrypoints` と、それを import する側）。API の版、頁送り、再試行の扱いを確かめて踏襲する
- A-6 各対象に最小の読み取り（DB の retrieve、頁の children の先頭一頁）を行い、到達性を `manifest.csv` の `status` に記録する

### Task B 見出し抽出

- B-1 `export_notion.py` に見出し抽出を実装する。子を持つブロックは降り、`child_page` `child_database` へは降りない。toggle 化された見出しも見出しとして拾う
- B-2 `controls/` に陽性フィクスチャ（各階層の見出し、toggle の内側の見出し、子頁を含む）と陰性フィクスチャ（段落と箇条書きだけ）を置き、抽出器が前者を全件、後者を零件返すことを確かめる
- B-3 実対象二頁に対して走らせる。頁の大きさを二通りにして出力が一致することを確かめる

### Task C 旧データベースの export

- C-1 到達できた各 DB の全行を頁送りで取り、`raw.jsonl` `properties.csv` `bodies.jsonl` を書く。`unreachable` の DB はディレクトリを作らず manifest に理由を残す
- C-2 同じ export を二回走らせ、生成物の要約値が一致することを確かめる
- C-3 陰性対照として存在しない database id を与え、零件の成功ではなく失敗として記録されることを確かめる。陽性対照として `task_distribution` の DB に本契約の行が一件以上あることを確かめる（export はしない。件数だけ）

### Task D 対照と検査

- D-1 秘匿の形を数える。判定に要るのは形の有無と長さだけで、検査が値を出力してはならない。危険な形は Notion の token の接頭辞、鍵の書き出し、長い符号化文字列。変数名や指紋は単独では危険でない
- D-2 個人情報の形（電子メールの形）を export と抽出物で数える。零でなければ commit せず停止して判断へ戻す
- D-3 生成物の合計バイト数を測る。閾値を超えたら commit せず停止して判断へ戻す（閾値は §7）
- D-4 `make forbidden-check` を回し結果を記録する。開始前から在る未追跡による fail は `environment` として記録する
- D-5 各対象の `last_edited_time` を Task A の時点と Task D の時点で照合し、変わっていないことを記録する

### Task E 報告と送出

- E-1 `REPORT.md` を保存先に、`RESULT.md` `audit.md` `result.yaml` を契約ディレクトリに書く（構成は §8）
- E-2 `tasks/inbox.d/T-2026-08-31-notion-legacy-toc-and-export.md` に判断を一行以上書く
- E-3 commit と push を行い、PR を存在させる。作成の方法は実行者が決める。番号を RESULT に書く
- E-4 `make task-report` で台帳へ送る。秘匿の検査で止まったら本文を直して送り直す
- E-5 抑止を**移動**で解除し、退避した未追跡を元へ戻す

## 7. 想定外と停止条件

| 事象 | 扱い |
|---|---|
| 資格情報の読み込みが成立しない | 停止。`governance.decisions_required` の三つ目 |
| 対象の過半が `unreachable` | 到達できた分は続け、`escalate_if` に該当として RESULT に書く。共有設定は利用者の操作領域 |
| 生成物の合計が **五十メガバイト**を超える | commit せず停止。`decisions_required` の一つ目 |
| 個人情報の形が非零 | commit せず停止。`decisions_required` の二つ目 |
| 二回の export で要約値が一致しない | 差分の場所を audit に残し `escalate_if` に該当として書く。`last_edited_time` の変化があれば原因として記録 |
| 頁送りの二通りで一致しない | 同上 |
| 実行基盤に操作を拒まれる | 回避せず利用者へ提示して許諾を得る |

## 8. 報告の構成

`RESULT.md` は起票者が判断に使う事実だけを書き、目安 150 行以内。証跡は `audit.md` へ。
同じ内容を二度書かず、`RESULT.md` から `audit.md` を行番号で指す。

| 節 | 入れるもの | 入れないもの |
|---|---|---|
| 判定 | verdict と各 Phase の結果 | 手続きの全文 |
| 完了判定 | §6 の表に実測値を足したもの | 命令の全文 |
| 実測 | 到達性、件数、バイト数、要約値、退役の候補（登録簿との差） | 経過の説明 |
| 起票者の誤り | 型と内容。一件三行以内 | 引用の全文 |
| 逸脱 | 何をなぜ | 手順の再掲 |
| 想定外と UNKNOWN | 測れなかったものと理由 | ログ |
| 送出 | PR 番号、`make task-report` の終了コード | 出力の全文 |

`audit.md` には命令とその出力、退避の一覧、対照の出力、秘匿と個人情報の検査の出力（値は含めない）、
`forbidden-check` の出力、台帳の応答を残す。

`result.yaml` は様式の版 3 に従い、`positive_controls` `issuer_defects` `deviations` を空にしない。
起票者の誤りが無かった場合はその旨を書く。
