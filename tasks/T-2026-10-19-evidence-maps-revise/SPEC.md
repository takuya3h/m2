# 証拠地図 C・B・N の書誌を照合結果で改めた版をパッチで置き、様式の検査と照合をやり直す

**task_id:** T-2026-10-19-evidence-maps-revise  **kind:** impl

**本契約では GPU を使用しない。**

## 背景

前の契約 T-2026-10-18-evidence-verify-place（pass、PR #231 は統合済み）が、証拠地図 C v2（D→P）・B v2（P→D）・N v1（新規性の照合）を docs/evidence/ に置き、書誌 ID を照合した（docs/evidence/verification/）。不在は 0 件だったが、書誌に差・欠けがあり、照合不能も出た。利用者は「地図を直してから提案カードの生成会話に渡す」と決めた（2026-10-19）。

起票者が照合の結果を読み、三つの地図の**書誌の欄だけ**を改めた（版は C v2.1・B v2.1・N v1.1。行の中身・数値は変えていない）。改めた中身はパッチ一件（62122 バイト）にまとめた。台帳の添付には入れず、利用者が実行ホストの受け渡しの置き場に置く（下の「環境の罠」の三）。

本契約は三つを行う。

1. **当てる。** パッチを当て、改訂後の三つの地図の要約値が下の表と一致することを確かめる
2. **検査する。** 様式の検査と照合を三つの地図にやり直し、結果を docs/evidence/verification/ に上書きする（改訂前の結果は git の履歴に残る）
3. **並べる。** 照合の分類の件数を、起票者が本書に事前に書いた予測と並べる。**予測と違っても地図は直さない**

## 改めた中身（起票者が行ったこと。実行者は手を加えない）

- 地図 C: C-05 の掲載先に照合の値（arXiv の comment は CVPR 2022）を併記／C-06 に著者／C-16 に題名／C-17 に TPAMI の DOI（arXiv の doi 欄の値）と掲載先の照合の値／C-21 の題名を arXiv の現行版に（R1 の題名は括弧に残した）／C-12 の出所の欄から別の論文の ID を外した（地図 N に書誌の行がある）
- 地図 B: B-02・B-03・B-06・B-10 の題名の欄を略称から照合の値の題名に（略称は括弧に残した）／B-02 の書誌 ID の欄から N1 の別の ID を外した（別の文献と分かったため。地図 N §8）／B-22 に著者／B-18 に起票者が web 検索で特定した arXiv ID／§5 の最後の列に行ごとの照合の結果
- 地図 N: N-01 の著者を照合の値の 6 名に／N-10 の題名を IEEE Access 版に、arXiv 版を別の行（N-46）に分けた／N-15 に起票者が Crossref の書誌検索で特定した DOI／N-18 に題名・著者／§2 の末尾に、照合表の外（§3〜§5・§8）で ID だけが書かれていた文献の書誌の表（N-30〜N-46）を足した／§8 の 1610.08844 の記述を直し、他の行の扱いを「照合済み」に
- 三つとも、見出しの前の「版」「状態」と §0.2 の規則（「照合〔2026-10-19〕の値」の意味）を足した

**照合の値を写した欄（N-30〜N-46 など）を照合し直しても、写し誤りの検査にしかならない。** 各 ID の論文が地図の文脈と対応することは、起票者が照合先の題名と突き合わせて確かめた。

## 環境の罠（実行者が知り得ないこと）

1. **bengio の .git/info/exclude に 3 行が足してある。** andrew で走っている契約（stage2_pilot_folda）と完了済みの frame_signal_audit の出力が Syncthing で experiments/ に届き、未追跡として task-start を止めたため、利用者の判断で足した（前の契約の RESULT §2、F 2026-10-19）。**その 3 行を消さない。experiments/ の未追跡を移さない・消さない**（同期で他の台からも消えうる）。ほかの未追跡が現れたら手順書の「汚れの扱い」に従う
2. **作業ツリーが清浄になると、常駐の同期がそのとき居た分岐へ phase0 を早送りで取り込み push することがある**（前の契約で一度観測した）。task-start が抑止の目印を置いた後は止まる。目印が置かれる前の動きは記録だけする
3. **パッチは台帳の添付に入っていない。** 起票者の環境は Notion の API に直接届かず、添付は本文をそのまま送る方法に限られ、6 万バイトの差分を送り直すと写し誤りが入りうるため、利用者が `~/slocal2/m2-incoming/T-2026-10-19-evidence-maps-revise/` に置く。当てる前に起点の地図の要約値（上の表の改訂前）を確かめる。当てる手段は実装を読んで決めてよい。記録のためにパッチの写しを tasks/T-2026-10-19-evidence-maps-revise/ にも置く

## Task

各 Task の手段は実装を読んで決めてよい。決めた手段と理由は audit.md に残す。

### Task A — 起点を確かめる（Phase A）

- A-1. 分岐が `feat/` で始まり、起点が origin/phase0 であることを記録する。起点の commit を記録する
- A-2. 三つの地図の要約値が上の表の改訂前の値と一致することを確かめる。**一つでも違えば停止する**（G1）
- A-3. パッチを `~/slocal2/m2-incoming/T-2026-10-19-evidence-maps-revise/` から読み、要約値とバイト数が上の値と一致することを確かめる。置き場が repo の作業ツリーの外にあることも確かめる。**違えば停止する**（G1）。置かれていなければ利用者に伝えて待つ。一致したら写しを tasks/T-2026-10-19-evidence-maps-revise/ に置き、写しの要約値も確かめる
- A-4. 変えないファイル（上の表の四件と reports/ の五件）の要約値を測って記録する
- A-5. 照合先（Crossref、DOI の解決、DataCite、arXiv の API）へ到達できるかを確かめる。**どれにも届かなければ停止する**（G1）
- A-6. 改訂前の照合結果（docs/evidence/verification/ の三件の機械が読める形）から、地図ごとに抽出された ID の集合と分類の件数を記録する（Task C の比較の基準）

### Task B — 当てる（Phase B）

- B-1. パッチを当てる前に、当たるかを確かめる。当たらなければ停止する（G2）
- B-2. パッチを当て、三つの地図の要約値とバイト数が上の表の改訂後の値と一致することを、当てた後のファイルから計算して確かめる。**一つでも違えば停止する**（G2）
- B-3. 作業ツリーの変更が三つの地図だけであることを、git の変更の一覧（集合）で示す。行の増減を上の集計と並べる

### Task C — 検査と照合（Phase C）

- C-1. 様式の検査を三つの地図にかける。違反があっても**地図を直さない**。内容を記録して停止し、利用者に諮る（G3）
- C-2. 照合器で三つの地図を一つずつ照合し、結果を docs/evidence/verification/ に保存する（同じ名前の改訂前の結果は上書きされる）
- C-3. 抽出された ID の集合を、A-6 の改訂前の集合と**集合の差で**比べ、上の「抽出される ID の集合の変化」の表と一致するかを示す。違えば一件ずつ理由を書き、利用者に諮る（G3）
- C-4. 地図ごとの分類の件数を、上の「分類の予測」と並べる。予測と違った ID は一件ずつ、照合器が比べた地図の行・題名と著者の判定の説明・照合先の値を書く。**予測に合わせて地図や照合器を直さない**
- C-5. 次の点は必ず報告する
  - 新しく書いた三件の ID（C-17 の DOI、B-18 の arXiv ID、N-15 の DOI）の分類と、照合先が返した題名・著者・掲載先
  - 地図 N の N-30〜N-46 に書いた ID が、照合器の結果でどの行と比べられたか（その表の行か、別の行か）
  - 書誌 ID の無い行の一覧

## 想定外のときの扱い

- 起点の地図の要約値が表と違う、受け渡しのパッチの要約値が違う → 停止して利用者に諮る（G1）
- 照合先のどれにも届かない → 停止して利用者に諮る（G1）
- パッチが当たらない、当てた後の要約値が違う → 停止して利用者に諮る（G2）
- 様式の検査で違反が出る、抽出した ID の集合が表と違う → 記録して利用者に諮る（G3）。地図も照合器も直さない
- 照合で「書誌に差」「不在」が出る → 件数に関わらず止めずに記録する。地図は直さない
- 作業ツリーを別の契約が使っている形跡（抑止の目印が別の契約の所有、他の分岐の未統合の変更。T-2026-10-19-conventions-and-defect-records が実行中など）→ 停止して利用者に諮る
- 実行基盤が操作を拒む → 回避せず利用者に提示して許諾を得る
