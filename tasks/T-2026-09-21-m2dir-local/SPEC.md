# 常駐処理が三種目の repo の位置を見つけられるようにする

**task_id:** `T-2026-09-21-m2dir-local`  **kind:** `impl`
**depends_on:** `T-2026-09-20-dlsta-syncthing-join`
**実行ホスト:** `dlsta`  **repo:** **`~/local/m2`**

## Goal

**dlsta は群れに入ったが、常駐処理が repo を見つけられない。**

前契約の実測：

    keeper.sh:28 と m2-sync.sh:10 は M2DIR を
    ~/slocal2/m2 か ~/slocal/m2 にしか解決しない

**本ホストは `~/local/m2` である。** よって**除外規則の自動反映も、分岐の自動同期も働かない。**
同期処理は動いている（中継と同期処理の起動は常駐処理の別の分岐が担う）が、**版管理の側が止まっている。**

**本契約は正本の解決候補に `~/local/m2` を足す。**

### 最大の危険 — 順序

**候補は上から順に試され、最初に見つかったものが使われるはずである。**

| 足す位置 | 帰結 |
|---|---|
| **末尾** | 既存の台は既存の候補で止まる。**本ホストだけが新しい候補に届く** |
| 先頭 | **他の台に `~/local/m2` が在れば、そちらを掴む。** 別の repo で自動同期が走る |

**末尾に足す。** ただし**実装を読んで、本当に「上から順に最初のもの」か確かめる。**

**他の台に `~/local/m2` が在るかは本ホストから測れない**（禁止 2）。
**在っても既存の候補が先に当たれば無害である。** 末尾に足す理由はそこにある。

### 常駐処理は自己更新されない

**`keeper.sh` を変えても、各台の `~/bin/keeper.sh` は変わらない。** 手で配置する必要がある。

**ただし既存の台は既存の候補で動いている。変更は要らない。**
**配置が要るのは本ホストだけである。**

**`m2-sync.sh` は常駐処理が自己更新する。** ただし**常駐処理が repo を見つけられないと、
自己更新の元（版管理）にも届かない可能性がある。** 実装を読んで確かめる。

## 0. 前提と禁止事項

    cd ~/local/m2
    touch .sync-pause
    grep -c "sync-pause" ~/bin/m2-sync.sh
    git --no-pager status --porcelain | grep -c ''
    source .venv/bin/activate && source scripts/load_env.sh \
      && make task-start TASK=T-2026-09-21-m2dir-local

**それでも置く。** 効いたかどうかを記録する。

| 3 | 中継と同期処理を止める。同期処理の設定を変更する |

## 想定外が起きたときの扱い

| 事象 | 対応 |
|---|---|
| **最初のもので止まらない実装だった** | **停止して判断を仰ぐ。** 末尾に足しても安全とは限らない |
| **既存の候補が在るとき新しい候補を掴んだ** | **停止して報告。** 既存の台を壊す |
| 二つの正本で書き方が違う | **両方を同じ意味に揃える。** どう揃えたかを記録する |
| 常駐処理の起こし直しで中継が止まる見込み | **判断を仰ぐ** |
| 起こし直した後に中継か同期処理が止まった | **記録して報告。** 自分で戻そうとしない |
| 抑止が効かなかった | **記録する。** repo を見つけられていない証拠である |
| 模擬ができない | **`UNKNOWN` とする。** 推測で「無害」と書かない |
| 実行基盤が操作を拒んだ | **迂回しない。利用者へ提示して許諾を得る** |

**言い訳をしない。事実と、測れなかったことを書く。**
