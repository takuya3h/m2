## 1. 背景（前回の二つの欠陥）

**欠陥 A（最良の回を、評価と同じ val で選んでいた）。** 前回は 1 epoch ごとに val を測り、最も高い epoch の値を結果にした。

**欠陥 B（D1・D3 の空の腕が比べる相手になっていなかった）。** 空の腕は零の信号で学ぶ。零から始めた界面に零を入れると勾配が届かず、
D1・D3 の空の腕は塔単独と同じ値になった（前回の REPORT の構造上の注意）。そのため差には、信号の中身の効果と、
零でない値が入ることで界面が学べるようになった分とが混ざる。前回の D1-L1 は予測・交差適合版の予測・正解のどの腕でもほぼ同じ +0.009 だった。

## 3. 用語と腕

- **PD** は工程から検出（受け取り手は検出塔）、**DP** は検出から工程（受け取り手は工程塔）。型の名前（P1-W1 など）は前回の SPEC §3 と同じ
- **4 epoch 目の値**: 学習を 4 epoch 終えた時点の状態で val を測った値。途中で止めない。最良の回を選ばない。
  指標・クラス別・動画別のすべてをその状態で出す
- **入れ替えの腕**: 予測（交差適合なし）の腕と同じ信号の値を使い、フレームとの対応だけを壊した腕。
  - train の信号は train のフレームのあいだで、val の信号は val のフレームのあいだで、それぞれ一つの固定の並べ替え（seed 42）で入れ替える。
    test のフレームは使わない
  - 並べ替えは split 全体のフレームにわたって行う（動画の中だけで入れ替えない。動画単位の情報を残さないため）
  - 同じ方向の型では同じ並べ替えを使う。学習時と評価時の両方で入れ替えた信号を使う
  - 集合を入れる型（D3）は、フレームごとの集合を丸ごと別のフレームの集合と入れ替える
  - 型ごとの信号: P1-W1・P1-W2・P2L・P3・P2F は P0、D1-L1・D2 は D0、D1-L2 は D0-RT、D3-L1 は D0-INST-UQ から埋め込みを除いたもの、D3-L2 は D0-INST-UQ
- **空の腕**、**予測-noCF**、**正解**、**予測-CF**、**正解予測-CF** は前回の SPEC と同じ

## 5. 事前登録（測る前に固定する）

### 5.1 量

すべて seed 42 の 4 epoch 目の値。回し直した run がある腕は回し直した値を使い、前回の値は並べて記録する。

- **空の腕との差** Δ空(型, 腕) = 指標(型, 腕) − 指標(同じ型の空の腕)
- **入れ替えの腕との差** Δ入替(型, 腕) = 指標(型, 腕) − 指標(同じ型の入れ替えの腕)
- **前回の値** Δ前回(型, 腕) = 前回の REPORT の Δ（最良の回）
- P2F は学習が無いので、塔単独・入れ替え・予測・正解の 4 つの値を並べる
- 指標: PD は overall mAP、標的群 AP（併記）、陰性対照群 AP。DP は macro Jaccard、frame accuracy（併記）、クラス別 Jaccard
- 参考（費用なし）: DP の seed 123・456 の 4 epoch 目の値を `history.json` から並べる。読み方の規則には使わない

### 5.2 読み方の規則（記述だけ）

1. 型ごと・腕ごとに、4 epoch 目の値、Δ空、Δ入替、Δ前回、動画ごとの Δ空と Δ入替を表にする
2. seed が一つなので、「seed の幅を超える」「幅の内」の判定はしない。差は 1 本ずつの差として書く。陽性・陰性・有意などの語は使わない
3. **予測-noCF の Δ入替を「その時刻の信号の中身による差」として読む。** 正解の腕の Δ入替も並べる
4. Δ空 と Δ入替 の符号が食い違えば、両方を書き、一つにまとめない。PD の overall mAP と標的群 AP、DP の Jaccard と accuracy の食い違いも同じ
5. Δ前回 と Δ空 の差を「選び方による差」として記録する（回し直した腕では、再現の差も含む）
6. DP のクラス別 Jaccard は、空の腕との差が最も大きい工程を型ごとに書く
7. 結果は関門の判定と設計の判断に使わない（§0）

### 5.3 予測（記述のための事前の記録。外れても本契約の判定は変わらない）

1. P1-W1 と P1-W2 の正解の腕の Δ空（標的群 AP）は、Δ前回 より小さい
2. D1-L1 の予測-noCF の Δ入替（Jaccard）は、Δ空 より小さい
3. P1-W1、P1-W2、P2L の正解の腕の Δ入替（標的群 AP）は正である
4. D1-L2、D3-L1、D3-L2 の予測-noCF で、空の腕との差が最も負のクラスは dressing である
5. P2F の入れ替えの値（標的群 AP）は、塔単独より低い

### 5.4 既知の限界（報告に必ず書く）

- 折りは 1 つ、val は 2 動画、seed は 1 つ。区間推定もクラスタの推論もできない。工程は動画 09 が塔単独で上限に近く、差はほぼ動画 10 で決まる
- 4 epoch 目の値にも epoch ごとの揺れは残る（選び方の偏りは除くが、揺れは除かない）
- 回し直した run は前回の run と完全には一致しない（GPU の計算の非決定性）
- 入れ替えの腕は、フレームとの対応を壊すと同時に、時間方向のつながりも壊す。差には両方が含まれる
- 前回の限界（受け取り手も train で学習済み、塔のホストの違い、工程注釈だけのフレームを使っていない、型ごとに学習率を探していない）はそのまま残る

## 8. 停止して諮る条件

- 装置に本契約以外の compute プロセスがある（Task A-3）
- 前回の信号か run の記録が andrew に無い、または要約値が前回の記録と食い違う（Task B-1、B-2。`history.json` が無い DP の run は回し直しの表に入っているので停止しない）
- 塔単独の再現の差が 0.005 を超える（Task B-3）
- 既存スクリプトの既定の挙動を変えないと実装できない
- 入れ替えの腕の定義（§3）が型の構造と合わず、意味を変えないと実装できない
- 記憶領域が足りない
- 発散・非数が出た腕は、その腕を止めて記録し、諮る。ほかの腕は続けてよい
- 実行基盤が書き込み・移動・削除を拒む（回避せず、利用者に提示して許諾を得る）

停止のときも、それまでの実測を `RESULT.md` と `audit.md` に書き、PR と `make task-report` まで行う。

## 9. 報告の構成

**`RESULT.md` は起票者が判断に使う事実だけ。150 行以内。** 命令と出力は `audit.md` に置き、`RESULT.md` から行番号で指す。

| 節 | 内容 |
|---|---|
| 判定 | status と G1〜G3 の結果 |
| 完了判定 | §7 の表に実測値 |
| 実測 | 塔単独の再現値、入れ替えの記録（対応が変わった割合、同じ動画から来た割合）、型ごと・腕ごとの 4 epoch 目の Δ空・Δ入替・Δ前回、回し直しの再現の差、1 本の所要時間 |
| 起票者の誤り | 型と内容。一件 3 行以内 |
| 逸脱 | 何をなぜ |
| 想定外・UNKNOWN | 測れなかったものと理由 |
| 送出 | PR 番号、`make task-report` の終了コード |

`REPORT.md`（`experiments/analysis/stage2_pilot_fix/`）には、型ごと・腕ごとの全値、動画ごとの値、DP のクラス別 Jaccard、
前回の値との並べ、§5.2 の読み方による記述、§5.3 の予測との照合、§5.4 の限界を置く。冒頭に「非公式の測定。関門と設計の判断に使わない」と書く。
