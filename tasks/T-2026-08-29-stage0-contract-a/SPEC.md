## 3. Phase A — 前提の実測と退避の処分

### Step A-0 承認済みの退避の処分

- 退避の一覧を記録してから、二件を drop する。drop の前後の一覧を audit へ残す
- 前契約が照合済み（禁止領域配下の全件が追跡下と一致、復帰すべきものは復帰済み）であることが
  drop の根拠である。**照合の記録は前契約の audit にある。本契約で再照合は不要**

### Step A-1 事前記入値の照合

spec.yaml の `created_from` と `conventions_rev` は起票者が前契約の報告から短縮形で事前記入した。
現物と照合し、一致すればそのまま、違っていれば実測値で置換して L1 と L2 を通す。
**報告や成果物に要約値・識別子を書くときは、判定に要る精度を超える桁を書かない。**

### Step A-2 入力データの所在の実測

各項目が要する入力の所在を測り、**項目ごとに {実施可能／不可能（理由）} を確定する。**
これが G1 の内容である。少なくとも次を確かめる。

- 15 動画の工程・術具・HTS のアノテーションファイルの所在と形式
- 追加 6 動画のアノテーションと、それに術者・症例の属性情報が付いているか
- 既存信号（GAP・region-token・在否・幾何）の保存済み特徴の所在。**特徴の再抽出は行わない**
- 検出の予測出力（評価時の予測ファイル）の所在。**推論のやり直しは行わない**
- 索引と run ディレクトリ（K1 照合に使う metrics・config・台帳の記録）
- Cholec80 の実体（アノテーションだけでもよい）が philip にあるか。
  **無い場合、他ホストの実測は行わず「philip に無い」とだけ報告し、取得の可否は判断へ回す**
- 方針文書のリポジトリ内での所在（統合済みの README の導線が指す先が実在するか。
  無ければ「未配置」と報告する。**本契約では配置しない**）

**不可能な項目は測ったふりをせず、理由つき UNKNOWN として残す。** 全項目 UNKNOWN でも
契約は成立する（その場合の verdict は fail ではなく、所在の実測が成果になる）。

## 4. Phase B — 八項目の実測

各項目の出力は docs/stage0/ に置き、RESULT には要点の数値のみ、全表は成果物と audit に置く。

### A1 折りの材料

15 動画それぞれの工程分布（工程ごとのフレーム数または時間）、術具の出現数、
HTS アノテの有無を一表にする。**折りの設計そのものは行わない**（設計は方針側の作業）。

### A2 追加 6 動画と Phase 公式 test の動画 ID 重複

重複の有無と件数。ID の対応づけの方法（何と何を突き合わせたか）を audit に記す。

### A3 追加 6 動画と test 折りの術者・症例の重複

属性情報が存在する場合のみ実測する。無ければ「属性情報が存在しない」ことを実測として報告する
（これ自体が R4 の前提の判断材料になる）。

### A4 既存信号のクリップ ID 識別プローブ（記述統計）

保存済みの特徴に対し、クリップ ID を当てる線形プローブを学習して識別率を測る。
**GPU を使わない範囲の手法（線形分類器程度）に限る。**

- 偶然水準（クラス数の逆数）を併記する
- 分割は既存の分割ファイルを用い、**分割の再定義はしない**
- **この数値を「指紋である／ない」の判定に変換しない。** 識別率と偶然水準の対だけを報告する

### A5 H(tool|phase) の解析的上界

アノテーションから工程条件付きの術具分布を数え、情報量の上界を算出する。
計算式・対数の底・平滑化の扱いを成果物に明記する。**推定値と実測値を区別して書く。**

### A6 検出誤りの分解

保存済みの予測出力と正解から、誤りを分類誤り・局在誤り・見落としに分解し、割合を出す。
分解の基準（何をもって局在誤りとするか。しきい値）を成果物に明記する。
**基準は既存の評価実装にあるものを優先し、新しい基準を発明しない。**

### A7 K1 の出所照合（本契約の中心）

台帳の数値（§1）が、**metrics の空でない実在の run に遡れるか**を確定する。

- 数値の照合は**許容差を明示して**行う。丸め表示を実数として扱わない。
  一致判定に使った桁数と許容差を audit に記す
- 候補は少なくとも三系統を試す: 無効判定された 010-012 の aligndetr seed 群／
  2026-07-10 以降の作り直し版／それ以外の一致
- 各候補について、config が宣言する凍結条件と実体の ckpt の対応、metrics の有無、
  AlignDETR の検出性能 0.686 に対応する値の所在を記す
- **結論は三値のいずれかで書く**: 数値は無効 run 由来／作り直し版由来／実在の run に遡れない。
  複数系統が同じ数値を持ち結論が割れる場合は escalate する
- 照合器の対照: **台帳の数値の最終桁を一つ変えた入力では一致が消えること（陰性）と、
  索引に確実に存在する既知の数値では一致が出ること（陽性）を示す**

### A8 Cholec80 の実体確認と L0 代理（データがある場合のみ）

- 実体確認: アノテーション（工程・術具在否）の有無、動画数、形式
- ある場合のみ: 術具在否ベクトルから工程を当てる線形分類（全通し／選別／逆選別の三条件）を
  CPU で行う。選別の定義は方針文書の該当節から引く。**暫定の記述統計であり、
  runindex に載せない。判定に使わない**
- 無い場合: 実体確認の結果だけを報告し、取得の可否を判断へ回す（escalate ではなく判断待ち）

## 6. 禁止事項

1. experiments 配下・data 配下・runindex 配下への書き込み（読み取りは可）
2. 分割の再定義。既存の分割ファイルだけを使う
3. 外部データの取得・外部サービスへの問い合わせ（Cholec80 を含む。無ければ無いと報告する）
4. GPU の使用。特徴の再抽出・推論のやり直し
5. 数値の推定を実測として書くこと。測れないものは UNKNOWN
6. 本契約の数値を合否・採否の判定へ変換すること
7. 過去の報告・完了済み契約・履歴の書き換え
8. 秘匿情報の出力・複製・移動

**禁止は実行者の操作に対するものであり、同期処理による配布や衝突ファイルの生成を含まない。**

## 7. 想定外の扱い

| 事象 | 対処 |
|---|---|
| 入力データが SPEC の想定と違う場所・形式にある | 実測を優先し、どこに何があったかを報告する |
| 特徴・予測出力が存在しない | 該当項目を理由つき UNKNOWN とする。**再抽出で埋め合わせない** |
| K1 の照合で複数系統が同じ数値を持つ | 全系統を列挙して escalate |
| Cholec80 が無い | 実体確認の結果だけを報告し、取得可否を判断待ちへ |
| アノテーションに欠損・矛盾がある | 件数と内容を報告し、補完せずそのまま集計から除いた旨を明記 |
| 処理が長時間かかり終わらない項目がある | 途中までの範囲を明示して部分結果とし、残りを UNKNOWN とする |

失敗時の巻き戻し: 変更は分岐上のみ。停止する場合も分岐と audit を残したまま stopped で報告する。

## 8. 報告の構成

RESULT.md は起票者が判断に使う事実だけを書く。目安は百五十行以内。

- 判定: verdict と関門の結果
- 完了判定: §5 の表に実測値を埋めたもの
- 項目別の要点: 八項目それぞれ三行以内（数値の要点と成果物の経路。全表は成果物へ）
- **A7 の結論**: 三値のどれか・根拠 run・K1 を実測扱いにできるかの判断材料
- 実測: 次の契約で使う値
- 起票者の誤り: 型と内容。一件三行以内
- 逸脱・想定外・UNKNOWN・判断待ち
- 送出: PR 番号と終了コードのみ

命令とその出力の全文・照合の過程・対照の出力は audit.md へ置き、
RESULT.md からは行番号で指す。同じ内容を二度書かない。
