## 1. 問い（yes/no で答えが出る一文）

EgoSurgery の無ラベル動画（折りの train 動画と 17〜21。ラベルは使わない）で、視線でマスクを選ぶ映像 MAE（A-01 の GGMAE 型）を ViT-S のスクラッチから学び、その重みを折りの train 動画の工程ラベルで全体 fine-tune して候補 0 の時間ヘッドを載せた工程塔は、比較の相手（P\*-15-COCO）より val J（5 折り平均）が +3.0 以上高いか。

## 3. 先行研究がやらなかった／効かなかった理由の推定

- A-01 は分割 1 つ・seed 1 回で、折りごとの再事前学習は行っていない（推測: 800 epoch × 5 折りの計算量と、データセット論文としての目的のため）。
- A-01 は推論の規約（クリップの中で予測する時刻の位置）を書いていない（地図 §3）。過去のみのクリップで測ったものは地図に無い（§10.2、§10.5）。
- ImageNet や Kinetics で初期化した対照が無い（A3c）。A-38 では Kinetics 初期化が SurgMAE を上回っており、スクラッチの比較だけでは一般の初期化に勝つかが分からない。
- 大規模化の方向（A-02）へ研究が移り、少数動画での対象データ上の SSL を詰める研究は増えていない（推測）。

**三版の改訂（2026-10-23。利用者の決定 J1）。** 判定は点推定でなく区間で書く。5 折りの対応差（腕2 − 腕1。各折りは seed 2 本の平均）の平均 d̄ と標準誤差 SE から、区間 d̄ ± t(4, 0.975) × SE を作る。区間の下端が 0 を超えたら採る。区間の上端が下の閾値（元の #7 の値）未満なら捨てる。それ以外は保留。frame accuracy の同方向要件（val の 5 折り平均の差 ≥ 0）はそのまま。test は使わない。元の #7 の閾値は「捨てる」側の境として残す。

## 9. 最安の殺し実験

**三版の改訂（2026-10-23。利用者の決定 J3）。** 殺し実験の判定は「凍結＋線形層」でなく「凍結した backbone の特徴の上に候補 0 で確定する時間ヘッドを載せた val macro Jaccard（1 折り、1 seed）」で行う。理由: backbone 単体のフレーム単位の順位は時間ヘッドを載せた J の順位を予測しない実測（F 2026-09-26）。費用は特徴の取り出し約 8 分と時間ヘッド約 10 秒で、線形層と同じ桁。殺し実験はクリップ入力の案でも 1 フレーム入力で行う（利用者の決定 (6)）。 殺し実験は 1 フレーム入力（T=1 に複製）で行い、主判定のクリップ入力とは分ける。

一折りだけ。事前学習は短い予算（#14 の最小: epoch 400 の半分以下、推測で GPU 一日以内）で、(a) 視線 MAE、(b) random 0.90 の MAE を同じ予算で学ぶ。(c) 公開の ImageNet-1K ResNet-50 を凍結。三つとも backbone を凍結し、フレーム単位の線形層だけを工程ラベルで学び、val J を見る（時間ヘッドなし）。(a) が (b) と (c) の両方を下回れば案を殺す。(a) が (c) を下回り (b) を上回れば、全体 fine-tune に進む前に #14 の予算を見直す。候補 0 で保存される backbone の特徴は使わない（依頼文 §4）。

## 14. 初回にセットで試す設定の掃引集合と固定の理由

**三版の改訂（2026-10-23）。** (a) 初期化を掃引の軸に足す: {スクラッチ, Kinetics-400 の VideoMAE ViT-S からの継続}（A-38 Table 7 の否定例 Kinetics 初期化 92.85 ＞ SurgMAE 87.78 に答える腕。計 96 点）。(b) 17〜21 に視線はある（利用者 2026-10-23）ので、データ範囲の掃引は視線マスクの腕でも定義できる。(c) 無ラベル段に val 2 本は入れない（前提 (4)）。(d) fine-tune の処方は比較の相手（候補 0）に揃える。A-01 の fine-tune の設定（batch 64、再サンプリング、lr 5e-4→5e-5）には揃えない。理由: 比較の相手との差を事前学習源に帰属させるため。(e) 入力 224² はそのまま。腕1 側に「ResNet-50、全画面 224²、候補 0 の処方」の参考腕を足し、解像度の効果を腕1 側で測る（前提 (3)。比較の相手は P\*-15-COCO のまま）。クリップ入力は仮説の操作として認める（前提 (6)）。入力解像度と検出塔との関係は利用者の決定 2026-10-23（前提 (3)(5)）: 公開データの段の非対称は候補 5 の測定に限って認め、Stage 2 に持ち込む形は採られた後に決める。

掃引する主要因（初回にセットで。後から足さない）:
- マスク比 {0.85, 0.90, 0.95}（A-01 Table 3b で 0.90 が最良だが ±0.05 で −2.3〜−2.7）
- τ {0.50, 0.75}（Table 3c で 0.50 が最良、0.25 で崩れる。0.25 は入れない）
- マスクの選び方 {視線, random 0.90}（#8 の対照）
- 事前学習の epoch {400, 800}（A-01 は 800。短い側を入れる）
- 事前学習のデータの範囲 {折りの train のみ, 折りの train ＋ 17〜21}（依頼文 §3 の 4 の未決を掃引で扱う）

固定する交互作用と理由:
- ViT-S、224²、10 フレームのクリップ、batch 256、fine-tune 100 epoch 相当（A-01 に揃え、設定差を交絡にしない。ただし fine-tune の止め方は収束規則〔依頼文 §3 の 8〕に従い、上限 36 epoch）
- 入力の作り方: 比較の相手は短辺 800 の全画面。本案は 224² へ縮小した全画面（推測: A-01 と同じ）。解像度の差は交絡として #16 に書く
- クリップ: 時刻 t を末尾とする過去 10 フレーム（0.5 fps で 20 秒）。中央に置く形は online-causal に反するため掃引に入れない
- 時間ヘッドの入力: ViT-S の CLS（384 次元）をフレーム特徴とし、線形の射影で候補 0 の時間ヘッドの入力次元に合わせる。射影は時間ヘッドと一緒に学ぶ
- 検出塔: 変えない。本案は公開データの段を持たない（スクラッチ）ため、「公開データの事前学習は両塔で同じ構成」の規則を満たせない。意図的に変える理由: 検出塔の backbone は候補 0 で確定し、本依頼の範囲外。本案で検出塔にも同じ SSL を当てる形（ViT-S スクラッチ ＋ 視線 MAE → 検出の fine-tune）は COCO 段の除去を伴い、検出塔の設計変更になるため候補にしない
- 折りごとに事前学習をやり直す。評価動画は事前学習に入れない

## 14. 初回にセットで試す設定の掃引集合と固定の理由

**三版の改訂（2026-10-23）。** (a) 解像度を掃引の軸にする: {224², 448², 短辺 800 系統}（前提 (3)。DINOv3 は patch 16 で可変の入力を受ける。800 系統は約 4,450 トークンで計算量は 224² の数百倍。殺し実験の前に 1 本で記憶量と時間を測る）。(b) 凍結の範囲の「全体 fine-tune」の水準を adapter または LoRA の水準に置き換える: {全凍結＋線形, adapter/LoRA, 上位 4 ブロック}（A-47 Table II で PETL ＞ 全体 fine-tune、Surgical-DINO で LoRA ＞ 素の fine-tune）。(c) 計 3 × 2 × 2 × 3 = 36 点。入力解像度と検出塔との関係は利用者の決定 2026-10-23（前提 (3)(5)）: 公開データの段の非対称は候補 5 の測定に限って認め、Stage 2 に持ち込む形は採られた後に決める。

掃引する主要因:
- 凍結の範囲 {全凍結＋小さな適合層（線形射影＋1 ブロックの adapter）, 上位 4 ブロックのみ fine-tune, 全体 fine-tune}（A-50 の提言。A-47 の adapter 型を含める）
- モデル規模 {ViT-B の蒸留版, ViT-L}（A-02 は L と H。H は固定で外す。理由: 推測で計算量が大きく、A-02 で L と H の順位が Acc と J で入れ替わる）
- fine-tune の学習率 {比較の相手と同じ, その 1/10}（公開重みの崩れを避ける側を入れる）

固定する交互作用と理由:
- 入力: フレーム単体、224² に縮小した全画面。クリップ入力は案 3 で扱い、ここでは画像基盤モデルの転移だけを問う

- 収束規則: 依頼文 §3 の 8
- 対象データ上の継続事前学習は行わない（それは案 4 と §11.5 の 2 の方向で、本案と排他）
- 検出塔: 変えない。本案は公開データの段が ImageNet → COCO と異なるため、「公開データの事前学習は両塔で同じ構成」を満たさない。意図的に変える理由: 検出塔の backbone は候補 0 で確定し、ViT 系の検出器への置き換えは本依頼の範囲外。対称にする変種（検出塔も DINOv3 初期化）は、採られた後に利用者が Stage 2 の形を決めるときの選択肢として #11 に残す
- 事前学習に評価動画は入らない（対象データで事前学習しない）

- 凍結の範囲 {全体 fine-tune, 上位 4 ブロックのみ}（A-41 は全体、A-50 の提言は両方）

- 推論: 時刻 t を末尾とする過去のみのクリップ。中央に置く形は online-causal に反する

## 14. 初回にセットで試す設定の掃引集合と固定の理由

**三版の改訂（2026-10-23）。** (a) 出発点の掃引 {COCO 重み, ImageNet 重み} のうち、主判定は COCO 重みからの継続だけ。ImageNet 重みからの腕は記録だけ（鎖の対称性を主判定の腕の中で揺らさない）。(b) 無ラベル段に val 2 本は入れない（前提 (4)）。(c) MoCo v2 の batch 256（224〜256 のクロップ）が A6000 一枚に載るかは殺し実験で測る。A-34 の「100 epoch 超で −2」は SwAV/SimCLR、「飽和」は平均の記述で、掃引 {MoCo v2, SwAV} × {100, 300} はこの交互作用を踏む。

- SSL の方式 {MoCo v2, SwAV}（A-34 Table 3 で MoCo v2 が単一フレームの 5 本で最良、Table 4 で SwAV が時間モデルの 5 本で最良。DINO は 10 本で −0.9 のため外す）

- SSL の epoch {100, 300}（A-34 で 100 epoch 以降は飽和〔A3g〕、100 超で最大 −2〔旧 A〕）
