# 生成会話への依頼 — 工程塔の時間ヘッドの候補（提案カード）

**書いた人:** 起票者（運用会話、2026-10-23）。規則は repo の規約 `conventions#proposal_gate` の「役割分離」「提案カード」「生成会話への依頼文」。
**渡すもの:** 本書、証拠地図 A v2.1（`2026-10-21-A-phase-tower-candidates.md`）、カードの雛形（`_template.md`）の三つだけ。repo、Notion、ほかの地図、前のカード、報告者の解釈の文書は渡さない。
**対になる依頼:** 初期化・事前学習・基盤モデルの候補は、別の生成会話で扱う（本書とは別の依頼文）。本会話ではその軸を変えない。

---

## 0. この会話でしてほしいこと

1. 一人称の開放手術映像の online の工程認識で、**工程塔の時間ヘッド**（フレームごとの特徴の列から工程を予測する部分）の候補を、提案カードとして **三案以上五案以下** 出す。互いに排他的な方向にする（同じ系統の変種を並べない）
2. 各案を、雛形の 16 項目すべてが埋まった一枚のカードにする。**推奨・順位・比較の結論は書かない**（判定は利用者）
3. カードの #10（費用）・#13（F の却下・予測外れとの同型でないことの宣言）・#15（両腕の実測値）は **UNKNOWN** と書く。起票者が repo の実測と記録で埋めてから批判会話へ回す
4. 文献は証拠地図 A の行で引く（行 ID と書誌 ID を書く）。地図に無い文献を引くときは DOI か arXiv ID を付け、「地図に無い」と明記する。ID の無い引用は引用として扱われない
5. **区間の欠けの扱い**（§3 の 6）を、各案の中で扱う。扱わない案は、扱わない理由を #14 か #16 に書く

## 1. 本研究の設定（決定から書ける範囲）

- データ: EgoSurgery。一人称の開放手術映像。術具と工程の両方のラベルを持つ **15 動画**が共通の実験単位。工程の注釈は 0.5 fps のフレームに付く（工程 9 種）
- 問い（M §1.2）: 一方のタスクの情報が他方のタスクの判断を良くするか。二塔・界面分離型（M §5.1）。各タスクが自分のラベルだけで学習した最良のモデル（塔）を持ち、学習後は凍結する。結合は塔の間の小さな界面だけで行う
- 工程塔 P の役割（M §5.1・§5.2）: D→P の受け取り手、P→D の送り手。界面に渡すのは工程塔単独の同時刻 t の出力 P0(t)（online-causal で t までを見た出力。F 2026-10-14）。関門 G1.5 は P\*-15 に対して D→P が主判定を満たすかを見る
- 評価（M §4.1・§4.2）: 工程の主指標は macro Jaccard、co-primary は frame accuracy（同方向要件）。判定単位は動画。折りは動画単位の 5 分割（F 2026-09-17 の折り表）。設計の判断は val の値だけで行う（F 2026-10-05）
- 塔の選定（M §5.1）: 候補間で recipe・seed 数・探索回数を同一にしたトーナメント。同一 epoch ではなく収束の度合いを揃える

## 2. いま決まっている工程塔（カードはこの塔を比較の相手にする）

両塔の学び直し（候補 0）で確定する P\*-15-COCO が、Stage 2 の主の工程塔になる。カードはこの塔を**比較の相手**とし、構造の違いだけを問う。

| 項目 | 決定（F の行の日付） |
|---|---|
| backbone | ImageNet-1K の ResNet-50 を、折りの train 動画の工程ラベルで fine-tune（stem だけ凍結、layer1〜4 を学習）（2026-09-18） |
| 初期化の鎖 | Stage 2 の主測定は COCO 系統（ImageNet → COCO 検出 → EgoSurgery）。初期化源の効果は Stage 2 で測らない（2026-10-06）。in-domain より前の段は検出塔と揃える（M §5.1） |
| 入力 | 短辺 800 の全画面（2026-10-18） |
| 時間ヘッド | 三周目の 10 構成（因果的な時間畳み込み、Transformer による集約、平滑化の損失の系統）から val で選ぶ（2026-09-18、2026-10-17）。処方（学習率ほか）はハイパーパラメータ探索で選び直す（2026-10-19、2026-10-22） |
| 学習の長さ | 同じ収束規則で揃える。val の主指標が 4 epoch 停滞したら学習率を 1/10（一回）、さらに 4 epoch 停滞したら打ち切り、上限 36 epoch（2026-09-22） |
| 学習・評価のフレーム | 15 動画の工程注釈をすべて使う（工程注釈だけの 1,796 フレームを含む 17,233 フレーム）。追加動画 17〜21 は主測定に入れない（2026-10-16） |
| online | 全候補に online-causal を課す。評価も未来のフレームを使わない（2026-08-28）。strictly past-only（2026-10-03） |
| ホスト | 確定の塔とその変種は同じホスト（andrew）で学ぶ。比べる腕は同じホスト・同じ装置型（M §4.5、2026-10-21） |
| 塔どうしの細部 | 検出塔と工程塔の最適化の細部（学習率、weight decay、batch、精度など）は揃えない（2026-10-17） |

## 3. 縛るもの（決定ごとに、どこまで縛るか）

1. **online-causal は全案の前提**（2026-08-28、2026-10-03）。未来のフレームを見る構造、固定クリップの中の未来を使う構造は候補にしない。offline の手法を候補にするなら、過去のみに直した形で書く
2. **backbone と初期化の鎖は変えない**（2026-09-18、2026-10-06、2026-10-22 の二本に分ける決定）。本会話の案は、候補 0 で確定する backbone の特徴の上で時間ヘッドだけを替える案に限る。backbone を同時に変える案、事前学習を変える案は出さない（別の会話で扱う）
3. **学習・評価のフレームの集合は変えない**（2026-10-16）。1,796 フレームを含む 15 動画の全工程注釈。17〜21 は使わない。フレームの間引きや追加は候補にしない
4. **収束規則は変えない**（2026-09-22）。時間ヘッドの止め方もこの規則に従う。学習率などの処方は設定の水準で、カードの #14 の掃引に入れる
5. **評価の指標と判定の単位は変えない**（M §4.1・§4.2、2026-10-05）。#7 の成功の閾値は、val の macro Jaccard（5 折り平均）で、比較の相手（§2 の塔）との差で書く。frame accuracy が同方向であることを添える。test の値を使わない。val の動画がほかの折りで test になる点は、起票者が prereg に書く（2026-10-19）
6. **区間の欠けの扱いは本会話の範囲**（2026-10-23）。工程の注釈のある区間だけが残り、区間の境でフレームの番号が振り直される列を、時間ヘッドが境を越えてつなぐか、区間ごとに状態を初期化するか、欠けの長さを入力に与えるか。各案で立場を書く。**ただし界面の側の時刻の扱い（P→D のフレーム対応）は別のカードで決める。** 本会話の案は工程塔単独の学習と推論の中の扱いだけを決める
7. **界面に渡す出力の形は変えない**（2026-10-14）。時間ヘッドの出力は、フレーム t ごとの工程の事後確率（online-causal で t までを見たもの）として取り出せること。この形を出せない構造は候補にしない
8. **順序と採否の関係**（2026-10-22）。候補 0 は今の範囲で進み、本カードは並行して作る。採られた案で主の工程塔を差し替えるかの条件は、判定の後に利用者が決める。カードの #11 には「採られた場合に Stage 2 の主の工程塔が替わりうる」と書けるが、替わるとは書かない
9. **費用や締切の推測で候補を狭めない**（2026-10-03）。#10 は UNKNOWN。計算量が大きい案も候補に残す

## 4. カードの候補として開いているもの

- 時間ヘッドの系統（因果的な時間畳み込みの深さと受容野、再帰型、因果的な注意、状態空間モデル、記憶機構、多尺度、進捗やタスクの構造の事前知識、境界や平滑化の損失、online の後処理）。地図 A §1.1 の系統表が入口
- 区間の欠けの扱い（§3 の 6）。地図 A §1.2 の系統表が入口
- backbone の特徴を固定したまま時間ヘッドだけを学ぶ形（Stage 1 と同じ二段階）か、backbone と時間ヘッドを一緒に学ぶ形か。後者は backbone の学習の処方に触れるので、触れる範囲を #14 と #16 に書く
- 最安の殺し実験（#9）は、候補 0 で保存される見込みの backbone の特徴（フレームごと 2048 次元、1,796 フレームを含む、列の作り方は Stage 1 と同じ。2026-10-22。保存できるかは起票時に確かめる）の上で時間ヘッドだけを学ぶ形で書いてよい。その場合、特徴が保存されない場合の代わりの形も書く
- 設定の水準（学習率、受容野の長さ、層の数、損失の重みなど）は #14 の掃引集合に入れ、初回にセットで試す。後から足せない

## 5. 守ること

- 新しさや効き目を強める形容詞を使わず、値（期待効果量、成功確率、費用）で書く。規約の禁止語は次のとおり（完全一致で検査される）: 最大の新規性／世界初／画期的／有望／筋が良い／本命／未踏／空白／決定的／確実に効く／明らかに／大幅／劇的／必ず改善／唯一の
- 地図の「見つからなかったもの」（§10）と「未検証の組み合わせ」（§11）を、その案が新しい・価値があるという根拠として肯定的に読まない。見つからない理由には、技術的な困難、価値が乏しいと見なされていること、偶然がありうる
- #2・#4 の効果量は、指標・値・表番号・設定を添えて書く。設定の違い（データセット、タスクの粒度、入力、online か）を必ず書き、「文献に数値がある」を「効く」と読み替えない
- #5（期待効果量）は、#2 のどの値からどう外挿したかを書く。EgoSurgery の条件（少数動画、0.5 fps、一人称、online）と文献の条件の違いを割り引きの根拠として明示する
- #14 では、掃引する主要因と固定する交互作用を分け、固定の理由を書く
- #16 では、差を時間ヘッドの効果と読むために排除すべき交絡（学習の長さ、backbone の特徴の違い、評価のフレームの集合、ホスト、同点の扱い）を列挙し、排除していないものはその影響の向きを書く
- 本書に無い事実は「依頼文に無い」と書く。推測は「推測」と明記する

## 6. 出力の形

- 一つの文書。冒頭に案の一覧（案の名前、系統、#1 の問い、区間の欠けの立場）を表で置く
- 続けて、案ごとに雛形のとおりのカード（一覧表と 16 項目の見出し）。#10・#13・#15 は UNKNOWN
- 最後に、案を出すときに読んだ地図の行 ID の一覧と、地図の外から引いた文献の一覧（DOI か arXiv ID つき）
- 却下表と失敗時手順の節は空のまま残す（批判会話と修正案のときに使う）
