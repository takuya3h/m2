# 生成会話への依頼 — 工程塔の初期化・事前学習・基盤モデルの候補（提案カード）

**書いた人:** 起票者（運用会話、2026-10-23）。規則は repo の規約 `conventions#proposal_gate` の「役割分離」「提案カード」「生成会話への依頼文」。
**渡すもの:** 本書、証拠地図 A v2.1（`2026-10-21-A-phase-tower-candidates.md`）、カードの雛形（`_template.md`）の三つだけ。repo、Notion、ほかの地図、前のカード、報告者の解釈の文書は渡さない。
**対になる依頼:** 時間ヘッドの候補は、別の生成会話で扱う（本書とは別の依頼文）。本会話ではその軸を変えない。

---

## 0. この会話でしてほしいこと

1. 一人称の開放手術映像の online の工程認識で、**工程塔のフレームごとの表現を作る部分**（初期化源、自己教師あり事前学習、手術や一般の基盤モデルからの転移）の候補を、提案カードとして **三案以上五案以下** 出す。互いに排他的な方向にする
2. 各案を、雛形の 16 項目すべてが埋まった一枚のカードにする。**推奨・順位・比較の結論は書かない**（判定は利用者）
3. カードの #10（費用）・#13（F の却下・予測外れとの同型でないことの宣言）・#15（両腕の実測値）は **UNKNOWN** と書く。起票者が repo の実測と記録で埋めてから批判会話へ回す
4. 文献は証拠地図 A の行で引く（行 ID と書誌 ID を書く）。地図に無い文献を引くときは DOI か arXiv ID を付け、「地図に無い」と明記する。ID の無い引用は引用として扱われない
5. 各案で、**事前学習のデータに評価の動画が含まれるか**と、**検出塔との初期化の鎖の対称性**（§3 の 2・3）を必ず書く

## 1. 本研究の設定（決定から書ける範囲）

- データ: EgoSurgery。一人称の開放手術映像。術具と工程の両方のラベルを持つ **15 動画**が共通の実験単位。工程の注釈は 0.5 fps のフレームに付く（工程 9 種）。工程の注釈だけがある追加動画 17〜21 がある
- 問い（M §1.2）: 一方のタスクの情報が他方のタスクの判断を良くするか。二塔・界面分離型（M §5.1）。各タスクが自分のラベルだけで学習した最良のモデル（塔）を持ち、学習後は凍結する。結合は塔の間の小さな界面だけで行う
- 工程塔 P の役割（M §5.1・§5.2）: D→P の受け取り手、P→D の送り手。界面に渡すのは工程塔単独の同時刻 t の出力 P0(t)（online-causal で t までを見た出力。F 2026-10-14）。関門 G1.5 は P\*-15 に対して D→P が主判定を満たすかを見る
- 評価（M §4.1・§4.2）: 工程の主指標は macro Jaccard、co-primary は frame accuracy（同方向要件）。判定単位は動画。折りは動画単位の 5 分割（F 2026-09-17 の折り表）。設計の判断は val の値だけで行う（F 2026-10-05）。事前学習に評価動画を含む重みは、自他ともその旨を明記する（M §4.2）
- 塔の選定（M §5.1）: 候補間で recipe・seed 数・探索回数を同一にしたトーナメント。同一 epoch ではなく収束の度合いを揃える

## 2. いま決まっている工程塔（カードはこの塔を比較の相手にする）

両塔の学び直し（候補 0）で確定する P\*-15-COCO が、Stage 2 の主の工程塔になる。カードはこの塔を**比較の相手**とし、表現の作り方の違いだけを問う。

| 項目 | 決定（F の行の日付） |
|---|---|
| backbone | ImageNet-1K の ResNet-50 を、折りの train 動画の工程ラベルで fine-tune（stem だけ凍結、layer1〜4 を学習）（2026-09-18） |
| 初期化の鎖 | Stage 2 の主測定は COCO 系統（ImageNet → COCO 検出 → EgoSurgery）。初期化源の効果は Stage 2 で測らない（2026-10-06）。in-domain（EgoSurgery）より前の段は検出塔と揃え、公開データの事前学習は D と P で同じ構成を用いる。禁じるのは in-domain の情報が塔をまたぐことだけで、凍結も公開データの排除も要求しない（M §5.1） |
| 入力 | 短辺 800 の全画面（2026-10-18） |
| 時間ヘッド | 三周目の 10 構成（因果的な時間畳み込み、Transformer による集約、平滑化の損失の系統）から val で選ぶ（2026-09-18、2026-10-17） |
| 学習の長さ | 同じ収束規則で揃える。val の主指標が 4 epoch 停滞したら学習率を 1/10（一回）、さらに 4 epoch 停滞したら打ち切り、上限 36 epoch（2026-09-22） |
| 学習・評価のフレーム | 15 動画の工程注釈をすべて使う（工程注釈だけの 1,796 フレームを含む 17,233 フレーム）。追加動画 17〜21 は主測定に入れない（2026-10-16） |
| online | 全候補に online-causal を課す。評価も未来のフレームを使わない（2026-08-28）。strictly past-only（2026-10-03） |
| ホスト | 確定の塔とその変種は同じホスト（andrew）で学ぶ。比べる腕は同じホスト・同じ装置型（M §4.5、2026-10-21） |
| 塔どうしの細部 | 検出塔と工程塔の最適化の細部（学習率、weight decay、batch、精度など）は揃えない（2026-10-17） |

## 3. 縛るもの（決定ごとに、どこまで縛るか）

1. **online-causal は全案の前提**（2026-08-28、2026-10-03）。クリップを入力にする映像モデルを候補にするなら、過去のみのクリップで推論する形で書き、その形での性能の落ち方を #2・#4 の文献で示す
2. **初期化源は設計の水準で、カードと批判会話を通してから契約にする**（2026-10-03）。候補に入れてよいもの: 無ラベルの手術動画での自己教師あり事前学習（視線データは利用者が用意できる。視線でマスクを選ぶ型を含む）、内視鏡・腹腔鏡以外の映像で学習された手術基盤モデルからの初期化、一般の画像・映像の基盤モデルからの初期化、公開の重みを初期値にして対象データで自己教師あり学習を続ける形
3. **検出塔との対称性は、各案が決めて書く**（M §5.1・§4.5）。規則は「in-domain より前の段は両塔で揃え、公開データの事前学習は同じ構成」。工程塔だけ初期化源を変える案は、検出塔の側をどうするか（同じ初期化源を検出塔にも当てる／当てずに理由つきで「意図的に変える」と書く）を #14 と #16 に書く。in-domain の情報（EgoSurgery の術具のラベルや検出塔の出力）が工程塔の事前学習に入る形は候補にしない
4. **事前学習のデータの範囲は開いている**（C §3 の未決）。折りの train 動画だけ／15 動画すべて（ラベルは使わない）／追加動画 17〜21 を含む／外部の開放手術の映像を含む。各案でどれを取るかと、評価の動画が事前学習に入る場合の漏れの扱い（折りごとに事前学習をやり直す、入れたうえで明記する、対照を置く）を書く。**評価に使う重みの学習に評価動画が入る場合は、その旨をカードに明記する**（M §4.2）
5. **公開の重みの事前学習に EgoSurgery が含まれる場合の扱いは開いている**（C §3 の未決）。使う（漏れを明記）／使わない／対照を置く。案ごとに立場を書く
6. **時間ヘッドは変えない**（2026-10-22 の二本に分ける決定）。本会話の案は、候補 0 で確定する時間ヘッド（§2）をそのまま載せる前提で書く。時間ヘッドを同時に変える案は出さない（別の会話で扱う）。表現の次元や形が変わる場合は、時間ヘッドの入力に合わせる部分（射影など）を #14 に書く
7. **学習・評価のフレームの集合は変えない**（2026-10-16）。fine-tune と評価は 15 動画の全工程注釈。17〜21 を使ってよいのは事前学習（ラベルなし）だけで、使う場合はその旨を書く
8. **収束規則は変えない**（2026-09-22）。fine-tune の止め方はこの規則に従う。事前学習の長さの決め方は各案が書く
9. **評価の指標と判定の単位は変えない**（M §4.1・§4.2、2026-10-05）。#7 の成功の閾値は、val の macro Jaccard（5 折り平均）で、比較の相手（§2 の塔）との差で書く。frame accuracy が同方向であることを添える。test の値を使わない
10. **界面に渡す出力の形は変えない**（2026-10-14）。塔の出力はフレーム t ごとの工程の事後確率
11. **順序と採否の関係**（2026-10-22）。候補 0 は今の範囲で進み、本カードは並行して作る。採られた案で主の工程塔を差し替えるかの条件は、判定の後に利用者が決める。工程塔の系統が増えたときの Stage 2 の形（COCO 系統の主測定に系統を足すか）も未決（C §3）。#11 には「採られた場合に Stage 2 の主の工程塔が替わりうる」と書けるが、替わるとは書かない
12. **費用や締切の推測で候補を狭めない**（2026-10-03）。#10 は UNKNOWN。事前学習の計算量が大きい案も候補に残す

## 4. カードの候補として開いているもの

- 系統: 対象データ上の自己教師あり事前学習（画像／映像、マスク方式の改変、事前知識でマスクを選ぶ）、手術の基盤モデルからの転移（凍結／部分的な fine-tune／全体の fine-tune）、一般の画像・映像の基盤モデルからの転移、公開の重みからの継続事前学習、一人称の非手術映像で事前学習した重みからの転移。地図 A §1.4 の系統表が入口
- backbone の構造（ResNet 系のまま／ViT 系へ）。構造を変える案は、時間ヘッドの入力に合わせる部分と、検出塔との対称性（§3 の 3）を書く
- 凍結の範囲（全体を凍結して線形か小さな適合層だけ／部分的に fine-tune／全体を fine-tune）
- 入力の形（フレーム単体／短いクリップ）。クリップの場合は online の制約（§3 の 1）の下での作り方
- 視線データの使い方（事前学習のマスクの選択に限る／入力やマスクの教師にも使う）。推論時に視線を使う案は、推論時の入力が RGB だけでない点を #16 に書く
- 最安の殺し実験（#9）。本会話の案は backbone を替えるので、候補 0 で保存される backbone の特徴は使えない。凍結した重みに線形の層だけを載せる形など、GPU 一日以内で案を殺せる形を書く
- 設定の水準（学習率、事前学習の epoch、マスク比、入力解像度の扱いなど）は #14 の掃引集合に入れ、初回にセットで試す。後から足せない

## 5. 守ること

- 新しさや効き目を強める形容詞を使わず、値（期待効果量、成功確率、費用）で書く。規約の禁止語は次のとおり（完全一致で検査される）: 最大の新規性／世界初／画期的／有望／筋が良い／本命／未踏／空白／決定的／確実に効く／明らかに／大幅／劇的／必ず改善／唯一の
- 地図の「見つからなかったもの」（§10）と「未検証の組み合わせ」（§11）を、その案が新しい・価値があるという根拠として肯定的に読まない。見つからない理由には、技術的な困難、価値が乏しいと見なされていること、偶然がありうる
- #2・#4 の効果量は、指標・値・表番号・設定を添えて書く。設定の違い（データセット、タスクの粒度、入力、凍結か fine-tune か、評価の動画が事前学習に入るか）を必ず書き、「文献に数値がある」を「効く」と読み替えない
- #5（期待効果量）は、#2 のどの値からどう外挿したかを書く。EgoSurgery の条件（少数動画、0.5 fps、一人称の開放手術、online）と文献の条件の違いを割り引きの根拠として明示する
- #14 では、掃引する主要因と固定する交互作用を分け、固定の理由を書く
- #16 では、差を表現の作り方の効果と読むために排除すべき交絡（学習の長さ、時間ヘッドの違い、評価のフレームの集合、ホスト、事前学習への評価動画の混入、検出塔との非対称）を列挙し、排除していないものはその影響の向きを書く
- 本書に無い事実は「依頼文に無い」と書く。推測は「推測」と明記する

## 6. 出力の形

- 一つの文書。冒頭に案の一覧（案の名前、系統、#1 の問い、事前学習のデータの範囲、評価動画の混入の有無、検出塔との対称性の立場）を表で置く
- 続けて、案ごとに雛形のとおりのカード（一覧表と 16 項目の見出し）。#10・#13・#15 は UNKNOWN
- 最後に、案を出すときに読んだ地図の行 ID の一覧と、地図の外から引いた文献の一覧（DOI か arXiv ID つき）
- 却下表と失敗時手順の節は空のまま残す（批判会話と修正案のときに使う）
