## 0. この会話でしてほしいこと

1. 一人称の開放手術映像で、**手と術具の把持関係を推論するモデル（以下「把持塔」）の出力を、術具検出か工程認識（またはその両方）の改善に使う手法**の候補を、提案カードとして **三案以上五案以下** 出す。互いに排他的な方向にする
2. 各案を、雛形の 16 項目すべてが埋まった一枚のカードにする。**推奨・順位・比較の結論は書かない**（判定は利用者）
3. カードの #10（費用）・#13（F の却下・予測外れと同型でないことの宣言）・#15（両腕の実測値）は **UNKNOWN** と書く。起票者が repo の実測と記録で埋めてから批判会話へ回す
4. 文献は証拠地図 H の行で引く（行 ID と書誌 ID を書く）。地図に無い文献を引くときは DOI か arXiv ID を付け、「地図に無い」と明記する。ID の無い引用は引用として扱われない
5. 各案で、§3 の 4・7・9・11 の点（把持塔の学習に使う注釈の範囲、交差適合の扱い、把持塔を外した系との比較、初期化の鎖と対称性）を必ず書く

## 1. 本研究の設定（決定から書ける範囲）

### 1.1 データ

- EgoSurgery。一人称（術者の頭部カメラ）の開放手術映像。術具の box と工程の両方のラベルを持つ **15 動画**が共通の実験単位（M §3.1）。工程の注釈は 0.5 fps のフレームに付く
- 把持関係の注釈は EgoSurgery-HTS（手・術具・手と術具の組の画素の分割。地図 H の H-48）。**術具の注釈があるフレームの範囲にだけある**（M §3.3）。工程の注釈だけがあるフレームには把持の注釈が無い
- 折りは動画単位の 5 分割（F 2026-09-17 の折り表）。各折りで train 10 本・val 2 本・test 3 本

### 1.2 問いと型（M §1.2）

問いは「一方の情報が、他方のタスクの判断を良くするか」。相互改善を探す型を三つに分ける。

| 記号 | 型 | 比べるもの |
|---|---|---|
| S1 | 推論時の情報交換 | 受け取り手の塔単独 対 受け取り手に送り手の出力を界面で入れた系 |
| S2 | 学習時の教師交換 | 受け取り手の塔単独 対 受け取り手を送り手の出力の補助損失か蒸留で学んだ系 |
| S3 | 表現の共有 | 別々の二塔 対 共有の一モデル |

- **塔**: 一つのタスクのラベルだけで学習した最良のモデル。学習後は凍結する。検出塔 D（術具の box）、工程塔 P（工程。online-causal）がある（M §5.1）
- **界面**: 塔の間の小さな学習モジュール。結合はここでだけ行う。**送り手**は出力を渡す側、**受け取り手**は受ける側
- v3.3（F 2026-10-31）で、S1・S2 の送り手（教師）に**把持塔**を置けるようになった。S3 の共有モデルの学習には把持ラベルを混ぜない

### 1.3 判定（M §1.3・§4）

- **定義 A（主）**: 提案手法で、術具検出の差（Δ_det）と工程認識の差（Δ_phase）がともに主判定を満たして正。分母は各タスクの塔単独
- **定義 B（A を外したとき）**: 一方のタスクで主判定を満たし、他方は Δ ≥ −m（m は非劣性の幅。値は未決）
- **把持塔を使う系も定義 A・B の判定の対象にする。把持塔を外した系の値を必ず並べる**（F 2026-10-31、M §1.3・§6）
- **主判定**: 判定単位は動画（15 本。各動画は test にちょうど一度）。腕ごとに動画ごとの対応差（seed 平均）を取り、折りをクラスタとするブロック・ブートストラップの 95% 区間で読む。差は四つに分ける: 陽性（区間がすべて 0 より上）、陰性（すべて 0 より下）、実質零（すべて −m〜+m の中）、判定不能（いずれでもない）（F 2026-10-14）
- **指標**: 工程は macro Jaccard が主、frame accuracy が co-primary（同方向であること）。検出は overall mAP が主、標的群 AP が co-primary、陰性対照群 AP は差がほぼ 0 であるべき（M §4.1、F 2026-08-28）
- **段階（Stage）と関門**: Stage 2 は S1、Stage 3 は S2、Stage 4 は S3 の診断。Stage 5 が提案手法。関門 G2・G3 は「その型で方向ごとに見込みがあるか」、G5 は「三つの型を通して両方向に見込みがあるか」で、見込みの無い方向・型を落とす（M §5.2）。**把持塔を使う腕も関門の判定に使う**（M §5.2、v3.3）。把持塔を送り手にする腕は Stage 2、教師にする腕は Stage 3 に入り、構成はカードで決める（M §5.2）

## 3. 縛るもの（決定ごとに、どこまで縛るか）

1. **把持ラベルを検出塔・工程塔の学習データに混ぜない**（2026-10-31）。把持塔の出力を使ってよいのは、推論時の界面の入力（S1）と、受け取り手の学習時の教師（S2）だけ（M §5.1）。検出塔・工程塔を把持の注釈で多タスク学習する案、把持のラベルで受け取り手の塔を学び直す案は出さない
2. **主張の核は二タスクの改善**（2026-10-31、M §1.1）。把持関係の推論の精度そのものを改善の対象にしない。把持塔の性能を報告だけにするか主張にも使うかは開いている（§4）
3. **把持塔を外した系を並べる**（2026-10-31、M §6 の T3）。各案は、何を外した系と比べるか（把持塔の入力を空にした界面、把持塔の出力を同量の非関連特徴に替えた界面など）を #7・#16 に書く
4. **把持塔は折りごとに、その折りの train 動画の把持の注釈だけで学ぶ**（M §3.1 の規律: 選定は折りの val、test は腕ごとに一度。把持塔の出力を受け取る系は test 動画で評価されるため）。設計の判断は val の値だけで行う（2026-10-05）。把持塔は、それを使う腕の起票の前に学習して確定する（M §5.2）
5. **把持塔を送り手にする腕の受け取り手は、ほかの腕と同じ**（M §5.1 の「受け取り手を全腕で同一にし、変えるのは界面の入力だけ」）。S1 の案は、受け取り手と界面を変えずに界面の入力だけを替える形で書く。S2 の案は、受け取り手の構造・処方・収束規則を S2 の分母と揃え、補助損失か蒸留の項だけを足す形で書く（S2 への当て方は起票者の読み。別の読みを取る案は、その読みと理由を書く）
6. **online の規則を破らない**（2026-08-28、2026-10-03）。工程塔へ渡す把持塔の出力は、時刻 t までのフレームだけから作る。把持塔がクリップを入力にするなら、過去のみのクリップで作る形で書く
7. **交差適合の規則は送り手に当たる**（M §5.1、2026-10-14）。把持塔を送り手にする案は、把持塔の train 動画での出力をどう作るか（交差適合を当てるか、当てないならその理由）を書く。S2 の教師にする案も、教師の出力を train 動画でどう作るかを書く
8. **界面に渡す信号の形と時刻**（2026-10-14、M §5.1）。把持塔単独の同時刻の出力。入力の次元が受け取り手ごとに違えば固定次元 K で揃える。把持塔の出力の形（画素のマスク、手ごとの把持の有無、手と術具の組の確率、特徴量など）は開いている（§4）
9. **初期化の鎖と対称性は各案が決めて書く**（M §5.1・§4.5。把持塔の初期化の鎖・凍結・両塔との対称性は未決）。規則は「in-domain（EgoSurgery）より前の段は塔どうしで揃え、公開データの事前学習は同じ構成。禁じるのは in-domain の情報が塔をまたぐことだけ」。把持塔を検出塔や工程塔の重みから始める案は、in-domain の情報が塔をまたぐ形になるかを書く。比べる腕の条件は対称性の表（揃える／意図的に変える〔理由つき〕／UNKNOWN）で #15 に書く
10. **把持塔を使う腕も関門と定義 A・B の判定に入る**（2026-10-31、M §5.2）。#7 の成功の閾値は主判定（§1.3）で、val の値で書く。test の値を使わない。確認的な腕の本数の上限（2026-10-14）の中で、把持塔の腕をどう選ぶかは開いている（§4）
11. **学習の長さは収束規則で揃える**（2026-09-22。val の主指標が停滞したら学習率を下げ、再び停滞したら打ち切る規則を塔に当てる）。把持塔の学習の止め方は各案が書く
12. **設定の掃引は初回にセットで入れる**（2026-09-16）。後から設定を足して救わない
13. **費用や締切の推測で候補を狭めない**（2026-10-03）。#10 は UNKNOWN

## 4. カードの候補として開いているもの

- **使う注釈の範囲**（未決）: 手と術具の組の分割だけ／手の分割と術具の分割も／注釈の追加の分（extra）も。各案でどれを取るかと、その理由
- **把持塔の形と出力**: 画素の分割、手と物体の枠と接触の状態、手ごとの把持の有無、active object（把持されている術具）の位置、把持の表現の特徴量。出力の豊かさ（低次の要約から高次の特徴まで。M の軸 1 の L0〜L3 に当たる）
- **受け取り手と方向**: 把持塔 → 検出塔、把持塔 → 工程塔、両方。両方に入れる案は、定義 A の判定で一つの系とみなすか、片方向の二本として出すかを書く
- **型**: S1（推論時に界面で入れる）／S2（学習時の教師。補助損失・蒸留・特権情報）。S2 の案は、推論時に把持塔が要らない形になる点を #12 に書ける
- **段の位置**: Stage 2（S1）、Stage 3（S2）、Stage 5（提案手法の改良）のどこに置くか
- **機序を分ける対照**: 検出塔と工程塔の間には、構造と処方を同じにして学ぶラベルだけを受け取り手のタスクに替えた「対照の送り手」を置き、実際の送り手との差（知識の上乗せ）が陽性のときだけ「相手タスクの知識が効いた」と書く（2026-10-19）。**把持塔の腕にこれに当たる対照を置くか、置くならどう作るか、同じ書き方の規則を当てるかは開いている**。各案の立場を書く
- **把持塔の性能の扱い**: 報告だけにする／主張にも使う
- **把持の注釈が無いフレームの扱い**: 工程塔は把持の注釈の無いフレームでも学習・評価する（2026-10-16）。把持塔の出力はそのフレームでも作れるが、参照入力段の「正解」は注釈のあるフレームにしか無い。各案での扱い
- **第二データセット**（M §3.4）: 第二データセットの条件の一つは「手法が使う両タスクのラベルが同じ動画にある」。把持塔を使う手法で、把持の注釈も要るとこの条件を読むかは未決。各案は Stage 6 で何が要るかを書く
- **最安の殺し実験**（#9）: 例えば、把持塔の正解（注釈）を界面に入れる参照入力段で余地があるかを先に見る形、凍結した把持塔の出力に線形の層だけを載せる形など。GPU 一日以内で案を殺せる形
- 設定の水準（把持塔の学習率、出力の閾値、K、補助損失の重みなど）は #14 の掃引集合に入れ、初回にセットで試す

## 5. 守ること

- 新しさや効き目を強める形容詞を使わず、値（期待効果量、成功確率、費用）で書く。規約の禁止語は次のとおり（完全一致で検査される）: 最大の新規性／世界初／画期的／有望／筋が良い／本命／未踏／空白／決定的／確実に効く／明らかに／大幅／劇的／必ず改善／唯一の
- 地図の「見つからなかったもの」（§10）と「未検証の組み合わせ」（§11）を、その案が新しい・価値があるという根拠として肯定的に読まない。見つからない理由には、技術的な困難、価値が乏しいと見なされていること、偶然がありうる（2026-10-18）
- #2・#4 の効果量は、指標・値・表番号・設定を添えて書く。設定の違い（視点、ドメイン、課題の粒度、入力、凍結か fine-tune か、推論時に手と物体の正解を使ったか）を必ず書き、「文献に数値がある」を「効く」と読み替えない
- #5（期待効果量）は、#2 のどの値からどう外挿したかを書く。本研究の条件（一人称の開放手術、15 動画、0.5 fps、online、凍結した塔と小さな界面）と文献の条件の違いを割り引きの根拠として明示する
- #14 では、掃引する主要因と固定する交互作用を分け、固定の理由を書く
- #16 では、差を把持の情報の効果と読むために排除すべき交絡を列挙し、排除していないものはその影響の向きを書く。少なくとも次を検討する: 把持塔が学ぶ術具の分割に含まれる術具の位置と種類の情報（把持の関係ではなく術具の手がかりとして効く可能性）、塔を一つ足したこと自体の効果、界面の容量、交差適合の有無による train と val・test の信号の質の違い、時間の文脈、評価するフレームの集合、ホスト、初期化の鎖の非対称
- 論文の書き方は「受け取り手が単独では使い切れていなかった予測上の価値がある」までにとどめ、「因果的に改善した」とは書かない（2026-10-14 の界面についての規則。把持塔の腕にそのまま当てるかは開いているが、因果の主張は書かない）
- 本書に無い事実は「依頼文に無い」と書く。推測は「推測」と明記する
