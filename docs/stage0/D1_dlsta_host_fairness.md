# D1 — dlsta のホスト公平性

契約 `T-2026-09-23-dlsta-host-fairness`。2026-09-26 JST（容器時計 2026-09-25 19:05–19:45 UTC）に dlsta で実測。
値の出所: 同名ディレクトリの `phase_tower_values.json` と `detector_tower_values.json`。証跡は契約の `audit.md`。

## 判定（系ごと。事前に固定した SPEC §2 の区分）

| 系 | 量 | d_host | d_seed（評価は記録の seed 間 pstd） | d_rerun | r | 区分 |
|---|---|---|---|---|---|---|
| 工程塔 | 短い学習（epoch 平均損失 12 点） | 0.005011444276481136 | 0.005917019621681293 | 0.0 | **0.8469541419328871** | **要注意**（0.5 < r ≤ 1） |
| 工程塔 | 評価（val macro Jaccard） | 0.0 | 0.029117551357664122 | 0.0 | **0.0** | **無視できる**（r ≤ 0.5）。ただし d_host と d_rerun がともに 0 で同程度 |
| 検出塔 | — | UNKNOWN | UNKNOWN | UNKNOWN | — | **判定不能**（当該ホストに学習・評価コードが無い） |

境界の当て方: 0.8469541419328871 は 0.5 を超え 1 以下 → 要注意。0.0 は 0.5 以下 → 無視できる。

### 割り当ての帰結

- **工程塔（本契約で測った処方＝r2 の backbone fine-tune）**: 学習を伴う比較は**要注意**。
  **対になる腕は同じホストに置き、折り単位でホストを割り当てる。** 学習済みの塔を当該ホストで評価するだけなら、
  指標は記録と全桁一致した（ホストを跨いでよい）。
  二つの区分のうち割り当てを決めるのは学習の方である（腕も折りも学習を含むため）。これは実行者の解釈であり、SPEC は二つの量の組み合わせ方を定めていない。
- **検出塔**: 区分を付けない。当該ホストで検出塔を回す前に Relation-DETR の本体と設定の配備が要る（後続契約）。
- 区分が「無視できる」の場合でも、**枚数と実効 batch は揃える**（§8.0 条件 (4)）。

### 解釈上の制約

- **d_seed は当該ホストの種の対 1 組（42 と 123）だけから出している。** r はこの 1 組に依存する。参考: 参照ホスト（ilya）の記録の種の対（42 と 123）の差は同じ定義で 0.007571731384811341。
- **ilya は RTX 6000 Ada（別世代）である。** 差がホストによるのか世代によるのかは分けられない。ilya の driver・torch・cuDNN は記録に無く UNKNOWN。
- **短い学習は一歩ごとの損失ではなく epoch 平均で比べた**（参照の run に一歩ごとの記録が無く、利用者の判断で代替）。
- d_rerun が 0 なのは、当該処方が `use_deterministic_algorithms(True)`・TF32 無効で回るため。当該ホストでは同じ種の二回が**ビット単位で一致**した（checkpoint の sha256 も一致）。したがって d_host 0.005011 は非決定性と区別できる。
- 本判定は**本契約で測った処方にだけ**当てはまる。r2 の検出塔（収束規則）と **r3 の工程塔（短辺 800・全画面）には当てはまらない。** 記憶量も同じ。

## 装置間の接続（dlsta）

NVLink（NV4）で結ばれた対は GPU1–GPU2 と GPU3–GPU4。GPU0 は単独（同じ NUMA 内は PCIe の NODE）。
NUMA 0 = GPU0–2、NUMA 1 = GPU3–4。二枚の処方は (1,2) か (3,4) に置けば同じ形になる。参照ホスト側の接続は UNKNOWN。
