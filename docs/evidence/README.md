# docs/evidence/ — 証拠地図

文献探索の報告から起票者が起こした**証拠地図**と、その元の報告、機械照合の結果を置く。
分担は F 2026-10-03 の決定による。起票者が地図を起こし、機械で照合し、利用者が原典を確かめる。
**照合が済むまで、地図を提案カードの生成会話へ渡さない。**

## 置き場の構成

| 経路 | 中身 |
|---|---|
| `docs/evidence/<日付>-<地図の記号>-<内容>.md` | 地図。見出しの前に `**種類:**` の欄を持つ（新様式） |
| `docs/evidence/_template.md` | 地図の雛形。様式の正本で、様式の検査はここの「検査が見る項目」と同じ項目を見る |
| `docs/evidence/reports/` | 元の報告。**手を加えずに置く**（末尾の改行の有無も変えない）。地図の `**元の報告:**` の sha256 はこの中身の値である |
| `docs/evidence/verification/<地図の名前>.json` `.md` | 照合の結果。JSON は機械が読む形、Markdown は人が読む要約 |

命名の規則: 地図は `日付-地図の記号-内容.md`（例 `2026-10-18-C-d2p-interface.md`）。日付は起こした日、
記号は地図の系統（A・B・C・N など）、内容は問いの短い英語。照合の結果は地図と同じ名前で `verification/` に置く。

**起票者用の文書（報告者の解釈と提案、作業メモ）は repo に置かない。** 地図は報告に書かれた事実だけを載せる
（雛形の §0.2）。

## 照合（書誌 ID の実在と書誌）

一つの命令で一つの地図を照合する。

    make evidence-verify MAP=docs/evidence/2026-10-18-C-d2p-interface.md
    # 同じこと。終了コードを見分けるときはこちら
    .venv/bin/python tools/verify_evidence_ids.py docs/evidence/2026-10-18-C-d2p-interface.md

| 終了コード | 意味 |
|---|---|
| 0 | 不在も到達不能も無い |
| 1 | 不在が一件以上ある（到達不能は無い） |
| 2 | 使い方の誤り・地図が読めない |
| 3 | 到達不能が一件以上ある |

`make` 経由では 0 以外がすべて make の終了コード 2 になる。

問い合わせずに抽出した ID だけを見るには `--extract-only`（地図のファイル名・種別・ID のタブ区切り）。

### 抽出の規則

- DOI: `10.` で始まり（`10.<4〜9 桁>/`）、空白・全角の括弧・読点・句点・表の区切り `|`・バッククォートの前で切る。
  末尾の ASCII の句読点と、対応の無い閉じ括弧は外す。大文字小文字は書かれたまま残し、比べるときは区別しない
- arXiv ID: 新形式（4 桁.4〜5 桁）だけ。前が英数字・下線・点のもの、後ろが数字のもの、DOI の内側のものは拾わない
  （`10.1109/TMI.2016.2593957` の `2016.25939` を拾わないため）。版（`v2`）は外す
- 同じ ID は一つにまとめ、現れた行をすべて残す。照合は ID ごとに一度

### 照合先と作法

| 何を | どこで |
|---|---|
| DOI の実在 | doi.org の handle（`/api/handles/<DOI>`。responseCode 1 が在る、100 が無い）。**登録機関によらない** |
| DOI の登録機関 | doi.org の `/doiRA/<DOI>` |
| DOI の書誌 | 登録機関が Crossref なら Crossref の REST API、DataCite なら DataCite の REST API |
| arXiv の実在と書誌 | arXiv の API（`/api/query?id_list=...`）。一つの地図の ID をまとめて一回で引く |

- 問い合わせに連絡先（メールアドレスなど）を入れない。User-Agent は `egosurgery-evidence-verify/1.0`
- 照合先ごとに逐次に引き、間隔をあける（arXiv 3.1 秒、ほか 1 秒）。arXiv は 3 秒に 1 回・接続 1 本、
  Crossref の公開の枠は 5 件／秒・同時 1 本（各サービスの文書による）
- 429 と 5xx は 10・30・60・120・300・600 秒と待って引き直す（尽きるまで最長 約 19 分）。接続できないときは 5 秒待って
  一度だけ引き直す。尽きたら到達不能。arXiv の 429 は `Retry-After` を返さず、4 分あけても続き 10 分あけると戻った
  （2026-10-19 の実測）

### 五つの分類

| 分類 | 意味 |
|---|---|
| 実在・書誌一致 | 照合先が在ると答え、地図の行の題名と著者のうち比べられたものがすべて一致した |
| 実在・書誌に差 | 照合先が在ると答え、題名か著者のどちらかが一致しなかった（差の中身は結果の `title`・`authors` にある） |
| 実在・照合不能 | 照合先が在ると答えたが、比べられなかった。地図に比べる行が無い、行に題名も著者も無い、照合先が書誌を返さない、のいずれか |
| 不在 | 照合先が**無いと答えた**（DOI は handle の responseCode 100、arXiv は応答の feed に該当の entry が無い） |
| 到達不能 | 判定に使える応答を得られなかった（接続できない、429・5xx が続いた、想定外の応答）。**不在と混ぜない** |

掲載先の違いは分類に入れない。照合先の掲載先と地図の掲載先を、参考として結果に並べる。

### 地図のどの記載と比べるか

- 列の見出しに `ID` と `文献` と書誌 ID の列（「書誌 ID」または DOI・arXiv を含む見出し）を持つ表の行のうち、
  **その ID が書誌 ID の列に書かれた最初の行**と比べる。使った行の ID と行番号を結果の `map_row` に残す。
  ほかに同じ ID を持つ行は `other_rows` に並べる
- 注記や出所の欄に書かれた別の文献の ID は、その行の文献の書誌とは比べない。本文や書誌 ID の列の無い表にしか
  現れない ID は「実在・照合不能」になる
- 「文献」の欄は「著者 年, 題名」と読む。全角の括弧の中は注記として外す。年が無く「〜ほか, 題名」の形も読む。
  どちらでもなければ著者も題名も無いとする（推測で埋めない）

### 書誌一致の判定規則

両側に同じ正規化を当てる。発音記号を外し（NFKD）、大文字小文字を揃え（casefold）、英数字以外（空白・記号・ハイフン）を
除く。HTML のタグと実体参照は先に外す。複合姓（Abu Farha）や発音記号（Lüddecke、Gaël）を片側だけ正規化すると
差と誤る（前回の照合の誤検出）。

- **題名**: 照合先の題名が地図の題名に含まれれば一致（全体）。地図の題名（4 文字以上）が照合先の題名に含まれれば一致（部分。
  略称や副題の省略）。どちらでもなければ差。Crossref の副題は「題名: 副題」も候補にする
- **著者**: 地図の名前が照合先の著者に当たるとは、正規化した名前が姓または氏名と等しいか、二文字以上の余りを残して
  姓で始まる・終わるか、姓が地図の名前で終わる（二文字以上の余り）こと（Li と Lin を取り違えない）。arXiv は氏名だけを
  返すため、最後の語を姓とする
  - 地図が「〜ほか」と書いたとき: 「ほか」の前の名前が、照合先の同じ位置の著者に当たれば一致
  - 「ほか」が無いとき: 地図の名前すべてが照合先の誰かに当たり、照合先の著者すべてが地図の誰かに当たれば一致。
    片方に余りがあれば差（人数の違いも差）
- 地図の行に題名も著者も無ければ照合不能。片方だけあれば、あるほうで決める

## 様式の検査

    make evidence-check                                          # docs/evidence/ の地図すべて
    make evidence-check MAP=docs/evidence/2026-10-18-N-novelty.md
    .venv/bin/python tools/check_evidence_map.py <地図>.md ...  # 終了コード 0 違反なし / 1 違反あり / 2 読めない

見出しの前に `**種類:**` の欄を持つ文書だけを検査する（雛形・旧様式の地図・報告・照合の結果は対象外として表示する）。
見る項目は雛形の「検査が見る項目」と同じで、食い違わないことを `tests/test_check_evidence_map.py` が縛る。

- 見出しの前の五つの欄（版・種類・状態・元の報告・検索日）と、種類の値（`探索の地図` / `新規性の照合`）
- 種類ごとの必須の節（見出しの語で探す。番号は問わない。コードの囲みの中の見出しは数えない）
- citation の印の残骸（`turn1view1` の形、`【…†…】`、`filecite`）と私用領域の文字（U+E000〜U+F8FF）
- BMP 外の文字
- 禁止語。**規約（`context/conventions.md` の proposal_gate）から読む。写しを持たない**（`tools/check_proposal.py` の関数を使う）
- `**元の報告:**` の欄で `sha256` の後に書いた値が、64 桁の小文字十六進で、`reports/` の実在のファイルの要約値と一致する

違反があっても**地図を直さない**。記録して利用者に諮る。

## 版の扱い（v1）

旧様式の地図（見出しの前に `**種類:**` が無いもの。2026-09-16 の地図 A・B）は**削除も書き換えもせず残す**。
後継の地図があるものは、表題の行の直後に v1 であることと後継の経路を一文で明記する（地図 B の v1 に済み）。
旧様式の地図は様式の検査の対象外である。
