### 主経路（推奨・チャンクサイズに依存しない「§11 先置き」方式）

子ページ保全（§11 の 23 本タグを最初の `replace_content` に含める）と、1 回出力上限への耐性を両立させるため、**§11 を最初に置いてから前後を継ぎ足す**。

1. **`replace_content`**（本体 `361ee4d4`）—— `new_str` = ファイルの **910〜965 行目だけ**（§11 セクション：見出し ＋ 23 本の `<page url>` タグ ＋ §11.21 横断的知見）。
   - これは約 3K と小さく 1 回で確実に出せる。ページは「§11 のみ」になり、**23 本の子ページが保全**され、旧バナー・旧本文はすべて消える。

2. **`insert_content` `position: start`** —— §11 の手前に §0〜§10 を入れる。`content` = ファイルの **2〜909 行目**（概要 blockquote 〜 §10 末尾）。
   - 1 回上限を超える場合は分割し、**後ろのブロックから先に** start 挿入する（例：先に「§6〜§10」を start 挿入 → 次に「§0〜§5」を start 挿入 → 結果は §0〜§5, §6〜§10, §11 の正順）。start 挿入は常に先頭に積まれるため、逆順に入れると最終的に正順になる。

3. **`insert_content` `position: end`** —— §11 の後ろに §12〜§16 を足す。`content` = ファイルの **966〜1589 行目**（§12 ＋ §13 ＋ §14 ＋ §15 ＋ 関連ページ ＋ §16）。
   - 1 回上限を超える場合は **前のブロックから順に** end 追記する（例：先に「§12〜§13」→ 次に「§14〜§16」）。end 追記は順序どおりに積まれる。

各挿入後に `fetch` で順序（§0→…→§16）を確認してから次へ進むと安全。テーブルはすべて新規 content 側にあり、サーバーがブロックに変換するため `old_str` 照合は一切不要。
