# task — TASK 契約の実行

## 実装系について

この手順は実装系に依存しない。Claude Code では `/task <task_id>`、
Codex では `$task` または本ファイルを読ませることで同じ手順を実行できる。

検査は `make task-validate` と `make task-preflight` が行う。
**判断を実装系に委ねる箇所は無い。** 手順書が求めるのはコマンドの実行と、
終了コードと状態表示に従った停止だけである。

利用者に選んでもらう箇所（「0. 始める」の汚れの扱い）は、選択肢を番号つきの文で示し、利用者の返事を待つ。
選択の画面を持つ実装系でも持たない実装系でも、同じ書き方で成り立つ。

## 命令の書き方

実装系によっては命令ごとに新しいシェルが起きる。前の命令で読み込んだ
仮想環境や資格情報は次へ引き継がれない。したがって手順書のすべての命令は
単独で実行して完結する形で書き、読み込みは同じ命令の中に入れる。

実装系による差は次のとおり。

- シェル: 引き継がれない実装系がある。命令は単独で完結させる。
- 通信: 外部への通信で承認を求められることがある。承認して進む。
- 履歴: 頁送りが無いホストがある。履歴を読む操作は `git --no-pager` を使う。

## 使い方

    /task T-YYYY-MM-DD-slug

## 手順（この順序を変えない）

**この手順書は、`/task` を受けた時点でホストが居る分岐の版で動く。** task-start が新しい分岐へ
切り替えても、読み込み済みの手順は変わらない。手順書の改訂が各ホストに効くのは、居る分岐に統合が入ってからである。

### 0. 始める

利用者は識別子を一行渡すだけでよい。分岐の確認、作業ツリーの確認、抑止の目印、契約の取り込みは
ここで行う。**状態は終了コードではなく、読み取りだけの命令で先に調べて判定する。**
`task-start` の終了コード 3 は五つの原因を兼ね、`make` 経由では失敗がすべて 2 に潰れるためである。

`<task_id>` が `T-YYYY-MM-DD-<slug>` なら、この契約の分岐は `feat/<slug>` である（task-start と同じ規則）。

    cd "$(git rev-parse --show-toplevel)" && git branch --show-current && git --no-pager status --porcelain --untracked-files=all && git branch --list "feat/<slug>" && git --no-pager ls-remote --heads origin "refs/heads/feat/<slug>" && git --no-pager log --all --oneline -1 -- "tasks/<task_id>"; ls -d "tasks/<task_id>"; cat .sync-pause

上の出力から、**次の順に**判定する。先に当たったものだけを行う。

1. **再開**: 現在の分岐が `feat/<slug>` で、`tasks/<task_id>/` が在る → 0 を飛ばして「1. 読む」へ。
   目印の有無と中身を記録する。目印が無ければ、task-start と同じ形の所有の記録で置く（「5. 実行する」）
2. **分岐の重複**: `feat/<slug>` が手元か遠隔に在るのに現在の分岐ではない、または `tasks/<task_id>` の履歴が
   別の分岐に在る → **停止して利用者に伝える。自動で分岐を切り替えない**
3. **detached HEAD**: 現在の分岐の表示が空 → **停止して利用者に伝える**
4. **汚れ**: `status --porcelain` が 1 行以上 → 一覧を分類して利用者に示し、選んでもらう（下記）。
   **選ぶまで task-start を呼ばない**
5. **清浄**: どれにも当たらない → 仮想環境と資格情報の読み込みと task-start を同じ命令で行う

       source .venv/bin/activate && source scripts/load_env.sh && make task-start TASK=<task_id>

6. **task-start の失敗**: 出力に `[task-start] 完了。` が無い → **出力をそのまま示して停止する。**
   巻き戻しは task-start が行う。原因は終了コードではなく `[task-start]` の行で読む

**汚れの扱い。** 一行ずつ、次の三つで分類して示す。

| 分類 | 見分け方 |
|---|---|
| 追跡下の変更か未追跡か | `status --porcelain` の先頭 2 文字が `??` なら未追跡 |
| 禁止領域に属するか | 経路が `experiments/`、`data/`、`runindex/` で始まる |
| 大きさ | `du -sh -- <経路>` |

利用者に次の選択肢を番号つきの文で示し、返事を待つ（どちらの実装系でも、選択は利用者の返事で受け取る）。

1. 未追跡のうち禁止領域に属さないものを repo の外（`~/m2-evacuated/<task_id>/`。経路の階層を保つ）へ**移して**退避し、task-start を**一度だけ**やり直す
2. 利用者が自分で片付けてから、もう一度 `/task` を受ける
3. 中止する

**消さない。** 追跡下の変更と、禁止領域に属するもの（同期処理が全台へ配るため、移すと他の台でも消える）は
退避の対象にせず、利用者の判断を待つ。退避したら、退避先と一覧を `audit.md` に記録する。
戻すかどうかは、報告の後に利用者へ確かめる。

**目印の記録。** task-start の表示のうち、どちらが出たかを記録する。「8. 終える」で使う。

- `[task-start] .sync-pause を作成` → この契約が置いた目印である
- `[task-start] .sync-pause は実行前から存在するため触れません` → 別の抑止が効いている
  （利用者の保守の可能性がある）。**利用者に伝え、続けるかを確かめる**

### 1. 読む

- `tasks/<task_id>/spec.yaml`
- `tasks/<task_id>/SPEC.md`
- `kind: exp` なら `tasks/<task_id>/prereg.md`

契約が `tasks/<task_id>/` に無い場合、配布台帳から取得する。

    source scripts/load_env.sh && make task-notion TASK=<task_id>

取得と検証までを行う。失敗したらそこで停止し、出力をそのまま報告する。
**本文の要約値が一致しない場合は取り込まない。** 台帳が本文を改変した可能性がある。

### 2. 検証する（L1 + L2）

    make task-validate TASK=<task_id>

**exit != 0 なら、ここで停止して報告する。** 修正を推測で行わない。
WARN が出た場合は、内容をユーザーに提示してから続行の可否を尋ねる。

### 3. 参照を解決する

| spec の記載 | 解決先 |
|---|---|
| `inputs.denominator.ref` | `runindex/experiments.csv` から実測値・n_seeds・split を取得 |
| `inputs.sigma_policy`（省略時） | `context/conventions.md#sigma` の既定値を継承 |
| `inputs.frozen_source.ref` | ckpt の sha256 を照合 |
| `contract.inject_verbatim` | `context/conventions.md` の該当アンカーの**原文** |

解決結果は `RESULT.md` の「1. 解決された参照」に記録する。
**要約してはならない。原文をそのまま使う。**

### 4. L3 プリフライト（実行直前）

    source .venv/bin/activate && make task-preflight TASK=<task_id>

**終了コードが 0 でなければ、ここで停止して報告する。** 出力をそのまま提示すること。
検査項目を自分で判断してはならない。何を検査するかは契約と検査器が決める。

`SKIP` は「合格」ではなく「実行されなかった」を意味する。SKIP された項目があれば、
その一覧を報告に含める。

`WARN` は「該当があった」を意味する。**合格ではないが停止の根拠でもない。**
`P9 spec_lint` は契約の本文を走査して起票者の既知の誤りを出す（層 4 の二重の網）。
契約の誤りは実行者の責任ではないため終了コードを変えない。**該当があれば報告に含める。**
起票者の誤りは 4 層で捕まえる。各層が何を守るかは `tasks/README.md` の
「起票者の誤りは 4 層で捕まえる」を参照。**文言による自制は働かなかったため機械にした。**

`P6 decisions_answered` が FAIL なら、出力に列挙された項目をユーザーへ提示して停止する。
**自分で決めてはならない。**

### 5. 実行する

#### 実行前に自動同期を止める（契約の禁止事項を守るため）

常駐する `m2-sync.sh` は 30 分ごとに **実行者の操作なしで作業分岐へ `origin/phase0` を
統合し、push し、Draft PR を作る。** 契約は「統合しない / 自動統合を有効化しない」を
禁止事項に置くため、実行者がどれだけ気を付けても守れない。実際に統合された記録がある
（`~/claude-sync/sync-alerts.log` の `auto-merge: feat/canonical-index-refresh <- origin/phase0`）。

**目印のファイル（repo 直下の `.sync-pause`）で止める。目印は「0. 始める」の task-start が置く。**
中身は所有の記録（`task_id=<task_id>` と `branch=feat/<slug>` の 2 行）で、「8. 終える」の道具が読む。

task-start を経ずに契約の分岐で作業を始めた場合（「0. 始める」の再開で目印が無かった場合など）に限り、
**task-start と同じ形の所有の記録で**置く。中身の無い目印は道具が外せない。

    printf 'task_id=%s\nbranch=%s\n' "<task_id>" "feat/<slug>" > .sync-pause    # task-start を経ない場合だけ

置いてある間、`m2-sync.sh` は分岐へ一切書き込まず、毎ループ記録だけ残す。
常駐処理そのものは止まらないので、外せば次のループから元に戻る。
目印は `.gitignore` 済みで、同期の総取り規則 `**` にも落ちるため **その 1 台にだけ効く。**

実装は目印の**存在だけ**を見ている（`scripts/sync/m2-sync.sh` の `[ -f "$M2DIR/.sync-pause" ]`）。
中身も時刻も見ないので、所有の記録を書いても抑止の挙動は変わらない。外し方は「8. 終える」に従う。

隔離の場で実物のスクリプトを走らせて双方向を測った（2026-08-11 lecun）。
抑止があるとき分岐の先頭は動かず behind も減らない。**別名へ移した後は先頭が進み、
記録に `auto-merge` と `auto-push` が出る。**

🔴 **外し忘れると、そのホストだけ自動同期が止まったままになる。** 他ホストの更新が
入らず、commit も push されない。止まっていることは記録に出る。

    grep '一時停止中' ~/claude-sync/sync-alerts.log | tail -3

**この抑止は `origin/phase0` に届いてから効く。** keeper は毎ループ `origin/phase0` から
`~/bin/m2-sync.sh` を自己更新するため、phase0 に無い版は稼働中の常駐処理に反映されない。
届く前は目印を置いても止まらない。稼働中の版が対応済みかは次で確かめる。

    grep -c sync-pause ~/bin/m2-sync.sh    # 0 なら未対応

- `plan.phases` の順に実行する。
- `plan.gates` は `after` で指定されたフェーズの直後に評価する。
  - `on_fail: stop` — 停止して報告
  - `on_fail: ask` — ユーザーに判断を求める
  - `on_fail: skip` — 以降のフェーズを飛ばして報告
- `outputs.stamp.task_id_in` が指定されていれば、生成される設定ファイルに
  `task_id` を書き込む。これが指示書と run を結ぶ唯一の鍵である。

### 6. 報告する

報告は 2 つ書く。**同じ結果を、人が読む形と機械が読む形で別々に書く。**

| ファイル | 何を書くか |
|---|---|
| `tasks/<task_id>/RESULT.md` | 散文。解決した参照、判断の理由、実測の経緯 |
| `tasks/<task_id>/result.yaml` | 事実だけの対。様式 `tasks/_schema/result.schema.json`、雛形 `tasks/_templates/result.yaml` |

散文から値を機械で抜こうとしない。**書き手が最初から対で書く。**
`issuer_defects` を空にしない。型は `check_does_not_check`
`asserted_without_measuring` `self_contradiction` `shell_assumption`
`asymmetric_comparison` `rule_read_narrowly` である（正本は `tasks/_schema/result.schema.json`）。

**報告の版 3 は `positive_controls` を要求する。空にできない。**
判定が通ったことは、その判定が働いていることを意味しない。主要な判定について
**何を入力すれば失敗するはずか**（`breaking_input`）と**実際に何が起きたか**
（`observed`）を対で書く。測っていない場合は `observed` に `UNKNOWN` と書く。
版 1 と版 2 の過去の報告には要求しない。**過去を書き換えて通す方法は採らない。**

**生成物は作り直さない。phase0 への統合の後に自動で作り直される**
（`.github/workflows/regen-projections.yml`）。契約の分岐で作り直すと並行する契約と衝突し、
作り直さずに鮮度の検査を回すと自分の報告の分だけ必ず差分が出て落ちるためである。
投影に現れることは、統合の後に phase0 の上で確かめる。

**`deviations` セクションを空にしてはならない。** 指示書どおりに実行できなかった箇所、
自分で判断した箇所を必ず書く。逸脱が無い場合は「なし」と明記する。
このセクションが次の指示書の品質を決める。

#### 禁止領域に触れていないことを確かめる

**契約ごとに検査の命令を書かない。道具を使う。**

    source .venv/bin/activate && make forbidden-check

生成物（投影と集約結果）は禁止領域の内側にあるため、素朴に「差分が空であること」を
求めると**生成と両立しない**。道具は生成物を除外してから検査する。除外する場所は
生成器の実装から取るため、生成物が増えても古くならない。

生成物への手編集はこの検査では捕まらない。**再生成との差分で捕まる**
（`make taskindex-check` と `make inbox-check`）。**この 2 つは phase0 の上で使う道具であり、
契約の分岐では回さない。** 分岐の生成物は古いままなので、回すと必ず落ちる。

#### 生成物が併合で衝突したとき

**契約の分岐では作り直さない。** 契約は統合を禁じるため分岐では併合が起きず、
phase0 側の併合の後は自動で作り直される。`.gitattributes` が行を統合する組み込みの
方式を指定しているため、**衝突もしない。**

詳細と方式ごとの実測は `tasks/README.md` の「生成物の合流」を参照。

#### 報告を配布台帳へ送り返す

投影は索引の更新を待つため、**完了直後の受け渡しには使えない。** 契約が台帳経由で
即座に届いているのと同じ経路を、逆向きに使う。

    source scripts/load_env.sh && make task-report TASK=<task_id>

**送るのは記録して起票したあとである。** 順序の理由は 2 つある。送信は取り消せない
ため版管理に残ってから送るほうが安全であり、PR 番号まで含んだ報告を送れる。

送信が失敗しても**契約の完了は妨げない。** 失敗したら報告に含める。

🔴 **秘匿の検査で止まったら、本文を直してから送り直す。検査を無効にしない。**
外部へ送るのは一方向で取り消せない。検査は環境にある資格情報そのものが本文に
現れるかを直接照合する（値は出力しない）。

台帳は起票者が即座に読める。**人が転記する必要はない。** ただし
**台帳へ送っただけでは版管理に残らない。** 報告そのものは従来どおり記録すること。

対話で出た判断は、**その契約の記録へ 1 行で置く。**

    tasks/inbox.d/<task_id>.md

集約結果 `tasks/inbox.md` は `make inbox` が生成する。**手で編集しない。**
契約ごとに別のファイルへ書くため、並行して進む契約が同じ場所を書き換えず、
併合しても元の記録は衝突しない。集約結果は統合の後に自動で作り直される。

**1 契約 = 最低 1 行。** 置くものが無い場合も「なし」と書いた行を残す。
書式は `tasks/README.md` の「判断の受け皿」を参照。

台帳へ送ったら「8. 終える」へ進む。

### 7. 禁止事項

- 検証エラーを推測で修正しない
- `decisions_required` を自分で決めない
- 未測定の値を書かない（UNKNOWN と書く）
- `runindex/` を手で編集しない
- `tasks/inbox.md` を手で編集しない（`tasks/inbox.d/` へ書く）
- 数値を捏造しない
- **外部への送信を `make task-report` 以外の経路で行わない**
- **履歴を読む操作で頁送りの回避を省かない**（`git --no-pager`）
- **抑止の目印を手で置かない・手で外さない。** 置くのは task-start、外すのは `make task-release` である。
  例外は二つだけ。task-start を経ずに分岐で作業を始めた場合に所有の記録つきで置くこと（「5. 実行する」）と、
  「8. 終える」の `OWNER_UNREADABLE` で始めに「作成」と表示されていた場合に外すこと
- **抑止を外した後に、git の状態を変える操作をしない**（「8. 終える」）

外部への送信を 1 つの経路に限る理由。**送信は一方向で取り消せない。**
秘匿の検査は `make task-report` の内側にあるため、別経路で送ると検査を通らない。
資格情報が本文に現れていないかを、環境にある値そのものと照合している。

頁送りの回避を省かない理由。**対話用の頁送りが無いホストがある。**
そこでは命令が失敗するが、**失敗しても終了コードを見る検査は空振りする。**
`make agent-check` が文書側でこの規則を強制する。

### 8. 終える

契約の終わりに、「0. 始める」の task-start が置いた抑止を道具で外す。**終わり方は二つ。**

- **完了**: commit、push、PR の起票、`make task-report` を済ませた後に呼ぶ

      make task-release TASK=<task_id> END=complete

- **中止**: 完了せずに終えるとき（検証やプリフライトの失敗、gate の `stop`、利用者が止めた）に、理由をつけて呼ぶ

      make task-release TASK=<task_id> END=abort REASON="<理由>"

**利用者に問い合わせて、同じセッションで続けるときは呼ばない**（gate の `ask` など）。
**完了の前提を満たせないとき、自分で中止へ切り替えない。** 利用者に諮る。

完了の前提は五つで、**すべて**満たすときだけ外れる。現在の分岐が `feat/<slug>` であること、
追跡下に未 commit の変更が無いこと、遠隔の分岐の先頭が HEAD と一致すること、phase0 向けの PR が在る
（開いているか統合済み）こと、`tasks/<task_id>/RESULT.md` と `result.yaml` が HEAD に含まれること。
台帳の状態は前提に含まない。

**結果は一行の状態表示（`task-release: <状態> ...`）で判定する。** `make` 経由では失敗が make 自身の
終了コード 2 に潰れるため、終了コードでは判定しない。状態の一覧は `scripts/task_release.py` の冒頭と同じである。

| 状態 | 扱い |
|---|---|
| `RELEASED` | 終わり。外れた |
| `ABSENT` | 終わり。目印は元から無い |
| `PREREQ_MISSING` | 名指しされた前提を満たしてから、もう一度呼ぶ。満たせなければ利用者に諮る |
| `PREREQ_UNKNOWN` | 照会の失敗である。一度だけやり直し、変わらなければ利用者に伝える |
| `OWNER_UNREADABLE` | 「0. 始める」の task-start が「**作成**」と表示していた場合に限り、手で外す（下記）。「**実行前から存在**」と表示していた場合は外さず、利用者に伝える（人が保守で置いた目印を外さないため） |
| `OWNER_MISMATCH` | 外さない。別の契約の目印である。利用者に伝える |
| `POSITION_MISMATCH` | 外さない。repo の位置が `m2-sync.sh` の読む位置と違う。利用者に伝える |
| `RELEASE_FAILED` | 外れていない。実行基盤が削除と移動を拒んだ可能性がある。迂回せず利用者に伝える |
| `USAGE` | 外れていない。命令の書き方を直してもう一度呼ぶ。直せなければ利用者に伝える |

`OWNER_UNREADABLE` で外してよい場合だけ、次のどちらかで外す。外した後に目印が存在しないことを確かめる。

    rm -f .sync-pause                      # 削除できる環境
    mv .sync-pause .sync-pause.released    # 削除が実行基盤に拒否される環境（中身を書き換える方式は効かない）

**外した後に、git の状態を変える操作をしない。** 外すと `m2-sync.sh` が次のループから作業分岐へ統合と
push を行うためである。状態を変えない確認は、commit の前に済ませておく。

**外した結果は版管理にも台帳にも残らない。** 最後の応答で、状態表示の一行をそのまま利用者に伝える。
